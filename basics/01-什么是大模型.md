# 01 什么是大模型：一台读了整个互联网的完形填空机器

> 本篇面向零基础的读者：会写 Python，但对 LLM 的全部印象来自「能聊天、很神奇」。
> 读完你会获得：一套能 30 秒讲清「大模型是什么」的话术，以及 token / 预训练 /
> 指令微调 / RLHF / Prompt / 温度 / 参数规模这一串基础概念——它们是后面所有
> 深水区文章的入场券。

## 一、一句话定义：完形填空机器

把大语言模型想成一台**读了几乎整个互联网的完形填空机器**。

你给它一句话的前半段，它续后半段。它不是先「想清楚再写」，而是实打实地在给
**下一个词**算一个概率分布：

```text
输入：「中国的首都是 ___」

模型内部：下一个词是「北京」的概率 97%、「上海」1.2%、「南京」0.8%……
抽一个（通常抽概率高的）→ 填上 → 新文本塞回来，继续填下一个空
```

你看到的每句流畅回答，都是这个填空循环一口气重复了几百上千次的结果。
这个「填下一个空」的动作，学术名字叫 **next-token prediction**（下一个
token 预测）。它是理解整个 LLM 世界的唯一钥匙。

## 二、token：模型嘴里的「词」不是你以为的词

先说「空」里填的是什么。模型不直接处理汉字或英文单词，它处理 **token**——
文本切碎后的最小单位。

- 英文：常见整词是一个 token（`cat`），长词会被拆成几块
  （`unbelievable` → `un` + `believe` + `able`）。
- 中文：常见字/词组各占一两个 token（`北京` 大概率是一个，`䶮` 这种生僻字
  可能要被拆成好几个）。

一个粗略的换算：**中文 1 个 token ≈ 0.5–1 个汉字，英文 1 token ≈ 0.75 个单词**。
看到「上下文 128K tokens」，心里换算成「大概几万汉字」就有数了。

拆词的这个动作叫 **tokenization**（词表构建算法叫 BPE），它有一个经典翻车
现场——**让模型数 `strawberry` 里有几个 r**。模型经常答错，不是它蠢，是它
眼里根本没有「r 出现三次」这回事：`strawberry` 在词表里是
`straw` + `berry` 两个 token，字母级别的「r」在训练数据里从未成为统计单位。
人类靠字母看世界，模型靠 token 看世界，粒度不同，错得有道理。

## 三、为什么「填下一个空」能长出智能

这是最重要的一段直觉，值得多读两遍。

只学「预测下一个词」，模型想拿高分，就必须一层层升级自己的能力：

1. **先学会语法**：「我吃了一碗 ___」后面该接名词，接动词就离谱。
2. **再学会事实**：「中国的首都是 ___」想填对，得真的「记得」北京。
3. **还得学会推理**：「小明有 3 个苹果，吃了 1 个，还剩 ___」想填对，
   得潜移默化掌握「3 - 1 = 2」这套操作。
4. **甚至学会风格和意图**：接在「帮我写一封辞职信：」后面，该切到公文腔。

互联网上万亿词的填空训练，等于让模型考了无数次超纲开卷速答。
为了押对下一个词，它被迫在内部压缩出语言规则、世界知识和推理套路。
**填词只是表面动作，压缩出对世界的内部表示才是副产品——我们说的「智能」，
就是这个副产品在发光。**

这也解释了一个反直觉的现象：模型没有被专门教过编程，却会写代码——
因为预测 GitHub 上几亿行代码的下一个字符，等价于被迫学会语法和常见算法。

## 四、三次范式跃迁：机器怎么一步步学会填词

- **规则时代**（上世纪）：语言学家手写语法规则。句子稍微绕一点就崩，
  因为规则永远写不完整。
- **统计时代**（1990s-2010s）：数词频。「我上夜班，因为你白天 ___」，
  数历史文本里夜班后面最常跟什么。能用了，但只能看前几个词，
  遇到长句就失忆。
- **神经网络时代**（2017-）：Transformer 登场（下篇专门讲），
  模型可以看一眼整个上下文再填词，规模一上来，能力突然涌现。

ChatGPT 这一号产品，通用配方是四段式流水线，每一步角色一句话：

1. **预训练（Pretraining）**：在上面说的万亿词填空题上修炼，
   产出「什么都会一点、但不知天高地厚」的基座模型——这一步占了
   训练成本的 99%。
2. **指令微调（SFT）**：拿人工编写的「问题-好回答」对，教基座模型
   学会「听懂话、好好说」，从填空机变成聊天助理。
3. **对齐（RLHF/DPO）**：让人（或另一个模型）给它多个回答打分，
   用强化学习把「有用、诚实、无害」这套人类偏好写进模型的行为模式。
4. **推理（Inference）**：用户提问，模型循环做 next-token prediction，
   产出回答——你日常碰到的是这第四步。

## 五、日常使用的三个概念：Prompt、上下文、温度

- **Prompt（提示词）**：你发给模型的那段填空开场白。写得好不好，决定了
  模型被「激发」出哪部分能力——同一个模型，「写首诗」和「你是唐代诗人，
  用七言绝句写一首关于秋雨的诗」产出的东西天差地别。
- **上下文窗口（Context Window）**：模型一次能看到的 token 上限。
  超出窗口的内容会被从「短期记忆」里踢掉，和它长文本处理能力直接挂钩。
- **采样温度（Temperature）**：填词时抽选下一位选手的「胆量系数」。
  温度 0 永远选概率最高的（答案稳定、好复现，适合业务接口）；温度开高
  就敢从冷门候选里抽（答案飘忽、更「有创意」，适合写诗/头脑风暴）。

## 六、「大」有多大：参数规模的直觉

前面说模型内部「压缩了世界知识」，装这些知识的容器叫**参数**——
可以理解为模型脑回路里一个个可微调的小旋钮。

- GPT-3 的 175B 意思是 1750 亿个旋钮；现在主流的 7B/70B/405B，
  就是把旋钮个数按十亿计。
- 7B 是多大？如果每个参数用最常见的半精度（FP16）存，一个参数 2 字节，
  7B × 2 ≈ **14 GB 显存**——刚好塞满一张消费级显卡的内存条勉强能跑。
- 为什么「大就好」？旋钮越多，能记住的事实、能内化的推理套路就越精细；
  而且在训练数据管够的前提下，把模型造大是「涨能力」最确定的途径
  （scaling law 说的就是这件事）。

> 进阶指针：7B 级别的显存拆账（权重 + KV Cache 占比）是字节/滴滴必考

## 七、两个必须避开的误解

**误解一：大模型是个超大搜索数据库。**
不是。它没有把维基百科原文一张张存着，逐字检索给你。它背下的是
**压缩后的概率模式**——你问一个生僻问题，它大概率根本没「在哪儿见过」，
却也能现编出像模像样的答案。这也是为什么它会一本正经地胡说八道（幻觉）：
生成动作不查事实，只押下一个词谁最像。

**误解二：大模型在实时联网思考。**
默认不是。模型本身只会在本地（服务器上）做填空式推理，「联网搜索」
是外部系统把搜索结果当上下文塞进 Prompt 喂给它，属于应用层包装。
面试里把这两者混为一谈，会被资深面试官现场纠正。

## 八、▶ 面试挂钩：30 秒自我介绍话术

开场被问「介绍下大模型」时，别背论文、也别扯科幻，用这套三段式收尾：

1. **本质**：「大语言模型本质是一个超大规模的概率模型，训练目标是预测
   下一个 token 的分布；海量语料上训练后，它把语法、事实和推理模式
   压缩进了千亿级参数里。」
2. **管线**：「生产级产品通常走 预训练 → 指令微调 → 偏好对齐 三步，
   上线时逐 token 生成。」
3. **点一句工程敏锐**：「所以它的能力边界由 参数规模 × 数据质量 × 上下文
   决定，幻觉来源于它本质在做统计生成而非事实检索——这也是 RAG 和
   Agent 体系存在的根因。」

第三点最能立刻把你从「爱好者」区隔到「工程思维候选人」。
