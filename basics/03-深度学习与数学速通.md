## 一、神经网络到底在学什么：一个巨型可调函数

抛开所有名词，神经网络干的事只有一件：**拟合一个函数**。

输入 x，输出 y，中间是一大堆「矩阵乘 + 一点非线性」层层嵌套：

```text
第 1 层：h1 = f(W1 · x + b1)
第 2 层：h2 = f(W2 · h1 + b2)
第 3 层： y = W3 · h2 + b3
```

里面的 W、b 就是第一篇说过的「旋钮」（参数）。训练 = 拧这些旋钮，让
`预测值` 尽量贴住 `真实答案`。

类比：你去调一个**水枪旋钮阵列**——每个旋钮控制水流的一个分量，目标是
让水花恰好浇中远处一个形状诡异的靶子。你不可能手算出每个旋钮该拧多少，
只能：浇一次 → 看偏了多少 → 往回拧一点 → 再浇一次。神经网络训练就是
这个循环，只不过旋钮有几百亿个，「往回拧多少」由微积分（梯度）告诉你。

**为什么非线性 f 必不可少**：没有它，再多的矩阵乘叠起来也只等于一个
大矩阵，网络退化成一条直线，画不出水花、认不出猫。非线性是「让函数能
拐弯」的东西，ReLU 就是最简单的一个：负数归零，正数原样通过。

## 二、梯度下降：蒙眼下山

训练的目标叫 **loss（损失函数）**：离答案有多远。loss 越小越好——
把 loss 想成「离谷底的距离」，你就是那个蒙眼下山的人：

1. 站在当前参数的位置，**往四周探一探哪个方向最陡**（这一步就是
   算梯度，梯度的方向 = 上坡最陡的方向）；
2. **朝反方向迈一步**（上坡反方向 = 下坡方向，loss 会变小）；
3. 重复，直到四周都差不多平（谷底）。

**学习率（learning rate）= 步子大小**，它是训练里最关键的旋钮之一：

- 步子太大：在谷底两侧来回横跳，甚至一脚跨到对面更高的山坡上
  （loss 震荡、不收敛）。
- 步子太小：方向对但走得慢，走到天黑还没下山（训练慢、卡在小坡上）。

所以常见做法是**前期步子大、后期自动调小**（学习率调度，warmup + 衰减），
先快速冲到山谷附近，再小碎步摸到谷底。

## 三、反向传播：一句话说完

网络是层层嵌套的：最末层的 loss 出错了，**谁的责任**？

**反向传播 = 把误差按责任大小逐层记账回去。** 最末层先分自己的责任，
再往上一层问「你这个输出害我错成这样，你改多少能弥补」，一层层往前
追责，直到第一层。责任大的参数多拧，责任小的少拧。

背后的数学叫**链式法则**——面试里不需要你推出完整公式，只要答得出
「为什么不是乱拧」：因为每个参数对最终 loss 的影响可以被精确算出来
（这就是梯度），按梯度拧就是按责任分摊，方向永远朝着让 loss 降得
最快的一边。

## 四、三个必懂概念各一段

### softmax：把分数变成概率

模型最后一层会给词表里每个词（几万个）打一个「原始分」（logit），
分数有正有负、可大可小，没法直接当概率用。softmax 干两件事：**全部
指数化变正数，再归一化成总和为 1**。效果：第一名拿大头，第二名小头，
越冷门的分数被压得越低——指数天然的赢家通吃。第一篇里
「北京 97%、上海 1.2%」就是这么来的。

### 交叉熵：罚单，越自信的错罚越狠

填空的答案是唯一的（下一个词真是「北京」），模型却给了一个概率分布。
交叉熵只盯一件事：**你给真答案分了多少概率**。把罚单直觉记成这样：

- 真答案概率 0.9 → 罚单 ≈ 0.1（小意思）；
- 真答案概率 0.1 → 罚单 ≈ 2.3（肉疼）；
- 真答案概率 0.01 → 罚单 ≈ 4.6（罚到怀疑人生）。

它是对数函数，所以「越自信的错，罚得越狠」——这是所有大模型训练默认
用的 loss。

### 过拟合：背书背到了题目上

训练集分数刷满，一到考场（没见过的数据）就翻车——模型把**题目本身**
背下来了，没学会解题方法，这就是**过拟合**。三板斧应对：

1. **加大数据量**：题库大了，背题没用，必须学方法（最有效的正则）；
2. **dropout**：训练时随机「打晕」一部分神经元（比如 10%），强迫网络
   别把答案押在某几个特定通路里，像考试时老师随机抽题、背题海没用；
3. 早停 / 权重衰减等：看到验证集开始变差就踩刹车；给大参数额外罚单，
   逼着模型用简单方案。

## 五、矩阵乘法为什么是所有事情的底座

##### 一次打分 vs 批量打分

一个神经元对输入打分：`score = w·x + b`，本质是向量点乘。可训练时
**成万个神经元 × 成百上千条样本**要同时打分——一个一个点乘得算到
明年。矩阵乘法把这件事变成一次操作：

```text
每个样本一行特征 × 每个神经元一列权重 → 一个矩阵里全是分数
```

GPU 就是专门为「同时做巨量矩阵乘」造的机器（下一篇展开），
所以模型结构不管怎么演进，最后都会落成一堆矩阵乘。

动手走一遍 3×2 @ 2×4（输出行数取左矩阵、列数取右矩阵）：

```text
A (3×2)         B (2×4)
[1 2]           [1 0 2 1]
[3 4]     @     [0 1 1 0]
[5 6]

第 1 行第 1 列 = 1×1 + 2×0 = 1
第 1 行第 3 列 = 1×2 + 2×1 = 4
...

结果 C (3×4)：
[ 1  2  4  1]
[ 3  4 10  3]
[ 5  6 16  5]
```

口诀：**行对列，同位相乘再相加**。看懂这一个例子，看懂 95% 的面试矩阵题。

## 六、浮点精度直觉：FP32 / FP16 / BF16

一个参数在显存里要占字节，存得越精细、占得越多：

- **FP32**：4 字节，精度最高，但存 7B 参数就要 28GB——老黄历；
- **FP16**：2 字节，精度砍一半，缺点是**能表示的最大值只有 65504**，
  大模型里梯度偶尔冲得很大，一冲就溢出（变成 inf/NaN）；
- **BF16**：也是 2 字节，但**范围和 FP32 一样大、精度更糙**。换来的是
  「不容易溢出」，训练稳。

经验和口诀：**推理用 FP16 够了，训练主流用 BF16**——训练要扛偶尔
爆发的梯度，BF16 的「大范围糙精度」刚好踩中痛点，还能省一半显存带宽。

## 七、▶ 面试挂钩

**问题 1：训练 loss 不降了，先查什么？**
给面试官一份有序的 checklist（从「最常见」到「最隐蔽」）：

1. **学习率**：先降到 1/10 再观察——震荡 or 卡死，一半问题在这；
2. **数据本身**：标签错、数据集没 shuffle、输入特征过了奇怪的预处理；
3. **loss / metric 写错**：索引错位（softmax 维度错）、mask 没生效；
4. **梯度出了问题**：NaN/inf（BF16 反而在这救场）、梯度爆炸没 clip；
5. **模型太浅 or 任务太难**：换个更小任务过拟合单 batch，验证管线。

**问题 2：为什么需要非线性激活？30 秒答**
「没有它，任意层网络叠起来都等于一层线性变换，表达力只有线性模型；
加入 ReLU/GELU 后，网络从『只会画直线』变成『能画任意复杂曲线』，
深度才真正开始起作用。」

**问题 3：softmax 为什么能上能下？**
「把 logits 指数化拉开差距、再归一化成概率；指数带来赢家通吃，
配合交叉熵只惩罚真答案那一项概率——这两个函数是一对搭档。」
