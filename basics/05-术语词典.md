# 05 术语词典：大模型黑话一页通

> 本篇面向零基础的读者：读技术文档、听面经复盘、围观群聊行情时，
> 被 embedding / epoch / TTFT 这类词卡住的人。
> 读完你会获得：一张按主题分组的速查表——遇到不认识的词回来翻这一页，
> 每个词配一句人话解释和一根「想深挖去哪」的进修指针。

## 为什么大模型圈黑话这么多

这个领域是学术界、芯片厂、云平台、应用公司四拨人挤在一起盖出来的，
每拨人都带了自己的行话：学术派贡献 attention、logits、epoch；
芯片派贡献 HBM、FLOPS、带宽；工程派贡献 serving、TTFT、sampling；
产品派又贡献了 Agent、workflow、guardrail。它们说的是同一个东西，
但没人负责统一命名——于是出现了**黑话密度最高、入门劝退力最强**
的一份词汇表。

好消息是：日常高频出现的词其实不到一百个，而且绝大多数是「一句话就能
翻译成人话」的简单概念，只是被英文缩写包了一层壳。这篇词典做的事，
就是把那层壳剥掉。

## 怎么用这本词典

- **按场景查，别顺序背**。术语是工具不是课文：读到哪卡住就翻到对应分组，
  看懂一句话解释够用就走。
- **一句话解释只是入场券**。它保证你听得懂别人在说什么，不保证你能跟
  面试官聊三分钟——后者靠第三列的进修指针。
- **遇到嵌套深词先跳去读 01-04**。比如「logits 经过 softmax」里的
  softmax 不在这里收录，它在 [03 数学速通](./03-深度学习与数学速通.md)
  里；显存、带宽、FLOPS 的直觉在 [04 GPU 算力入门](./04-gpu与算力入门.md) 里。
- 全文按「你在什么场景会听到这些词」组织，每组先有一句场景导读。

## ▶ 面试挂钩：面试官说黑话接不住时的三种得体应对

面试里被陌生术语砸中不丢人，硬装懂才致命。按这个顺序救场：

1. **直问澄清（首选）**：「您说的 XX 是指 Y 场景下的那个用法吗？」
   一句精准的追问反而显得你有工程严谨性——资深工程师都先对齐术语
   再答题。注意是「带着猜测问」，不是干巴巴的「什么是 XX」。
2. **按上下文猜（次选）**：接不住的词多半有上下文提示。用
   「如果我没理解错，这里 XX 的作用是……」开头，边说边看面试官反应，
   给自己一个被纠错的台阶。
3. **承认边界（兜底）**：「这个词我目前只听过名字，没实际用过，但我猜
   它解决的是 X 类问题，对吗？」大方承认 + 顺手展示推理过程，
   比支支吾吾浪费三分钟体面得多。

记住：面试官用黑话不是为了考词典背诵，是想看你面对未知的反应模式。

## 高频混淆辨析：这几对词最容易被追问

速查表里的黑话单独出现都好认，真正的坑在对比题——面试官最爱挑
「长得像、其实差很远」的词组追问。提前把下面几对想明白：

- **epoch vs step**：epoch 是「整个数据集过完一遍」，step 是「更新一次
  参数」。一个 epoch 里有几百几千个 step，说「训练了几千步」和「训了几轮」
  是两回事，别混着报数。
- **SFT vs RLHF vs DPO**：SFT 教模型「照着标准答案做题」，RLHF 和 DPO
  教模型「两个答案里挑更好的」。前者是有标准答案的模仿，后者是偏好的
  排序——DPO 是 RLHF 的简化版，不用单独训奖励模型。
- **workflow vs Agent**：workflow 的步骤是人提前写死的，模型只在几个
  环节里填空；Agent 的下一步是模型现场决定的。判断标准一句话：流程图
  能不能在跑之前就画出来，能的是 workflow，不能的才是 Agent。
- **TP vs DP vs PP**：DP 是每卡一份完整模型、并行喂不同数据；TP 是把
  单层计算切到多卡；PP 是把不同层分到不同卡。记口诀：DP 切数据，
  TP 切宽度，PP 切深度。
- **retrieve vs rerank**：retrieve 求快求全——先把可能相关的几十条捞回来；
  rerank 求准——把这几十条精排，只留最相关的几条进 prompt。
  一个管「别漏」，一个管「别错」。

这五对覆盖了「训练流程 / 应用架构 / 并行方式 / 检索链路」四个高频话题，
面试前值得逐题对自己讲一遍。
