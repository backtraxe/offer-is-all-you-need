# 06 训练是怎么发生的：从背书机器到能聊天的助手

> 本篇面向读完 [01-什么是大模型](./01-什么是大模型.md) 和
> [02-transformer直观入门](./02-transformer直观入门.md) 的读者：你已经知道
> 大模型是「填下一个空」的机器、内部由注意力 block 堆成，现在想知道
> **参数是怎么被「喂」出来的、为什么出厂的大模型就会聊天**。
> 读完你会获得：预训练/SFT/RLHF 三段流程的一张总图，每个阶段改变了模型的
> 什么「性格」，以及面试里被问训练流程时的标准三段答。

## 一、一句话总览：三次塑造

把训练想成培养一个应届生：

1. **预训练（Pretrain）**——让他在图书馆**读完全人类的书**，
   学会语言本身和世界知识。此时他只会「接着往下背」，还不会对着人说话。
2. **SFT（监督微调）**——给他看**几万条「好员工示范对话」**，
   教他「别人问、你就答」的对台词感。此时他会聊天了，但答得好不好没人管。
3. **RLHF（人类反馈强化学习）**——给每次回答**打分**，鼓励高分、抑制低分，
   把他的「性格」往有用、诚实、无害上捏。

一句话记忆：**预训练给知识，SFT 给形式，RLHF 给性格。**

## 二、预训练：在海量文本上玩亿万次「填下一个空」

还记得 01 篇的那个核心动作吗——**预测下一个 token 的概率分布**。
预训练就是把这一个动作重复到天文数字规模：

```text
拿一段真实文本："巴黎是法国的首都"
遮住最后一个词 → 让模型猜
模型说"伦敦" → 错了 → 计算差距（loss）→ 反向传播微调参数
模型说"法国" → 对了 → 同样产生小梯度，让下次更自信
循环万亿次，参数慢慢从随机噪声变成「浓缩的互联网」
```

三个关键体感，面试里说出任何一个都加分：

- **规模**：当今旗舰模型的预训练语料在**十万亿 token**量级，
  相当于把公开网页、书籍、代码库洗净去重后全读一遍。
- **成本**：一次旗舰预训练要烧掉**几千张顶级 GPU × 几个月**，
  花费以千万美元计——这就是为什么「预训练一次失败的 checkpoint」
  是每个 Infra 团队的噩梦，checkpoint 和容错才那么重要。
- **产物**：预训练出来的叫 **Base Model（基座模型）**。它是一个
  超强的「补全机器」但不会对话——你问「法国首都是哪」，
  它可能续写成「的首都是哪里？法国的首都是巴黎。意大利的首都是……」，
  只会把话题延续下去，不知道「问句后面该给答案」。

## 三、SFT：给基座模型看「标准答案示范」

SFT（Supervised Fine-Tuning，监督微调）的数据长这样：

```text
{"输入": "法国的首都是哪？",
 "输出": "法国的首都是巴黎。它位于法国北部，是政治、经济和文化中心。"}
```

准备**几万到几十万条**这样的「问 → 好答」对，继续用同样的
「填下一个空」目标训练基座——区别只在于数据从「整段互联网」换成了
「精选对话」，而且通常只给**回答部分**计算 loss（教它答，不教它问）。

SFT 后模型发生的变化叫**解锁对话格式**（unlocking）：
基座里其实早就存着「巴黎是法国首都」这条知识，
SFT 只是教会它「人类这样问时，你应该这样答」。
这也是为什么几次里程碑工作（LLaMA-Adapter、LIMA 等）发现
**几千条高质量示范**就能让基座像模像样地聊天——
知识在预训练里，SFT 只拧「表达方式」这个旋钮。

**一个常被追问的推论**：既然 SFT 只教形式，那模型「胡说八道」的毛病
SFT 治不了根——内容对不对还得靠基座的知识和后面的对齐手段。
这就是为什么幻觉问题贯穿整个生命周期（延伸阅读里有专文）。

## 四、RLHF：用「打分」捏性格

SFT 之后的模型会聊天了，但有两个问题 SFT 解决不了：

1. **「好」很难写成标准答案**。「给这首诗写个点评」没有唯一正确输出，
   没法靠示范覆盖。
2. **「别说什么」没法靠教「该说什么」学到**。示范集里不会包含
   「如何制造危险品」的拒答样例的每一种变体。

RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）
的思路是把「好」变成**分数**：

```text
第一步：让人对同一问题的多个回答排序（A 比 B 好、C 最差）
第二步：训一个「奖励模型（RM）」，学会打和人一样的分
第三步：用强化学习（PPO / GRPO 等）调语言模型，
        让它产出高 RM 分的回答，同时别偏离 SFT 模型太远
```

RLHF 带来两个直观变化：**更听话**（指令遵循变好）、**更安全**
（拒答不该答的）；代价是**可能变得更「圆滑」**——过度对齐的模型
回答变长变虚、爱打太极（所谓 alignment tax），这是今年面试很爱聊的
权衡题。

## 五、把三段连起来看

```text
互联网文本 ──预训练──▶ Base Model（有知识，不会聊天）
                          │ + 几万条示范对话
                          ▼ SFT
                     SFT Model（会聊天，没分寸）
                          │ + 人类偏好评分 + 强化学习
                          ▼ RLHF
                     Chat Model（会聊天、有分寸、有性格）
```

真实工业流程还要在中间插很多小步骤（继续预训练、退火、多轮 SFT、
拒答数据、多轮 RL……），但骨架永远是这三段。
遇到任何「新训练范式」，先问一句：**它替换了哪一段、
改了数据还是改了目标？**——这下你就能把新论文挂回地图上了。

## 六、▶ 面试挂钩

**问题 1：预训练、SFT、RLHF 分别给模型带来什么？30 秒答**
「预训练注入语言能力和世界知识，产物是只会续写的基座；
SFT 用示范对话解锁问答格式，产物是会聊天的 SFT 模型；
RLHF 用人类偏好打分做强化学习，把性格往有用、诚实、无害上对齐。
一句话：预训练给知识，SFT 给形式，RLHF 给性格。」

**问题 2：为什么 SFT 只需要几万条数据，预训练要万亿 token？**
「因为知识主要在预训练注入，SFT 解决的是『表达方式对齐』——
同一个知识用对话格式说出来。形式这个自由度远小于知识本身，
所以几千到几万条高质量示范就够；数据质量远比数量重要，
质量差的 SFT 数据反而会把基座知识带坏。」

**问题 3：RLHF 和 SFT 的本质区别是什么？**
「SFT 是『模仿唯一示范』，loss 直接把模型往标准答案上拽；
RLHF 是『优化一个打分函数』，允许答案多样，只要得分高。
前者适合有标准格式的任务，后者适合『好』难以穷举定义的开放任务。
代价是 RLHF 依赖一个可能被 hack 的奖励模型——reward hacking
和长度膨胀都是它的经典后遗症。」
