## 一、LoRA 层手撕

▶ 真题：手写 LoRA 层（初始化、forward、merge）——**极高频**（美团/字节/
快手，原理题自带手撕变体）

必背三件事：**A 随机 B 置零、scale = α/r、merge 时 W ← W + (α/r)·BA**。

```python
import torch
import torch.nn as nn
import math

class LoRALinear(nn.Module):
    """冻结主干 W，旁路低秩增量 ΔW = B @ A，输出 = Wx + (α/r)·BAx"""
    def __init__(self, in_dim: int, out_dim: int, r: int = 8, alpha: float = 16.0):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(out_dim, in_dim) * 0.02)
        self.weight.requires_grad = False                    # 主干冻结
        self.scale = alpha / r
        self.A = nn.Linear(in_dim, r, bias=False)            # A: 随机初始化，打破对称
        self.B = nn.Linear(r, out_dim, bias=False)
        nn.init.zeros_(self.B.weight)                        # B: 置零，保证 ΔW 从零出发

    def forward(self, x):
        frozen = x @ self.weight.T                           # 主干输出（不进梯度图）
        lora = self.B(self.A(x)) * self.scale                # 低秩支路
        return frozen + lora

    @torch.no_grad()
    def merge(self):
        """推理前把 LoRA 并回主干: W += (α/r)·B@A，推理零额外开销"""
        self.weight += (self.B.weight @ self.A.weight) * self.scale
        self.merged = True
```

**易错点清单：**

- **A 随机、B 置零**不能反也不能都随机——都随机时初始 ΔW ≠ 0，微调从
  一个随机扰动点开始，初期训练会劣化。原理展开见
  [lora与参数高效微调](../../interview-questions/训练与对齐/lora与参数高效微调.md)。
- 矩阵顺序：A 是 $r \times d_{in}$（降维），B 是 $d_{out} \times r$
  （升维），`merge` 里 `B.weight @ A.weight` 得 $d_{out} \times d_{in}$——
  和主干同形，写 merge 时最容易把 A/B 顺序搞反。
- `scale = alpha / r` 别漏乘，也别加错位置（加在 B(x) 之后、相加之前）。
- 主干 `requires_grad = False`（或训练循环里 `freeze backbone`），否则
  LoRA 就退化成全量微调还多俩矩阵。
- forward 里低秩支路**不要 detach**， detach 掉就没梯度了。

**面试官常见追问：**

- **「LoRA 参数量多少？」** $r(d_{in} + d_{out})$ 每层，d=4096、r=16 时
  约占全量 0.4%；全模型挂上约 0.5%。
- **「merge 之后还能接着训吗?」** 能，但训的是新主干；正确姿势是训练态
  不 merge，推理前才 merge；想继续训新任务就在 merge 后的主干上**新开
  一组 A/B** 从头训。
- **「QLoRA 哪里不同？」** 主干再压到 4-bit NF4（双重量化 + paged
  optimizer），LoRA 支路仍 BF16 计算；显存大头从 14 GB 降到 ~5 GB。
- **「target_modules 挂哪里？」** 常见 q/k/v/o + FFN 三个矩阵全挂；预算紧
  就优先挂 attention 的 q/v（LoRA 原论文的性价比选择）。

## 二、DPO loss 手撕

▶ 真题：手撕 DPO loss——**高频变体**（阿里/字节 live coding；原题
"PPO/DPO/GRPO 差异"的落地版）

trl 口径的极简实现。输入是 policy 和 ref 模型各自对 chosen / rejected
序列的**总 logprob**（面试里这一步通常给定，或让你顺手写
`gather` 版本）：

```python
import torch
import torch.nn.functional as F

def dpo_loss(policy_chosen_logp, policy_rejected_logp,
             ref_chosen_logp, ref_rejected_logp, beta: float = 0.1):
    # 隐式奖励: r(x,y) = β · log(π_θ(y|x) / π_ref(y|x))
    logratios_chosen = (policy_chosen_logp - ref_chosen_logp) * beta
    logratios_rejected = (policy_rejected_logp - ref_rejected_logp) * beta
    # BT 偏好模型: -log σ(r_chosen - r_rejected)
    logits = logratios_chosen - logratios_rejected
    return -F.logsigmoid(logits).mean()      # chosen 在前，别写反
```

白板上还可能要求补充"怎么从 logits 拿到序列 logprob"：

```python
def sequence_logprob(logits, labels):
    # logits: [B, L, V]（LM head 输出），labels: [B, L]，-100 处为 padding
    logp = F.log_softmax(logits, dim=-1)
    token_logp = torch.gather(logp, 2, labels.clamp(min=0).unsqueeze(-1)).squeeze(-1)
    mask = labels != -100
    return (token_logp * mask).sum(-1)       # 每个样本的 Σ log π(y_t | x, y_<t)
```

**易错点清单：**

- **chosen 在前、rejected 在后**——`-logsigmoid(chosen - rejected)`。
  写反是面挂高发点，rlhf 模块专门提醒过。
- beta 乘的位置：乘在 log-ratio 上（trl 口径），不是加在 sigmoid 外。
- policy 的 logprob 参与梯度，**ref 的要 detach / no_grad**——ref 是冻结
  的 SFT 模型。
- 用 `logsigmoid` 而不是手撸 `-log(1 + exp(-x))`——数值稳定，面试官会等
  这个细节。
- gather 前记得处理 padding label（-100 会越界），然后按 mask 求和。

**面试官常见追问：**

- **「β 的意义？」** 控制偏离 ref 的力度：β 大保守、贴近 SFT；β 小激进、
  偏好学得猛但风险文本崩坏。
- **「为什么 π_ref 在分母里？」** KL 约束以内置形式存在：防止单纯拉高
  chosen 概率时顺带把其他好答案压没。
- **「DPO 不需要什么？」** 不需要训 RM、不需要 critic、不需要在线采样——
  一次 forward 走 policy + ref 两个 pass，SFT 级工程复杂度。
- **「已知病理？」** 容易过拟合长度、chosen/rejected 概率**可能同时下降**
  （DPO 只约束差值）——IPO/KTO/SimPO 都是来修这些的。

## 三、GRPO advantage 计算（伪代码）

▶ 真题：手写 GRPO advantage——**高频**（阿里深挖，给定 rewards 数组现场算）

就五行，但边界条件决定分数：

```python
import torch

def grpo_advantage(rewards: torch.Tensor, eps: float = 1e-8):
    # rewards: [B, G]，同一个 prompt 采的 G 个回答的奖励
    mean = rewards.mean(dim=1, keepdim=True)     # 组内均值当 baseline（替代 critic）
    std = rewards.std(dim=1, keepdim=True)       # 组内 std 归一化波动
    adv = (rewards - mean) / (std + eps)
    return adv                                   # [B, G]，广播到该回答的每个 token
```

**易错点清单：**

- 归一组维度是 **G 维**（同一 prompt 内），别归一到 batch 维——方向反了
  整个 baseline 语义就没了。
- std 加 eps 防全同分除零；更讲究的写法是**组内全同时直接令 adv=0**
  （这批样本天然不贡献梯度，DeepSeek 的官方口径）。
- `std` 用有偏（除以 G）还是无偏（除以 G−1）说清楚：trl 默认 G−1，
  白板答出"有些微差别、不影响主逻辑"即可。
- advantage 是**回答级**的，要沿 token 维广播（PPO 的 A 才是 token 级
  GAE），别把这两个混了。

**面试官常见追问：**

- **「为什么不用 reward 直接算？」** 绝对奖励带 prompt 难度偏置和 RM 尺度
  漂移；组内均值是自适应 baseline，降方差 + 消尺度；critic 学的就是
  这个 baseline，GRPO 用采样均值免费估出来，把 critic 全省了。
- **「组内全对/全错怎么办？」** advantage 全零，不贡献梯度——天然过滤
  太简单/太难的 prompt。
- **「G 多大？」** 常见 8~64；G 太小 baseline 噪声大，G 越大 rollout 越贵，
  这是新的方差/成本旋钮。
- **「GRPO 的 KL 放哪？」** 放 loss 里（$-\beta D_{KL}(\pi_\theta \| \pi_{ref})$，
  用 k3 无偏估计），PPO 通常折进 reward——字节追问过这个差异。

## 四、Megatron 风格 TP：Column/Row Parallel Linear

▶ 真题：Megatron 张量并行怎么切——**高频**（三维并行八股的代码版）

记忆点一句话：**Column 切输出维 → 前向不用通信，输出按列拼接；Row 切
输入维 → 输入先 scatter（或上游已切好），部分和要 all-reduce**。两个成对
用（FFN 的 up 用 Column、down 用 Row）就把通信压到每层 2 次 all-reduce。

```python
import torch
import torch.distributed as dist

class ColumnParallelLinear(nn.Module):
    """W: [out, in] 沿 out 维切到 tp_size 张卡。本卡持有 [out/tp, in]
    forward: 全量输入 x → 本地 X @ W_i.T → 各卡输出沿最后一维拼起来
    通信点: 前向 0 次（如果下游能直接吃切开的输出，标记 g: gather 可选）"""
    def __init__(self, in_dim, out_dim, tp):
        super().__init__()
        self.weight = nn.Parameter(torch.empty(out_dim // tp, in_dim))

    def forward(self, x):                    # x: [B, L, in]（全量，各卡一致）
        out_local = x @ self.weight.T        # [B, L, out/tp]，无通信
        return out_local                     # 下游 RowParallel 直接接，不用拼

class RowParallelLinear(nn.Module):
    """W: [out, in] 沿 in 维切到 tp_size 张卡。本卡持有 [out, in/tp]
    forward: 本卡的切片输入 x_i → X_i @ W_i.T 得部分和 → all-reduce 求全量
    通信点: 前向 1 次 all-reduce"""
    def __init__(self, in_dim, out_dim, tp):
        super().__init__()
        self.weight = nn.Parameter(torch.empty(out_dim, in_dim // tp))

    def forward(self, x):                    # x: [B, L, in/tp]（本卡那一片）
        partial = x @ self.weight.T          # [B, L, out] 部分和
        dist.all_reduce(partial)             # Σ_broadcast，所有卡拿到完整结果
        return partial
```

FFN 里的标准配法（一张嘴就知道你懂 Megatron）：

```text
up   = ColumnParallel(d → 4d)     # 无通信，各卡拿到激活的不同切片
down = RowParallel(4d → d)        # all-reduce 一次
```

**易错点清单：**

- 列切/行切**别记反**：Column 切 weight 的**行**（输出维），因为 PyTorch
  的 `weight` 布局是 `[out, in]`，切 out 维=切行——名字来自输入矩阵
  右乘视角。答面试直接说"切输出维/切输入维"，不容易绕。
- Row 的 all-reduce 加在 forward **末尾**（得到部分和之后）。
- Column 的输出**不要急着 gather**，下游 Row 正好就是切片输入，gather
  一次白花一次通信。
- all-reduce 里被广播的是**加和**（sum），不是平均；TP 不分梯度均值。
- TP 组内的各卡激活副本一致，所以 batch 数据是复制的——数据并行的活
  在 TP 组**之间**做。

**面试官常见追问：**

- **「为什么 Column+Row 成对用？」** 每次 forward 通信只有 Row 那一次
  all-reduce；Attention 的 qkv(Column) + o(Row)、FFN 的 up(Column) +
  down(Row)，一层正好 2 次。
- **「TP 的显存 / 通信账？」** 权重/激活切 tp 份，每层通信 ~2 次 all-reduce，
  通信量与 batch·seq·d 成正比——所以 TP 只敢放单机 NVLink 内。
- **「TP 和 PP 怎么分场景？」** TP 通信频繁走机内高速互联；PP 通信量小只
  传边界激活，跨机也能用；DP 补外圈。展开见
  [三维并行](../../interview-questions/distributed-training/三维并行.md)。
- **「LayerNorm 怎么切？」** 盲点是这是 element-wise 的——不切，每张卡复制
  计算；真正麻烦的是 attention 里的 softmax（跨 head 还好，都是按行算的）。

## 五、ZeRO-3 分片模拟（玩具伪代码）

▶ 真题：ZeRO-1/2/3 各分片什么——**高频**（滴滴/百度高频；代码版让你演示
"分片-收集"流程）

单机上用 Python 列表模拟 dp_world=4 的玩具版，目标是讲清楚 ZeRO-3 的
**参数用的时候才 all-gather、用完就扔**：

```python
# 玩具版: dp_world = 4，一个 16 元素参数张量 W
W_full = list(range(16))                       # 完整参数（逻辑上）
dp_world, rank = 4, 1                          # 模拟 4 卡 DP，当前是 rank 1

# 1) 分片: 每卡只持有自己那 1/4 参数 + 对应梯度 + 优化器状态
shard = W_full[rank::dp_world]                 # rank 1 → [1, 5, 9, 13]
#    ZeRO-1 = 只分优化器状态；ZeRO-2 = 加分梯度；ZeRO-3 = 连参数也分掉

def forward_with_zero3(layer_shard, world):
    """用到本层参数时，临时收齐全量，算完立刻释放"""
    full = all_gather(layer_shard, world)      # 通信点 1: 本层参数 all-gather
    out = compute_with(full)
    release(full)                              # 用完即弃，显存只短暂涨一份
    return out

def backward_and_step(shard_grads, world):
    # 通信点 2: 梯度 reduce-scatter —— 全卡求和但每卡只留自己那片的均值
    shard_grad = reduce_scatter(shard_grads, world)
    shard_grad = shard_grad / world
    # 通信点 3（若配 ZeRO-1 语义）: 只有自己那片的优化器状态，更新自己的参数片
    new_shard = adam_update(shard_grad)        # m/v 也只有 1/4
    return new_shard
```

三条通信原语别搞混（面试口试级别必背）：

| 原语 | 行为 | 用在 |
|---|---|---|
| **all-gather** | 每卡的片拼成全量，各卡都得全量 | forward/backward 临时收参数 |
| **reduce-scatter** | all-reduce 后各卡只留自己均分的那片 | 梯度平均并就地分片 |
| **all-reduce** | reduce-scatter + all-gather 的组合 | TP 的部分和聚合 |

**易错点清单：**

- ZeRO-3 的参数**不是常驻全量**——"用前 all-gather、算完 release"是这个
  设计的灵魂，说成"每卡存全量"就露馅了。
- 梯度用 **reduce-scatter** 不用 all-reduce（后者多一次通信量）。
- 显存账本记住锚点：ZeRO-1/2/3 的优化器主状态分别从 16N 压到
  ~4N/~2N/~16N÷dp 量级（以"每参数 16 字节"为基准）——只答方向也行：
  分的东西越多，状态显存越小、通信越大。
- 玩具代码里的 `W_full[rank::world]` 只是示意，真实实现按连续块切
  （contiguous chunk），实现细节可以现场说，不必背。

**面试官常见追问：**

- **「ZeRO-3 比 ZeRO-2 多省什么、多花什么？」** 多省：参数本身也分片
  （权重占的 2N/参数也除 dp）；多花：每层 forward 和 backward 各多一次
  all-gather，通信量约 ×1.5~2，小 batch 下吞吐可能不升反降。
- **「显存公式？」** 每卡 ≈ 权重 2N/dp + 梯度 2N/dp + 优化器 12N/dp +
  激活不随 dp 降——追问"ZeRO 解决不了什么"时答：激活显存，那是梯度
  检查点/TP/PP 的活。
- **「和 FSDP 什么关系？」** PyTorch FSDP 就是 ZeRO-3 的原生实现，
  sharding_strategy=FULL_SHARD。
- **「NCCL timeout 怎么排？」** 先看是不是某 rank 早退/慢（straggler），
  查 NCCL_DEBUG=INFO 日志、nvlink/IB 健康、checkpoint 存取抢带宽——阿里
  考过，答流程别背玄学。
