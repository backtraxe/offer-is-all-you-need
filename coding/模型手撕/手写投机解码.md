> EAGLE、DFlash 列为一等公民，面经里 MTP 接受率、EAGLE-3 TTT 被反复
> 追问）——深问之后最自然的现场题就是「**把 draft-verify 这一轮的

> 算法岗与 Infra 岗都可能出。
> **白板三行骨架**：draft 产 k 个候选 → target 一次前向并行 verify →
> 逐位接受、首个拒绝截断并补 bonus token。
> 理论支撑：[投机解码 2026 专题](../../interview-questions/inference/投机解码2026专题.md)

> 层落地。

## 背诵总纲

```text
draft:      x_prefix --小模型自回归 k 步--> [d1, d2, ..., dk]（每步存概率 q_i）
verify:     target 一次前向 k+1 个位置 --> p_1..p_k 与 p_bonus
accept:     i = 第一个使 rand() >= p_i(d_i)/q_i(d_i) 的位置
输出:       d_1..d_{i-1} + bonus_i（被拒绝位用修正分布补采）
```

骨架必须记住的行：**verify 是一次前向不是 k 次**（把 k 个候选拼进同
一段序列喂进去）、`min(1, p/q)` 接受率、bonus 来自**修正分布**
（贪心情形退化为直接取 target 在该位置的 argmax/采样）。

## 一、贪心版：可以 20 行写完的最小循环

▶ 真题变体：「draft 是贪心小模型，target 也是贪心，写一轮
draft-verify」——**2026 预备新题**（先把这版写对，采样版是加分）

```python
import torch

@torch.no_grad()
def greedy_spec_decode_step(draft_model, target_model, prefix_ids, k):
    """一轮贪心投机解码。
    draft_model/target_model: 输入 ids 返回最后位置 logits 的 callable
    prefix_ids: [1, T] 已确认前缀
    返回: new_tokens（本论被接受的 token 列表，长度 1..k+1）
    """
    # 1) draft 自回归产 k 个候选（贪心）
    ids = prefix_ids
    drafts = []
    for _ in range(k):
        logits = draft_model(ids)
        nxt = logits[:, -1].argmax(-1, keepdim=True)
        drafts.append(nxt)
        ids = torch.cat([ids, nxt], dim=1)
    # 2) target 一次前向，并行验证 k 个位置
    tgt_logits = target_model(ids)  # [1, T+k, V]，位置 T-1..T+k-2 预测 T..T+k-1
    T = prefix_ids.shape[1]
    accepted = []
    for i in range(k):
        target_pick = tgt_logits[:, T - 1 + i].argmax(-1)
        if target_pick.item() == drafts[i].item():
            accepted.append(drafts[i].item())
        else:
            accepted.append(target_pick.item())  # bonus：target 亲自纠正
            return accepted                       # 首个拒绝即截断
    # 3) 全收：再多赚一个 bonus（位置 T+k-1 的预测）
    accepted.append(tgt_logits[:, T + k - 1].argmax(-1).item())
    return accepted
```

三个必背要点：

1. **verify 是把 k 个候选拼进一段序列喂 target 一次前向**——候选位
   置 i 的正确性由「target 在位置 T-1+i（即看完前缀+前 i 个候选后）
   自己会选谁」决定；这正是「token 串行生成、验证可并行」的核心；
2. **首个拒绝即截断**：其后的候选全部作废（它们建立在错误前缀上），
   该位置由 target 的预测补上（bonus token）——**每轮至少前进 1 个
   token，所以期望加速比下界是 1，永不会比纯自回归慢于「draft 开销」
   那一截**；
3. **全部接受时还能多赚一个**：target 在最后一个位置还白送一个
   next-token 预测——最多一轮前进 k+1 个。

## 二、采样版：rejection sampling（保证分布无损）

▶ 追问变体：「采样场景下怎么保证输出分布和 target 直接采样一致？」
——**高频追问**（vLLM 文档明示的三段无损声明就是这题的答案）

```python
@torch.no_grad()
def sampling_spec_decode_step(draft_probs, target_probs, draft_tokens):
    """一轮采样版裁决逻辑（概率已算好，只做判定）。
    draft_probs/target_probs: [k, V] 各位置上两模型对该 token 的分
    draft_tokens: [k] draft 采出的 token
    返回: accepted token 列表
    """
    accepted = []
    for i, tok in enumerate(draft_tokens):
        q = draft_probs[i, tok]
        p = target_probs[i, tok]
        if torch.rand(()) < torch.clamp(p / q, max=1.0):
            accepted.append(tok)          # 按 min(1, p/q) 接受
        else:
            residual = torch.relu(target_probs[i] - draft_probs[i])
            residual = residual / residual.sum().clamp(min=1e-12)
            accepted.append(torch.multinomial(residual, 1).item())  # 修正分布补采
            return accepted
    # 全收：从 target 在下一位置的分布正常采一个 bonus
    accepted.append(torch.multinomial(target_probs[-1], 1).item())
    return accepted
```

无损论证的口头三段（写完必被追问，背熟）：

1. **理论无损**：接受规则 `min(1, p/q)` + 拒绝时从
   `norm(relu(p − q))` 补采，合起来的边际分布精确等于 target 的
   p——这是拒绝采样的经典结论，差异只在浮点精度内；
2. **贪心是它的特例**：p、q 都退化成 one-hot 时，规则天然变成
   「相同才接受、不同取 target」——所以版本一不用再证；
3. **工程不保证 logprob 逐位稳定**：batch 数值非确定性会让
   logprob 微小漂移——要严格复现输出必须声明这点（与
   [训推逐位一致专题](../../interview-questions/distributed-training/训推逐位一致专题.md)
   的「批次无关」诉求同源）。

## 三、期望加速比：现场定量 30 秒

设每轮平均接受长度 E（含 bonus），draft 每 token 成本相对 target
为 α（小模型/头的相对开销），则：

```text
加速比 ≈ E / (1 + k·α)      （verify 一次前向 ≈ 1 个 target 步）
```

口算练习：k=4、α=0.1、接受率 80%（几何近似 E≈(1−0.8^5)/(1−0.8)+1
≈ 4.2）——加速比 ≈ 4.2/1.4 ≈ **3.0×**。面试给结论时主动带三要素：
**k、接受率、draft 相对成本**——只报倍数不报口径是减分项（对照
[专题 4.3 节实测矩阵](../../interview-questions/inference/投机解码2026专题.md)
的「先 Suffix 摸天花板再上 EAGLE-3」）。

## 四、高频追问（写完代码紧跟的连环炮）

| 追问 | 答题要点 |
|---|---|
| draft 用什么停？固定 k 还是自适应？ | 固定 k 是最小实现；自适应按 draft 置信度/接受率动态调（DSpark confidence head、vLLM adaptive verification）；原则是「接受率掉就缩短预算」 |
| 树形候选怎么验？ | 把多条草稿铺成树，attention 加 **tree mask**——分支内因果可见、分支间互不可见；verify 仍是一次前向，逐路径做同样的拒绝采样 |
| KV cache 怎么处理被拒位置？ | 被拒位置之后的 KV 作废（实现上用连续 block 截断或 tree mask 不写入）；下一轮的 prefix 只含「接受 token + bonus」 |
| 为什么 EAGLE 接受率比独立小 draft 高？ | draft 直接消费 target 的 hidden states（三层融合），分布天然贴近；独立小模型只能靠蒸馏对齐，有信息瓶颈 |
| 大 batch 下收益为什么衰减？ | decode 从 memory-bound 转向 compute-bound：batch 越大，verify 的额外 token 前向越接近真实算力成本；收益曲线与人造小 batch 光环要分开报 |
| 手写时最容易错哪行？ | verify 的下标偏移：`tgt_logits[:, T-1+i]` 对应第 i 个候选（model 的第 t 个输出 logits 预测第 t+1 个 token）；写错一位全盘皆错——白板上先画位置对齐图再写循环 |
