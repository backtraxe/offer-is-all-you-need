## 一、阿里业务 Agent 一面（硕 4，Java 转 Agent）

## 二、阿里国际 Agent 开发一面（社招 5-8 年岗）

重心是「能不能把 Agent 平台跑稳」+ 云上后端基本功。12 题带追问：

1. **ReAct 和 plan-execute-replan 区别**（必问）：ReAct 想一步走一步，
   灵活但无全局；plan-execute 可控可并行但依赖初始计划，replan 是关键
   ——每步执行后校验、失败原因回灌 planner，计划别做太细。
2. Agent 状态和上下文怎么管理（显式可序列化状态、session_id 隔离、
   token 预算、分层：近期原文/早期摘要/大工具结果按 id 引用）。
3. **Agent 死循环怎么处理**：步数上限 + 重复检测（动作+参数指纹连续
   相同或两三状态横跳即打断）+ 强制收敛（回灌「已重复尝试 X 失败」
   提示换思路）；预防侧：工具重试上限、错误信息写清。
4. 工具怎么注册、多模型架构怎么设计（统一 schema 注册表、按场景召回
   工具描述而非全量塞、执行解耦、多模型路由 + 失败降级）。
5. SSE 流式输出（事件分段、`data: [DONE]`、客户端断开要停止生成省
   token、Nginx 关缓冲；对比 WebSocket 单向/双向）。
6. 怎么减少 token 用量（「少进、少出、少调、多缓存」四方向）。
7. 端到端延迟高怎么系统性优化（**能主动拆延迟、分级用模型、讲出
   Prefix Caching/连续批处理/投机解码是「高级信号」**）。
8. chunking 策略（结构切 > 固定切、overlap 10-20%、父子分块）。
9. 百万级向量索引（HNSW 延迟优先 vs IVF+PQ 省内存）。
10. Redis 大 key / 缓存穿透（后端基本功固定考区）。
11. 平时怎么用 AI coding 工具（「当结对工程师不当搜索框」;
    鉴权/SQL/命令执行/性能热点代码必须自己把关）。

## 三、腾讯 / 月之暗面 Agent 一面（*原帖为引流贴，取题不取文风*）

两场一面 6 题，全部落在「把模型能力组织成成本可控、故障可退、结果可
评测的系统」：

1. Workflow 和 Agent 的分界线（控制流由代码预设 vs 模型决定下一步；
   工程折中：外层状态机限定路径、局部节点开放动态决策）。
2. 为什么复杂任务不一定适合 Agent（「复杂=步骤多 ≠ 路径未知」；
   只有动态规划收益超过随机决策/循环失控/工具误用的成本时才上 Agent）。
3. RAG 从文档到答案的完整流程（解析→清洗→去重→切片→元数据→索引；
   改写→召回→权限过滤→重排→按 token 预算组装→带引用回答）。
4. Agentic RAG 与一次检索生成的区别（多跳/召回冲突场景；
   **必须配置状态、预算、停止条件**）。
5. 上下文被截断怎么处理（保系统约束+当前问题+高相关证据；历史摘要；
   长文档改按需检索）。
6. 多轮补检的成本延迟怎么限制（最大轮数/总 token/费用/截止时间四重
   预算；去重+独立子查询并行；预算耗尽退化固定 RAG）。

## 四、MiniMax 两帖：Agent 岗教科书命题 + 服务端魔幻流程

### 4.1 「Agent 什么时候停止」三连问（Agent 开发岗，高阶候选人复盘）

面试官坚持的标准口径：**tool-calling loop 在模型不再输出 tool call /
next action 时终止**；连同追问「等待用户输入时 Agent 会不会 thinking /
tool call / 输出」、「Agent 如何管理状态（pending / 会话 ID / 监视器 /
超时）」。候选人按工程语义分层展开（pending 挂起、外部控制器、协议兼容），
被面试官定性「是否可以理解为你没有开发过」。

**答题策略**（对高阶候选人尤其重要）：题目不限定范式时，**先把讨论收缩
到面试官的认知框架**——两秒版答案「标准 tool-calling loop 里，模型不再
输出 tool call 即循环结束」，再展开工程语义（异常、挂起、外部状态、
多范式：structured action / message routing / planner 终局判断）。反过来，
「只考最简 loop 教科书实现」也是一面照妖镜：说明岗位偏既定路线下的
loop/tool call 执行者，不是 Agent 定义者——offer 选择信号。

### 4.2 服务端岗流程实录（被多人评论附议「避雷」）

一面由隔壁传统后端组代面、项目经历对不上只能尬聊（照样给过了）；二面
反复只有一句「你有什么技术难点」，最后要求**投屏用 coding agent 现场
实现一个系统设计**（朋友圈 feed：加好友/发帖/worker 扇出/删好友读时
权限兜底 + unittest + HTTP 烟测），中途面试官因会议室到点离场失联。

**增量情报**：「投屏用 coding agent 现场做系统设计」已出现在真实面试中，
属本仓 [ai编程与claudecode内幕](../interview-questions/agent/ai编程与claudecode内幕.md)
提到的「AI 原生招聘信号」的实证——会用 agent 协作做工程已是被直接
考察的能力，而不是氛围品味。

## 八、面试官视角：「一上午面六个，全是半吊子」（*引流贴，取追问清单*）

简历关键词全覆盖（LangGraph/CrewAI/MCP/RAG/记忆系统）但三轮追问露馅。
最有鉴别度的是四层自检：

1. **工具层**：模型调工具报错、参数不合 schema、下游超时，代码层怎么
   处理？（只会 try-except vs 指数退避 + schema 校验 + 异常链路降级/人工
   兜底）

### 1. 腾讯/月之暗面 Agent 一面复盘（188 赞，附博主标准答）

两场一面考同一件事：**能否把模型能力组织成成本可控、故障可退、
结果可评测的系统**。四组高频问答口径值得直接背：

- **Workflow 和 Agent 的分界线**：Workflow 控制流由代码预设，模型只
  处理节点任务；Agent 的下一步由模型结合当前状态决定。工程上用外层
  状态机限定路径，只在局部节点开放动态决策。复杂 ≠ 适合 Agent：
  流程可枚举就选 Workflow（稳定、便宜、易测试），只有动态规划收益
  超过随机决策、循环失控、工具误用的成本时才用 Agent。
- **RAG 全链路一口气版**：文档解析→清洗→去重→切片补元数据→建索引；
  查询改写→召回→权限过滤→重排→按 Token 预算组装证据→生成带引用
  →日志做坏例分析。Agentic RAG 多出来的就是改写查询、拆问题、切
  数据源、补检、核验，但必须配状态、预算和停止条件。
- **上下文被截断怎么处理**：先定位超限来源，保系统约束、当前问题、
  高相关证据；历史做摘要，长文档改按需检索；不能无差别截断关键约束。
- **多轮补检的成本与延迟治理**：设最大轮数、总 Token、费用、截止
  时间四个预算；仅证据缺失或冲突才补检；子查询去重、独立检索并行；
  预算耗尽退化为固定 RAG 或返回当前最佳证据。

### 4. Agent 岗 5 题大白话标准答（1956 赞，入门话术模板）

- ReAct vs Plan-Execute：混着用——大体先有计划，执行遇异常局部切
  ReAct；纯 ReAct 灵活跟随改需求，纯 Plan 省 token 但中间出岔子难
  处理。
- 防瞎编参数：优先 function calling 拿结构化输出；不支持就把工具
  定义写细 + Prompt 硬性要求 JSON + 正则解析格式校验，不对就重试、
  上限两次；关键参数后端设默认值兜底。
- 记忆：短期存 Redis（消息记录 + 状态变量）；长期把会话压缩摘要
  或抽取偏好入向量库，按需召回塞回上下文，注意控长。
- 多智能体：角色定死、职责与输出格式写进 System Prompt、消息用
  JSON 串带任务 ID、冲突加仲裁者或关键步骤人工介入。
- 工具失败：统一封装返回结构化错误喂回模型，让它自选重试/换工具/
  告知用户；重试两次、整体 30 秒超时、关键工具备降级 API。

入门够用；进阶口径以本仓 agent 专题为准。

- **最能分辨的一题：让候选人讲一次真实的线上故障——怎么发现、
  怎么定位、怎么修**。只跑过 demo 的人讲不出「发现」那一环。
- 死循环题的进阶判据：除了步数上限，**要看有没有做「同一工具同
  参数连续调用」的检测**——光靠步数上限，会烧完预算才停。
- 争议口径（1 赞，供参考）：开源 harness 已经很多且体系渐熟，
  agent 岗重的是业务逻辑落地而非 harness 细节。与正文「harness
  必考」的观察并存——**不同团队侧重不同，按目标岗 JD 取舍**。

### 2. 基模行情帖评论区（base-model-jobs）

- 「现在进基模是高位接盘」；楼主（社招亲历者）承认：**去了基模
  被取代的焦虑更强**，不是避风港。
- 旁证面经：有人「误闯」过基模面——问分布式训练、最多用过多少
  卡，然后就是常规 paper 与实习内容。
- 「训练能力被技术扩散」论：基模红利随方法论普及在消退。
- 吐槽：基模评测岗被踩为边缘选择（情绪化发言，只取一票印象）。

### 3. 字节 agent RL 帖评论区（bytedance-agentrl-3rd，楼主答问）

- 实习冷启动路径：**小公司热门方向或大公司边缘方向起步，靠实习
  找实习**。
- 「两段基座实习为何还去字节业务后训练」——楼主坦白：一线基座没
  对口论文和 conn 进不去，二三线基座 bar 大降但含金量存疑，不如
  核心业务组攒经验。**基模 K 型分化在候选人微观决策上的直接证据**。
- 确证：一面二面都没有手撕。

### 4. 140 问帖评论区（algo-140q，楼主答问 + 身份彩蛋）

- 有评论质疑「应用算法岗为何这么看重 RL，实际工作 RL 效果不如
  SFT」；楼主答：基座岗问得多，**search agent 后训练的 RL 也问得
  多**——RL 热度集中在基座与 agent 后训练两类岗。
- 职级锚点：这批 14 家面试一般为 P6-P7 档。
- 彩蛋：该楼主即美团 M17 基座 agentic RL 开源教程作者（十八节
  收录的 XiaoRed5 系列），教程可信度可上调半档。

### 5. 字节多模态帖评论区（bytedance-mm，楼主答问）

- 个人 think-with-image 项目的资源账：**租 4×48G 卡、跑约 50 小时、
  训练数据 10k step 左右**——准备同类项目的可照此评估预算。
- 「字节不是必撕吗？」——楼主转述面试官原话：**现在都 vibe coding，
  更看重定义问题的能力**。至此「手撕降权」第五次独立互证；但注意
  boundary：滴滴/小米同月仍在手撕，**按部门不按厂判断**。

### 6. 其余帖评论区扫获

- 平头哥帖 10 赞自嘲：「面试造航母，实际 codex 启动打螺丝」——
  AI coding 进生产是公开默认，面试话术可以大方承认日常工作流。
- 滴滴帖：有人补 search agent 的 GRPO 实验要 8 卡 A100；楼主申明
  这是项目延伸问题、不是背诵清单。

  读到第 40 页时关键信息不丢」**，lost-in-the-middle 的直接考点，
  对照 [长上下文训练工程专题](../interview-questions/训练与对齐/长上下文训练工程专题.md)
