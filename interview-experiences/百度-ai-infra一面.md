# 百度 · AI Infra 一面

> 来源：小红书面经帖（二手转述，已脱敏）｜岗位方向：AI Infra（推理优化，vLLM on Ascend 方向）｜轮次：一面

**一句话特征**：围绕简历上的 vLLM Ascend 项目连环追问——每个「我做的优化」都
被立刻问三件事：通信底层是什么、收益口径是什么、为什么不用替代方案。原帖
结尾「问建议，没什么建议，挺好的，然后秒挂」是经典的差异化教训样本。

## 考察点

### 简历项目（vLLM Ascend）

- 自我介绍；介绍实习中 vLLM Ascend 相关的工作。
- CPP（推测为 C++ 侧的调度/负载均衡优化）是怎么做的？优化的是负载均衡吗？
  有什么数据吗？
- 收益是整个任务算完，还是某一部分的？（收益口径追问）
- 精度是怎么测的？

### Ring Attention 与长文本

- 解释 Ring Attention 的原理。→ [三维并行](../interview-questions/distributed-training/三维并行.md)
- 多长的文本算长文本？
- DeepSeek V3.2 支持多长文本的推理？
- Ring Attention 的通信点在哪？通信形式做成什么样了？
- `isend` / `irecv` 底层是 TCP 还是什么？（通信原语的传输层追问）

### DCP 与 Decode 阶段

- DCP（Decode Context Parallel）的方案是什么？
- Decode 阶段计算强度不大，为什么还要做 CP？
- 为什么不用 Ring Attention（而选 DCP）？
- 异构 mask 是什么、「异构」在哪？

### KVCache 管理

- 讲讲 KVCache 管理，是什么样的设计模式？→ [vLLM 与推理加速核心](../interview-questions/inference/vllm与推理加速核心.md)
- 是不是就是后端的几个 memory 统一管理了一下、由一个 router 路由？
- 会影响三级缓存吗？
- layout 既影响三级缓存又影响 PD 分离——对于一个 PD 分离场景，layout 需要做
  哪些修改？→ [设计分布式推理服务](../system-design/设计分布式推理服务.md)

### 手撕与反问

- 手撕：二分查找。→ [通用手撕清单](../coding/工程手撕/通用手撕清单.md)
- 反问：问建议——「没什么建议，挺好的」，然后秒挂。

## 结构借鉴

这篇面经提供了「秒挂」复盘视角，值得提炼为**追问链防御法**——简历上写的每一个
优化，提前备好四层弹药：

1. **实现层**：落到具体机制（是几个 memory pool 统一管理 + router，还是别的
   设计模式），「好像就是 X 了一下」等于没答；
2. **收益口径**：整体耗时还是局部算子？数据是多少？口径模糊的收益第一反应
   会被质疑；
3. **替代方案对比**：为什么不用 Ring Attention / DCP 的另一个分支——面试官
   要的是决策过程，不是结论；
4. **底层追问**：通信原语的传输层（isend/irecv 走什么）、计算强度推导——原理
   概念必须能一路钻到工程原语。

反问环节的教训同样直接：所有回答都「稳」但无一处让面试官记住你，在深度追问
型面试里反而走不远——准备 1-2 个有数据、有坑、有取舍的「故事点」，效果远好
于全面平顺。
