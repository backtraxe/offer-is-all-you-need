## 一、主线直觉：不给 API，给一双眼睛和一只手

一句话主线：

**GUI agent 的核心取舍是用人机界面本身当接口，拿效率换通用性（OpenAI CUA
原话是复用人类日常工具，2025-01）。**

传统工具调用复用的是结构化 API——功能注册、JSON schema、确定性返回。GUI
agent 不依赖这一点：它只看屏幕截图、只输出鼠标键盘动作，因此能操作**任何**
软件，包括没有 API、没有 a11y 标注、厂商早已不维护的长尾桌面程序。代价也
同样肉眼可见：一步一张全屏截图、一次推理只出一个（或少量）动作、任务耗时
等于步数乘单步延迟——这是把「能做什么」拉满、把「多快做完」让渡出去的
路线选择。

这条路线从「研究预览」到「旗舰正面战场」只用了两年：

- **桌面 OSWorld 首发基线只有 14.9%（Claude 3.5 Sonnet 官方，2024-10）**，
  放宽步数预算后也只有 22.0%，论文期最佳模型 12.24%（2024）。
- **OpenAI CUA 把桌面打到 38.1%（官方，2025-01）**，WebArena 58.1%、
  WebVoyager 87%，而当时人类基线是 OSWorld 约 72.4%、WebArena 78.2%。
- **Sonnet 4.5 官方宣称 61.4%（Verified 实测 62.88，2025-09）**，第一次
  逼近人类及格线。
- **OSWorld-Verified 头部已集体越过人类基线 72.36（官方榜单，2026-07~08）**：
  Sonnet 4.6 72.11 → Opus 5 83.39 → Fable 5 85.96（均为 General model），
  最强 Agentic 框架 Intelligence-Indeed Agent 90.19（2026-07）。

两年两代际，从一成半涨到八成半以上。面试里这条时间线就是开场白：它说明
computer use 不是「能不能点得到」的问题，而是**模型代际能力 + 环境工程 +
安全工程**三个轮子一起转的问题。

## 二、机制：串行控制回路与 grounding

### 2.1 串行控制回路：一步一截屏，没有视频流

Anthropic、OpenAI CUA、Gemini 2.5 Computer Use（2025-10-07 发布）三家的
官方循环已经完全趋同：

1. 客户端截取**一张**屏幕截图（可附历史截图与动作轨迹文本）；
2. 模型完成一次推理，输出**一个**（或少量）动作——click、type、scroll、
   key 等，往往带 CoT 内省或显式 thought 字段；
3. 客户端用虚拟鼠标键盘执行动作；
4. 把新截图（Gemini 的实现里附带当前 URL）作为新的观测回送模型；
5. 循环，直到模型声明完成、步数预算耗尽，或触发人工接管。

Gemini 2.5 Computer Use 把它显式做成 `computer_use` tool 的 function-call
循环：动作执行后以 function response 的形式回传「新截图 + 当前 URL」
（官方博客，2025-10）；UI-TARS-1.5/2 在此基础上叠加了 RL 炼出来的
System-2「先想后点」推理（官方，2025-04/09）。

有两个工程直觉必须背下来：

- **回路是串行的，帧率就是单步频率**（三家官方实现均如此）。没有任何一家
  官方实现是连续视频流输入——追问「为什么不做视频流」的答案是 token 成本
  与帧冗余，下面第七节面试题 Q1 展开。
- **任务耗时 = 步数 x 单步延迟，步数预算直接决定分数**（Verified 榜单实测
  口径）。同一个 computer-use-preview：15 步预算 26.0，100 步预算 31.4
  （官方榜单，2025）——还没换模型，光把预算放开就涨了五个多点；跨配置
  可以差十个百分点以上。所以任何横向对比，第一字段永远是步数预算。

### 2.2 Grounding 从外挂检测收敛到原生坐标回归

「把屏幕上的一个像素点指出来」是 GUI agent 的核心原子能力。工业界团过
一个完整的收敛过程，当前主流是第一条：

1. **原生坐标回归（当前主流）**：VLM 直接输出像素坐标。Claude、CUA、
   UI-TARS、OS-Atlas、ShowUI 全部走这条路线。坐标协议有两种形态：一种是
   直接在训练/推理分辨率上出坐标（UI-TARS 系用海量 GUI 截图 SFT + RL 炼
   坐标精度）；另一种是**输出归一化网格坐标再由客户端映射回真实分辨率**
   ——Gemini API 输出零到九百九十九的归一化网格（官方文档口径）。坐标
   能力是数据炼出来的：OS-Atlas 开源了 1300 万余个 GUI 元素的跨平台
   grounding 语料（论文摘要，2024-10）；ShowUI 用 UI-guided token
   selection 把视觉 token 砍 33%，2B 参数模型零样本 grounding 达 75.1%、
   训练提速 1.4x（论文摘要，2024-11）。
2. **Set-of-Mark 加外挂检测**：在截图上给可交互元素标号，模型只输出序号。
   WindowsAgentArena 的 Navi agent 对着五种屏幕解析器做了横评——UIA 树 /
   DOM 树 / OCR / Grounding DINO / OmniParser——结论是**有可访问性树的
   SoM 显著优于纯 OCR 加图标检测**（官方，2024-09），OmniParser 的图标
   captioning 还有增益。这条路对通用 VLM 友好、无需微调模型，但多一道
   检测器，就多一处标的错号的失败源，多屏与弹窗遮挡下尤其脆。OmniParser
   仓库实测 25.5K star（gh API，2026-10），说明这条路在工程圈依然活跃。
3. **a11y 树 / DOM 兜底，混合通道收敛**：考官问「能不能不点像素」，实用
   主义答案是能。ChatGPT Agent 把视觉浏览器 + 文本浏览器 + 终端 + API 单
   API 四个通道合并由模型自选（官方，2025-07），UI-TARS-2 把终端和文件
   系统并进 hybrid GUI environment（技术报告，2025-09）。**要不要给
   GUI agent 发明 API 的判据只有一条：谁便宜谁上**——能不点像素就不点，
   但没有 API 的地方必须有像素能力兜底。

### 2.3 分辨率与 DPI：坐标漂移是最大的工程坑

OSWorld 官方分析有两条结论要背（2024 起持续维护的一页 FAQ）：

- 更高的截图分辨率提升成功率；
- 当前 VLM agent 对 UI 布局变化和噪声不鲁棒。

工程推论直接对应生产上的三座大山：HiDPI 与 DPI 缩放、多屏偏移、弹窗
遮挡。坐标漂移类 bug 的高发区是「逻辑像素与物理像素的换算」——macOS
Retina 两倍缩放、Windows 125%/150% 缩放下，模型按归一化坐标出的点，映射
代码错一个系数就是整屏系统性偏移。正确姿势是：

1. **把分辨率与 DPI 固化进环境镜像**（OSWorld 和 WAA 的镜像就是这个思路，
   评测也比的才是同一个东西）；
2. 给坐标映射层写单元测试，把「归一化 → 逻辑 → 物理」三段拆开测；
3. 评测报告必须带分辨率配置字段，否则成绩不可比（详见第七节面试题 Q7）。

## 三、环境工程：评测基准即基础设施

### 3.1 桌面/移动基准地图

| 基准 | 规模与口径 | 基线数字 | 环境形态 |
|---|---|---|---|
| OSWorld | 369 任务（361 可用，8 个 Google Drive 题有网络依赖，2024） | 人类 72.36%，论文期最佳 12.24% | Ubuntu 真 OS VM |
| OSWorld-Verified | 修复社区报告问题后重建（2025-07）；AWS headless 全量评测不超一小时；OSWorld 2.0 已上线（2026-06） | 2026-07~08 头部已超人类（见数字锚） | 同左，镜像复刻 |
| WindowsAgentArena | 154 任务（官方，2024-09） | Navi agent 19.5% vs 人类 74.5% | Docker 内嵌 Win11 VM |
| WebArena | 812 任务（论文，2023/2024） | 官方口径见评测专题 | 自托管 Docker 站群 |
| WorkArena / WorkArena++ | 33 / 682 任务（2024） | —— | BrowserGym 栈、ServiceNow 实例 |
| AndroidWorld | 116 个程序化任务、20 个真实 app、动态参数化（2024） | 官方基线 M3A 30.6% | Android 模拟器 |
| GUI-Odyssey | 8,334 条跨 app episodes、平均 15.3 步、212 个 app（2024-06，ICCV 2025） | —— | 数据采集而非评测 |

读懂这张表的三个点：

- **桌面 GUI 基准是整机镜像工程，web 基准是站群工程**。WebArena 全自托管
  Docker fixture；OSWorld/WAA 是 VMware/VirtualBox/Docker/AWS 四类 provider
  的完整 OS——成本高一个数量级，所以 headless 并行和云化是刚需，也是
  面试加分谈资。
- **评测速度是环境工程的成果**：OSWorld-Verified 做了 AWS 并行后全量孩子
  一小时以内跑完（官方，2025-07）；WAA 把 Windows 11 塞进 Docker 上 Azure
  并行后全量评测只要 20 分钟（官方，2024-09）。
- **AndroidWorld 的意义在「程序化任务 + 动态参数化」**：同一任务模板每次
  换参数实例化，相比静态题集更抗背题，更接近训练资产而非评测资产——
  这条线与 [agentic-rl专题](../训练与对齐/agentic-rl专题.md) 和
  [rl环境工程专题](../训练与对齐/rl环境工程专题.md) 深度融合。

### 3.2 VM 快照三重用途：初始化、重置、回滚

**环境工程即 checkpoint 工程。** VM 快照在 GUI agent 场景有一套完整三重
使命：

1. **任务初始化**——config 描述初始态（装什么软件、开什么文件、放什么
   数据），评测开始时直接恢复到快照而不是现场安装，任务才可复现；
2. **评测重置**——每道题结束后回滚到初始态，隔离题间状态污染；
3. **失败回滚**——长任务中途出错时回滚快照重试，等价于训练侧的 env
   reset。

这和 RL 环境工程专题里讲的 sandbox/快照体系是**同一套思想跨域复用**：
任务即环境、VM 快照即 reset、评测脚本即 reward function——UI-TARS-2 的
核心叙事就是 multi-turn RL，用统一沙箱平台做大规模 rollout 反哺模型
（技术报告，2025-09），两个专题可以直接串着答。

工程取舍也要会说：快照恢复是秒级到分钟级，长任务中途 checkpoint 需要在
存储成本与回滚粒度之间权衡；而**真实用户机器上无法快照**——只能退化为
动作级 undo、写前确认、先读后写，这也是产品级 computer use（Operator
watch mode、ChatGPT takeover mode）存在的全部理由。

### 3.3 数据侧：三组必背数字

- **OS-Atlas 语料攒了 1300 万余个 GUI 元素**（论文摘要，2024-10），
  开源最大的跨平台 GUI grounding 数据集——坐标能力是用元素级标注堆
  出来的，不是提示词教出来的。
- **ShowUI 小模型账：2B 参数、二十五万样本、零样本 grounding 75.1%、
  视觉 token 减 33%、训练提速 1.4x**（论文摘要，2024-11）——直接打在
  「小模型做 grounding、大模型只做 planning」的降本点上。
- **GUI-Odyssey 是第一条跨 app 轨迹线：8334 条 episode、平均 15.3 步、
  212 个 app**（2024-06，ICCV 2025）——它同时给出了「桌面任务平均 15
  步」这个长度假设，和步数预算 15/50/100 的配置相互印证。

生态热度的实测口径（gh API，2026-10）：UI-TARS-desktop 39.2K star、
OmniParser 25.5K、UI-TARS 本体 11.6K、ShowUI 1.9K——桌面客户端落地件与
感知侧工具面宽度远超论文本身。

## 四、安全：GUI 特有注入面，防线落在环外

通用的提示注入威胁模型与 L0~L4 分层防御链见
[agent安全与防护](./agent安全与防护.md)，本篇只讲 GUI agent 把通用威胁
「视觉化」之后产生的三类**特有**注入面，以及三家厂商已经收敛的防线位置。

### 4.1 特有注入面一：像素注入

攻击内容不以文本 token 进入上下文，而是**渲染成像素**：网页里的诱导弹窗、
仿冒的「免责声明」、藏在角落的小字「点击这里继续」。文本侧护栏（对输入
做字符串或 token 级判定的那一层）对它完全失效——因为护栏看到的是字符串，
而 agent 看到的是截图。模型必须由「看懂屏幕」的能力来完成防御，这正是
把判定权移出 CUA 模型的理由：**注入与防御在同一个模型视野里是立场不明
之战**（与安全专题里「单模型防线挡不住重试攻击」的论证同构）。

### 4.2 特有注入面二：弹窗钓鱼与假按钮

铺满屏幕的假「支付成功 / 系统升级」窗口、劫持点击目标的覆盖层按钮。
更阴的是**确认 UI 影子注入**：GUI agent 的确认对话框本身也会出现在屏幕上
被模型读到，二阶注入可以直接伪造一个「用户已确认」的画面喂给模型。所以
防线必须落在**动作语义层**而不是像素层——支付、删除、外发类动作强制走
带外人工确认通道：ChatGPT Agent 的高危动作二次确认加 Watch Mode（官方，
2025-07）就是产品级模板，与「读屏画面本身不可信」这个前提自洽。

### 4.3 特有注入面三：限制域收缩与能力外溢

限制域是减负而不是削弱：Operator 的站点 blocklist、对银行交易类任务的
主动拒绝、Gemini 的可配置高风险动作确认清单（CAPTCHA、医疗、系统完整性），
本质都是**先冻结权限面，再摄入不可信截图**——L2 架构级约束在 GUI 场景的
落地。反面信号值得背：**官方自报能成功绕过 CAPTCHA 的 UI-TARS-1.5，
被字节自己列入了滥用风险**（2025-04 口径）。能力越强，限制域越要收紧，尤其是
榜单头部已经超过人类基线之后——「比人更能点」没有证据推出「比人更少被
假按钮骗」。

### 4.4 防线位置：环外监测是三家共识

谱系已经收敛，按厂商口径记：

- **OpenAI：环外监测模型实时看屏，可疑即暂停**（Operator 系统卡，
  2025-01），配 cautious navigation 训练让模型识别屏幕注入，但防线
  主体在环外；
- **Google：per-step 安全服务**（官方，2025-10），在模型给出动作后、
  客户端执行前做独立判定；
- **ChatGPT Agent：高危动作带外确认**（官方，2025-07），判定链路完全不
  经过屏幕画面。

答题时一句收口：**像素层的判断就用非像素的通道做，模型内部的训练拒识
（cautious navigation）是加固项、不是防线。**

## 五、工程议题七条

1. **串行回路的吞吐天花板**。一步 = 一次模型调用（一张全屏截图、几千
   视觉 token）+ 一次截屏/执行往返，任务端到端耗时线性放大。三个缓解
   方向各有代价：复合动作/批处理牺牲中途纠偏机会（错一步可能错一串）；
   planner-grounder 分工（7B 级 OS-Atlas/ShowUI 系做定位、大模型只做
   规划，GTA 与 Agent-S 系框架在榜单上就是这个形态）牺牲规划与定位的
   耦合；上下文只带近一到三帧截图加全文文本轨迹，牺牲视觉历史。
2. **坐标漂移与分辨率矩阵**。训练/推理分辨率、VM 虚拟分辨率、DPI 缩放、
   多屏偏移、弹窗遮挡，任何一个错位都表现成「点偏了几个像素」。对策
   三件套：分辨率与 DPI 固化进环境镜像、坐标映射单元测试、评测报告
   带分辨率字段。
3. **环境隔离即 checkpoint 基础设施**。VM 快照三重用途（初始化/重置/
   回滚）详见第三节；真实用户机器不能快照，只能用动作级 undo 加写前
   确认加先读后写。
4. **错误恢复是成功率的大头**。弹窗（cookie 同意、更新提示）、加载延迟、
   误点的恢复能力比首步精度更决定成败。CUA 靠 CoT 自纠正加逐步重评估
   （官方）；框架系靠 planner-grounder 分工兜底。标准工程组合：动作前后
   截图 diff 校验、重试上限与指数退避、卡死检测熔断转人工接管。
5. **历史上下文成本**：OSWorld 官方分析明确**文本轨迹历史有效、纯截图
   历史基本无效还贵**（2024 起）。带近一到三帧截图即可，长任务轨迹回忆
   靠文本加周期摘要——与 [记忆与上下文工程](./记忆与上下文工程.md) 专题
   里的做法同源，ShowUI 的 33% 视觉 token 削减（2024）正面打的就是这个
   点。
6. **评测噪声与横向可比性**。同一个模型换预算能差十个百分点以上
   （15 步 26.0 到 100 步 31.4，Verified 实测）；8 个 Google Drive 题受
   IP/账号/限流影响需要手工配置或剔除（官方 FAQ，2025-07）；跨 OS 结论
   可迁移（官方分析：不同 OS 表现强相关），但镜像版本与分辨率不同则
   成绩不可比。
7. **GUI-only 不是终态，混合形态已经主流化**。ChatGPT Agent 合并四通道
   并宣布 Operator 停服（2025-07）；UI-TARS-2 把终端和文件系统并进
   环境（2025-09）。工程含义：编排层允许模型按效率自选通道，既省
   token 又降低 grounding 漂移风险。

## 七、▶ 面试题

### Q1（高频）把 computer use agent 的控制回路画出来，延迟和成本的敏感点在哪？

答案骨架：串行环 = 单步延迟 x 步数；单步 = 一次完整 VLM 推理（一张全屏
截图几千视觉 token）+ 一次截屏/执行网络往返。缓解手段三选一且有取舍：
复合动作批处理（牺牲中途纠偏）、planner-grounder 分工小模型降本（牺牲
规划-定位耦合）、上下文只带近一到三帧截图加文本轨迹（OSWorld 官方分析
背书）。深度提示：必被追问「为什么不做视频流」——token 成本与帧冗余，
当前没有任何一家官方实现做连续视频流；自报单步秒级/任务分钟级只是
社区经验，不能当实测引。

### Q2（高频）grounding 选原生坐标回归还是 set-of-mark？

答案骨架：权衡矩阵——原生坐标（UI-TARS / Claude / CUA）链路短、无需
外挂检测器，但吃分辨率、DPI、布局漂移；SoM（WAA Navi 实测 UIA 树版显著
优于纯 OCR 版）对通用 VLM 友好，但多一处检测器失败源，多屏与弹窗下标的
序号易错。深度提示：加分项是给出混合方案（检测器做候选生成 + 坐标回归
做精定位），再提 OS-Atlas 1300 万元素语料点出坐标能力的训练本质
（2024-10），以及 Gemini 零到九百九十九归一化网格由客户端映射的协议
形态（2025-10）。

### Q3（中频）截图分辨率调多高？DPI 缩放出 bug 怎么定位？

答案骨架三层：第一层引 OSWorld 官方结论（分辨率越高成功率越高，且模型
对布局扰动不鲁棒）；第二层答工程姿势——坐标映射必须留「逻辑像素与物理
像素」换算层并配单元测试，环境镜像固化分辨率与 DPI；第三层答映射协议
——Gemini 的归一化网格坐标由客户端换算，映射代码错一个系数就是整屏
系统性偏移。深度提示：Anthropic 官方推荐分辨率的网传口径（XGA）本轮
未核实，答题可说「按模型文档口径执行并固化镜像」，不要编具体数字。

### Q4（高频）设计一个 GUI agent 的长任务容错与 checkpoint 方案。

答案骨架分三层：动作级（前后截图 diff 校验、重试退避、卡死熔断转人工
接管）；任务级（VM 快照三重用途：初始化、重置、回滚，OSWorld/WAA 的
镜像即答案）；会话级（文本轨迹加周期摘要进上下文，复用
[记忆与上下文工程](./记忆与上下文工程.md) 的方案）。深度提示：追问
「真实用户机器上不能快照怎么办」标准答案是动作级 undo、写前确认、先读
后写；可顺势接 RL 环境工程专题的沙箱/快照体系——同一套思想跨域复用。

### Q5（中频）为什么桌面 GUI agent 比 web agent 难？为什么 web 反而先落地？

答案骨架四维：数据（web 有 DOM/a11y tree 可用、轨迹好采集，跨 app
桌面数据直到 GUI-Odyssey 2024 才出现）、环境（无状态浏览器 vs 整机 VM
快照）、动作空间（web 控件有语义化）、评测成熟度（WebArena 812 题全
自托管可复现 vs OSWorld/WAA 要整机镜像）。深度提示：厂商侧证据直接引
Gemini 2.5 Computer Use 官方明示「未针对桌面 OS 优化」（2025-10）——
web 先行是厂商路线图的主动选择，不只是学术难度问题。

### Q6（高频）GUI agent 的注入面比工具调用 agent 多了什么？怎么防？

答案骨架：先引安全专题的三类威胁模型与 L0~L4 分层（见
[agent安全与防护](./agent安全与防护.md)），再讲 GUI 特有增量——指令以
像素形式进上下文，文本护栏失效（恶意弹窗、假按钮）；确认 UI 本身在屏幕
上，可被影子注入伪造「用户已确认」。防御落到环外：独立监测模型看屏
（Operator，2025-01）、per-step 安全服务（Gemini，2025-10）、高危动作
带外确认（三家趋同）、限制域收紧（blocklist/任务白名单）。深度提示：
追问「为什么不在 CUA 模型内部训练拒识」答——可以训（cautious
navigation 就是），但单模型防线挡不住重试攻击，与安全专题的论证同构。

### Q7（中频）OSWorld 四成八和六成二的模型真有那么大差距吗？

答案骨架：先亮评测口径敏感度——步数预算（同款 agent 15 步到 100 步差
五个多点，跨配置十点以上）、是否用 a11y tree、是否多次 rollout、原版 vs
Verified（2025-07 修复社区报告问题后口径变了，UI-TARS-2 自报 47.5 而
Verified 实测 53.10）、8 个 Google Drive 剔题、分辨率配置。深度提示：
结论必须是「报成绩带齐六个配置字段，否则不可比」，并点出 Verified 榜单
本身就是为解决这个问题而建的——这也是 2026 年社区以 Verified 为准的
原因。

### Q8（中频）GUI agent infra 和 RL 训练环境有什么关系？

答案骨架：UI-TARS-2 的核心叙事就是 multi-turn RL——统一沙箱平台做
大规模 rollout、数据飞轮反哺模型（技术报告，2025-09）；AndroidWorld 的
程序化任务加动态参数化天然是训练资产形态（2024）。深度提示：落到复用
点三连——任务即环境、VM 快照即 reset、评测脚本即 reward function，
直接串 [rl环境工程专题](../训练与对齐/rl环境工程专题.md) 与
[agentic-rl专题](../训练与对齐/agentic-rl专题.md)；评测环境经
Verified/2.0 重建后正在向训练资产演进。
