## 一、机制拆解：一条三代谱系

### 1.1 第一代：外挂式上下文工程（harness 写策略，模型只执行）

压缩逻辑全部在模型之外，三种形态：

- **prompt 内摘要**：把消息历史交给一个（通常同款的）LLM 写摘要，用摘要
  替换原文。Claude Code 官方披露的实现正是如此：把消息历史发给模型，要求
  **保留架构决策、未解决的 bug、实现细节**，丢弃冗余的工具输出和消息，压缩
  后的上下文外加「最近访问的 5 个文件」继续工作（Anthropic Applied AI 团队
  博客《Effective context engineering for AI agents》，2025 年口径）。
- **分层记忆（MemGPT / Letta）**：把上下文当操作系统的内存页管理——
  core memory 常驻、agent 可用专用工具自我编辑；archival / recall memory
  放外部存储、按需换入。这是 MemGPT 论文（arXiv:2310.08560，2023-10）
  提出的虚拟内存比喻，工业实现是 Letta。
- **文件系统记忆**：不写摘要写文件——NOTES.md、todo list、可回查指针。
  Anthropic 同一篇博客称之为 structured note-taking / agentic memory，
  并在 Claude Sonnet 4.5 发布时以 memory tool public beta 的形式落到
  Claude Developer Platform（2025-09 口径）。

这一代的共性要背下来：**压缩策略是工程师写的 prompt 和阈值，模型只是
执行者**。误差来源有三类：生成式摘要不可控的数字漂移、实体混写，以及串行
执行——每压一次，整个 agent 停一次。

### 1.2 谱系之间的裂纹：压缩点即 prefix cache 断层

第二代不是一个新产品，而是一个**关键认识**：压缩不只是「省 token」，还是
「改写上下文分布」。prefix cache 按 token 序列精确匹配，压缩点之前的段落
被替换后旧缓存全部作废，命中率从摘要边界重新起算（这条账的完整展开在
[记忆与上下文工程](./记忆与上下文工程.md) 的 §3.6，本篇不重复）。

由此推出的保守做法在各家趋同：

- **最近一段原文保留不动**，压缩点越靠后越好（Claude Code 社区口径有
  「保留最近约 20K」的说法，属社区实测、非官方数字，见第五节）；
- 稳定内容（system prompt、工具 schema）永远放最前；
- 压缩后要接受一次 uncached prefill，换取后续每一轮的前缀命中收益。

### 1.3 第三代（上）：激活态 latent 记忆——拼了命想省掉「重新描述历史」

这一支的思路是**把历史压成模型内部的连续表示，根本不再写回 token**：

- **RMT（Recurrent Memory Transformer，NeurIPS 2022）**：在段与段之间
  传递 memory token 的激活；lucidrains 社区实现 425 star、官方 booydar 仓
  776 star（均 2026-10-12 实测）。
- **ICAE（Microsoft，ICLR 2024）**：把长上下文压成少量 memory slots 的
  连续向量，论文摘要口径是**用约 1% 的额外参数实现 4 倍压缩**
  （arXiv:2307.06945）；官方 getao/icae 仓 178 star（实测）。AutoCompressor、
  Activation Beacon、Gist tokens 同属此支。
- **MemoryLLM（UCSD，ICML 2024）**：把「可更新的 latent memory 池」嵌进
  transformer，self-update 机制让模型主动遗忘旧知识；官方仓 326 star
  （实测）。其长期记忆扩展 M+（ICML 2025）与 Larimar（IBM，ICML 2024，
  官方仓 34 star，实测；给 LLM 挂情节记忆读写头做模型编辑与遗忘——会议
  归属按仓描述口径）都在这条线的延伸带上。

这一支的共同坑也要背下来：**压缩后的记忆槽不可读**——无法用自然语言
inspect，无法被审计，也无法向后兼容升级。它是纯学术上的优雅，工程上是
黑上加黑。

### 1.4 第三代（下）：把「压缩 / 丢弃」本身做成 RL 可优化动作

这是 2025–2026 的新派，也是本篇的主角。思路定义清晰化：

1. 给模型一个**定长的内部状态槽**（memory 槽，用自然语言 token 表示，
   因此可读、可审计）；
2. 每轮让模型**同时输出推理段落与状态更新**；
3. 用任务的**终局 reward 反传「哪些信息该留」**——不喂任何压缩监督。

MEM1 在 7B 模型上用 PPO，全程不喂压缩示例，纯靠结果信号学会在定长记忆里
做 consolidate（详见 §2.4）；MemAgent 用 RLVR（扩展自 DAPO）在「多段、
上下文独立」的对话流上端到端优化「读块 → 写记忆槽 → 读下一块」的
recurrent 流程，不改模型架构，硬把记忆策略训了出来（arXiv:2507.02259）。

两条数据流用文字版精确描述：

- **MemAgent 流（阅读消化型）**：长文本切块 → 第 i 块与上一段记忆槽一起进
  上下文 → 模型输出新记忆槽 → 循环到尾 → 基于最终记忆槽回答问题 →
  verifier 给 0/1 reward → RL 回传整条 recurrent 链。
- **MEM1 流（agent 型）**：每轮 observation → 模型一次前向输出
  `<memory>` 更新后的内部状态 `</memory>`、reasoning 与 action →
  下一轮**只有 memory 槽进上下文**——上下文长度在长任务中保持恒定，
  这就是「内存恒定预算」的机制出处。

注意两支与第三代（上）的本质差别：latent 一支把历史压成不可读向量，
RL 一支把历史压成可读 token 记忆槽、且保留策略本身可学——**压缩产物
可读才谈得上审计，保留策略可学才谈得上进化**。面试里能讲清这个差别，
就把浅档答法甩开了。

### 1.5 谱系收口：厂商原生 compaction 暗盒

三条线最终汇到「训练原生 compaction」:Anthropic 与 OpenAI 的旗舰 agent
产品已经把压缩做成模型与 harness 协作的系统能力（Claude Code 原生
compaction、Codex 三路 compact)，但**两家的压缩侧训练细节均未公开**——
压缩 prompt 是否单独后训练、server 端模型侧配方，截至 2026-10 没有技术
报告。工程事实可见、训练配方暗盒，这就是谱系的最右端。

## 三、工程实践：触发、保什么、怎么调

### 3.1 压缩三大触发

公开系统的共同做法，按触发源分三类：

1. **防守式（pressure 触发）**：到预留水位就压，让用户无感。社区口径多在
   窗口的八到九成处触发，但 **Claude Code 与 Codex 的具体水位都没有官方
   数字**（见第五节），面试里说「预留 10% 上下的 buffer 水位」是安全的
   方向性表述；
2. **溢出式（overflow 兜底）**:provider 直接报错（如
   token_limit_reached),agent 在同一条消息内同步压缩重试——Codex 这条
   兜底在源码里可见；
3. **显式触发**:session 开头规划性地清一次，或用户手动 /compact。

第三代训练线则把「何时压」重新定义了：**恒定预算**——MemAgent 在 32K
文本上训练、8K 窗口推理，MEM1 在恒定 memory 槽下跑长 horizon——
**变成了「每轮都在压」，触发这件事直接消失**，这是训练带来的额度重构。

### 3.2 共识：压缩前先清工具输出

Anthropic 官方博客点名：消息历史深处那些工具的原始调用结果，**不必再
原样回看**——这是「最低垂的压缩果实」,tool result clearing 功能（2025)
就是为它做的。这与本仓 [deepseek-harness分析](./deepseek-harness分析.md)、
[codex源码分析](./codex源码分析.md) 里的 toolResultPruner / head-middle-
tail 裁剪是**同一设计共识**：工具输出占量最大、时效最短、冗余最高，压缩
的第一步永远是先清它，而不是先摘要对话。

### 3.3 压缩 prompt 的调法：先 recall 后 precision

官方博客的建议顺序不要背反：**先在复杂 agent trace 上调到不漏任何相关
信息（recall 拉满），再删冗余（precision 收敛）**。并有一个明确的警告：
「later 才显现重要性的 subtle context」会被过度压缩丢掉——也就是说，
压缩 prompt 的天花板不是写不好，而是**重要性很多时候是时序滞后暴露的**，
摘要看不见自己的盲区。

### 3.4 成本结构与回本账

外挂摘要压缩的一次性成本 = 一次摘要调用（text 生成）+ 一次 uncached
prefill（旧 prefix cache 作废的代价）。只要压缩后再聊 2–3 轮就回本
（完整账在 [记忆与上下文工程](./记忆与上下文工程.md) §3.6，本篇不重复）。
训练线把这笔账也内化了：MEM1 / MemAgent 的「每轮都压」使 prefill 长度
恒定，cache 结构每段重置但每段很短，代价被恒定长度摊平（MemAgent 的
linear-in-length 复杂度正是源于此）。

### 3.5 误差对比研究的空白

「native compaction vs 外挂摘要」**的严格 A/B 公开研究、本次未检索
到**。MEM1 / MemAgent 的论文数字只能证明「RL 训出的记忆策略 ≥ 全上下文与检索
基线」，不能读出「比同款模型的 prompt 摘要好多少」——它们的对照组里没有
「同模型 + 同款摘要 prompt」这一组。面试里别吹有硬对比数字，讲「各自相对
自身基线的收益」是安全口径。

### 3.6 可观测性：压缩事件必须留痕

- Claude Code 的 PreCompact / PostCompact hook 给了第三方注入与复盘点；
- Codex 源码的 CompactedHistoryMetadata 记 window number、response id、
  model hash;
- 工程底线：summary envelope 里必须带 provider、model、usage、触发源，
  否则线上排查「为什么突然变笨了」无从下手。

### 3.7 KV 复用影响两代之间的再对比

第一代摘要压缩打掉旧 prefix cache；第三代激活态记忆在新派里等于 block 级
重建 RMT 式 recurrent cache——看上去都贵，但**训练线的每段短、长度恒定，
摊薄到线性摊销**;latent 旧派则靠「不再重述历史」把重新编码的成本省掉。
两句话对比应付追问就够。

## 四、▶ 高频面试题

按 2026 年面的实际风向出题：这条线的题正在从「你怎么做摘要」升级到
「压缩这件事能不能训」。以下 8 条按频率降序，每条给深浅两档提示。

**Q1（极高频）：压缩的谱系怎么划分？外挂摘要、分层记忆、文件记忆、
激活态 latent、RL 行为压缩，各自优缺点？**

深度提示：浅档答四大策略表 + Letta / 文件记忆机制即可；深档必须能对比
**RMT / ICAE 与 MEM1 / MemAgent 的本质差别——前者压成不可读向量、后者
压成可读 token 记忆槽且策略可由终局 reward 优化**，再补一句「都可读性
决定是否可审计、可向后兼容」。

**Q2（极高频）：压缩会丢什么信息？怎么修？**

深度提示：官方口径的保留清单是架构决策、未解决 bug、实现细节；可丢的是
冗余工具输出。修法三层：回查指针（压缩产物留原始位置）、记忆外挂层
（详见 [agent记忆产品化专题](./agent记忆产品化专题.md))、以及 **tool
result clearing 先压源头**——最低垂的果实先摘。

**Q3（高频）：何时该压？阈值怎么定？**

深度提示：防守式低水位 + 溢出兜底 + 显式三触发；立刻带副账——压缩点
即 prefix cache 断层点，所以压缩点越靠后越好、稳定内容放最前、压后接受
一次性 uncached prefill 换每轮收益（完整账在边界文档）。追问「水位数字」
就说**官方未披露，社区口径八到九成，再给方向性设计原则**，别报死数。

**Q4（高频）：如何评估压缩质量？**

深度提示：**任务终局指标（任务完成率、基准分）是金标准，文本相似度只能
做辅助**;MEM1 用 final reward 直接反推压缩质量说明了同一件事——压缩
没有独立真值，只有终局真值。

**Q5（高频）：MEM1「内存变成恒定」是怎么做到的？**

深度提示：定长 memory 槽 + 每轮同时输出记忆更新与 reasoning + 下一轮只有
槽进上下文；RL 只奖励终局。再报数字锚——**在 7B 模型上性能做到 14B
对照的 3.5 倍、内存用量约为对照的 27%（官方 README 口径，2025-06）**。

**Q6（高频）:MemAgent 怎么用 8K 窗口处理 3.5M token?**

深度提示：切块循环 + 记忆槽逐段传递 + 上下文独立的 multi-conv RLVR
（DAPO 扩展）；数字锚——**外推到 3.5M token 的任务、损失不足 5.5%
（14B 档），512K RULER 得分在 95% 以上**（官方 README 口径，2025)。
浅档讲清「recurrent 数据流图」即可，深档要能解释为什么复杂度是线性
摊销。

**Q7（中频）:native compaction vs 外挂摘要的取舍？**

深度提示：native 侧零 prompt 成本、策略可进化，但不可迁移、不可解释、
被厂商暗盒锁定；外挂侧可移植、可观测，但摘要噪声（数字漂移、实体混写）
加每压一次全 agent 停摆。再补一句「严格 A/B 公开研究目前不存在」，
答出研究空白直接上一个档。

**Q8（中频）：压缩与前缀缓存冲突怎么解？**

深度提示：压缩点尽量靠后、稳定内容放最前、保留最近一段原文不动、压后
接受一次性 uncached prefill 换后续每轮命中；完整四方账指向
[记忆与上下文工程](./记忆与上下文工程.md) §3.6 与 [长上下文推理与kv体系](../inference/长上下文推理与kv体系.md)。

**深浅两档总提示**：浅档 = 四大策略 + Letta / 文件记忆 + 「任务成功率是
金标准」；深档 = 把 MEM1 的 end-to-end RL 无外生压缩监督、MemAgent 的
DAPO 扩展讲明白，并指出**训练原生 compaction 的公开研究 2025 年才爆发、
工业界（Anthropic / OpenAI）训练细节至今未公开**这条时序——能讲清楚
「什么已知、什么仍暗盒」，就是这条线的 top 答案。
