# 决策模型与 Jev：Agent 高频判断的专职裁判

> 本篇面向关注「agent 每一步决策能不能更便宜、更可信」的读者。
> 2026 年 9 月 TypeSafe AI 发布 **Jev**——一个不生成任何文本、
> 只输出候选概率分布的**判别式决策模型**，引爆了「System One
> Models / 决策模型」这条新赛道（OpenAI 跟进 Decisions API、
> Cloudflare 开源 Clef、Databricks 出 ai_decide）。
> 读完你会获得：决策模型与生成式 LLM 的本质分野、Jev 的机制拆解、
> 「Structured Outputs / 只调工具 ≈ 决策模型吗」的完整辨析、
> 以及它在 agent 架构里的正确位置。
> 时效口径：2026-10 核实。

## 一、是什么：不为生成而生的模型

Jev（TypeSafe AI，2026-09-15 发布；创始人是前 OpenAI
RLHF/InstructGPT 成员）的官方品类叫 **System One Model**——
对应卡尼曼的「系统一」快速直觉判断。它与 LLM 的根本分野：

**它不生成文本**。输入是结构化状态 + 若干带预设选项的问题，
输出是每个选项上的**离散概率分布**（外加由固定公式算出的
choice/score/confidence）。问题只有三种类型：

- `noul`：是/否判断（「这个按钮该不该点？」）
- `choice`：无序枚举（「这一步该用哪个工具？」）
- `score`：有序评分（「这条回复质量几分？」）

官方口径延迟 70–500ms，比前沿 LLM 快 40–200 倍、便宜 40–400 倍
（厂商自测，口径偏自家 workflow）；多个问题在一次调用里**并行打分**
（问题间不允许有依赖）。

## 二、与普通 LLM 的本质区别

| 维度 | 普通 LLM（自回归生成式） | Jev（判别式决策模型） |
|---|---|---|
| 输出 | 文本 token 序列 | 候选上的概率分布（不产文本） |
| 训练目标 | 下一个 token 预测 | 判断正确性 + **概率校准**（官方称 RLCD，纯合成数据） |
| 置信度 | 无原生概念，靠事后拼凑或 verbalize | 由分布集中度按固定公式算出，程序直接消费 |
| 推理路径 | 逐 token 串行，prefill 成本随输入线性 | 候选并行打分，多问题一次调用 |
| 典型角色 | 全职工（感知+决策+表达） | 决策点专职裁判，表达留给 LLM |

**概率校准是最深的差异**。普通 LLM 的「过自信」是通病——说 90%
把握的事实际只对 70%；Jev 的训练目标直接优化校准（外界推测损失
含 Brier score 类惩罚项），让置信度数字与实际正确率对得上。
这让「>90% 自动执行、60~90% 升级大模型、<60% 转人工」这种
**可统计决策的门禁系统**第一次有了可信地基。

## 三、核心辨析：「限制输出长度 / 只调工具」≈ 决策模型吗？

这是中文社区正在辩论的原题（GPT + Structured Outputs 能否替代 Jev）。
答案：**功能上可近似，本质上不等价**。

**「限制输出长度」这一半尤其不成立**：截短输出只是解码期的事后
约束——模型的校准问题、逐 token 串行路径、prefill 成本原封不动。
一个只会说「是/否」的 LLM，说「是」时依然没校准、依然要付整段
上下文的 prefill 钱。

**「只调用工具 / 结构化输出约束」是最接近的近似，但四层差距仍在**：

1. **训练目标**：约束 LLM 只在枚举里选，它的「选择」依然来自
   next-token 概率，未经过校准优化；遇事后的 confidence 能否拿去
   做自动化门禁，这是分水岭；
2. **输出性质**：LLM 输出本质还是文本，confidence 是「顺便说一句」
   的口头承诺；Jev 输出的是程序可消费的原生分布；
3. **成本结构**：自回归哪怕只产一个 token，也要全量 prefill 状态
   描述；Jev 单次并行打分。一天判断一次无所谓——**一个任务判断
   几十上百次时**（agent 每步决策）就是一两个数量级差距；
4. **多判断形态**：Jev 一次调用并行回答多个独立问题；LLM 要么
   串行多轮、要么生成一大段再解析（又引入解析错误面）。

一句话收拢：**约束输出改变的是「生成的形状」，决策模型改变的是
「模型是什么」**——前者拿通用模型模拟判别器，后者从训练层就是
为判别而生。

## 四、在 agent 架构里的位置

典型用法（Browser Use 社区 `jev-ultrafast` 插件的示范结构）：
**17 次 Jev 调用 + 2 次生成调用**完成一次机票查询——
每一步元素点击/分支判断走便宜快速的决策模型，只有总结与生成
留给大模型。这正是「**少量生成调用 + 大量廉价判别调用**」
混合架构的产品化——与「小模型路由 + 大模型生成」的工程趋势同源。

冷静视角（两头挤压，面试加分配方）：Jev 的生态位**上端**被大模型
厂商便宜好用的结构化输出挤压（OpenAI 迅速跟进 Decisions API 就是
信号），**下端**被传统专用分类器挤压（固定标签任务更便宜更准）。
它最稳的位置是中间地带：**需要通用语义理解、候选集合频繁变化、
不想为每个小判断单独训模型**的决策点。

## 五、▶ 面试挂钩

**问题 1：决策模型和 LLM 是什么关系？会取代吗？**
「互补不是取代。决策模型是判别式——输入状态+候选，输出概率分布，
不生成文本；LLM 是生成式。分工逻辑是『判断给判官、表达给作家』：
agent 每步的选择（点哪个元素、用哪个工具、这步过不过）走高频低
价的决策模型，只有需要语言产出的环节给 LLM。混合架构下生成调用
次数可以降一个量级——成本、延迟、可控性三赢。」

**问题 2：Structured Output / Function Calling 约束了输出空间，
不就是决策模型吗？**
「功能近似、本质不同：约束输出只是解码期的事后限制——模型的
next-token 概率没有校准概念，confidence 是口头承诺；决策模型的
概率分布是训练目标的一部分（校准优化），置信度可直接做门禁。
另外成本结构完全不同：自回归生成一个 token 也要全量 prefill，
决策模型是并行打分——单点判断无所谓，agent 每步都判断时差距
一到两个数量级。」

**问题 3：什么场景值得上决策模型？**
「三个特征同时满足才值：高频（一个任务几十上百次判断）、
候选可变（不值得为每类判断训固定分类器）、决策需要置信度门禁
（按分数自动执行/升级/转人工）。反例也值得说：低频判断（一天
几次的审批）直接用 LLM 就行；固定标签的常规分类（情感分析）
传统小模型更便宜更准——决策模型不包打天下。」

**问题 4：概率校准为什么重要？**
「自动化门禁的前提。没有校准，『90% 置信度自动执行』意味着实际
错误率不可知——门禁形同虚设。校准让置信度数字与实际正确率
对齐，才能做可统计的风控：错误率可预算、阈值可调、责任可追溯。
这也是判别式模型对生成式模型最不容易被追上的优势——生成模型的
训练目标里没有校准这一项。」
