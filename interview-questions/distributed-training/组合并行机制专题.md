# 组合并行机制专题：进程组坐标化编址、EP 切分与梯度三本账

> **面向**：求职「分布式训练 / 训练框架」岗的候选人。前置：先读
> [三维并行](三维并行.md)（单维概念课），本篇回答它没展开的组合
> 层问题。
> **读完获得**：Megatron `initialize_model_parallel` 默认次序
> （TP 最内、PP 最外）从「编号连续性」角度的完整推导；EP 为什么
> 是从 DP 维里切出来的第五族组（EDP）；「一份参数的梯度在多大
> 范围内求和」的统一判据与七行对账表；只有装进完整 Transformer
> 才会出现的两处通信（tied embedding、输出头反向求和）。
> **口径**：机制框架整理自「HNU 高性能网络」组合并行连载
> （2026-10，附三个可跑实验脚本 exp18/19/20 的作者实测）；集群
> 配比数据（Llama-3 405B、DSv3）为公开报道约数。

## 一、为什么一种并行不够用：四把刀切的是正交的维度

| 并行 | 切的维度 | 单开的上限 |
|---|---|---|
| TP | 单层的权重矩阵（层内） | 一个 NVLink 域：8 卡（NVL72 整机柜 72） |
| PP | 模型的层（深度方向） | 段数一多气泡率压不住，通信量不降反增 |
| DP | 数据（副本间） | 不省单卡显存：16B/param 全量复制，撞显存墙 |
| EP | MoE 的专家（MoE 层内） | 只管 MoE 层 FFN，attention 归别的并行管 |

512 卡的账：TP 最多占 8（机内域），剩 64 倍只能靠 DP×PP 的乘积
填；模型一大盘、单卡装不下参数，PP 或 FSDP 必须上场。所以组合
是被逼的：

```
总卡数 = t × d × p （MoE 模型里，MoE 层再在 DP 维上细分出 EP）
```

真实配比（公开报道约数）：Llama-3 405B 用 TP8×PP16×DP128 铺满
16384 张 H100；DSv3 用 PP16 路流水、EP 跨 8 节点 64 卡加机内
TP。本篇关心的是铺完之后——**每张卡手里那一份计算，和其他卡
怎么衔接**。

## 二、进程组的画法：每张卡一个 (tp, dp, pp) 坐标

### 2.1 三维网格与全家桶组表

N 张卡哪几张算一组？把卡排成 t×d×p 的网格：宽 t 格、深 d 格、
高 p 格，一格一张卡。同一横排 t 张卡合切每层（TP）、同一纵深
d 张卡各吃一份数据（DP）、同一竖列 p 张卡各管一段层（PP）——
**每个格子同时在三条直线上，这就是「一张卡同时属于好几个
进程组」的几何含义**。三维之外按需再加两族：MoE 的 EP/EDP
（§四）和 tied embedding 的首末段配对组（§六）。

编址规则一句话：**先沿 tp 数、再沿 dp 数、最后沿 pp 数**——
这就是 Megatron 默认编址「TP 最内、PP 最外」的全部含义：

```
rank = tp_rank + t · (dp_rank + d · pp_rank)
```

「内/外」落到编号上就是**连续性**：

| 组 | 编号形态 | stride |
|---|---|---|
| TP 组 | 连续（{0,1}、{2,3}…） | 1（最内） |
| DP 组 | 隔 t 个一跳（{0,2}…） | t（居中） |
| PP 车道 | 隔 t·d 个一跳（{0,4}…） | t·d（最外） |

为什么连续性是金矿：**连续编号的卡在同一台机器上**（RANK =
node_rank × nproc_per_node + LOCAL_RANK）。所以**编址顺序直接
决定哪类通信落在机内 NVLink、哪类落到跨机网卡**——这不是
风格问题，是性能问题（§三）。

### 2.2 new_group 的三个非直觉点

1. **全体集合调用**：建组要登记成员表、分配组内编号、NCCL 交换
   通信地址——都在 world 范围协调，所以**不在组里的进程也必须
   参与每一次 new_group**，调用序列全体一致；缺一个进程，其余
   进程永远阻塞在内部同步点上（「卡在 new_group 不动」的经典
    hang 就是这么来的）；
2. **members 是坐标公式的确定性函数**：每张卡本地各算一遍、
   结果必然一致——分组方案是**算出来的共识**，new_group 只是
   让它生效；
3. **只留自己的句柄**：`if rank in members`——每个进程只保存
   包含自己的那组句柄（tp_group/dp_group/pp_group/emb_group 四
   个变量），其余建完就扔；在不属于自己的组上发通信是非法操作。

## 三、为什么是这个顺序：通信强度 vs 物理距离

原则一句话：**通信最贵最频的维度，放进最小的物理范围**。

| 组 | 通信 | 频次 × 单条大小 | 适合的物理范围 |
|---|---|---|---|
| TP | 激活 all-reduce | 每层 4 次 × s·b·h，**延迟敏感** | 必须机内（NVLink 域） |
| DP | 梯度 all-reduce | 每 step 1 次 × GB 级，**带宽敏感** | 跨机，摊到多机网卡池 |
| PP | 边界 send/recv | 每 micro-batch 2 条 × s·b·h | 跨机即可，量小 |
| EP | all_to_all | 每 MoE 层 2 次 × 动态 | 最好机内，组大了难保证 |

64 卡实例（8 台 8 卡机，t=8、d=4、p=2）：

- **TP（stride 1）**：组员全在同一行（同一节点），每层 4 次小
  消息在 NVLink 域内 all-reduce——**网卡上一个字节都看不到**；
- **DP（stride 8）**：整个 TP 组被复制到 4 台机，梯度同步按
  位置劈成 8 个平行 4 卡组（组 k = 各机的第 k 张卡）；8 个组的
  流量同时压在本机那张网卡上——**最大流量摊给最多网卡**；
- **PP（stride 32）**：按层切段，节点 i 的 GPU j → 节点 i+4 的
  GPU j，32 条车道每 micro-batch 一来一回——量小但**延迟直接
  决定流水线进度**。

**反例（DP 最内、TP 跨机）最能记住**：rank = dp + 8·(tp + 4·pp)
时两类通信同时放错——TP 的每层 4 次激活 all-reduce 全部赶上
跨机网络（延迟差一个数量级，且暴露在每层前后向、无法像 DP
那样藏进计算空隙）；DP 的 GB 级梯度 all-reduce 被关进机内
（NVLink 是全机唯一不缺带宽的地方，本该摊到多机网卡的最大
流量憋在单机内部）。**带宽大户和延迟敏感户位置对调，双输**；
连带损失是 t 上限从 8 掉到 4，每卡权重分片翻倍、显存跟着涨。

## 四、EP 组摆哪：从 DP 维里切一刀

EP 不是与 TP/DP/PP 并列的第四维。两条理由决定它从**同一段的
DP 组里**划：① DP 组里的 d 张卡本来就拿不同数据，token 已被
切好，改放不同专家后 all_to_all 恰好在这组卡之间重分发，**零
额外数据搬运**；② 非专家参数（attention、embedding、router）
的梯度仍要在整个 DP 组求和，**DP 组必须原样保留**。

切法（编址视角）：

```
dp = ep + e·edp   （e 张卡一个 EP 组，edp = d/e 份专家副本）
rank = tp + t·(ep + e·edp + d·pp)
```

注意 **edp 不是与 pp 并排的新维度**——它和 ep 合起来还是原来
那根 dp 轴。ep 排最里（编号最连续）的理由同 §三：all_to_all
每层都有、延迟敏感，这个次序让 TP×EP 这块连续编号的卡尽量落
在一个机内域。这个嵌套次序 **tp → ep → edp → pp** 就是 Megatron
`initialize_model_parallel` 的默认次序（面试默写题）。

切完 dp 轴上有五族组：

| 族 | 成员关系 | 干什么 |
|---|---|---|
| TP 组 | 编号差 1 | 每层 4 次 all-reduce，照旧机内 |
| **EP 组** | dp 轴相邻（差 t） | all_to_all 换 token；**组内无 all-reduce** |
| **EDP 组** | dp 轴隔一点（差 t·e） | **同名专家的梯度在这里求和** |
| DP 组 | 整根 dp 轴 | 稠密参数（含 router）梯度照旧 |
| PP 车道 | 差 t·d | 段间 send/recv，与 EP 无关 |

为什么需要 EDP 这个新族：rank0 和 rank2 都持有专家 0，但各自
的 EP 组喂给它的 token 不同——**同一份参数的两个副本梯度不同，
必须求和，否则两个副本越训越远**。MoE 层有两种范围不同的通信
（token 在相邻点之间换、专家梯度隔一点加），所以需要两个组。
两个极端助记：e=1 时 EP 组退化成单卡等于没开 EP；e=d 时 EDP
组退化成单卡，每个专家全局独一份、梯度零同步。

**两个易错点**：router 在 EP 组内虽有多份，但它是普通稠密参数，
**梯度跟 DP 组走，别放进 EP 组**；专家权重每卡一份互不重叠，
EP 组内部**没有任何梯度同步——EP 组里唯一的通信是 all_to_all，
没有 all-reduce**。

## 五、完整 Transformer 的三本账

把组合装进完整网络（词嵌入 E → L 层 → 输出头 logits = h@Eᵀ
共享权重 → CE loss），三本账分开记：

### 5.1 数据怎么分

**batch 只被 DP 真正切开**；PP 让它分段接力；TP 组内人手一份
（切的是权重不是数据）；EP 不预先切数据，只在 MoE 层内部按
路由**临时换手**——MoE 层一过，token 各回各的卡，车道照旧。

### 5.2 激活怎么传（前向一图流）

沿一条 DP 车道看完全程（车道间前向零通信）：

```
[首段] 词嵌入：各卡查半张词表、查不到记零 → TP all-reduce ×1
       每层：attention 出口 + FFN 出口 → TP all-reduce ×2/层
       边界激活 send ──────────────────┐
[末段] recv ◄─────────────────────────┘  （段间 send/recv ×1）
       每层同上 ×2/层
       输出头：半张词表算半份 logits → TP all-gather ×1（新账①）
       CE loss
（MoE 模型：每个 MoE 层内部再插两次 all_to_all 分发/收回）
```

边界 send 藏一层冗余：层出口 all-reduce 后 t 张卡手里边界激活
是同一份，t 条车道发的是同一个张量——**每卡各发一份**（Megatron
经典做法，代码直接）还是**发一份+对端机内广播**（跨机字节 ÷t），
是一道可以自己算账的练习题。

### 5.3 梯度怎么传：拆两本账

- **激活梯度**（传回上游）：沿 5.2 原路返回，TP 组每层 2 次 +
  段间 1 次，**全部卡在反向关键路径上**（上游收不到边界梯度就
  干等——这就是「PP 边界晚到一会儿、气泡就大一会儿」）；
- **权重梯度**（留下更新）：反向过每层时本地算出，**永远零
  通信**——唯一的问题是这份参数在别处有没有副本、副本梯度与
  我是否不同。

由此收敛出全系列统一判据（面试金句）：

> **一份参数的梯度需要在多大范围内求和，取决于它被多大范围
> 复制、且各副本算出的梯度不同。**

套到七行参数上（LN 行是开不开 SP 的分叉点）：

| 参数 | 复制范围 | 各副本梯度 | 需要的同步 |
|---|---|---|---|
| TP 分片权重 | 不复制，每卡一片 | —（token 全在本地） | **无**，梯度天然完整 |
| LN（无 SP） | TP 组内复制 | 相同（消费同一份激活） | **无**（求和反而放大 t 倍） |
| LN（开 SP） | TP 组内复制 | 不同（各吃一半 token） | TP 组 all-reduce |
| MoE router | DP 组复制（含 EP 组） | 不同 | DP 组 all-reduce |
| MoE 专家权重 | EP 组内不复制；EDP 组间复制 | 不同 | EDP 组 all-reduce |
| tied embedding | 首段↔末段复制 | 不同（两路用法） | **embedding 组 all-reduce** |
| 一切复制参数 | DP 车道间复制 | 不同（数据不同） | DP 组 all-reduce |

时序对应：反向途中只有激活梯度在走（TP 每层 2 + 段间 1），
权重梯度全程本地记账；**反向结束后这张表才逐行兑现**——
embedding 组一次、EDP 组一次、router 与其余复制参数合在 DP 组
兜底；前两行零通信所以任何账上都不出现。单独讲任何一种并行
时这张表只有一两行，**组装成整体后七行才全部到齐**。

## 六、只有组装起来才冒出来的两处通信

**① tied embedding 的梯度**：E 被首段（查表嵌入）和末段（转置
算 logits）各用一次，两路梯度来源不同（「哪些词被查到」vs
「哪些词的 logit 影响了 loss」），总梯度是两路之和——首末段
之间、同一 (tp, dp) 位置上要多一次 all-reduce。这就是 Megatron
的 `embedding_group` 与训练循环末尾
`allreduce_word_embedding_grads` 的由来；中间段不参与，别的
车道不管。

**② 输出头的反向求和**：前向半词表 all-gather 拼全 logits
（5.2 新账①），反向还有它的对偶——每个词的 logit 都经 E 的
对应行向 h 回传梯度，V 份贡献加总才是完整 dL/dh；E 被切成
两半，每卡只能算「经过我这半张词表」的那半贡献，**两半必须
TP 组内 all-reduce** 反向才能继续往下走。这正是列切层
`gather_output=True` 的前向「原样分发/反向求和」对偶的首次
完整出场——末段 backward 因此比首段多出一次 all_reduce。

两处说明同一件事：TP 的切分对偶律（列切「入口复制」、行切
「出口求和」，前向与反向互为对偶）**在完整网络的边界上同样
成立**。

## 六·增、MoonEP：把 EP 负载失衡做成「有解的规划题」

K3 的 2.8T MoE 训练给出 EP 家族的新锚点（arXiv:2607.24653 官方
口径，本仓未复核；开源 github.com/MoonshotAI/MoonEP）。标题里
「完美」不是修辞，是定义：**每个 rank 恰好收到 S×K 个 token**
（S 序列长、K 每 token 选专家数），所有 rank 计算量逐字相同：

- **冗余专家上界定理**：设 E 个专家、EP 并行度 R，可证每 rank
  至多 E/R 个冗余专家槽位必存在可行方案，且该界 essentially
  tight（报告附录 E 给出两条定理证明）。预留 E/R 槽位 → 规划
  永远有解 → **训练永不因失衡中断**。对照 ECHO/UltraEP 预设
  cap 的路线：cap 内无解就停训，cap 还得手调，停了也有残余
  失衡——三毒全中。
- **在线规划**：每步算最优太贵。离线用整数线性规划（ILP）算
  代表用例做参照，线上跑一个近优 GPU 规划 kernel，开销可忽略
  且从不越 E/R 上界。前向从当前 micro-batch router 输出规划
  并预取冗余专家，反向先把冗余专家梯度存本地 reduce buffer、
  算完再 reduce 回 home rank。
- **零拷贝通信**：规划 kernel 预计算每个 token 的目的地，直接
  发到远端 expert-grouped 位置后把通信 buffer 的 view 直返计算
  ——取消中间拷贝。最坏失衡下 DeepEP 需要容量 S×K×R 的通信
  buffer，**MoonEP 固定 S×K**。
- **同步免除**：常规 MoE 每层每步都要 host-device 同步拿真实
  shape 再发射计算，层间 stall；完美均衡让 shape 静态，免同步。

面试接法：把它挂回本篇 §五 的三本账——MoonEP 没有发明新记账
方式，而是把「失衡税」从运行时问题改造成**可证明有解的负载
规划问题**；再勾一句 [MoE 架构](../llm基础/moe架构.md) 的
常规 EP 失衡账（DeepEP 派），「先限定界、再规划、后零拷贝」
三段式就是 2.8T 规模的显存与通信答案。

## 六·增二、A2 速记：KDA CP 与 TSP

- **KDA CP（86）**：KDA 段状态可分解，用固定大小 all-gather 做 context
  parallel；2.8T 参数、1M 上下文，KCP 线性扩展。
- **TSP（103）**：把 TP 与 SP 折叠到同一设备轴，权重与激活同时按 1/D
  分片；128K 显存 **38.8GB vs TP 70GB**；1024 卡 **173M vs 86M**。

## 七、▶ 面试题

**Q1【高】TP/DP/PP 的排布顺序为什么是 TP 最内、PP 最外？**
答：两个链条。① 编址上 rank = tp + t·(dp + d·pp)，越内的维度
组员编号越连续，连续编号同机；② 编址顺序因此决定通信落在
哪个物理范围，而原则是「最贵最频的通信放进最小范围」：TP
每层 4 次延迟敏感小消息必须机内 NVLink，DP 每 step 一次 GB 级
带宽敏感大消息摊到多机网卡，PP 每 micro-batch 两条量最小
跨机足够。反例记住双输：TP 跨机则每层 4 次暴露在网络上且无法
藏进计算空隙，DP 入机内则最大流量憋在单机、网卡闲着。

**Q2【高】EP 组的梯度怎么同步？router 的梯度放哪个组？**
答：先分族。EP 组（相邻）只做 all_to_all 换 token，**组内没有
任何梯度 all-reduce**——专家权重每卡一份互不重叠。同名专家的
不同副本在 **EDP 组**（隔 t·e）间求和，因为各 EP 组喂给它们的
token 不同、梯度不同。router 是稠密参数，跟着 attention/
embedding 一起在 **DP 组**兜底求和，不进 EP 组。判据一句话：
复制到哪、梯度求和到哪。

**Q3【高】initialize_model_parallel 的默认组次序是什么？为
什么？** 答：tp → ep → edp → pp。编址式 rank = tp + t·(ep +
e·edp + d·pp)：ep 排最里让 TP×EP 这块连续编号的卡尽量落在
一个机内域（all_to_all 每层都有、延迟敏感）；edp 只是 dp 轴被
EP 切完后剩下的那段，不是独立新维；pp 在最外因为段间通信量
最小。e 个极端检查：e=1 时 EP 退化单卡等于没开，e=d 时 EDP
退化单卡、专家梯度零同步。

**Q4【中】tied embedding 在 PP 下为什么要专门建一个组？**
答：词嵌入矩阵被首尾两处使用：首段查表嵌入、末段转置算
logits。两段的副本各自反向，梯度来源不同（被查到 vs 影响
loss），总梯度是两路之和——所以首段与末段同一 (tp, dp) 位置
之间要 all-reduce 一次，这就是 embedding 组（Megatron 的
embedding_group / allreduce_word_embedding_grads）。这是**只有
装进完整网络才会出现的通信**：单构件实验里看不到它。

**Q5【中】name 一次「输出头」在 TP 下的前向与反向通信。**
答：前向一次 all-gather——各卡用手里半张词表算出半份 logits，
必须拼全词表才能对全词表算 CE loss；反向一次 all-reduce——
每个词的 logit 经 E 对应行向 h 回传梯度，V 份贡献合起来才是
完整 dL/dh，两半词表各算一半贡献必须求和。口诀：**列切层
「入口复制、出口求和」，前向反向互为对偶**。末段因此比中段
多这两次通信。

**Q6【中】new_group 为什么不在组里的进程也要调？**
答：建组不是本地记账。登记成员表、分配组内编号、NCCL 交换
通信地址建 communicator 都要在 world 范围内协调——全体进程的
调用序列必须逐次相同，缺一个进程，其余进程阻塞在内部同步点
上（经典 hang）。分工是「调用全体一致，句柄各留各的」：
members 是坐标确定性函数，每张卡算出的是同一个分组方案。

**Q7【中】PP 边界激活为什么要发 t 份冗余？有更省的发法吗？**
答：TP 层出口 all-reduce 后，组内 t 张卡手里的边界激活同一
份，t 条车道发的是同一张量。Megatron 经典做法每卡各发一份
（GPU j → 对段 GPU j），代码直接；省法是 tp_rank 0 发一份、
对端收到后 TP 组内机内广播——跨机字节 ÷t，多一次机内广播。
选哪条看网卡带宽是不是瓶颈：是就值得换，不是就别折腾；这也
是「组合层才有的冗余」，单讲 TP 或 PP 都看不见。

**Q8【低】LN 的梯度在 TP 组要不要 all-reduce？**
答：看 SP。LN 在 TP 里不切（组内每卡一份完整的），问的是
各副本梯度是否相同：不开 SP 时各卡消费同一份激活，梯度天然
一致——**求和反而放大 t 倍，零通信**；开 SP 后激活沿序列维
在组内再切一刀，各卡只吃一半 token，梯度不同——要 TP 组
all-reduce。这行是「复制范围相同但梯度可同可不同」的最小
反例，专治把「复制到哪求和到哪」背成「复制就要求和」。
