## 一、问题：性能优化在悄悄改变策略

RL 训练的大头时间在 rollout，所以系统本能地往低精度计算、低精度
KV cache、通信与 kernel 优化上走。但这些优化会**改变推理侧的数值
路径**：rollout 引擎生成回答，训练引擎对同一段回答重算概率并
更新——同一组权重下，两边对同一个 token 算出的 logprob 不再相同，
**训练优化的就不是实际采样的那个策略**（on-policy 悄悄变
off-policy）。

证据（两组实验，均未开算法修正）：

| 模型/任务 | 基线（高性能但不一致） | 一致版（diff=0） |
|---|---|---|
| DeepSeek-V4-Flash（FP8，数学推理 GRPO，100 步） | 训推 KL 从 **2e-3 涨到 29.9**，同期 reward 回落 | 每步 diff/KL 全 0，reward 不回落 |
| Nemotron-3.5-30B-A3B（Mamba 混合+NVFP4，SWE-bench Pro agentic RL） | 训练分数从 **0.56 掉到 0.22**，entropy 0.05→2.6 | KL 恒 0，entropy 稳在 0.05，分数 0.56→0.59 |

注意第二条基线的 KL 其实**在变小**（0.015→0.002）却仍崩了——
不一致的症状不一定是 KL 单调恶化，entropy 失控是另一种死法。
训练不稳定的代价不是玄学：崩溃、回滚、重跑增多，**有效训练
占比下降**——「更快地完成有效训练」靠的是少崩，而不是单步更快。

## 二、A/B/C 三难：已有做法的谱系

目标拆解为三件事，通常只能同时拿两件：

- **A 高性能**：rollout/训练够快，低精度与通信优化都得用；
- **B 高一致**：两引擎对同一权重算的是同一个策略；
- **C 低成本泛用**：换模型/精度/硬件时对齐成本可接受。

| 做法 | 保住 | 放弃/付出 |
|---|---|---|
| 算法修正：TIS（截断重要性采样）/ MIS（整条序列超阈即丢）/ FlashREINFORCE（轨迹级信任域过滤）/ Score Centering（加性漂移修正） | A、C（不动引擎，与模型无关） | 数值差异仍在，只是限其影响；低精度下差异变大，修正跟着吃力；P1-VL 实验里 TIS **只推迟了崩溃** |
| R3（回放 rollout 时的专家路由） | A + 补上 MoE 路由这一块 | 只消路由翻转，其余差异仍在 |
| QAT（训练 forward 模拟量化，反向走 STE） | A + 量化那部分差异 | 只模拟权重时，激活/KV/kernel/归约差异仍在 |
| 严格数值对齐（Thinking Machines 批不变 kernel / slime / IsoExec / 本文） | **B** | TM 用通用批不变 kernel 付出 A（26s→55s，优化后 42s）；slime/IsoExec/本文在高性能路径上对齐保住 A，付出 C（逐模型逐算子对齐） |

两个关键区分（面试加分）：

1. **引擎间差异 ≠ 版本间差异**。本文对齐的是「同一权重版本、
   两个引擎」；异步训练里「旧权重 vs 新权重」的版本差异仍归
   TIS/MIS/Score Centering 管——两者可叠加，且**逐位一致的训练
   是衡量算法修正效果的基线**。
2. 本文给 A 定的及格线是**rollout 吞吐不低于高性能基线的 70%**
   （rollout 是 RL 最耗时部分）——最后做到 91.3%/87.5%。

## 三、diff=0 的精确定义：五要素 + 三条附加约定

**diff**：每轮更新前，同一权重版本、同一 token 前缀下，rollout
返回的每个有效采样 token 的 logprob 与训练侧重算 old-logprob 的
差。验收是**精确相等**——逐 token |p_rollout − p_train| 的
max/mean/std 全为 0，k3 KL 为 0，不是小于阈值。五个维度：

1. **kernel 确定（单卡）**：同一 kernel 同一输入同一输出。GPU 默认
   不保证——split-K 改变累加顺序，浮点加法不满足结合律；
2. **批次无关**：一个请求的结果不依赖同批还有哪些请求。动态拼批/
   拆批、按 batch 大小选 kernel、动态 split 数全在禁列；
3. **阶段一致**：同一 token 在 prefill 和 decode 里结果相同——
   两阶段各走最优 kernel 是默认做法，**强行统一路径是一致版性能
   损失的主要来源**，也是优化重点；
4. **跨卡一致**：AllReduce/reduce-scatter/EP 合并结果固定。两档：
   同布局只要求不随时序变；**不同布局（rollout DP8/EP8 vs 训练
   EP32/CP4）要求换并行度仍不变**，常规解是固定归约树（贵），
   本文的解是把归约**移出比较路径**（见 4.5）；
5. **同一份数值契约**：同样的量化舍入、累加精度、kernel 算术——
   两引擎各自满足前四条但算法不同，结果照样不等。

附加三条：

- **离散选择一致**：Top-K、MoE 路由会把上游 1 ulp 差异放大成
  整个 token 集/专家组合的不同——平局打破规则、输出顺序、合并
  规则两侧必须同套；
- **每步只做 1 次更新**（step batch = mini-batch）：多次 mini-batch
  更新从第二次起训练权重已非采样权重，diff=0 管不到（实测每步
  4 次更新时，每更新一次约 7% 的 token 换专家组合）；
- **反向算对 + 恢复后仍一致**：前向一致不代表梯度对（本文梯度
  含 STE 代理分量，需独立参考核对）；checkpoint 恢复后的第一步
  也要仍一致。

根因只有两类：**运算顺序不同**（归约顺序随调度变）或**计算路径
不同**（两侧/不同形状跑不同 kernel 分支）——所以工程顺序是
**先消静态差异，再钉住动态路径选择**。

## 四、核心决策与逐算子 recipe（DeepSeek-V4-Flash）

**核心决策：推理 kernel 定数值，训练只补反向**。rollout 占大头
且推理 kernel 全是吞吐调过的，让训练迁就推理：训练 forward
直接调 vLLM 同一批 kernel 取值；kernel 无反向，用自定义
`autograd.Function` 包住，反向对 BF16 主权重求导、FP8 量化在
反向里当恒等（STE）；个别融合 kernel 的输出没法求导的，用
PyTorch 重跑同计算**只取梯度、值仍用 kernel 的**
（`visible + (graph - graph.detach())`）。代价全在训练侧：存
kernel 输入输出给反向 → 显存压力 → 开全量重算（forward 实际
跑两遍）。

逐算子取舍表（保留/放弃/代价三段式，背诵骨架）：

| 算子 | 保留 | 放弃 | 主要代价 |
|---|---|---|---|
| Dense GEMM | W8A8 + DeepGEMM 批不变模式（每个输出只有一种累加） | M<32 走 FlashInfer 的分支、小 batch 专用 gate kernel、mHC 融合 split | rollout 小 batch 不能换快 kernel；训练每次 forward 重量化权重 |
| FP8 KV cache | FP8 存储（约 BF16 的 57%，决定并发上限） | decode 直读 FP8 的 FlashMLA kernel | decode 统一走「反量化+收集到 BF16 工作区+同一 sparse attention」：多一次收集反量化；训练多一块私有 cache |
| DSA Top-K | 稀疏注意力本体 | 默认 Top-K 的平局规则与输出顺序 | 两侧多一次排序（确定性 Top-K 单次约 5.9µs，融合后吞吐反升 6.7%）；prefill 按请求多次 launch |
| 专家 GEMM | FP8 分组 GEMM（DeepGEMM） | FlashInfer TRT-LLM MoE（cubin 不可验证批不变） | TRT-LLM 的多 stream 通信-计算重叠没了，rollout 差距主源之一 |
| 跨卡归约 | 训推不同布局自由（DP8/EP8 vs EP32/CP4） | TP>1 | LL 通信无法与计算重叠（串行 86 次 all-to-all） |
| CUDA Graph | 图（decode 每步几十个小 kernel，launch 开销主导时必须） | 只为性能存在的捷径分支 | 工作区按上限预留 |

三个最值得抄的工程细节：

1. **Top-K 固定平局**：分数拼「请求内位置」成唯一键，平局取
   位置较大者；用请求内位置而非 batch 全局位置——否则同一请求
   换 batch 位置平局就不同；选中集合相同还不够，**index 顺序决定
   attention 累加顺序**，统一按位置降序、无效项垫尾。R3 式回放
   不采用是因为每层每 token 最多 2048 个 index，长回答下每条
   序列 GB 级。
2. **跨卡归约移出比较路径**：TP=1（线性层无 all-reduce）；EP 的
   all-to-all **只搬运不改值**，专家输出回到 token 所在 rank 按
   top-k slot 顺序 FP32 本地累加（EP8 与 EP32 同结果）；CP 只
   换边界隐藏状态/all-gather 拼接。训练侧 normal 模式到达顺序
   不定，就**额外 dispatch 路由元数据、按逐位哈希把专家输出对回
   它的 token 和 slot**。
3. **CUDA Graph 三冲突**：① 走图还是 eager 取决于同一步 token
   总数——两条路径必须逐位相同（第一个 bug：短上下文捷径分支
   在捕获时按 dummy 长度被固化进图，改成只依赖静态上界）；
   ② 图里不能有主机同步和随 batch 变的形状；③ **图记住的是
   地址，权重每步要换**——必须新权重拷回原位、原地重算派生
   参数，「第一步一致」不够，skill 要求更新/导出/reload 后再比。
   模式选 FULL_AND_PIECEWISE（纯 decode 整图、混合步分段）：
   PIECEWISE 不如它（10423 vs 16409 tok/s），FULL 让混合步整步
   eager、TTFT 764→1792ms。

性能对账（官方口径）：一致版 rollout 吞吐为基线 **91.3%**
（前 89 步 88.6%）；起初差距 33% 里**约 83% 来自无法重叠的 LL
通信**；试 DBO（双 micro-batch 交错）反慢 39%——每层专家权重
读两遍，而权重读取已吃 HBM 带宽 84%；最终靠「共享专家走辅助
stream + 统一传输」追平至 **16834 vs 16313 tok/s（+3.2%）**。
**两天误判的坑**：一致版 DeepEP 被脚本钉在 RoCE、基线走带宽高
得多的 MNNVL——**比较瓶颈前先确认两组走同一种传输**。

## 五、工程化：Agent + skill 把 C 补回来

对齐工作的瓶颈是专家判断密度（哪个后端批不变、平局怎么对齐、
布局不同怎么对齐量化……换模型全要重来）。拆成两类**目标明确、
可直接测量**的工作后，就可以交给 agent 长跑：

1. **把 diff 降到 0**：定权重定输入，找两侧**第一次**算出不同
   结果的算子 → 缩成最小复现 → 修 → 回真实训练验证；
2. **在 diff=0 前提下追回性能**：profile 找热点、单算子 A/B——
   **变快但结果变了不算，micro benchmark 快但真实 rollout 没变
   快也不算，调慢基线缩小差距更不算**。

skill（train-inference-consistency，已随 verl PR#7688 等开源）
把流程拆成 C0–C10 关卡，五步骨架：

- **C0–C1 定目标立基线**：列模块/精度/并行清单；基线调到正常
  高性能交人审——**基线是「一致版慢了多少」的分母**；
- **C2–C4 小模型先自洽**：从完整模型切 4–6 层小模型（每类算子
  都要出现、相邻层交互保留、尺寸量化同完整模型），先让推理
  引擎**内部**一致（单跑 vs 拼批、整段 vs 逐 token）；
- **C5–C7 接上训练**：训练直调推理算子，逐层比找第一个分叉层；
  补反向，用**不依赖被测代码的独立参考**核对梯度；
- **C8–C9 真实 RL 放大**：连续更新两次、更新前后同版本权重各
  比一遍；过审后换完整模型，含 checkpoint 恢复第一步验证；
- **C10 追回性能**：逐算子优化、每改一处重查一致、交付镜像上
  与基线成对比较。

两个设计最妙：**① 基线和一致版由两个 agent 同时推进**——一个
只管把基线调快，一个只管做出一致版，基线调好后**强制停下来等
人审**，防 agent 为缩小差距把基线调慢；**② 把踩过的坑写进流程**：
运行的程序必须和看到的源码同版本；checkpoint 要验证恢复后第一
步；性能结论必须有公平基线和可追溯原始数据；比通信瓶颈前先
确认同传输。skill 降的是定位与回归成本，**不替代人的判断**——
基线审核、精度取舍、recipe 审核仍归人。

## 六、迁移验证：Nemotron（Mamba 混合 + NVFP4）

换结构差异大的模型检验泛化：Mamba-2/attention/MoE 混合，路由
专家 NVFP4 W4A16、Mamba 投影 FP8、attention FP8 KV。关键对齐点：

- **递推结构**：decode 不再走自己的单步递推，而是**精确重放
  prefill 的分块算术**（固定 autotune 配置、fp32 状态）——与
  IsoExec 的 CPR（chunkwise-parallel recurrent，训/prefill/decode
  同一套舍入顺序）思路一致；注意 IsoExec 的「零 mismatch」是
  契约范围内的、端到端还有 1e-7 量级差，**与本文逐位相同不是
  一个定义**；
- NVFP4 路由专家：CuTe-DSL 分组 GEMM 单一 tactic、不做 split-K、
  按 slot 顺序 fp32 合并；Norm/FP8 量化统一批不变 kernel，禁止
  改数值的融合；
- 训练侧（Megatron-LM 轻量 fork）**直接 import 推理侧同一批函数**，
  不用 R3 路由回放——路由上游逐位相同，路由天然一致。

结果（SWE-bench Pro 远程沙箱 agentic RL，每步 32 任务×8 轨迹、
轨迹均长约 5.7 万 token）：一致版 KL 恒 0、分数 0.56→0.59；
基线 entropy 0.05→2.6、分数 0.56→0.22；前 30 步 rollout 吞吐
为基线 **87.5%（官方口径）**——「A 不低于 70%」的及格线在
两个模型上都达成。

## 八、▶ 面试题

**Q1【高】RL 的训推不一致从哪来？为什么会有？**
答：两个引擎、两条数值路径。rollout 引擎为吞吐做低精度计算、
低精度 KV、按 batch 动态选 kernel、split-K 等优化，每一处都
改变浮点结果（浮点加法不结合）；训练引擎重算 old-logprob 走
另一条路径。同一权重同一 token，两边概率不同，训练优化的就不
是采样时的策略——on-policy 变 off-policy，且差异可能随更新
累积。证据是基线 KL 从 2e-3 涨到 29.9 伴随 reward 回落。

**Q2【高】TIS/MIS 这些重要性采样修正够不够？本文路线的区别？**
答：修正的是影响，不是差异本身。TIS 截断概率比换方差可控、
MIS 丢整条超阈序列、Score Centering 加性消漂移——都不动引擎，
接入便宜（保 A 保 C），但低精度下差异变大时修正跟着吃力，
P1-VL 的实验里 TIS 只推迟了崩溃。本文是消除差异：训推两侧对
每个 token 的 logprob 精确相等。两者管辖的其实是两件事——
修正管「新旧权重版本的策略差」，对齐管「同权重两引擎的数值差」，
可叠加；且对齐版是衡量修正算法效果的基线。

**Q3【高】diff=0 要满足哪几个维度？通俗讲。**
答：四加一加三。kernel 确定（单卡同人同出）、批次无关（结果
不依赖同批邻居）、阶段一致（prefill/decode 同数）、跨卡一致
（归约顺序固定或移出比较路径）、同一份数值契约（量化舍入
累加全同）。附加：离散选择的平局与顺序一致（1 ulp 会被 Top-K
放大成 token 集不同）、每步只更新一次（否则权重已旧）、反向
算对且恢复后仍一致。根因归两类：运算顺序变了，或计算路径
变了——所以先消静态差异，再钉死动态路径。

**Q4【高】为什么让训练迁就推理，而不是反过来用批不变 kernel
换掉推理侧？** 答：时间是判决。rollout 占 RL 训练大头，推理
kernel 每个都为吞吐调优过；以训练为准等于放弃这些优化（Thinking
Machines 的通用批不变路线推理从 26s 涨到 55s、优化后 42s）。
所以保留部署级高性能 kernel、改造它们满足一致性：去动态分支
（batch/shape 相关的 kernel 切换）、统一阶段路径、固定离散
选择规则。训练侧只补反向（STE 代理梯度 + 独立参考核对）。

**Q5【中】跨卡一致最难的是训推布局不同，本文怎么解？**
答：不让跨卡归约出现在被比较的路径上。TP=1 免去线性层
all-reduce；EP 的 all-to-all 只搬运不改值，专家输出回到 token
所在 rank 按 top-k slot 顺序 FP32 本地累加——EP8 和 EP32 自然
同结果；CP 只拼接不求和。训练侧到达顺序不定，就额外 dispatch
路由元数据、逐位哈希对回 token 和 slot。这是「换思路」而不是
「付代价」——对比固定归约树的常规解几乎免费。记住前提：
**每步只更新 1 次**，且 TP>1、decode CP 会把归约引回来、目前
不支持。

**Q6【中】CUDA Graph 和逐位一致冲突在哪？怎么办？**
答：三处。① 走图还是 eager 取决于该步 token 总数（即同批还有
谁），两条路径必须逐位相同——坑是捷径分支按捕获时的 dummy
长度固化进图，改成只依赖静态上界；② 图内禁主机同步和动态
形状——与批次无关同向，很多设计两边受益；③ 图记地址不记值，
权重更新必须拷回原存储位，否则图继续引用旧权重。模式用
FULL_AND_PIECEWISE：纯 decode 整图、混合步分段；PIECEWISE
吞吐差一截，FULL 让混合步全 eager 把 TTFT 从 764ms 拉到
1792ms。

**Q7【中】为什么说「diff=0 不是训练质量的充分条件」？**
答：diff=0 只保证两引擎算得一样，不保证算的东西适合训练。
例：每步多次更新时 diff=0 依然成立，但更新之间路由在漂移
（实测 7% token 换专家）；梯度含 STE 代理分量，前向一致不
说明梯度算对（要独立参考核对）；回答长度在两组间不同会污染
吞吐对比。所以它是工程验收目标，训练质量（reward/下游分数/
entropy 曲线）要单独验收。

**Q8【低】Agent+skill 这套工程化里，最适合抄的两个设计？**
答：① 双 agent 分立：一个只调基线、一个只做一致版，基线完成
后强制人审——从机制上防「为了差距好看把基线调慢」；② 把踩
过的坑写成流程检查项：程序与源码同版本、checkpoint 恢复后
第一步必验、性能结论必须公平基线+可追溯原始数据、比瓶颈先
确认同传输（RoCE 钉死误判两天的学费）。本质：把专家的排查
动线固化成可回归的关卡（C0–C10），换模型时人来审、agent
来跑。
