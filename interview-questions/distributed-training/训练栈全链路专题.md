# 训练栈全链路专题：一个训练任务的一生

> **面向**：已经零散装过 gang、ZeRO、NCCL、ckpt、训推一体这些词，但被面试官
> 一句「讲讲一个训练任务从你提交到收敛的完整过程」打穿的读者。本篇把
> 平台 → 框架 → 运行时 → RL 串成一条链路，让你能顺着讲、也能顺着被追问。
>
> **读完获得**：① 一张「任务生命周期」九阶段对照表，每阶段标好深潜去处；
> ② 八个环节的统一拆法——这一环干什么、面试官怎么追问、答不上去哪篇补；
> ③ 三条高频连锁追问剧本（任务起不来 / MFU 低 / RL 为什么贵）的应答路径。
>
> **口径**：本篇是链路图，不是知识库。机制一律不新讲，只讲每一环在哪篇深潜、
> 环节之间怎么咬合；文中所有数字均转发自对应深潜文档，引用前去原文核日期。

## 一、链路总览：任务生命周期九阶段

一个训练任务从出生到上模型库，走这么九站——括号里是本篇环节编号，RL 场景
在链尾追加两站：

| 阶段 | 关键机制 | 深潜去处 |
|---|---|---|
| ① 提交与调度（环节 1） | gang 整组准入、配额排队、按通信拓扑放置 | [集群调度与资源管理专题](../集群调度与资源管理专题.md) |
| ② 拉起与初始化（环节 2） | rank 编排、通信域初始化、镜像一致性 | [训练生产排障手册](./训练生产排障手册.md) |
| ③ 数据加载（环节 5） | rank 分片采样、预取、顺序大文件 | [训练框架与稳定性](./训练框架与稳定性.md) 第五节 |
| ④ 训练循环（环节 3、4） | 框架选型 + 3D 并行与 ZeRO 拆解 | [三维并行](./三维并行.md)、[zero与显存优化](./zero与显存优化.md) |
| ⑤ 通信（环节 6） | 三并行通信形态分治、慢节点与拥塞 | [通信与网络专题](./通信与网络专题.md) |
| ⑥ 容错与存档（环节 7） | 续训三件套状态、异步落盘、弹性重启 | [训练生产排障手册](./训练生产排障手册.md) 第四节 e 支 |
| ⑦ 评估与导出（环节 8 前置） | 离线评估、权重导出、上推理引擎回放 | [高频面试真题汇总](../高频面试真题汇总.md) |
| ⑧ RL 追加：rollout（环节 8） | 训练侧与采样侧双引擎并肩跑 | [rl系统训推一体专题](./rl系统训推一体专题.md) |
| ⑨ RL 追加：权重回灌（环节 8） | 权重同步进推理引擎、训推一致性防线 | [verl深度拆解](../训练与对齐/verl深度拆解.md) |

**链路记忆的口诀**：先「上不上得来」（①②），再「跑不跑得快」（③④⑤），
然后「挂了能不能活」（⑥），最后「训完去哪」（⑦），RL 再加「双引擎怎么
对齐」（⑧⑨）。四句话对应第三节四条追问主线，背下来就能临场组句。

## 二、逐环节拆

### 环节 1：平台调度——任务为什么能上、上到哪

**这一环干什么**：把你的作业从队列里放进集群。三个决定在这一环做出：
gang 准入（整组 rank 要么全上要么一个都别上，部分启动等于占着卡等死）；
配额与排队（Kueue / Volcano 这层决定谁能抢先用）；拓扑感知放置（TP 组必须
塞进高带宽域内，通信域就是调度域——机内 NVLink 与跨机网卡有 18 倍带宽差，
把 TP=8 的 8 个 rank 撒到 8 台机器上等于亲手把训练打死）。

**面试官怎么追问**：为什么 gang 是约束不是优化项（答：AllReduce 是同步集合
通信，一个 step 结束于最慢的 rank）→ 部分启动会死锁，调度层的解答是什么
→ 多租户怎么公平分（配额、借还、抢占）→ 拓扑感知到底感知的是什么。

**答不上时去哪篇补**：[集群调度与资源管理专题](../集群调度与资源管理专题.md)，
它的第〇节「K8s 原生调度三个结构性不匹配」就是本环节的全部追问根。

### 环节 2：拉起与初始化——rank 怎么知道彼此是谁

**这一环干什么**：调度把 Pod 放下后，每个进程先回答「我是谁、队里多大、
去找谁报到」——就是 `RANK` / `WORLD_SIZE` / `MASTER_ADDR` 这一套环境变量
（torchrun 或 elastic launcher 注入）。然后 NCCL init：拉起通信域、做拓扑
探测、决定算法与 channel。镜像一致性是这一环的隐形硬约束：所有 rank 的
NCCL 与依赖版本必须同版同参数，否则 init 能过、性能悄悄崩。

**面试官怎么追问**：`MASTER_ADDR` 挂了会怎样（全员报到失败、任务僵在 init）
→ NCCL init 在干什么（拓扑探测决定走 NVLink 还是 RDMA、选哪种算法）→
为什么镜像升级一次能把 MFU 打掉一截——这就是排障手册「故事二」：数字从
47 掉到 40，根因是新版 NCCL 拓扑识别结论变化、算法切换，靠 `NCCL_ALGO`
显式锁回旧算法止血，一上来先 `NCCL_DEBUG=INFO` 对比两份日志。

**答不上时去哪篇补**：[训练生产排障手册](./训练生产排障手册.md) 第三节故事二；
想顺手记 rank 编排字段，搜 torchrun 参数八股去
[高频面试真题汇总](../高频面试真题汇总.md)。

### 环节 3：框架选型——这活该给谁干

**这一环干什么**：在写第一行训练代码前，决定任务在哪个框架上跑。链路视角
下这不是「背横评表」而是「对场景做选择」，五个常见场景：

| 场景 | 首选框架 | 一句话理由 |
|---|---|---|
| 稠密大模型预训练、千卡以上 | Megatron-LM | 3D/EP 最全最成熟，MFU 标杆 |
| 显存紧的全量微调 | DeepSpeed | ZeRO-3 全家桶，HF 生态融合好 |
| 留在纯 PyTorch 生态 | FSDP2 / TorchTitan | 官方原生 ZeRO，生态内闭环 |
| 做实验、对齐验证 | LLaMA-Factory | LoRA/QLoRA 一键全模型 |
| RL 后训练（PPO/GRPO） | veRL / slime | 训推一体、接 vLLM 与 SGLang |

**面试官怎么追问**：你用过哪几个（要答三层分层结构：预训练 / 微调对齐 / RL
后训练）→ 每层的「招牌特性」一句话 → 一定收尾带真实使用经历——「7B 用
LLaMA-Factory LoRA 起了头，70B 全量时换 FSDP+TP 自己配，原因是……」；
没真用过就说「实验过 X、读过 Y 源码」，坦诚比吹强。

**答不上时去哪篇补**：[训练框架与稳定性](./训练框架与稳定性.md) 第一节七
框架横评表；DeepSpeed 一族细节去 [deepspeed专题](./deepspeed专题.md)。

### 环节 4：并行策略选择——模型怎么拆到这些卡上

**这一环干什么**：框架定了以后回答「这份模型怎么切、哪些卡一起干活」。
决策直觉是逐级加码的：

1. 单卡放得下数据并行就够：DP，复制权重、各算各的数据分片；
2. 显存紧、还单卡能训得动：上 ZeRO（FSDP / DeepSpeed），梯度、优化器、参数
   分片三档逐步加压；
3. 单卡连参数都摆不下：加 TP（张量并行，拆矩阵）与 PP（流水线并行，分层
   切）；
4. 还有 MoE：EP 一句话——把专家散到专家并行的那一组卡上，通信换显存；
5. 3D 组合的顺序直觉是「先 ZeRO、后 TP、再 PP」——省显存靠 ZeRO 最便宜，
   TP 吃机内带宽最贵时刻意留 NVLink，PP 解决物理放不下后的深度切割。

**面试官怎么追问**：7B / 13B / 70B 分别怎么配 → TP 是机内还是跨机
→ PP 的 bubble 怎么消 → ZeRO-2 与 ZeRO-3 的显存账怎么拆 → MoE 的 EP
与 TP 谁优先。

**答不上时去哪篇补**：[三维并行](./三维并行.md) 与
[zero与显存优化](./zero与显存优化.md)；EP 细节与 3D 源码证据去
[megatron源码深度拆解](./megatron源码深度拆解.md)。

### 环节 5：训练循环与数据——喂得上才算训得上

**这一环干什么**：框架与并行都在位后，每一步的核心动作只剩三件事：
dataloader 吐样本、前向 + 反向算 loss、通信把梯度合起来再更新。链路视角
下这一环最常见的坑是「千卡 GPU 嗷嗷待哺、IO 跟不上」——标准答案四件套
一句话：workers 并行 decode、数据放并行文件系统或 NVMe 缓存、shuffle 成
顺序大文件、GPUDirect Storage 绕 CPU 进显存。多轮对话任务再加上 loss mask
这一件：只对 assistant 回复算 loss，system 与 user 部分要 mask 掉，多轮
拼轮次时还要想清楚轮边界怎么锚。

**面试官怎么追问**：dataloader 慢怎么定位（先确认是 CPU decode 慢还是文件
系统慢，四件套对号入座）→ 分片采样怎么做到不重不漏、能续训
（`DistributedSampler` + 存 dataloader state）→ 多轮 loss mask 怎么写不
漏轮次。

**答不上时去哪篇补**：[训练框架与稳定性](./训练框架与稳定性.md) 第五节；
mask 细节去
[多轮对话loss-mask专题](../训练与对齐/多轮对话loss-mask专题.md)。

### 环节 6：通信与 NCCL——链路上最贵的每一段都要换带宽算

**这一环干什么**：训练循环里每一次 AllReduce / AllGather / P2P，都是把
时间换算成带宽。三并行的通信形态各有一张脸：

| 并行 | 形态 | 频率与体量 | 对带宽的需求 |
|---|---|---|---|
| DP | 梯度 AllReduce | 低频大量，每个 step 末一次 | 跨机网卡即可，可与计算重叠 |
| TP | 中间结果 AllReduce / AllGather | 高频小量，挨层通信 | 必须 NVLink 级别 |
| PP | 层间 P2P | 次数最少、最省带宽 | 最常见瓶颈反而是 bubble 不是带宽 |

**面试官怎么追问**：TP 为什么必须留机内（口诀：DP 低频大量、TP 高频小量、
PP 最省）→ 慢节点怎么定位（straggler：某卡集合通信总拖到尾）→ 拥塞与
PFC 怎么把 NCCL 炸进超时（排障手册故事一：整点拥塞 + watchdog 默认
600 秒太小——同 ToR 另一租户回填打满上行）→ 怎么预防（rail 分平面、租户
隔离、超时调整）。

**答不上时去哪篇补**：[通信与网络专题](./通信与网络专题.md)；事故侧故事去
[训练生产排障手册](./训练生产排障手册.md) 第三节故事一与第四节 d 支。

### 环节 7：容错与 ckpt——挂了能不能无缝活过来

**这一环干什么**：千卡月级训练里不出故障才是新闻，所以这一环解决两件事：
挂了能续上、续上能对上。续训三件套 state 不能只存 step 数：
dataloader state（样本位置）、RNG state（采样顺序）、optimizer state
（AdamW 的 m/v/FP32 master）三者缺一，loss 接缝处就冒台阶。写了也对：
async ckpt 先把 snapshot 拷进 pinned CPU 内存再后台落盘，GPU 不等 IO；
配合并行文件系统或对象存储。再往上是弹性：心跳 + 健康检查踢坏节点、
elastic launcher 让新节点替补上位。

**面试官怎么追问**：ckpt 里都有什么（把三件套各缺一项会出什么症状讲成
答案）→ 异步写到底快在哪（拷贝进 pinned memory 那一段才是关键）→ 复跑
loss 对不上怎么查（排障手册第四节 e 支：分片是否同轮、state 是否齐全、
resume 路径是否同版本）。

**答不上时去哪篇补**：[训练框架与稳定性](./训练框架与稳定性.md) 第二节
异步 checkpoint；事故现场拆解去
[训练生产排障手册](./训练生产排障手册.md) 第四节 e 支。

### 环节 8：RL 后训练链尾——训推一体，一套任务两个引擎

**这一环干什么**：SFT 到环节 7 就完整毕业了；RL 要在链尾追加两站：
rollout（用 vLLM / SGLang 起一套推理集群出样本）与 weight sync（把训练侧
新权重同步回推理引擎）。所以 RL infra 的矛盾总根是一句话：**一个引擎对
四个引擎的结构性不对称**——SFT 只驱动训练引擎，RL 一步要同时驱动
rollout、actor、reference、reward 四类引擎，切换与对齐的开销就是贵的
原因。权重同步实现有三条路线：卡粒度 NCCL 全量广播最直接；checkpoint-
engine 分桶流水化；delta 稀疏同步最省带宽；外加一条「训推一致三层防线」
兜住权重版本对齐。

**面试官怎么追问**：RL 比 SFT 多哪些机器（双引擎、中间件、缓冲队列）
→ 权重同步怎么不挡训练（分桶流水、异步化）→ 训推不一致的后果
（off-policy 漂移污染样本、推理侧权重版本错配）→ colocate 还是 disaggregated
怎么选（显存腾挪换残机，还是另起一套推理集群）→ 为什么 GRPO 比 PPO
对系统更友好（少了 critic 集群，critic 变为组内 advantage）。

**答不上时去哪篇补**：[rl系统训推一体专题](./rl系统训推一体专题.md)、
[verl深度拆解](../训练与对齐/verl深度拆解.md)；实战段去
[rl训练工程实战](../训练与对齐/rl训练工程实战.md)。

## 三、链路追问剧本

### 剧本一：任务起不来怎么排

按链路自上游往下走五步，每步一句内完成：

1. **环节 1（调度准入）**：看任务卡在队列还是已经下来——卡队列 = 配额 /
   gang 准入问题；下来了 = 继续往下。
2. **环节 2（拉起 init）**：看进程是 init 卡死还是立刻报错——`MASTER_ADDR`
   不通查网络，NCCL init 起不来查 `NCCL_DEBUG=INFO` 日志里的拓扑结论。
3. **环节 2 与 6 一起查**：若本任务之前跑过、升级过镜像后挂——版本一致性
   问题，回滚或显式 `NCCL_ALGO` pin 回去（排障手册故事二）。
4. **环节 5（数据加载）**：init 过了但第一个 step 卡——dataloader 路径、
   workers 数、数据权限三件齐对。
5. **环节 7（存档状态）**：若为续训任务——查 ckpt 分片是否同轮、state
   是否齐全，缺的那座重提一次「存档—kill—恢复—前一百步 loss 逐位一致」
   验收。

### 剧本二：MFU 低从哪环开始查

原则是「先分桶再进环节」，四步链：

1. **环节 6（先分桶）**：`nsys` / prof 时间线把时间拆成三桶——计算、
   通信、IO，先知道时间花在哪。
2. 通信桶大 → **环节 6（慢节点与拥塞）**：查慢节点（straggler 比对各
   rank 集合通信耗时）与拥塞（PFC、`XmitWait`、租户干扰）；往回查
   **环节 1（拓扑放置）** 的放置是否合理。
3. 计算桶大 → **环节 4（并行配比）**：并行配比有没有把 TP 塞错位置，
   重计算是 full 还是 selective，kernel 融合（FlashAttention、fused norm）
   有没有开齐。
4. IO 桶大 → **环节 5（dataloader）**：四件套逐项核；若是周期尖刺 →
   **环节 7（ckpt）**：同步写挡训练，该上异步。

### 剧本三：RL 为什么比 SFT 的 infra 贵

总根一句话，展开五步：

1. **环节 8（总根）**：SFT 一个 engine 到底，RL 一步要驱动四类引擎——
   总根就在这里。
2. **环节 8（切换开销）**：生成 ↔ 训练的切换开销 = 显存腾挪 + 引擎重启 +
   权重同步，这都是 SFT 没有的硬开销。
3. **环节 9 与 8（权重同步）**：每条同步路线都要占通信带宽或额外 CPU 侧
   中间件，colocate 下还要在训练卡上腾显存给 vLLM——推理侧 GPU 就是直接
   成本。
4. **环节 4（并行对齐）**：训练侧与采样侧的并行配置各自最优还不一致，
   对齐要再加一层转换与一致性防线。
5. **环节 6（异步化换来的复杂度）**：异步化（partial rollout、staleness
   上限）用工程复杂度换回吞吐，坑位变多——这就是为什么 RL infra 岗单独
   起薪。

## ▶ 面试题

**题一：一个训练任务从你提交到收敛经过哪些环节，各自的负责人是谁？**

按生命周期九阶段顺讲：调度层（Kueue / gang）管能不能上 → 拉起层
（launcher + NCCL init）管组件怎么互相认识 → 数据层（sampler + dataloader
四件套）管喂得上 → 框架层（Megatron / DeepSpeed / FSDP）管拆模型 → 通信层
（NCCL + 拓扑）管梯度对上 → 容错层（三件套 state + async save）管挂了活
→ 评估导出。RL 场景追加 rollout 与 weight sync 两站。每站一句话、不报菜
名，是这题的高分答法。

**题二：给 70B 稠密模型、64 张 H 卡，框架与并行怎么配？**

链路答法合并环节 3 与 4：场景是「稠密大模型大规模训练」→ Megatron；
显存直觉——70B 参数光 BF16 权重就要 140GB 量级，单卡放不下 → 先 ZeRO
（Distributed Optimizer，省优化器状态），再 TP 拆到机内（TP=8 绑 NVLink），
再按需 PP（层切足够深时 bubble 与显存分布折算）。追问单机显存账与 3D
组合的具体例子去 [三维并行](./三维并行.md)。

**题三：为什么 gang 是调度层约束而不是优化项？**

AllReduce 是同步集合通信，一步的结束取决于最慢的 rank——任何一个缺席，
整个作业不可用。**这就是 all-or-nothing 的调度表达**：要么整组同时
上、要么一个都别上；部分上等于占卡空转甚至 NCCL 超时死锁。所以它必须
写进调度准入（Kueue / Volcano），不是事后优化能补的。

**题四：断点续训要存什么、天坑在哪？**

三件套全存：model + optimizer（m/v/FP32 master）+ dataloader state
（样本位置）；外加 RNG state、step 与 lr scheduler 顺手带上。天坑：只存了
step 没存样本位置（续训后 loss 接缝台阶）、分片不同轮、resume 代码路径与
首训版本不一致。验收标准一句话——「存档—kill—恢复—前一百步 loss 逐位
一致」。

**题五：RL 训练链路比 SFT 多了哪几环，贵在哪？**

多了 rollout（推理引擎集群）与 weight sync（中间件）两环；且训练侧与采样
侧必须同权重、同步节奏。贵在：① 独立推理 GPU 或与训练争抢 colocate 显存；
② 切换开销（显存腾挪 + 引擎重载）高频发生；③ 多一道训推一致性防线
（off-policy 修正、staleness 上限），复杂度与坑位一起翻倍。

**题六：讲一个你参与过的训练任务「为什么慢 / 为什么挂」？**

用链路语言组织，别平铺——推荐模板：先定环节（如「属于通信环故障，
不是框架 bug」）→ 再给分桶证据（MFU 对比、`nsys` 时间线、NCCL 日志）
→ 再讲从「哪个环节、哪份日志」定位根因 → 最后讲「换了哪个环节的做法」
（如「版本 pin 上 NCCL、灰度 canary 跑通才推生产」）。这个结构对面试官
来说等于「我真的在链路上」——比背任何答案都有说服力。
