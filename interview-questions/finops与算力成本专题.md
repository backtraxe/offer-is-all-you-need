## 一、直觉：这张卡这一秒有没有在出有用的 token

AI Infra 的成本问题，归根结底就一句话：**这张贵得要命的卡，这一秒有没有在出
有用的 FLOPs 或 token**。所有的 FinOps 手段，都是在把分母里的浪费挤掉。浪费
只有两类：

1. **算不出 token 的浪费**：idle（夜里空转的推理池）、故障（Llama 3 那种
   54 天 466 次中断）、排队（高峰过 provisioned、低谷吃不饱）。
2. **算出来但没用的浪费**：冗余计算（能蒸馏不蒸馏）、过大的模型（7B 能干的活
   派 70B）、没复用的 KV（同一个 system prompt 每请求重算一遍 prefill）。

记好这个二分法，它决定了后面所有手段的归类：砍价类手段降单价，但单价只是分子
的一半；挤浪费类手段抬吞吐和利用率，那才是分母。**省钱的第一优先级永远是填谷，
不是砍价**——这句话是整篇的主线，也是面试时最想听到的那句。

## 二、推理三段式成本公式

唯一正确的拍脑袋框架只有这一条：

```text
$/M output token = GPU-hr 单价 / (单卡聚合吞吐 tok/s × 利用率 × 3600)
```

展开成节点口径就是：（GPU-hr 单价 × GPU 数）/（聚合吞吐 tok/s × 3600 × 利用率）。
三个旋钮的故事完全不同：

- **单价**：2026-10 实测 H100 云按需已经跌到 $2.9–6.88/GPU-hr（RunPod PCIe 档
  $2.89、Lambda SXM $3.99、AWS p5 on-demand $6.88，全部官方价表口径）。2023 年
  还 $12 级的价格三年跌了六七成。**面试报 $10+/GPU-hr 会被当场纠正**。
- **吞吐**：受模型大小、量化、batch、引擎（vLLM/SGLang）、SLO 约束共同决定。
  vendor benchmark 给的是极端 batch 的峰值数字，真实生产按 P99 时延卡 batch
  上限，吞吐可能只有峰值的 30–50%——拿 vendor 峰值做成本测算，预测偏差 2 倍起。
- **利用率**：时间轴上卡忙碌的占比。30% 和 60% 直接决定 $/token 翻倍与否，
  这是三者里杠杆最大、也最被低估的一个。

## 三、70B 完整推导账（2026-10 价格锚，推导示例）

面试官最爱的一题：给你一台 8 卡机，现场推一个 70B 的 $/M token 报价。完整推法：

1. **硬件与单价**：8×H100 SXM 节点，TP8 部署。云按需取 $4/GPU-hr（2026-10
   neocloud 中位口径），节点时租 $32/hr。
2. **吞吐假设**：Llama-3 级 70B 在 vLLM/SGLang 高并发、FP8、batch 拉满下，聚合
   输出吞吐按 5,000 tok/s 量级——这是社区常见量级假设，**未经官方 benchmark
   核实，属推导示例**，白板上有义务主动声明这一点。
3. **满负荷成本**：$32 /（5000 × 3600）= **$1.78/M output token**。
4. **打利用率折扣**：实际 50% 利用率（很多自建池的真实水位），直接翻倍到
   $3.5/M。
5. **对照官方价**：DeepSeek-V4-Pro-0813 输出价 $3.96/M（官方价表，peak 时段）。

第五步是全题题眼：**头部 API 的定价基本就是「70B/激活 37B 级模型 + 满负荷 +
20–30% 毛利」贴在成本线上的价格**。价格战打的从来不是单价战，是利用率战和
毛利垫厚度。能把这套账三步推完的人，面试官会直接跳过下一个八股题。

▶ 面试题（极高频）：「现场推一个 70B 的 $/M token 报价。」必被追问：吞吐假设
从哪来（答社区量级 + 声明推导）、利用率假设多少（30%/50%/满负荷三档都算一遍）、
input/output 分开算没有（必须分开，见下节）、再加一台节点边际成本怎么变
（单价不变、吞吐近似线性，但调度开销引入新利用率损耗）。

## 四、输入侧为什么便宜：prefill 算力记账法

输出价是输入价的 5–10 倍（各家价表均实证），原因要能说清：

- **prefill（input）是 compute-bound**：每 token 前向 2N FLOPs 上限，70B 即
  1.4×10^11 FLOPs/token。H100 BF16 理论 989 TFLOPs，按 40% MFU 折 396 TF 有效，
  理论上限 ~2.8M input tok/s/GPU；实际受 KV/带宽约束再打一两个数量级折扣，
  但底子仍是「算得动」。
- **decode（output）是 memory-bound**：每生成一个 token 要把全部参数从显存读
  一遍，batch 收益受显存带宽天花板限制，天然贵。
- **cache hit 几乎免费**：KV 复用后连 prefill 都省了，只付读显存的钱——所以
  DeepSeek cache-hit 价是 cache-miss 的 1/50（$0.006 vs $0.3 per M input，官方
  文档），Anthropic/OpenAI cache read 是 0.1×。Anthropic 官方还把 cache write
  收 1.25×（写显存占容量、机会成本），hit 只收 0.1×——这一进一出就是 KV cache
  的成本本质——**显存占用时间就是金钱**，token 关联的显存被占多久就收多久的钱。

▶ 面试题（高频）：「API 卖 $10/M input 凭什么赚钱？」答算力记账法倒推毛利，
再引出 prefix caching 的成本结构，顺手讲 PD 分离怎么让 prefill 池和 decode 池
各自拉满（衔接 [inference/长上下文推理与kv体系.md](./inference/长上下文推理与kv体系.md)）。

## 五、训练成本模型：6ND 公式与两个口径锚

训练侧的总成本公式：

```text
总成本 = 6×N×D / (峰值 FLOPs × MFU × 3600) × GPU-hr 单价
```

其中 6×N×D 是 dense 训练的 FLOPs 总量（N 参数量、D token 数，前向 2ND 反向 4ND）。
两个代入实例：

- **70B × 2T tokens**（推导值）：6×7e10×2e12 = 8.4×10^23 FLOPs；H100 按 40%
  MFU → 约 58 万 GPU-hr；$4/hr → 约 $2.3M，等价于约 700 张卡跑一个月。
- **Llama 3 405B**（官方数字 + 推导折算）：官方口径 3.8×10^25 FLOPs、15.6T
  tokens、16K H100。同法折算约 2,600 万 H100 GPU-hr，$2–4/hr → $6000 万–$1 亿
  量级。**这是推导值，Meta 未公布美元账单**，讲的时候必须带这句。

**训练账单最大的可优化项不是单价，是故障与空闲**。Llama 3 的故障账（论文官方
口径）：54 天窗口 466 次中断（47 计划内 + 419 计划外），78% 硬件相关，其中
GPU 类占 58.7%；Meta 靠自动化恢复做到 >90% effective training time。压缩后的
那个 <10% 损耗，在 16K H100 上也是每月百万美元量级。所以 checkpoint 策略是
成本策略：存得密，IO 抖动 + 存储费 + 训练降速；存得稀，单次故障回退数小时。
在这种每天 ≥1 次中断的强度下，异步/分层 checkpoint 是把 78% 硬件故障损耗压进
<10% 有效时间的关键手段——**本质是交钱买故障隔离**。

对照 **DeepSeek-V3 官方账面**：2.788M H800 GPU-hr（pretrain 2.664M + 长上下文
0.119M + 后训 5K），按 $2/hr 折算 $5.576M。三个口径要点：① 官方明确写
excluding prior research and ablation，不含消融/数据/人力/失败 run；② $2/hr
是报告自己假设的折算价，不是采购价；③ 全生命周期成本通常是账面正式 run 的
5–20 倍（社区/投研口径）。SemiAnalysis《DeepSeek Debate》「冰山一角、集群
$1.6B 级」的论点社区广传，但原文 404 未核，引用时只当社区口径讲。

▶ 面试题（高频）：「DeepSeek-V3 说训练只花 $5.576M，为什么人家烧几十亿？」
这题是「读过官方报告的人」和「做过真实训练的人」的分水岭：口径区分答完，
追「2048 张 H800 是自有还是租的」（自有则 $/hr 是机会成本不是现金成本）。

▶ 面试题（高频）：「Llama 3 的 466 次中断对应多少美元？怎么降低？」推 16K
H100 每天中断一次 + 恢复 30min 的损耗占比，然后给 ROI 排序：异步 checkpoint >
健康度预测/热备节点 > 提高 checkpoint 频率。

## 六、清单价 token 价为什么不能横比

直接拿各家价表比 $/M 是新手错误，四个原因：

1. **四维折扣矩阵**：cache-hit/off-peak/batch/fast-mode 每个维度都是数量级或
   半价级差异。DeepSeek off-peak 一律半价（peak 时段 UTC 01:00–04:00、
   06:00–10:00 工作日）；OpenAI/Anthropic Batch API 五折。横比必须按自己业务的
   input/output/cache-hit/peak 分布折算成「我的业务价」。
2. **tokenizer 不同账不同**：同一文本在不同 tokenizer 下 token 数可差 30%
   （Anthropic 官方写明 4.7 起换 tokenizer「约多 30% tokens」）。单价便宜 20%
   但 token 多算 30%，实际是贵的。
3. **SLA 不同**：Fast mode 加钱买的是时延保证，off-peak 价不保证时延。把离线批
   价当在线价比，是在拿无 SLA 商品比有 SLA 商品。
4. **输入输出权重不同**：Agent 场景 input≫output（长上下文 + 工具回灌），按
   1:1 折算出来的「综合价」对你的账单毫无意义，积分权重完全变了。

记几个 2026-10 实测锚（全部官方价表口径）：DeepSeek-V4.1-Flash peak 输入
cache miss/hit $0.3/$0.006、输出 $1.2 per M tok；V4-Pro-0813 peak
$1.32/$0.044/$3.96；OpenAI gpt-6.1-sol $2 输入/$10 输出、cached 输入 $0.10；
Claude Haiku 5.5/Sonnet 5.5/Fable 5.1 分别 $0.10+0.50 / $2+10 / $10+50 per M
tok。注意 OpenAI 页面标注 gpt-5.6-sol 促销定价期至 2026-11-21——新型号价表
是否含补贴促销未知，引用时带观察时点。

## 七、自购 vs 云：回本模型，不是差价问题

回本年限公式：

```text
回本年限 = (整机价 + 机位 + 电力 + 运维年摊) / (云 GPU-hr 价 × 8760 × 实际利用率 × 卡数)
```

三个关键判断：

- **电价从来不是决定变量**：700W 卡按 $0.1/kWh 约 $0.07/hr，对比 $4 时租占
  比 <15%。常说「电力是算力成本大头」是把数据中心建设期和单卡运营期混为一谈。
- **决定变量是利用率**：按 2026 云价（$3–4/H100-hr）反推，自购要利用率稳定在
  ~60% 以上才约 2–3 年回本；低于 40% 很难赢云。自购锁的是「把利用率风险从
  云厂商手里买回来自己扛」。
- **整机价口径**：2026 未实测（2024 社区口径 HGX H100 8 卡整机约 $250K–400K，
  本轮未取得可靠 2026 来源，故只给公式不给代入值）。

▶ 面试题（高频）：「什么时候该自购而不是租云？」回本公式 + 利用率敏感性答完，
必追三连：「只有 30% 利用率呢」（租，且先把利用率做上去再谈买）、「电力运维各
占多少」（<15%，别浮夸）、「B200 发布会把 H100 资产折价多少」（这正是下一条）。

**价格演进本身的账**：B200 on-demand 比 H100 贵约 60–70%（Lambda $6.69 vs
$3.99，官方），但推理吞吐提升 >2×——**按单 token 成本才算得出该买新卡**；
而签长期预留锁的是单价，锁不住下一代卡的掉价曲线。这就是容量规划里「预留签
1 年还是 3 年」的答案：1 年价高但对冲掉价，3 年便宜但赌架构不换代。

## 八、利用率经济学：MFU、填谷与潮汐

两个口径容易混，面试要分开：

- **MFU**：卡忙的时候有效算力占比（训练口径，Llama 3 论文按 BF16 理论峰值算
  38–41% 量级）；
- **utilization**：时间轴上卡忙碌的占比（运营口径，本篇主线）。

从 30% 提到 60%，同样是账单，token 产出翻倍 = 单位成本减半，等效于砍价 50%
而不用跟供应商磨。手段全集：

- **弹性伸缩 + 潮汐调度**：训练/离线批填夜间谷，推理错峰；白天推理、夜里跑
  离线 embedding 回填和评测集，同一张卡打两份工。
- **quota 超卖**：按历史峰值分布超卖算力配额，等效降单价，代价是极端峰值撞
  SLO 的风险敞口。
- **spot/可抢占池**：训练省 40–60%（Vast 官方宣称可抢占档 50%+ cheaper），
  但要求 checkpoint 间隔小时级 + 自动断点续训 + MTBF 建模；推理 spot 只适合
  无 SLA 离线批，在线流量被回收即撞 SLO。
- **idle 治理**：夜间缩容的最大坑是扩容冷启动——模型加载分钟级，与 SLO 直接
  冲突，解法是预热池 + 预测式扩缩容，不是定时器。

## 九、降本组合拳：乘法叠加与上菜顺序

各单项的倍数（社区/blog 常见口径，讲数量级）：

| 手段 | 倍数 | 性质 |
|---|---|---|
| 量化（FP8/INT8/INT4） | 2–4× | 吞吐侧 |
| 投机解码 | 1.5–3× | 吞吐侧 |
| 缓存（prefix/KV/语义） | 2–10× | 看命中率 |
| 小模型分流（路由/蒸馏） | 5–20× | 看分流比 |
| batch/off-peak | 2× | 单价侧 |

组合拳是**乘法**不是加法：全部叠上可到 8–50×，一个半到两个数量级，把剩余
成本打到 $0.05–0.5/M 档（社区口径）。但有三个坑：

1. **顺序错了会互相吞收益**：先分流再量化，小模型侧的量化收益被分流吃掉——
   正确顺序通常是量化 → 缓存 → 投机解码 → PD 分离 → 路由/蒸馏（把质量风险最大
   的收益最大的留最后做）；
2. **每步都要 eval 回归 + 灰度**：这本身是工程成本，小团队「省的钱不够付工程师」
   时，做到前两步就该停；
3. **吞吐测算口径灾难**：每个倍数都是别人 benchmark 的峰值口径，落到自己流量
   形状（in/out 比、并发、SLO）必须重测，否则组合后的预测偏差层层放大。

▶ 面试题（极高频）：「客户要把推理成本降 10 倍，你的组合拳顺序？」按上面的
顺序答，并且每步带可观测性指标：$ per request、缓存命中率、分流回退率。只报
手段不报观测指标的答案是不及格的。

## 十、组织与流程：账单看不见，浪费管不住

- **showback/chargeback 是基础设施**：没有分摊时团队按峰值预算 +50% 冗余是常态；
  上了分摊后两周内砍掉 20–30% idle 卡是常见现象（社区/咨询口径，非硬数据）。
  成本问题一半是技术问题，另一半是「账单对谁可见」的组织问题。
- **预算告警打在 GPU-hr 消耗率上，不要打在美元上**：单价在持续下跌，美元口径
  会把「用量涨了但被降价掩盖」的行为变化全部抹平。
- **容量规划三件套**：需求预测（产品路线图 × 每请求 token 量 × Agent 化膨胀
  系数——Agent 场景单请求 token 量是 chat 的数倍到数十倍）、峰值冗余策略
  （P99 峰值预留 + spot 兜底 + 外部 API 溢出路由三层）、供应商多元化（防单一
  云价格/容量风险，也防被一家锁死议价权）。
- **数据成本回流**：数据清洗/合成/标注用自家模型推理 + 谷电时段 spot 跑；
  RL/后训的 reward 打分量后期飙升（DeepSeek-V3 后训只花 5K GPU-hr 是特例，
  一般后训/RL 占账单 10–40%，社区口径），别把预算全押在 pretrain 上。

▶ 面试题（中高频）：「做容量规划，明年 token 量涨 5 倍，你怎么办？」需求预测
三因子 + 峰值冗余三层 + 供应商多元化，追「预留签 1 年还是 3 年」见第七节答案。

## 十一、▶ 面试题清单（频率标注 + 答法指路）

1. **现场推 70B 的 $/M token 报价（极高频）**——三段式公式 + 第三节完整账，
   主动声明吞吐假设是推导口径。追问：input/output 分开算、边际节点。
2. **API 卖 $10/M input 凭什么赚钱（高频）**——prefill 算力记账法 + cache
   write 1.25× / hit 0.1× 的显存时间成本本质。
3. **Llama 3 的 466 次中断值多少钱（高频）**——损耗占比推导 + 异步 checkpoint/
   热备的 ROI 排序。
4. **什么时候该自购（高频）**——回本公式 + 利用率敏感性三连追问（30% 利用率、
   电力占比、下代卡折价）。
5. **降 10 倍推理成本的组合拳顺序（极高频）**——量化 → 缓存 → 投机 → PD →
   路由/蒸馏，每步带观测指标。
6. **DeepSeek-V3 说训练只花 $5.576M，为什么别人烧几十亿（高频）**——口径
   区分：账面不含消融/数据/人力；全生命周期 5–20× 是社区口径。
7. **为什么输出价是输入价 5–10 倍（高频）**——decode memory-bound vs prefill
   compute-bound + KV cache 显存时间成本 + PD 分离各自拉满。
8. **token 量涨 5 倍怎么做容量规划（中高频）**——需求三因子 + 冗余三层 +
   预留年限对冲掉价曲线。
