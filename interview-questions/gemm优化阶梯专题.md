# GEMM 优化阶梯专题：从朴素内核到接近 2 倍的 13 级拆解（AMD Helios 案例）

> 面向已经读过 [CUDA 与 Kernel 专题](./cuda与kernel专题.md)（roofline
> 判据、Triton/CUDA 选型）的读者。本篇以 Simon Boehm 经典 CUDA GEMM
> worklog 的阶梯教学法为蓝本，拆解 AMD 在 Helios（MI455X，CDNA 5）上
> 用 HipKittens 走的 **13 级 BF16 GEMM 优化阶梯**（ROCm 官博，
> 2026-10）：每一级只引入一个新硬件特性或调度技巧，并配 ATT（AMD
> 高级线程追踪）热循环视图。走到一半就超过调优良好的 MI355X GEMM
> 内核，最后一级接近其**两倍**。读完获得：① 一张「操作 → 单级收益
> → 机制」的总表；② 每个级别的「为什么有效」一句话原理；③ 一条
> 反直觉结论——**最大两级收益来自最朴素的两刀（异步 48%、tile 80%）**，
> 新特性每级只有 4–8%；④ 6 道 kernel 面试题。
>
> **口径声明**：全部单级增幅与硬件参数为 ROCm 官博实测
> （M=N=K=8192、500 次预热+100 次测量+清 L2、早期样片），
> 测试环境声明「固件与软件持续改进中」，绝对值以原文为准。

## 〇、先看硬件三张牌（决定每一级怎么走）

| 层级 | Helios（MI455X） | 与旧 AMD 的差异点 |
|---|---|---|
| 计算 | 256 个 WGP（8 XCD），每 WGP 4 SIMD；**wave=32 线程**（旧代 64） | 32 线程与 32 条物理 SIMD lane 对齐，lane 归属规整，布局优化简化 |
| 片上内存 | 每 WGP 320 KB LDS，**六个 64 KB 分区**（最多五个给 LDS） | 新增**分区冲突**维度：两条每周期 256 B 通路各服务一个 SIMD pair，并发打同一分区会串行化 |
| 缓存/主存 | L2 两块一致 96 MB（NUMA：近端 >40 TB/s、远端 ≈20 TB/s）；HBM4 432 GB、23 TB/s | 旧代的 XCD-L2+LLC 简化为单一 L2；cache hint 支持设备/主机侧预取 L2 |
| 新原语 | **TDM**：描述符驱动的全局↔LDS DMA，最多五维仿射，scatter-gather；**工作组集群**最多 16 个，集群内多播 L2 数据 | 地址生成、padding、按需转置、补零卸载给专用单元；lane 发射带宽让给矩阵指令 |

执行模型：一个 WGP 4 SIMD；工作组调度到 WGP；集群保证最多 16 个工作
组就近并发，可声明共享数据、重复 L2 请求被多播去重。

## 一、13 级总表（操作 → 单级增幅 → 一句话机制）

| 级 | 引入的动作 | 相对上级 | 机制一句话 |
|---|---|---|---|
| L0 | 朴素基线：全局→寄存器→LDS，barrier 串行 | 基准（25.3% MI355X） | 搬运与计算完全不重叠，矩阵单元空转 |
| L1 | LDS 双缓冲 | <1% | 双缓冲对了，但填充仍经寄存器、段尾整体排空，收益不兑现 |
| L2 | **异步直达 LDS**（不经 VGPR） | **+48%** | 省掉寄存器往返、寄存器压力下降，双缓冲收益这才兑现 |
| L3 | 输出 tile 64² → **128²** | **+80%** | 算术强度随 tile 边长三次方涨、搬运按二次方涨；WGP 内复用暴涨 |
| L4 | 256² | +25% | 复用继续涨（问题小的时候牺牲占用率） |
| L5 | K 向四子步寄存器流水 | +19% | LDS→寄存器这段也与计算重叠，不只看 HBM→LDS |
| L6 | A/B ring 放入不同 LDS 分区 | ≈0% | 避开分区冲突；此形状无关键，别的形状/低精度有收益 |
| L7 | **TDM 描述符搬运** | **+38%** | 只有两个 wave 投递描述符，地址生成/padding/转置/补零卸载，lane 发射让给矩阵指令 |
| L8 | **split barrier**（通知与等待拆分） | +4% | 最后一段只用寄存器的 WMMA 塞进 arrive 与 wait 之间，掩盖一部分同步 |
| L9 | 4×4 工作组集群 + 多播 | +7% | A panel 沿列、B panel 沿行共享，一次 L2 返回喂四个工作组 |
| L10 | 经 LDS 暂存的 epilogue | +8% | wave 局部累加器先在 LDS 重整为行主序，全局写回更宽更合并 |
| L11 | 每 SIMD 一个 wave + 三槽寄存器 ring | +6% | 单 wave 内部更高复用，三槽流水维持重叠，64 条 WMMA 一大组 |
| L12 | 每 SIMD 两个 wave（4×2），sched_group_barrier | +6% | 两个共驻 wave 互相掩盖延迟；ring 退回两槽，调度器补位 |

归一化结论（官博口径）：**走到一半已超过 MI355X 调优 GEMM 内核，
末级接近其两倍**。

## 二、逐级的「为什么」（面试追问按这个颗粒度答）

**L1 双缓冲为什么不涨？** 结构对，但填充仍 `global→寄存器→LDS`，
每块 K 结束还要整体排空——搬运路径本身没变便宜。**优化动作与瓶颈
必须对上**：双缓冲治的是重叠，瓶颈却是搬运成本。

**L2 异步直达为什么 +48%？** 拷贝 fire-and-forget（asynccnt 提交），
不经 VGPR：寄存器压力释放（为后面大 tile 腾地方）、写回路径消失、
填充不用抢在迭代最前面。**这是全阶梯第一记重拳**——先让数据进
得出，再谈别的。

**L3 大 tile 为什么 +80%？** GEMM 单 tile 的算术强度约
2MNK/(MK+KN+MN)，M=N=K 时 ≈ 2N/3：**tile 边长按三次方喂复用、
搬运按二次方付代价**，在寄存器/LDS 预算内 tile 越大越好。四个 WGP
各算一个 64² 相邻 tile，共享 panel 要加载四遍；一个 WGP 算 128² 只
加载一遍。**第二记重拳比第一记还大**——复用分布比搬运速度更值钱。

**L5 加流水段为什么有用？** L1 之后 HBM↔LDS 重叠了，但 LDS→寄存器
这一段仍串行：四子步流水让「下一个子步的 LDS 读」与「当前子步的
WMMA」交错。**流水是分层消等待：每一段，都要问‘这一段和谁重叠’**。

**L6 分区感知摆放为什么这例无效也要学？** 五个 64 KB 分区、两条
通路各服务一个 SIMD pair——并发打同一分区会串行化。把 A、B ring
放不同分区即可免费避开。此形状没测出差异，但**硬件新维度的冲突
必须先排查再谈调优**。

**L7 TDM 为什么 +38%？** 描述符驱动的 DMA：只有两个 wave 投递描述符
（wave0 投 A、wave1 投 B，分引擎奇偶），其余继续算；地址生成、
padding、按需转置、补零、重排全部硬件做。**lane 发射带宽还给矩阵
指令**——和 Ver-Rubin/FBTriton 案例同族「把工作从通用单元卸载到
专用单元」。

**L8 split barrier 为什么把「最后的 WMMA」搬进 barrier？** 常规
barrier 是 arrive 完立刻 wait，早到的 wave 空转。拆开后：最后的
LDS 读完成 → 数据已在寄存器 → **arrive** → 先做完仅靠寄存器的最后
WMMA → 再 wait 同伴。**同步窗口里塞有效计算**（`compiler_fence`
保证这段 WMMA 不搬出窗口）。

**L9 集群多播为什么省的是 L2 流量？** 4×4 集群声明共享：A panel
沿列共享、B panel 沿行共享，四个工作组复用同一次 L2 返回；多播
掩码必须含请求者、≤5 目标（写错=正确性错误）。**多播的本质是把
N 次重复请求压成一次广播，它买的是「有效 L2 带宽」不是额外硬件**。

**L10 epilogue 为什么要经 LDS？** 累加器在 wave 内是分散的列布局，
直接写全局是窄写；经 LDS 暂存重排成行主序再写，得到**宽且合并**
的全局写出。

**L11 vs L12 为什么一增一减 wave 数都涨？** L11 每 SIMD 一个 wave：
单 wave 拿 128×128 的输出 tile、三槽 ring，寄存器级复用最高，但
靠 trick 维持重叠；L12 回到两个 wave（寄存器 512/lane，ring 两槽），
**用调度器在 wave 等待时切换补位**换延迟掩盖。**占用率与复用是
一对永远在 trade 的旋钮**：L11 压占用要复用，L12 让回调度要掩盖。

## 三、这篇教会的方法论（面试收尾金句）

1. **单级收益排序和直觉正好相反**：最朴素的两刀（异步搬运、大 tile）
> 占掉大部分增益（48%+80%）；新特性（TDM、split barrier、集群多播）
> 每级 4–8%，但代价更低、对不同形状更通用；
2. **每一级只改一件事，并且配证据**——ATT 追踪看指令流，而不是看
> 总时间猜原因；
3. **旧代的调度直觉继续成立**（MI350/MI355X 的 4-wave 交错、8/16
> wave ping-pong 在 Helios 照用），新硬件特性当**叠加项**用，不是
> 推倒重来；但分区化 LDS、TDM 这种改变数据摆放物理约束的，布局
> 设计要前置考虑。

## 四、▶ 面试题与追问

**Q1【高】GEMM 优化的通用第一刀是什么？为什么大 tile 收益最大？**
先看 tile：算术强度 ~ 2N/3（方阵），tile 边长三次方涨、搬运二次方
涨。L3 一次性 +80% 来自把 WGP 级复用从「四个处理器各算小 tile」改成
「一个处理器算大 tile、panel 只加载一遍」。后续一切调度都在为这块
大 tile 的流水服务。

**Q2【高】双缓冲为什么不保证收益？**
双缓冲治「重叠」，治不了「搬运贵」：填充经寄存器往返时，即使
buffer 结构完美，路径本身把吞吐压在搬运上。**先拆掉搬运路径的成本
（异步直达/TDM），双缓冲的收益才会兑现**——顺序错了就是 L1 的 <1%。

**Q3【中高】AMD Helios 与 Hopper/Blackwell 在 GEMM 调度上的最大
架构差异？**
三个：wave 32 线程（对齐 32 lane，亲和性好）；LDS 分区化带来分区
冲突新维度；TDM 描述符卸载地址生成与布局工作（英伟达侧对应物是
TMA）。**面试别背型号，背「lane 亲和、分区冲突、描述符卸载」
三个维度**。

**Q4【中高】split barrier 给哪些场景？**
任何「完成信号后可以只做寄存器计算」的段落：GEMM 的最后一组 WMMA、
softmax 后的本地归约、多 tile 归并的收尾。原则：把「必须等的同步」
与「不等数据已就绪的计算」分离。**能塞进 arrive-wait 窗口的计算
都是白赚**。

**Q5【中】工作组集群/线程块集群的真实限制是什么？**
调度：集群内所有 CTA 必须共同调度（不能部分到）；共享：多播掩码
含自己、目标数有限（本例 ≤5）；正确性：掩码写错是正确性错误不是
性能问题。所以集群是「形状规范 + 集群小」时的红利，不是通用旋钮。

**Q6【中】为什么说「新特性是叠加项不是推倒重来」？证据？**
四级以上的基础调度（异步+双缓冲+流水+大 tile）在不同硬件代际全都
成立；Helios 后四级（TDM、split、集群、epilogue）每级只加 4–8%，
且都以「保留前五级的全部流水」为前提。**真正作废的是数据摆放的
物理约束（分区、描述符布局），调度骨架穿越代际**。
