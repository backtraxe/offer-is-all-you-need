## 一、主线直觉：瓶颈从 decode 翻转到 prefill 与缓存

一句话主线：Agent 负载**是「读多写少」的极端形态，推理服务的资源模型随之
从 KV 池加 decode 吞吐，翻转成前缀持久性加 prefill 带宽加路由记忆**。

Chat 负载的性质是短输入、中等输出、回合间相关性弱；Agent 把这几条全部
反转。先看最硬的一组实测：**编码 Agent 单步中位输入 195K token、输出仅
317 token（llm-d 对 219 个生产 Claude Code 会话的实测，2026-07）**；输入占
全部处理 token 的 98.6%。大盘口径同向：TraceLab 对 8,058 个会话、665K 步
的实时面板（2026-10-11 抓取快照）给出平均每步输入 226K/输出 840 token
（Claude 侧）与 125K/375（Codex 侧）。制约吞吐的是 prefill 容量和缓存
命中，不是解码——这条翻转是后面所有机制的根。

Agent 负载反转了六个性质，每条都对应一个后面的专题机制：

1. **超长共享前缀**：system prompt、工具 schema、记忆区、文件上下文构成
   的静态头部动辄数万 token；**相邻主 agent 步的输入逐 token 前缀复用中位
   达 99.6%，且 96% 的步复用率不低于九成（llm-d，2026-07）**。
2. **逐轮追加**：agent loop 每步只是 append 一个 action/observation，
   **相邻步输入增量中位仅 632 token、峰值尾部 p99 仍有 148K（llm-d，
   2026-07）**；若无缓存，prefill 工作量随步数平方增长。
3. **多轮亲和**：会话内步间高度耦合，请求换一台引擎落点就要重算约 20 万
   token 的 prefill——路由必须带记忆。
4. **分支与并行采样**：best-of-n、MCTS、self-consistency、sub-agent
   fan-out 共享长前缀、各出短输出，是 RadixAttention 的复用主场；
   **过半请求属于 sub-agent 组、组内请求数中位为 7（TraceLab/llm-d 实测，
   2026）**。
5. **结构化输出硬约束**：两轮 LLM 调用之间夹着一个必须可解析的函数调用，
   输出要过 JSON schema/CFG 的 token 掩码。
6. **迭代编辑形态**：diff/blame 类请求把上下文切成「改一小段、全文重送」，
   对 block 级复用与位置独立缓存（EPIC、CacheBlend 类）提出要求。

llm-d 的六件套就是这条推理链的完整实例：**六件套依次是 MLA 压 KV、宽 EP 腾显存、前缀
路由找回命中、CPU offload 保命、PD 分离各司其职、MTP 减 decode 步数（llm-d
agentic-serving guide，2026-07）**。本篇不重复六件套的机制细节（见
[长上下文推理与kv体系](./长上下文推理与kv体系.md) 与
[推理引擎2026新进展](./推理引擎2026新进展.md)），只回答一个问题：agent
负载下，这些旋钮为什么必须这样拧。

## 二、机制一：前缀缓存与会话亲和

### 2.1 缓存失效不是玄学，是一张有限清单

以 Anthropic 官方文档（2026-10 现行版）为准，缓存按 **tools → system →
messages 的层次组织（Anthropic 文档，2026）**：改前层会使该层及之后全部
失效。推论非常硬：

- 改工具定义约等于全缓存作废；
- 开关 web search、citations、speed 等能力会改 system prompt，同样炸掉
  后段；
- tool choice 只影响 messages 层，是代价最小的动态手段。

另外两个容易被忽略的约束：**最低可缓存长度为 512–4096 token 量级、命中
要求逐字节一致（Anthropic 文档，2026）**。逐字节的意思是连 JSON 序列化
的键序不稳定都能打破缓存——Anthropic 文档点名 Go 与 Swift 的序列化器。
Manus 的教训清单同源且更口语：**把 system prompt 开头放秒级时间戳视为自杀、
上下文必须 append-only、工具中途增删既炸缓存又让模型对历史上调用过的
工具失忆（Manus 上下文工程博客，2025-07）**。

### 2.2 Prompt 架构收敛为「静态区/动态区」布局

最佳实践由此收敛成一张布局图：工具定义与 system prompt 冻结在头部；动态
能力变更走 logits mask 或新机制，不动前缀；时间戳、本轮用户输入、记忆
增量一律放尾部。

Cache breakpoint 的位置是深坑级细节：**缓存断点要打在跨请求不变的最后
一块之后，而不是打在常变块上（Anthropic 文档反模式案例，2026）**。反模式
案例是 breakpoint 打在含时间戳的块上：写入只发生在 breakpoint，读只找
历史写入点，lookback 窗口（20 块）内找不到任何历史写入点，于是每轮全量
miss 还多付缓存写费。金句记好：**内容稳定不等于可命中，可命中要求历史
上曾在同一字节位置写过 breakpoint**。

### 2.3 会话亲和的 2026 收敛答案：sticky until saturated

黏性路由的收益是前缀复用，代价是热点。2023–2025 年的做法是多信号加权
打分，2026 年收敛为最小配置：**前缀亲和 filter 负责黏性、瓶颈匹配的
scorer 负责量化收益、饱和阈值 τ 负责放量（llm-d sticky-until-saturated
博客，2026-08）**。三件套各自的口径：

- 亲和 filter：**共享前缀相似度大于 0.8 才倾向原端点（llm-d，2026-08）**，
  低于阈值视为新会话、走普通负载均衡；
- 瓶颈匹配 scorer：prefill 受限负载看**在飞未缓存 prefill token 数**，
  decode 受限负载看活跃请求数——信号不同是因为两种负载的拥塞源不同；
- 饱和阈值 τ：**τ 由硬件标定闭式推出，等于峰值 prefill 吞吐乘以可容忍
  的 TTFT 惩罚（llm-d，2026-08）**，示例为 Qwen3-32B 在 H100 上 20480
  tok/s 乘以 14s 得到 286,720 token，约合 35 个 8192-token chunk。

效果是**饱和不过热时吞吐达 k8s 轮询的 2–3 倍且 TTFT 不塌（llm-d 官方
实测，2026-08）**；前缀感知路由整体捕获了负载中 **96–97% 的可用复用
（llm-d，2026-07）**。之前的四信号加权混合被废掉的理由也很工程：不可
解释、不可调——τ 把「调参」变成了「标定」。

### 2.4 KV 迁移还是重算：先看命中率梯队

命中率够高时根本不需要迁移。撑不住时的梯队是：**降级路径从 CPU offload 到 NVMe/远程
存储，再到副本间 P2P 拉取 KV block（llm-d P2P KV sharing 路线，2026-08）**。""
KServe/vLLM 生态沿 KV-Events 做精确索引支撑这条链。纯 GPU 内迁移
（Mooncake/Dynamo 式）适合请求已被冷端点接下后的补救。实操结论：先把
路由和缓存层做满，再谈迁移——**迁移是命中率失败后的补救，不是主路径**。

## 三、机制二：KV 生命周期与挂起会话

### 3.1 生命周期对齐「步」而不是「请求」

Agent 会话的真实形状和压测脚本完全不同：**单一主会话每小时量级的请求、
每请求 6–12 次工具调用、步间间隔中位 2s 但 p99 长达 11 分钟（TraceLab，
2026-06 论文与 2026-10 面板）**。KV 必须跨越人类思考的空窗期存活，这正
是 TTL 档位和 CPU/SSD 分层要解决的问题。

面板数据里更扎眼的一笔账：**人类等待时间总量约 3.2 万小时、远超生成时间
约 1.3K 小时（TraceLab Claude 侧面板，2026-10-11 快照）**——大量 KV 处在
「会话未死但人在想」的挂起态。实务结论有三：

1. KV 生命周期与 agent 步对齐：挂起会话的 KV 应主动降级到 CPU/SSD，
   而不是占住 GPU 池；
2. 显存预算拆两项分别建：**活跃主会话数乘中位上下文，加上 fan-out 峰值
   乘 sub-agent 短前缀**，后者短促但必须扛住；
3. runtime 侧暴露「下一步何时来」的信号（工具延迟预测、人类思考检测），
   让调度器提前降级——**工具延迟语义感知预测与追加长度感知 prefill 是
   TraceLab 论文点名的第一批优化机会（UW SyFI，2026-06）**。

### 3.2 CPU offload 的实测收益

llm-d 在 24 GPU、并发 32 下的实测：**收益为输出吞吐提升 13%、中位
TTFT 下降 32%、中位回合完成时间下降 27%（llm-d 官方实测，
2026-07）**。并发 128 时输出 2776 对 951 tok/s（约 2.9 倍）。暂停会话
恢复的场景下，**有缓存前缀的回合首 token 提速 2.8 倍（llm-d 暂停会话
实测，2026-07）**。这组数字是「挂起态降级」策略成立的理由：降级不是有损操作，是显存
经济学。

### 3.3 PD 分离叠加会话亲和：双端记忆问题

PD 分离下长会话的 KV 驻留在 decode 侧，下一轮 prefill 若落回另一台 P
实例就要复传或重算——**这正是 agent 负载推动的组合架构：P/D 两侧都会话亲和加跨侧
KV 复用（llm-d agentic-serving guide 部署形态，2026）**。
否则 PD 分离省下的调度自由会被长上下文的重传成本吃掉一半。面试时只答
出 PD 分离本身不算完，要指出 agent 负载下这唯一「规则改变」的点（机制
细节见 [长上下文推理与kv体系](./长上下文推理与kv体系.md)）。

## 四、机制三：结构化输出约束

### 4.1 逐 token 掩码的开销已被压到近零

2024 年之后的基准事实：**引擎 xgrammar 宣称较旧约束解码引擎最高百倍加速、
端到端接近零开销（XGrammar 论文，MLSys'25，2024-11，论文宣称口径）**。
路线是词汇表二分：context-independent token 编译期预校验，
context-dependent token 运行时解释，掩码计算与 GPU 流水重叠。生态位已
定型：xgrammar 是 vLLM（2024-12 接入）、SGLang（2024-11）、TensorRT-LLM
（2025-01）、MLC-LLM、Modular MAX、OpenVINO GenAI 的默认或官方结构化
引擎；**当前 vLLM 结构化输出后端默认 auto，在 xgrammar 与 guidance 间
选取（vLLM docs，2026-10 核对）**。

### 4.2 XGrammar-2：专治 agent 的动态结构切换

Agent 场景的新问题是「单次生成中多结构切换、跨请求不同 schema」——百
工具 MCP server 的 schema 又巨大。**新一代 XGrammar-2 用 TagDispatch 加跨
grammar 的子结构缓存，把编译成本再降 6 倍（arXiv 2601.04426，CAIS'26，
2026-01，论文宣称口径）**。开销的位置因此转移：逐 token 掩码近零了，
但 grammar 编译和持久化栈构建发生在 prefill 之前，**大 schema 的首次
编译直接进 TTFT**——缓解手段是子结构缓存与 warm-up 请求。

### 4.3 工具约束的主流手段：mask don't remove

工具调用侧的约束主流不是改 prompt，而是 **logits 掩码加 prefill 的
无状态约束（Manus，2025-07）**：工具列表在上下文中保持全集且不动，
decode 时按当前状态 mask 掉不可用工具的 token——模型不会失忆、前缀
不会失效。配套习惯是工具名前缀分组（browser 系、shell 系这类），让
掩码可以按组施加。中途加工具的新机制也存在（Anthropic inline-tools
beta，2026-09），但尚未进稳定版，属「知道有这回事」的档位。

## 五、机制四：BoN 与分支调度的复用经济学

### 5.1 成本曲线：一次长前缀加 N 次短解码

Best-of-n 与树搜索的 serving 成本可拆成一条近似公式（推导值）：
**1 份长前缀 prefill 加 N 份短解码——分支共享的恰是最贵的那段上下文**。
这让 agent 场景做 BoN 的边际成本远低于直觉：n 个分支共享 20 万 token
的前缀，各自只解码几百 token。

### 5.2 枝点复用由引擎自动完成

SGLang 的 RadixAttention 用 radix tree 持有 prompt 加生成结果的 KV，
Tree-of-Thought、self-consistency、ReAct 这类「按前缀分叉」的负载天然
命中；**其 tree 维护在 CPU、LRU 逐叶逐出、无命中也无明显开销，所以默认
常开（SGLang 发布博客，2024-01）**。开发者侧只需要「从同源前缀 fork」
（SGLang 前端 DSL 的 fork 原语；vLLM 侧 n 大于 1 的并行采样在 V1 APC
下自然复用同 prompt 前缀，机制推导值、页面未核到最新版，见文末说明）。

### 5.3 程序级调度：请求不是一等公民，程序才是

BoN 树里蒙特卡洛计数器请求互相队头阻塞，请求级 FIFO 被尾部分支拖住。
**Autellix 把 agent 程序提升为调度一等公民，用程序累计信息量做优先级
与抢占，同延迟下吞吐为 vLLM 的 4–15 倍（arXiv 2502.13965，2025-02，
论文宣称口径）**。同类问题在 RL rollout 出现：reward/verifier 评分依赖
全树完成，调度器若以请求为单位会被尾支拖死（串
[rl环境工程专题](../训练与对齐/rl环境工程专题.md) 的 verifier 咽喉一节）。

## 六、机制五：缓存定价与预热

### 6.1 缓存是一档定价，不只是优化

前缀缓存在商业侧的口径同样硬：**缓存读对比未缓存输入的单价差约十倍——
以 Sonnet 档位为例每百万 token 0.3 美元对 3 美元（Manus 引 Anthropic 官方
定价，2025-07）**。写侧口径：**缓存写为普通输入价的 1.25 倍（5 分钟
TTL 档）或 2 倍（1 小时档），缓存读为 0.1 倍、新代模型进一步降到 0.05
乃至 0.025 倍（Anthropic 文档，2025–2026）**。推论：缓存命中率直接就是
账单乘数：**其平均输入输出比约 100:1、典型任务约 50 次工具调用，
Manus 直言前缀缓存命中率是生产 Agent 最重要的单一指标（Manus，2025-07）**。

自建侧的成本锚：**以 64 张 H200 自建 GLM-5.2 的仅 GPU 租金口径为每百万
token 输入 0.05 美元、输出 3.55 美元，对照 Z.ai 1.40/4.40 与 Claude
Opus 4.8 的 5/25（llm-d 推导，2026-07，持续满载假设）**；MTP 让同 32
GPU 在每用户不低于 30 tok/s 下支撑的**并发能力约提升 8 倍（llm-d
GLM-5.2 实测，2026-07）**。

### 6.2 TTL 决策树与预热打法

步间空窗与 TTL 的错配是隐性上限：**主 agent 步间 p99 间隔 11.4 分钟、
默认 5 分钟 TTL 必然过期（TraceLab 面板与 Anthropic 文档口径叠加，
2026）**。决策树很清楚：

1. 步间间隔大概率小于 5 分钟：默认档，不动；
2. 超过 5 分钟但会话仍活：升 1 小时档（写价 2 倍），或到期前预热；
3. 低频 sub-agent 场景同理按 1 小时档处理；
4. 预热手段：**用 max_tokens 为 0 的纯预热调用（Anthropic 支持，2026）**，
   只写缓存不生内容。

成本模型不扣掉 TTL 错配导致的重复缓存写，等于全错——这是「黏性调度能
省多少」的隐性上限。

## 七、工程议题：五个真正咬人的点

### 7.1 缓存命中率塌方的排查路径反直觉

缓存 miss 往往发生在应用层改动之后：给 system prompt 加了时间戳、JSON
序列化键序漂移、工具 schema 每次运行重新生成导致字段序变化、记忆区
插入位置选在头部而非尾部。这些改动**单元测试全绿、功能无异常，只会
体现为 TTFT 和账单悄然翻倍**。所以线上必须有 cache hit rate 告警
（Anthropic 提供 cache diagnostics API 可比对相邻请求的分叉点；
TraceLab 的 local analyze 面板同思路）。坑中坑是 lookback 语义：写入
只发生在 breakpoint，读只找历史写入点——「内容稳定」不等于「可命中」。

### 7.2 动态工具列表 vs 缓存稳定性

RAG 式按需加载工具理论上省 token、提升选择精度，但**每次增删都炸掉
tools 层全部缓存，且让模型对历史调用过的工具产生幻觉（Manus 实测后
放弃，2025-07）**。2026 的两条妥协路线：Manus 式 logits mask 加工具名
前缀分组做无状态约束；Anthropic inline-tools beta（2026-09）在中途
system message 里追加工具定义、保持 tools 数组不动。考察「什么时候
值得牺牲缓存」的判断比背方案重要。

### 7.3 双稳态：亲和参数不能只在一个负载上调

不设饱和阈值时，亲和路由会把热端点喂到比冷端点更慢；b2b-saas 型「小
语料反复打」负载出现**双稳态——集群要么收敛到稳定的前缀分区、要么
陷入逐出风暴，中间没有平滑过渡（llm-d 官方实测，2026-08）**。这解释
了为什么 τ 必须是标定值而非经验值，也提醒压测要覆盖多种负载形态：
单负载调参在双稳态曲线上毫无外推价值。

### 7.4 grammar 编译成本转移进了 TTFT

结构化输出不再「慢」，但**百工具级大 schema 的首次编译直接进首请求
TTFT**；缓解是 XGrammar-2 的跨 grammar 子结构缓存与预热请求。选型上
lm-format-enforcer 这类 Python 解释器型引擎在 2026 年已事实落后
（star 2.0K、2026-04 后停止活跃，2026-10-11 实测）——具体口径见文末
未核实说明。面试时能被「mask 放在 decode 时不改 prompt，为什么合法」
这种追问考住的人不少：掩码只约束采样空间，不改变上下文条件分布的
定义，因此不违反 append-only 也不动缓存。

### 7.5 挂起会话与 autoscaling 信号错配

**Sub-agent 组内并发 p90 达 51、无预警到达（TraceLab/llm-d 实测，
2026）**，且 sub-agent 短上下文与主会话长上下文竞争同一 KV 池——按
分位数压测几乎必然失真（官方博客自己标注 percentile 要横着读）。
工程映射是 **autoscaling 信号要从 QPS 换成组级到达加在飞 token 数**，
这也是 llm-d scorer 以「未缓存 prefill token 在飞数」而不是「请求数」
为信号的原因之一。挂起态的反面：大量 KV 挂在「会话未死但人在想」的
状态里（人类等待 3.2 万小时对生成 1.3K 小时的面板账），降级时机需要
runtime 侧信号驱动，而不是等到 TTL 硬过期。

## 九、▶ 面试题

每题标注考察频率与深度提示；深挖方向指向仓内对应专题。

**Q1（高频）：为什么 agent 负载的瓶颈是 prefill 不是 decode？给中位
195K 输入、317 输出的形态，估算力需求结构。**
答法：从输入占全部 token 98.6% 出发 → prefill 与 decode 的 FLOPs 比 →
解释为什么 MTP（并发约 8 倍）和 PD 分离里 P 池远大于 D 池才是 agent
拓扑正解。深度提示：能报出 195K/317 与 99.6% 复用两个数是加分项；
深挖接 [长上下文推理与kv体系](./长上下文推理与kv体系.md)。

**Q2（高频）：怎么把 prefix cache 命中率从 83% 抬到 97%？先诊断什么？**
答法：先区分用户步 83% 与工具步 97–98% 的差距来源 → 诊断清单按
「tools→system→messages 层次失效表、JSON 键序、breakpoint 位置、TTL
与步间间隔」排序 → 落地物是 cache diagnostics 加命中率告警。深度提示：
**breakpoint 写在最后稳定块、lookback 只看历史写入点**这两个语义细节
是深坑级。

**Q3（中频）：best-of-n 和 MCTS 怎么 serve？成本曲线长什么样？**
答法：先给近似公式（1 份长前缀 prefill 加 N 份短解码）→ 对照
RadixAttention 的 radix tree 枝点复用 → 升级一档到程序级调度
（Autellix）：请求级 FIFO 在多分枝树里的队头阻塞。深度提示：能接
RL rollout 与 verifier 尾支问题者满分，串
[rl环境工程专题](../训练与对齐/rl环境工程专题.md)。

**Q4（高频）：会话黏性与负载均衡怎么权衡？路由阈值 τ 怎么定？**
答法：sticky-until-saturated 三件套（亲和 filter、瓶颈匹配 scorer、
饱和释放）→ **τ 由峰值 prefill 吞吐乘可容忍 TTFT 闭式标定，不再是
调参** → 追问 prefill 受限与 decode 受限负载信号为什么不同（在飞未
缓存 token 数对活跃请求数）→ 再问双稳态与热点放出机制。深度提示：
主动比较四信号加权混合为什么被废掉（不可解释、不可调），说明读过
2026 的迭代史。

**Q5（中频）：动态工具 schema 怎么同时满足灵活性和缓存稳定？**
答法分三档：不及格（每次重发工具列表，炸 tools 层）；及格（头部静态
区加 logits mask 加工具名前缀分组，Manus 模式叠加 XGrammar-2
TagDispatch 思路）；加分（inline-tools beta 中途追加、sub-agent 按组
持独立前缀、schema 编译预热进 TTFT）。深度提示：追问「mask 放 decode
时不改 prompt 为什么合法」能考住很多人。

**Q6（中频）：长会话挂起 10 分钟的用户回来怎么办？KV 谁养着？**
答法：生命周期对齐步而非请求 → 挂起态 CPU/SSD 降级加 TTL 决策树
（5 分钟刷新、1 小时档写价 2 倍、预热重算三选一）→ 引人类等待
3.2 万小时对生成 1.3K 小时的面板数据说明挂起是常态 → 升级问 KV
迁移与 PD 分离跨侧复用的时延账单。深度提示：提出「工具延迟预测
信号驱动降级时机」者接上了 TraceLab 论文点名的开放问题。

**Q7（低频）：结构化输出对吞吐还有开销吗？什么情况下还有？**
答法：xgrammar 百倍加速与近零开销、XGrammar-2 编译 6 倍提速是基准
答案（标「论文宣称」口径与年份）；剩余开销在首编译 TTFT、超大
schema、以及 regex/CFG 与 tokenizer 对不齐时 context-dependent token
比例升高。深度提示：**能区分逐 token 掩码开销与编译开销、并知道
vLLM 默认 auto 后端选型逻辑**的算闭环。

**Q8（中频）：agent fan-out 洪峰怎么压测与扩容？**
答法：先说为什么分位数压测必然失真（组内并发 p90 为 51、无预警到达）
→ autoscaling 信号换组级到达加在飞 token → KV 池要防 sub-agent 短
上下文挤占主会话长上下文 → 配合挂起降级与 P2P 拉取兜底。深度提示：
能把 llm-d scorer 信号选型（未缓存 prefill token 在飞数）和这题串
起来的，说明理解是网状的不是点的。
