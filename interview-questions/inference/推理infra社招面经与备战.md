> 的数据化复盘、百度推理岗 90 分钟三面实录等。读完你会获得：

> [推理服务slo与运营](./推理服务slo与运营.md)、[infra面试计算题专项](./infra面试计算题专项.md)。

## 一、岗位画像：同名「推理 infra」，干的事天差地别

一线面经的头号结论：**岗位名字一样，实际工作可能完全不一样**。真实
分布：

| 团队形态 | 日常内容 | 核心考察侧重 |
|---|---|---|
| Serving 平台（MaaS） | 多租户调度、限流、计费、API 网关、SLO 运营 | 分布式、网关、容量规划 |
| 引擎侧 | 调度器、KV Cache 管理、Prefix Cache、分布式（PD 分离、EP） | 引擎源码、性能分析、存储体系 |
| Kernel 侧 | 算子优化、量化 kernel、FlashAttention 变体 | CUDA/Triton、硬件架构 |
| 交付侧 | 客户私有化部署、国产卡适配、模型交付 | 全栈杂活、异构适配、沟通成本 |

组织上也有差异：有的团队 engine 和 kernel 小组分工明确，有的职责相互
重叠。**务必须面试时反问确认**：我进去具体做什么？前 3-6 个月负责什么？
有没有明确 owner 方向？是长期技术建设还是临时项目交付？——这条直接
决定 offer 怎么选，一线的经验是「岗位名字一样，实际工作可能完全不一样」。

部署与推理加速方向同理，面经还标出三条含金量赛道：

1. **自动驾驶/端侧**：算力、功耗受限下的极致优化（CUDA 是硬通货：
   CUDA C/C++、Tensor Core、共享内存与线程调度）；
2. **国产芯片**：生态不完善 → 需要全栈部署能力（模型转换、编译优化、
   推理框架自研、算子补齐、图优化、量化适配、异构调度；海光/曙光系还
   要懂 CPU+DCU 异构架构）;
3. **具身智能/机器人**：嵌入式低功耗实时推理（VLA、TensorRT-Embedded、
   MNN、端云协同、ARM 优化、模型轻量化）。

## 二、行情数字锚：2025-2026 推理 infra 社招

- 一位硕 3.5 从业者年初拿到的 offer **年包 140 万**档，评论区同款水位；
  博士三年那位的结论：「高一些的 offer 都在 double 以上，且还有议价
  空间」，最终选研究院型 offer：**涨幅约 60%、现金最高但无期权股票**。
- **行情在转好**：模型迭代快、推理需求指数级增长；但与基模算法的差距
  仍肉眼可见。
- **国产卡溢价**：各家都在真拿国产卡跑推理，MoE + PD 分离 + 大 EP 让
  推理不再是单机八卡；国产卡软件栈坑多文档少，**踩过坑的人稀缺**。
  超节点兴起让计算/存储/网络紧耦合，「既懂体系结构又懂推理框架」的人
  需求越来越大。
- **挂训练名的岗也要推理经验**：RL 后训练的 rollout 本质是推理任务，
  训练框架嵌 vLLM/SGLang 是标配（训推权重同步、异步 rollout、采样吞吐）；
  Agentic RL（多轮工具调用、长轨迹采样）、具身（VLA 实时推理）、
  世界模型（视频生成范式天然贵）同理——**挂「训练组/具身组」名头的岗位，
  实际对推理经验要求不低，推理人的选择面比想象宽**。
- 门槛：学历要求一般偏高（985 起步常见），但足够牛可破格。推理框架
  入行门槛已不低于训练 infra。

## 三、考察全景：六大技术面 + 一条实务链

### 3.1 项目追问八类（最深的一层）

一线总结的项目追问分类，优先级从高到低，前四类几乎每场必出：

1. **边界条件（高频中的高频）**：什么场景收益下降？小 batch 有效吗？
   长短序列表现一样吗？换模型成立吗？换硬件成立吗？极端负载会不会
   退化？——面试官不怕你承认边界，怕你说「什么场景都有效」。
2. **收益与口径**：收益多少、metrics 是什么、收益来自哪部分、在线还是
   离线环境、对比 baseline 是什么、消融怎么做。只说「性能提升明显」
   基本不够。
3. **方案对比与 why**：为什么选这方案？考虑过别的吗？两者能否结合？
   收益拐点在哪？谁工程复杂度更高、谁对系统侵入更大？——建议给出
   **简单建模**而非经验判断（如 GPU 分类回收/回写产生的代价，
   与显存占用收益的数量级对比）。
4. **开销分析**：额外查表/调度开销多大？是否引入 CPU-GPU 同步？是否
   增加显存、通信、访存？是否影响 batching 和 cache 命中率？
   **「infra 优化说白了就是各种 tradeoff」**。
5. 背景与动机：为什么做？原系统瓶颈在哪？研究型项目落地遇到什么？
6. 工程落地：改了哪些模块、对原系统侵入多大、如何保证正确性、如何
   debug 和 profiling、如何避免回归、线上出问题怎么降级。
7. 叙述结构：**问题 → 约束 → 方案 → trade-off → 结果**，别只罗列
   「我做了 ABC」。
8. 开放性系统理解：PD 分离怎么看？KV Cache 管理难点？Prefix Cache
   怎么设计？Agent 场景调度会遇到什么？MoE 推理核心瓶颈？通信计算
   怎么重叠？异构适配难在哪？——需要平时 follow 最新模型结构与 infra
   paper（DeepSeek-V4 这类模型结构特点在多个面试中被反复问到）。

### 3.2 性能建模：口头估算的基本功

很多问题需要现场估算：**计算量、访存量、通信量、有效带宽、并行后的
线性加速比、调度开销**。公式不要求精确，但要能说明假设、趋势和边界。
练法对照 [infra面试计算题专项](./infra面试计算题专项.md) 与把
[显存计算专题](../显存计算专题.md) 的账背熟。

### 3.3 技术栈纵向「不要完全断层」

一位面经原话：「我有一轮被集中问了芯片架构、通信协议、Kernel、量化、
编程模型、集合通信，我回答得不太好」。推理 infra 建议尽量打通多层：
**模型结构 → 并行 → 调度 → 存储（KV cache）→ 通信 → Kernel → 硬件**。
不是每层都是专家，但不能完全断层。十点里最关键的基建两条：

1. **Kernel 理解越深优势越大**，即便不太懂 CUDA/ascendC，也要能做到
   用 Triton 手搓 GEMM、FlashAttention；
2. **持续 follow 最新模型结构**（MLA、MTP、模型层结构变化）。

### 3.4 coding 题型分布（社招实测）

大约 70% ≈ 传统 leetcode（链表、图、动态规划、字符串、树），
**leetcode hot 100 过一遍是底线，重点是能在压力下稳定写出正确代码**；
20% ≈ 推理 infra 结合题（看过的高频两类：**实现一个支持 TP 的
transformer layer（MHA + MLP，写出每个张量 shape）、实现一个
KV Cache paged attention block manager（allocate/free 复杂度、如何
维护空闲块、如何处理碎片）**）；10% ≈ 新型场景题（**提前两天发题，允许
用 coding agent 和讨论，实现一个推理引擎 feature，面试围绕代码包讨论**——
在 vibe coding 大行其道的时代这种考法更合理也更有效）。
同类高频手撕还有：**手写 multi-head attention 并做算量分析**（字节、
商汤基座岗实测）、矩阵乘法优化思路（CPU cache 行为、blocking、
数据布局、并行化）、以及常用结构题在资源块管理器上的变形。

### 3.5 一条可复用的实务链：1500 请求 3500s → 130s

百度推理岗三面问穿的优化链（原文是一个比赛项目，作者被一路追问，
但链本身极值得背下来——它几乎覆盖了批处理调优的完整 why 链）：

1. 基线 3500s：decode batch size 1 → 128，→ 700s（decode 是访存瓶颈，
   组批摊薄权重读取）；
2. 改 serving 让 **prefill 也能组 batch**，→ 400s；
3. **padding 长度 4096→520**（数据集最长 500+ token，只留一点冗余），
   → 200s 出头（无效计算随 padding 平方/线性下降）；
4. **按预估生成长度排序改优先级队列，长的先推**（队列滚得越工整、
   拖尾越短），→ 再省 60s；
5. **warmup**（预热编译/加载，计时干净），→ 再省 8-9 秒，最终 130s。

**面试追问实例**（真实被问过）：为什么排序能提升吞吐？为什么没量化？
weight-only 和权重+激活量化分别卡在哪？投机采样考虑过吗？性能分析
工具用过吗？130s 包不包含模型启动时间？静态图编译和动态图区别？
CUDA Graph 和算子融合区别？被问住两处——profiling 靠「之前的 vLLM
经验」推断瓶颈被当场戳穿；基础概念（静态图 vs 动态图）只背过定义、
讲不到让面试官听明白。**做过的优化必须带 profiling 实锤**。

## 四、项目叙述模板与抗压训练

一线通行证打法：

- **四版本叙述**：每个项目备 30 秒概括 / 2 分钟正常 / 5 分钟深入 /
  追问版细节。面试常被打断，要能随时接回主线。
- **五层抗压**：一个项目最好准备到能被**连续向下追问五层**——可以
  借助 GPT/Gemini 模拟：你只给面试官看摘要，让模型扮演面试官按
  「为什么这么设计/对比方案/边界条件/开销/收益口径」连问。
- **边界与失败清单**：哪些场景有效、哪些无效、为什么无效、重做怎么改、
  上线风险点。这些是社招面评最重要的区分度。
- 软问题标准答法：
  - 自我介绍备 30秒/2分钟/5分钟版本，核心是「你过去做哪一层、擅长什么、
    想做什么、为什么和岗位 match」；
  - 为什么换工作：不吐槽老东家，讲「更匹配的技术方向、更完整的 owner
    职责、想在真实业务场景中深入一个方向」；
  - 失败项目：当时的判断依据 → 后来哪里错了 → 重来怎么拆目标 → 如何
    更早暴露风险 + 与其他团队的对齐方式；
  - 反问环节：问问团队现在最核心的技术挑战、和基模团队有无定期 meeting
    （有没有 model-system co-design 氛围）、正常工作节奏。

## 五、流程情报：轮次、节奏与坑

- **轮次**：社招技术面 2-4 面 + 交叉面/主管面 + HR 面，主管面多为
  「人事与宏观问题 + 项目指标 + 业务思考」，基本不出算法。
- **风格**：一面多为业务一线（项目深挖 → 项目相关八股 → 简单场景题 →
  少量算法题）；二面多为未来主管（复杂场景题常直接来自面试官团队的
  真实业务问题，夹杂跳脱问题）。
- **AI Coding**：严格实操考察的公司不多（集中在大厂），但相当多公司
  至少会**讨论你用 AI Coding 的工作流**——已是新考察项。
- **横向比较/泡池子**：流程普遍慢，遇到「横向泡池子」私下联系面试官
  没用，按节奏铺多家是关键。
- 谈薪：会卡涨幅，超阈值需二次审批；竞对 offer 真实可信同量级是最好
  筹码；**中小厂高报不该轻易撬动大厂定级，但大厂出价更容易带高中
  小厂报价——面序有讲究**（后面再谈具体策略）。
- 面试平台选在职/休息：连续月余高强度面试的精力消耗巨大；把面经
  记录、失分点复盘作为循环是用出来最有复利的时间。

## 六、gap / 转行叙事方法论

百度三面真实案例（gap 16 个月者被前 10 分钟连环问经历，结果通过并
获高度认可）：

- **离职原因照实说**（业务线被裁、跨过 C++ QT 转岗机会、不想走端侧
  小模型一条窄路），把 gap 期间做的事**讲成主动规划**（打比赛拿第一、
  系统学技术栈），反而成为「想清楚方向并付诸实践」的亮点；
- **面试官会提前翻 GitHub 等公开信息**（别惊讶会被要求「别念稿，
  只挑最关键的点讲」）；
- 线上面试面试官**能看到你是否切屏**；
- 遇到过软性问题如「和不一致意见时，你更坚持自己还是接纳别人」、
  「本硕机械，怎么走到推理这条路上」——需要准备真实一致的个人
  叙事主线。

## 七、面试问答

**Q1：你做的优化，收益来自哪里？怎么排除它本身不是偶然？**
先诉指标口径（在线/离线、batch 构成、分位数）→ 收益定位（结合
roofline/分阶段耗时拆解）→ 消融（关掉优化单独测）→ 划线边界条件
（什么输入下收益消失/变负）。

**Q2：KV Cache 管理的难点？**
两层次：引擎内（paged block 分配与碎片、prefix cache 复用、分层卸载）
+ 系统侧（KV 传输开销与 PD 分离怎么权衡、跨实例路由亲和、容量规划与
驱逐策略）。设计细节见 [长上下文推理与kv体系](./长上下文推理与kv体系.md)。

**Q3：一道 20% 题型：设计一个 KV Cache paged attention block manager**
述义 3 件事：内存布局（block 粒度、页表映射）、分配/释放（O(1)、
空闲块怎么维护）、碎片与回收（内/外碎片、连续性子件、引用计数与
prefix 复用）。能做进一步：超长对话场景下怎么选 block size、前缀缓存
的碰撞结构、分层存储怎么接入。

**Q4：你对我们团队了解多少？**
真实在看你意向，不是礼节题。面试前弄清：团队做训练还是推理、做框架/
serving/kernel/模型系统协同还是硬件适配、有没有公开技术文章或开源
项目、业务场景是什么、你为什么感兴趣。**「我觉得贵司平台很好」是不
及格答法**。

**Q5：Agent 场景下推理调度会遇到什么问题？**
四个新点：多轮会话的 prefix cache 命中率是生死线；长轨迹 rollout 的
batch 结构（突变波动）；工具调用带来的「中途暂停」调度（挂起-唤醒
与优先级）；Agent 工作负载的强突发与外场景耦合（多 agent 并发与
排队焦虑）。见 [vllm与推理加速核心](./vllm与推理加速核心.md) 与
[harness工程实战](../agent/harness工程实战.md)。
