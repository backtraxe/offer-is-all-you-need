## 一、主线直觉：把「随上下文长度增长的东西」搬掉

注意力这十年在工程上被改了五六版，面试时如果一版一版背名字，必被追问「每版省的
是什么」问死。答案是**一句话**：注意力优化的本质是把「随上下文长度增长的东西」
搬掉，而搬法只有三种：

1. **搬「存」**：decode 时每个 token 都要留念历史 KV，KV cache 是显存大头。GQA/MQA
   砍每 token 存的字节（K/V 头共享），MLA 用低秩表示再砍一刀（存得更聪明）。
2. **搬「算」**：即使存得省，每个 query 还是要对全量 KV 做注意力。稀疏注意力
   （NSA/MoBA/DSA）训练一个轻量选择器，让每个 query 只看 top-k 个 KV——**但 KV
   本体还在显存里，这是「省算不省存」的分水岭**。
3. **换数据流**：线性/SSM 类直接放弃「存历史再检索」的范式，维护一个常数大小的
   状态 S，decode 每 token 的算力不随 L 涨；hybrid 架构承认「线性层容量不够、全
   注意力太贵」，按 3:1 到 7:1 混搭，取帕累托前沿。

2025-2026 有两个范式切换信号，是本篇的时间锚：

- **稀疏注意力从推理时补丁变成预训练原生组件**：DeepSeek-V3.2-Exp 把 DSA 带上
  671B 旗舰（2025-09-29），三个月后正式版论文默认搭载，官方公告 API **降价超
  五成（api-docs 公告口径，2025-09）**。
- **hybrid 线性从学术玩具变成开源主力**：Qwen3-Next（2025-09）与 Kimi Linear
  （2025-10）同季发布，并且同日级进入 vLLM/SGLang 主线模型列表。

## 二、谱系拆解：六代各省什么账

### 2.1 六代一页表

| 代 | 代表 | 年份 | 每 token 存什么 | 每 query 算什么 | 省的账 |
|---|---|---|---|---|---|
| MHA | GPT-3 系 | 2017-2022 | 全头 K+V，70B 级约 5 MiB/token（本站计算） | 全量 KV | 基线 |
| GQA/MQA | Llama-2/3、Mistral | 2023 普及 | **约 320 KiB/token（GQA-70B 级，本站计算）** | 全量 KV | 存 + decode 带宽，FLOPs 不变 |
| MLA | DeepSeek-V2/V3 | 2024-05（arXiv:2405.04434） | **约 68.6 KiB/token，576 维 latent（本站计算）** | 全量 KV（latent 展开） | 存得更狠且不掉点 |
| 稀疏 | NSA/MoBA → DSA | 2025-02 → 2025-09 | KV 全量还在 | top-k（DSA 选 top-2048） | 算，不省存 |
| 线性/SSM | Lightning Attn、Gated DeltaNet | 2025-01 起 | 常数状态 S（如约 98 KiB/块，本站推导） | 递推更新 O(d²)/token | 算与存都不随 L 涨 |
| Hybrid | Qwen3-Next、Kimi Linear | 2025-09/10 | 1/4 层 MLA 账 + 3/4 层常数 | 同上 | 帕累托混搭 |

### 2.2 省存线：MHA → GQA → MLA

MHA 时代（2017-2022），每 token 每层存下全部头的 K 和 V：70B 级配置
（128 头 × 128 维 × 80 层 × K+V × 2B）算出来 **约 5 MiB/token（本站计算，
70B 级口径）**，1M 上下文一条 sequence 就要约 4.8 TiB——这就是 1M 上下文
长窗口长期只能按 API 计费的显存根因。

GQA（2023，Llama-2/3 普及）的做法是**砍头数不砍维度**：Q 头保持 128 个，
K/V 头压到 8 个共享，每 token 只存 **约 320 KiB/token（GQA-70B 级，本站计算）**，
1M 上下文约 305 GiB。它省的是「存」也顺带省了 decode 时的带宽读取量，但注意
FLOPs 不变——GQA 是纯显存/带宽优化，不是计算优化。MQA 是 GQA 的极端（n_kv=1），
质量掉分明显，生产里基本只出现在小模型。

MLA（DeepSeek-V2，arXiv:2405.04434，2024-05）换了个思路：**不做头共享，做 K/V
联合低秩压缩**。每 token 只存 576 维 latent（512 维 KV-lora + 64 维 RoPE 侧），
与头数彻底脱钩——DeepSeek-V3 的账是 576 维 × 61 层 × 2B ≈ **约 68.6
KiB/token（DSV3 配置，本站计算）**，1M 上下文约 65 GiB，只有 GQA 账的约 1/5，
而且官方口径不掉点。MLA 的三笔「隐藏手续费」面试要能说出来：

- RoPE 侧 64 维不能压（位置信息必须逐 token 保留）；
- 低秩压缩质量依赖**训练时一起学**，后训练阶段往老模型上套会掉点；
- up-projection 是「算力换显存」——decode 时要把 latent 展开回 K/V，显存带宽
  饱和时这笔开销要按 M/N/K 重新估，不是严格免费。

### 2.3 省算线：稀疏注意力（NSA/MoBA → DSA）

稀疏注意力的核心动作是**训练一个轻量选择器**：给每个 query 打分，只放 top-k 个
KV 进主算。NSA（DeepSeek）与 MoBA（Kimi，arXiv:2502.13189，2025-02-18 提交）
2025-02 同周发布，都是块级选择；DSA（DeepSeek-V3.2-Exp，2025-09-29）推到
token 级 fine-grained，lightning indexer 给每 query 选 top-2048。

它省下的是下三角 FLOPs 和 decode 读取量，但 **KV 全量还在显存里——省算不省存，
这是整场面试的分水岭**。也正因如此，DeepSeek 给 V3.2 的定价逻辑才讲得通：HF 卡
口径是 fine-grained sparse attention 对输出质量影响极小（DSA 与 V3.1-Terminus
严格对齐消融，benchmark 打平，官方表格口径），而实际下降的是推理延迟与算力成本
——所以官方公告敢写 **API 降价超五成（api-docs 公告，2025-09-29）**，本质是
把 attention compute 砍了，存储一分没省。

### 2.4 线性/SSM 与 hybrid：换数据流的一代

线性注意力去掉 softmax 换递推核，维护常数大小的状态 S（d_k × d_v 矩阵级）：
decode 每 token 是 O(d²) 的状态更新，**不随 L 涨**；prefill 用 chunkwise 算法
保持高 GEMM 占比。代表节点：Lightning Attention 随 MiniMax-01 进 456B 级生产
（2025-01-14，arXiv:2501.08313），是线性注意力进生产的第一枪；Gated DeltaNet
 随后被 Qwen3-Next 大规模采用。

Hybrid 是 2025 下半年的共识形态：按 3:1（Qwen3-Next、Kimi Linear）或 7:1
（MiniMax-01）把线性层与全注意力层交替。**线性层负责约 95% 的局部建模，少数
全注意力（或 MLA）层兜底精确长距离检索**——显存账随之变成「全局层的 1/4 比例
的 MLA 账 + 线性层的常数状态」，cache 不再随 L 直线扩张。

## 三、Kimi Linear 与 KDA 机制：说错会被刷的一段

Kimi Linear（月之暗面，论文 arXiv:2510.26692 v1，2025-10-30）是 2025 下半年
hybrid 叙事里最容易被追问的一个，因为官方宣称足够激进：**公平对比下全场景
（短/长/RL scaling）超过 full attention，号称线性架构首例（官方 README 口径，
2025-10）**。模型 48B 总参/3B 激活，1M 上下文，checkpoint 用 5.7T tokens 训练
（README 实测口径），公平对比实验跑在 1.4T tokens 上。

KDA（Kimi Delta Attention）的机制拆解，面试要讲到这个深度：

1. **底座是 Gated DeltaNet**：delta rule 让状态 S 按「写前擦除」更新（learn to
   forget before write），即新信息写入前先学会有选择地遗忘旧信息；gating 控制
   遗忘速率。
2. **KDA 的增量是更细粒度门控**（finer-grained gating，论文摘要口径）：门控做得
   更细，才能更有效利用有限的 RNN 状态容量——「finite-state memory 利用率」是
   关键词，说不出来这五个词基本等于没读过论文。
3. **配套自研 chunkwise 算法**：用 DPLR（Diagonal-Plus-Low-Rank）转移矩阵的专用
   变体，官方口径比通用 DPLR 少算且更贴经典 delta rule。
4. **3:1 KDA:MLA 混搭**：注意全局兜底层用的是 MLA 而不是 softmax MHA——hybrid
   的「全局层」也按省存路线进化，MLA 在这里**降格为 hybrid 内部的模块**，不再
   是独立卖点。

单步 decode 的数据流（文字版，白板要能画）：input token 进每层分流——KDA 层读
旧状态 S、delta-rule 写入、输出，状态恒定不分历史长短，**不产生任何 KV pool**；
MLA 层读 576 维 latent KV cache 做 latent attention；再过 MoE FFN 进下一层。
因此 1M 上下文时 KV cache 大头只剩 1/4 层数 × MLA 压缩字节，官方 README 口径
三层数字：**总 cache 最多省 75%（README，2025-10）**、**长序列 decode TPOT 最高
约 6.3× 于 MLA（README，2025-10）**、**RULER 128k 吞吐约 3.98×（README，
2025-10）**。注意「6×」与「75%」分别是 TPOT 与 cache 两个口径，引用时拆开说，
混着说会露怯（见第九节 Q3）。

热度与维护的反差也值得记：gh 仓 MoonshotAI/Kimi-Linear 实测 **1,615 stars
（2026-10-12）**，但最后 push 停在 2025-11-17——仓库维护节奏明显慢于模型热度，
生产采用要自己评估跟进成本。

## 四、2025-2026 三件大事：旗舰转正叙事

### 4.1 DeepSeek-V3.2：DSA 从「实验」转正成旗舰默认

时间线是全篇最重要的一条叙事：

- **2025-09-29**：DeepSeek-V3.2-Exp 发布（gh 仓实测 **1,654 stars、190 forks，
  2026-10-12**），671B 旗舰级首次量产 token 级稀疏注意力。与 V3.1-Terminus
  训练配置严格对齐做消融，benchmark 打平（官方表格口径）。配套 kernels 全部开源：
  TileLang / DeepGEMM（indexer logits，含 paged 版）/ FlashMLA（稀疏主算）。
  同日 API 公告 **降价超五成（api-docs 公告，2025-09）**。
- **2025-12-02**：主线 DeepSeek-V3.2 正式版论文（arXiv:2512.02556 v1）：性能对标
  GPT-5，Speciale 版超 GPT-5、与 Gemini-3.0-Pro 持平并拿 IMO/IOI 金牌——
  **DSA 从 Exp 转正成旗舰默认架构**，「稀疏注意力能不能上旗舰」这个问题在
  2025 年底有了答案。

工程含义：训练阶段学选择器、推理阶段直接省算（训练原生稀疏）成为甜点位。这一刀
省的是 compute 单价，配合 API 降价形成正循环——面试问「为什么 DeepSeek 敢降价」，
答案链是 DSA 砍 attention compute → 推理延迟/成本下降 → 官方降价超五成。

### 4.2 Qwen3-Next：hybrid 线性进开源流量主力

Qwen3-Next-80B-A3B（阿里 Qwen 团队，HF 卡 2025-09-09 创建）：架构是 48 层 =
12 ×（3 × Gated DeltaNet + 1 × Gated Attention），512 experts 激活 10 + 1
shared，15T tokens 预训练，**原生 256K、YaRN 外推 1M（HF 卡口径，2025-09）**，
并带原生 MTP 投机解码。官方口径为：相比 Qwen-32B-Base，「训练成本约十分之一 +
32K 以上长度推理吞吐约 10 倍」（HF 卡，2025-09——注意这个对比基数是不同范式的
32B dense，面试被追问时要会指出这点）。社区数据：gh 仓 **4,266 stars（2026-10-12
实测）**，HF 下载 249.8k、1,059 likes——开源主力地位不靠宣称靠流量。

### 4.3 MiniMax-01 与 FLA：两端的生态位

- **MiniMax-01**（2025-01-14，arXiv:2501.08313）：7:1 lightning:softmax 混搭进
  456B 级生产模型，是「线性注意力进生产第一枪」的历史锚点。
- **FLA（Flash Linear Attention）**：fla-org/flash-linear-attention 是线性注意力
  kernel 的事实标准库——实测 **5,845 stars、752 forks（2026-10-12）**，2023-12-20
  创建，2026-10-11 还有 push（核验前一天还在动）。Kimi Linear 依赖 fla-core
  不低于 0.4.0，官方 KDA kernel 就直接开在 FLA 里。**记法：hybrid 线的 kernel
  命脉在社区库（FLA、Mamba 官方 kernel、causal-conv1d），稀疏线的 kernel 命脉
  在 DeepSeek 自家（DeepGEMM、FlashMLA）**。

## 五、引擎集成时间线：day-0 惯例与 4-6 周深水区

面试最能拉开差距的一张表（全部实测 release note 日期）：

| 引擎 | 版本 | 日期 | 内容 |
|---|---|---|---|
| vLLM | v0.10.2 | 2025-09-13 | Qwen3-Next hybrid attention |
| vLLM | v0.11.0 | 2025-10-02 | DeepSeek-V3.2-Exp day-0 |
| vLLM | v0.11.1 | 2025-11-18 | Kimi Linear + KDA kernel 走 FLA 路径（#27654/#27809）；同版合并 Mamba2 Automatic Prefix Caching 与 DSA indexer prefill chunking |
| SGLang | v0.5.2 | 2025-09-12 | Qwen3-Next |
| SGLang | v0.5.4 | 2025-10-26 | hybrid 模型 prefix cache（GDN/mamba）与 PD 支持（Qwen3-Next、DSV3.2-Exp） |
| SGLang | v0.5.5 | 2025-11-06 | Kimi Linear |
| SGLang | v0.5.6 | 2025-12-03 | Kimi Linear shared+routed expert overlap、Qwen3-Next Blackwell FP8 blockwise |

规律一句话：**模型发布到引擎可用约两周，day-0 已成惯例；但 hybrid 专属深水区
（prefix cache、PD 分离）要再拖 4-6 周**。证据链：Qwen3-Next 09-09 上 HF，09-12
SGLang v0.5.2（三天即可用），但 prefix cache 到 v0.5.4（10-26）才补齐，间隔六周；
Kimi Linear 10-29 发模型，vLLM v0.11.1（11-18）才落地，约三周，期间只能 HF
transformers 慢跑。根本原因是稀疏/线性层的 KV 行为让静态 PagedAttention 索引不再
通用——**hybrid KV pager 成为引擎侧新基建**（SGLang v0.5 系列、vLLM v0.11 系列
已在铺路）。

## 六、Kernel 生态分层与版本风险

2026 年的注意力 kernel 分三层（标来源年份）：

1. **通用主线三件套**：FlashAttention（Triton/CUDA）、FlashMLA、FlashInfer
   （paged/mm-attention），非稀疏、非线性模型的默认路径。
2. **稀疏线自家闭环**：DeepSeek 把 DSA 逻辑沉进自家 DeepGEMM（indexer logits）+
   FlashMLA 稀疏主算（2025-09）——**非 FlashAttention 现成货，短期只在 DS 自家
   生态跑得动**，这是 DSA 外溢到别家模型的最大门槛。
3. **hybrid 线社区依赖**：fla-core、Mamba 官方 kernel、causal-conv1d。**依赖不稳定
   是常态，版本 mismatch 是最常见落坑**：Kimi Linear 明确要求 torch 不低于 2.6 +
   fla-core 不低于 0.4.0（README 口径，2025-10）。生产上 hybrid 模型几乎是「锁
   版本全家桶」采购。

职业口径提醒：线性/hybrid 线的 kernel 供应链比 attention 主线脆弱一到两个量级，
选型时「kernel 谁维护、issue 谁修」要和模型质量放在同一张评估表里。

## 七、KV 字节账自算教学（白板题）

面试要求「算一笔 1M 上下文的 KV cache 账」，按五步走，全部数字可复现：
**本站计算**四个字的含义就是把下列代入过程背下来，而不是背结果。

**第一步，MHA 基线**。以 70B 级为例：128 头 × 128 维 × 80 层，K+V 两份，FP16
每个数 2B——128 × 128 × 80 × 2 × 2 ≈ 5.24 MiB/token。1M token 约 4.8 TiB 一条
sequence。结论：**单节点物理不可行，MHA 下 1M 窗口只能靠 API 侧分摊**。

**第二步，GQA 砍头数**。K/V 头从 128 压到 8：128 × 128 × 8/128 × 2 × 2 × 80 层
化简后约 320 KiB/token。1M ≈ 305 GiB。够几张 H100 装下，但并发一上去就崩。

**第三步，MLA 压维度**。576 维 latent × 61 层 × 2B ≈ 68.6 KiB/token，1M ≈ 65
GiB，约为 GQA 账的 1/5。记忆钩子：**这个常数来自 576 维 × 61 层，别背成 576 × 80**——Layer 数是 61 不是 80。

**第四步，hybrid 打折**。3:1 混搭只有 1/4 层随 L 增长：effective cache ≈ 1/4 ×
MLA 账 ≈ 16 GiB 量级 + 线性层常数状态（Qwen3-Next Gated DeltaNet 块 12 头 ×
head_dim 128 ≈ 98 KiB/块，本站推导）。与官方「总 cache 最多省 75%」口径吻合。

**第五步，回答 DSA 去哪了**。DSA 不进这张显存表——它的 KV 还是 MLA 全量，省的是
compute。白板题答到这一步主动补一句「稀疏的账在算力不在显存」，档次立刻拉开。

## 八、工程坑位速记（实测 release note 反推）

1. **hybrid 的 prefix cache 是引擎侧深水区**：模型上线到能 prefix-aware decode
   中间隔 4-6 周（Qwen3-Next：SGLang v0.5.2 09-12 可用 → v0.5.4 10-26 才有
   prefix cache）。灰度期要么关 prefix cache 吃重复 prefill，要么等。
2. **线性层 chunkwise kernel 是模型方的交付义务**：Kimi Linear 能直接 vllm serve
   是因为官方把 KDA kernel 写进 fla-core 并亲自提交了 vLLM 集成（v0.11.1，
   2025-11-18），晚于模型发布约三周。**模型方不给 kernel，hybrid 就不可用**——
   评估任何新 hybrid 模型的第一项就是查它的 kernel 交付物。
3. **DSA 需要专门 indexer kernel**：DeepGEMM indexer logits + FlashMLA 稀疏主算，
   没有通用替代。短期意味着：自家模型自家引擎自家 kernel，外溢慢。
4. **TP 切分会稀释 MLA/hybrid 的省存收益**：切得越细每卡状态占比越大、跨卡通信
   越敏感（本站工程推断，无直接 benchmark，面试被追问时主动标注这是推断）。

## 八·增、2026 四条增量：head 级混合 / GDN-2 / ReplaySSM / SketchSSM

### 8·增一、Head-Level 混合 Attention（HydraHead）

- 层间 3:1（Full:SWA）只是粗粒度；HydraHead 用**因果干预**找真正需要
  全注意力的 retrieval head，再按 head 混合 FA 与 GDN。
- 数字：FA 头只占 **6.5%**；512K NIAH **+69%**；RULER **94.53**。
- 面试点：先问「哪些头看全局」，再问「层间比例多少」——粒度从层换到
  头，和 RazorAttention/DuoAttention 同一条演进轴。

### 8·增二、Gated DeltaNet-2：擦除与写入拆轴

- KDA 的 β 仍是标量，擦除与写入共用一个门；GDN-2 把**擦除门放 key 轴、
  写入门放 value 轴**，做通道级解耦 delta 更新。
- 数字：1.3B/100B token；S-NIAH-3@2K **+26.6**；38.0→36.1 Kt/s。
- 面试点：线性注意力的「门控粒度」是 2026 的新追问——标量门 → 通道门
  → 分轴门，每一步都在换表达力。

### 8·增三、ReplaySSM：checkpoint + 输入缓冲

- SSM 状态不是只有「常数大小」这一个优点；每步都要写状态，状态 I/O
  本身就是成本。ReplaySSM 把状态存成 **checkpoint + 近期输入缓冲**，
  flush 时写回，回滚只移指针。
- 数字：算子 **1.46–1.80×**、投机 **1.85/2.10×**；KL **.136→.0038**。
- 面试点：常数状态 ≠ 零成本；要把「状态写带宽」算进 decode 账。

### 8·增四、SketchSSM / Sketch Linear Attention：全量写、草图读

- 状态写全量、读出读固定查询基草图，压缩误差不进递推链；适合长上下文
  线性层的高频 decode。
- 数字：状态流量 **9.4–10.7×**、decode **2.26×**、内核 **5.02–7.30×**。
- 面试点：与 ReplaySSM 对照——一个用「重放」换存储，一个用「草图」换
  读取；两者都在解 SSM 的状态带宽，不是模型结构本身。

### 8·增五、A2 速记：三条架构增量

- **MiniMax-M2.7（1）**：弃混合注意力回归 Full Attention，SWA 长文掉点；
  9.8B 激活/230B 总参；128K RULER **90→72**。
- **Qwen3.8（131）**：GDN:QSA=3:1 混合，GR 四分支，n-gram 外置；
  125B/6B/51B；QSA 256K 反超；FlashQLA **2–3×**。
- **MiMo-3 HySparse2（190）**：YOCO 式跨层 KV Bridging，稀疏层复用 FA
  KV，预填半程退出；预填 **5.02×↓**；KV **12.09→2.69GB**；RULER
  **+19.81**。

## 九、▶ 高频面试题

**Q1（频率极高，谱系题）**：从 MHA → GQA → MLA → 稀疏 → 线性/hybrid 讲一遍
演进，每代省什么、被谁干掉？
- 浅档：按 2.1 表格一句话版——GQA 砍头数（省存）、MLA 低秩（存得更聪明）、
  稀疏砍 compute（省算不省存）、线性换数据流（常数状态）、hybrid 混搭取帕累托。
- 深档：当场给 byte-arith——5 MiB → 320 KiB → 68.6 KiB/token 的数量级接力，
  并指出 MLA 干掉的是「GQA 头数与质量的对价关系」，而不是 GQA 本身是错的。

**Q2（频率极高）**：MLA 为什么比 GQA 省，RoPE 怎么塞进去？
- 浅档：K/V 联合低秩压缩成 576 维 latent（512 + 64 RoPE 侧），与头数脱钩。
- 深档：三笔手续费——RoPE 64 维不可压、低秩要训练时一起学、up-projection 算力
  换显存；最后一笔要会按 M/N/K 估「带宽饱和时是净赚还是净亏」。

**Q3（频率高）**：Kimi Linear 凭什么宣称超过 full attention？
- 浅档：3:1 KDA:MLA 混搭 + finer-grained gating 的状态利用率，1.4T tokens 公平
  对比；官方口径 cache 省 75%、1M TPOT 约 6.3×。
- 深档：说清两个「6/75%」分别是什么口径（TPOT vs cache）；再反一问：精确长距离
  retrieval 时全局层只占 1/4 比例，够不够用——能提出这个质疑点就赢了大多数
  候选人。

**Q4（频率高）**：linear attention 省算和 DSA 省算的本质区别？
- 浅档：linear 换数据流（递推状态，cache 常数），DSA 换选择（每 query 选
  top-2048，cache 全量）。
- 深档：两者可叠加——linear 层 + MLA 全局层 + 全局层上再跑 indexer；工程后果是
  一个要 hybrid KV pager、一个要 indexer kernel，底盘完全不同。

**Q5（频率中高）**：拆 Qwen3-Next 架构账。
- 浅档：12 ×（3 Gated DeltaNet + 1 Gated Attention）、512 专家激活 10、原生
  MTP、256K→YaRN 1M。
- 深档：「训练成本十分之一 + 10× 吞吐 vs Qwen3-32B」的官方口径怎么反驳——
  对比基数是不同范式 dense 32B，不是同参数量公平比；以及 Gated DeltaNet 的
  gating 与 RWKV/Mamba 的来源差异要能讲一句。

**Q6（频率中高，白板计算题）**：1M 上下文 KV cache 算一笔账。
- 浅档：报数量级——MHA 约 4.8 TiB、GQA 约 305 GiB、MLA 约 65 GiB、hybrid
  再打四折。
- 深档：完整走第七节五步代入，主动补「DSA 不进显存表」和「68.6 KiB 是 576 维
  × 61 层，不是 80 层」两个细节。

**Q7（频率中）**：hybrid 模型为什么不能直接用 FlashAttention / 为什么要专门的
KV pager？
- 浅档：线性层没有随长度增长的 KV pool，每个 chunk 是固定块，静态
  PagedAttention 索引不适用。
- 深档：给时间线证据——SGLang prefix cache 晚六周（v0.5.2→v0.5.4）、Kimi
  Linear 靠 fla-core 链迟三周（模型 10-29 → vLLM v0.11.1 11-18）。

**深浅两档总要求**：浅档能背谱系一句话版 + 三个数字锚（MLA 576 维、Kimi
Linear 官方口径 6×/75%、DS API 降价超五成）；深档能白板重算第七节字节账、能
指出「省算不省存」分界线、能复述至少一条引擎时间线作为「模型-引擎 gap」证据。
