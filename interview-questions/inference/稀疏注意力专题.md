## 一、三条收敛主线：省存 → 省算 → 不算

2025–2026 的旗舰注意力层几乎都在三条线里选答案：

- **KV 侧压缩「少存」**：MLA 用低秩 latent 表示替掉逐头 KV——DeepSeek 全家桶
  的地基。
- **可训练稀疏注意力「少算」**：NSA / MoBA / DSA 让模型自己学 top-k 选择，
  attention FLOPs 砍一到两个数量级。
- **线性 / SSM 混合「不算」**：lightning / KDA / Gated DeltaNet 把大部分层换成
  恒定状态递推，只留少数全注意力层兜底。

对号入座：DeepSeek-V3.2 = MLA + DSA；Kimi = MoBA → Kimi Linear（KDA）；
Qwen3-Next = 3:1 的 Gated DeltaNet : Gated Attention（官方宣称口径）；
MiniMax = 7:1 的 lightning : softmax（arXiv:2501.08313）。

2025 年的范式切换一句话：**sparse 从推理事后补丁变成预训练原生组件**——
NSA 与 MoBA 在同一周（2025-02）分别从 DeepSeek 与月之暗面发出，全是端到端
训练；DSA（2025-09/12）则是第一个在 671B 级旗舰模型上量产的 token 级稀疏
注意力，直接带动官方 API 降价 50%+。

先把分界线钉死，后面所有章节都是它的展开：**稀疏注意力省算不省存，驱逐/分层
省存不省算**。MLA 与稀疏注意力正交——MLA 解决「存」与 decode 带宽，稀疏
解决「算」，V3.2 把两者叠加。

## 二、MLA：低秩压缩的机制、数字与 RoPE 冲突

### 2.1 机制：不做头共享，做联合低秩

GQA/MQA 的路子是 K/V 头共享（砍冗余）；MLA 换了思路——把每个 token 的 K/V
**联合低秩下投影**成隐向量 c_t^KV ∈ R^512（**d_c=512**，即 4·d_h），用时再
Up 投影恢复各头的 K/V（arXiv:2405.04434）。缓存里只存 latent，不存各头
K/V。

三个关键点：

1. **Q 也做低秩压缩**（d_c′=1536），但那只是为了省训练显存，**不进 KV
   cache**——被追问「Q 压缩省了什么」时别答错账。
2. **缓存账**：每层每 token 存 (d_c + d_h^R) = **512+64=576** 元素（V2 共
   60 层），等效 **GQA 2.25 组**——「比 GQA 更省，比 MHA 更强」就押这句。
3. **矩阵吸收**：推理时 W^UK 吸收进 W^UQ、W^UV 吸收进 W^O，decode 等价
   「大 Q × 小 latent」的 MQA-like 形状，访存量按 latent 维计费——这是
   MLA 不掉点还提速的算术本质（FlashMLA kernel 形状也因此和标准 MQA
   不同）。

### 2.2 RoPE 冲突与解耦通道（高频追问）

**为什么冲突**：RoPE 的旋转矩阵是逐位置的，会夹在 W^UQ 与 W^UK 之间，
破坏矩阵吸收的结合律链条——吸收做不成，decode 就必须显式恢复各头 K/V，
省存红利当场蒸发。

**怎么解**：每头额外切出 **d_h^R=64** 维做**解耦 RoPE 通道**，各头共享一个
小 key k_t^R 专职携带位置信息，不参与低秩压缩。于是 576 = 512 + 64 的
加号就是这么来的——这个加法是「（arXiv:2405.04434）论文里最值得手推的
一笔账」。

**收尾提醒**：MLA 省的是 KV 字节，**不省 attention FLOPs**——Q 和全量 K
还是要逐对打分。所以 DeepSeek 后来才要在 MLA 之上再叠 DSA（第五节），
这就是「省存线」与「省算线」的接缝。

### 2.3 数字锚（DeepSeek-V2 vs DeepSeek 67B，arXiv:2405.04434，2024）

- KV cache **−93.3%、**训练成本 **−42.5%、**生成吞吐 **5.76×；**
- MLA 的 KV 量 ≈ GQA 2.25 组，性能反超 MHA；消融实验里 MLA 只需 MHA 的
  **14%（小 MoE）/4%（大 MoE）** 的 KV；
- 8×H800 单节点生成 **>50K tok/s**（含 6-bit KV 量化，论文 §3.2.3）。

V3 沿用同一套 MLA 维度（经 V3.2-Exp config 核实：kv_lora_rank 512、
qk_rope_head_dim 64），总账 671B/37B、14.8T tokens、2.788M H800 时
（arXiv:2412.19437，2024）。

## 三、NSA：三分支与块级选择（arXiv:2502.11089，2025-02）

### 3.1 三分支各管什么

| 分支 | 配置（经典值） | 职责 |
|---|---|---|
| 压缩 cmp | 块长 l=32、stride d=16，MLP 把块压成代表 token | 全局粗扫，给 query 提供粗粒度摘要 |
| 选择 slc | 选 n=16 个 l′=64 的 token 块 | 细看重要区域；固定含 1 个起始块 + 2 个局部块 |
| 滑窗 win | w=512 | 近邻全分辨率，兜住局部模式 |

三路各算 softmax，最后**可学门控融合**。滑窗独立存在是有讲究的：防止
「局部模式学得快、喧宾夺主」，让压缩/选择两支专心学全局语义。

### 3.2 两个「白嫖」设计（深挖点）

- **块重要性分数白嫖**：选块分数直接从压缩分支的注意力分数在块上求和
  得到（d<l 的滑动制块内累加），**零额外打分网络**。
- **GQA 对齐**：GQA/MQA 下强制组内所有 query head 选**同一批块**（分数
  按组聚合），避免组内并集撑大 KV 读取量——论文点名批评 Quest 的逐头
  选择在 GQA 下访存不省。

### 3.3 kernel、训练与数字

- **Kernel 设计**：按 GQA 组加载 query（同组共享稀疏 KV 块索引），组内
  共享 KV 传输、SM 负载均衡，Triton 实现。
- **加速比**：64k 序列前向 **9.0×**、反向 **6.0×**（A100）；decode 按 KV
  访存量折算 **11.6×**。对照基线：全注意力在 64k decode 占总延迟
  **70–80%** 的区间——这就是稀疏要解决的成本结构。
- **训练对齐**：原生端到端，训推同一稀疏模式。实验模型 27B（MoE，3B
  active）、270B tokens 8k 预训 + YaRN 拉长；通用榜「matches or
  exceeds」全注意力（摘要级口径），64k NIAH 满分，兼容推理强化学习
  后训练。

## 四、MoBA：MoE 式门控选块（arXiv:2502.13189，2025-02）

### 4.1 机制

上下文等分 n 个大小 B 的块当 expert；每块 key 做 mean pooling 得代表向量，
与 q 算 gate 亲和分（cosine），加 causal mask 后 top-k 选块，仅对选中块做
FlashAttention。**零新增参数**——全部开销就是一个打分矩阵。

### 4.2 招牌：全/稀疏无缝切换

任何层可随时在 MoBA 与 full attention 间切换（同一套参数），训练用层间
混合（浅层/末端层可保 full）兜底精度，切换无显著 loss spike。这直接回答
「选错 token 怎么办」——兜不住就切回全注意力，也因此特别适合对现成模型
做 continual pretrain 改造。

### 4.3 数字与 NSA 异同

- 8K 配置 block 512 + top-3 → **81.25% 稀疏度**；1M 配置 block 4096 +
  top-12 → **95.31% 稀疏度**。
- 加速：1M prefill 最高 **6.5×**；95.31% 稀疏度从 8K 一路扫到 10M，10M
  时 attention 耗时降 **16×**。
- 精度：Llama-8B-1M-MoBA（128K→1M 渐进拉长 + position interpolation，
  MoBA 激活期训 100B tokens）1M NIAH 通过，RULER **0.7818 vs 0.7849**
  （Full）——几乎打平。

与 NSA 的三点差异（面试爱考对比）：

1. **打分器来源**：NSA 从压缩分支注意力分数聚合（层级式白嫖）；MoBA 是
   独立的 mean-pool 门控（MoE 式）。
2. **结构**：NSA 是「细块选择 + 滑窗 + 压缩」三分支；MoBA 只选块，稀疏度
   由块大小与 top-k 直接控制。
3. **工程取向**：MoBA 强调与全注意力切换兼容（方便改造现成模型）；NSA
   强调与 GQA / kernel 算术强度对齐（decode 加速兑现率更高）。

## 五、DSA：第一个旗舰量产的 token 级稀疏

> 模型时刻 2025-09（DeepSeek-V3.2-Exp），论文 2025-12
>（arXiv:2512.02556）。本篇讲算法与训练，FlashMLA 稀疏 kernel 与
> HiSparse 分层驻留等工程侧见
> [长上下文推理与 KV 体系](./长上下文推理与kv体系.md)。

### 5.1 lightning indexer

在 MLA 之上加一个极轻量打分器：

`I_{t,s} = Σ_j w_{t,j} · ReLU(q^I_{t,j} · k^I_s)`

- **64 个 indexer head × 128 维**（config 核实），ReLU 替代 softmax（吞吐
  考虑），整体 **FP8** 跑；虽然沿 L² 扫描全部历史，但代价只及 MLA 主
  注意力的零头。
- 逐 **token** 选 top-k = **2048** 个 KV 进 MLA 主算，主注意力复杂度从
  O(L²) 降到 **O(L·2048)——每个 query 的成本与位置解耦。**
- 与 NSA 的关键差异：DSA 是 token 级粒度（不做块选择）、打分器是专用
  蒸馏小网络（不是注意力分数白嫖）、未来 token 不参与选择（严格保
  因果）。

### 5.2 两阶段训练：「先训眼睛，再训大脑」

1. **dense warmup**：冻结主模型，只训 indexer——用 **KL 散度**把 indexer
   分数对齐到主注意力（多头求和后）分布。**1000 步 ×（16×128K）=
   2.1B tokens**。
2. **sparse training**：全参数打开，主模型只吃 LM loss、indexer 只吃 KL
   loss；indexer 的输入 **detach**——防止主模型反向操控 indexer 作弊。
   **15000 步 ×（480×128K）= 943.7B tokens**，lr **7.3e-6**，全程 128K
   训练。

「detach 防作弊」是高频深挖点：如果 indexer 输入不 detach，主模型可以
调整表示去讨好/操纵打分器，稀疏模式就不再反映真实的注意力分布。

### 5.3 量产意义与数字

- 成本曲线：主注意力每 query 恒定 2048 KV，论文 Figure 3 用 H800 租赁价
  2 USD/时实测 per-token 成本随位置的变化，V3.2 vs V3.1-Terminus 在长
  位置差距拉大（精确数字未逐字核实，按调研降级——硬佐证是官方公告
  **API 降价 50%+ 的公告**，api-docs.deepseek.com，2025-09）。
- 性能：V3.2 对标 GPT-5，Speciale 拿过 IMO/IOI 金牌量级——证明「稀疏
  不拖累推理能力」。
- kernel：TileLang/CUDA 开源，FlashMLA 稀疏版落地。

三句定位收尾：

1. 驱逐类（StreamingLLM/H2O/SnapKV/Quest/DuoAttention）是**推理事后补丁**
   时代的答案——省存或省算但不同练，hidden failure 在于「后验选择换掉
   了训练分布」；
2. **纯 linear/SSM 没有干掉 softmax**，原因是检索能力不足（MiniMax 的
   NIAH 证据最直白），收敛形态是 1/4 ~ 1/8 比例的全注意力层兜底；
3. 2025 底 hybrid 线的最优证据是 **Kimi Linear**：公平对比反超 full
   MLA，说明「不算」线在架构竞赛里并没有输给「省算」线。

## 七、与 serving 工程的相互作用（六条）

总原则再背一遍：**稀疏注意力省算不省存，驱逐/分层省存不省算**。工程细节
（HiSparse hot buffer、多级页表、connector）全部在
[长上下文推理与 KV 体系](./长上下文推理与kv体系.md)，本节只给算法 × 工程
的接口认知：

1. **对 prefix cache**：正交且互相成就。公共前缀 KV 仍要全量保留（任何
   token 都可能进某个 query 的 top-k），复用价值不变；token 级稀疏
   （DSA）要求 indexer 的键 k^I 也缓存/复用——cache 键从「KV」变成
   「KV + 索引表示」，命中校验成本略升。
2. **对 KV 量化**：稀疏砍掉 attention FLOPs 后 decode 更纯 memory-bound，
   KV 量化收益相对放大。DSA 原生 FP8 KV + FP8 indexer（FlashMLA 稀疏版
   落地）；Quest 类方法需把 min/max 统计与量化 error 对齐设计，否则
   上界失真。
3. **对推测解码**：V3/V3.2 的 MTP 与 MLA/DSA 共存；但 linear/KDA 混合
   模型的 draft 层必须重建 recurrent state，不能简单沿用 Transformer
   draft 逻辑，稀疏模型 draft 一般用全注意力小窗。Qwen3-Next 原生 MTP
   （vLLM qwen3_next_mtp）已验证。
4. **对 PD 分离**：NSA 前向 **9.0×**、MoBA prefill **6.5×** → prefill
   算力需求大降，P:D 配比向右倾；decode 侧 NSA **11.6×**、DSA indexer
   开销恒定 → 长上下文 decode 成本接近「常数 + MLA 带宽」，KV 传输与
   分层（HiSparse hot buffer + 缺页换入）成为新瓶颈。
5. **对 TP/并行**：MoBA 的 10M 实验靠 KV 在 query head 维度广播扩 TP；
   MLA 的 latent KV 在所有 head 共享，天然省 TP 通信——这是 MLA × 稀疏
   在 EP/TP 混合并行下的隐性红利。
6. **引擎适配**：vLLM / SGLang 已分别支持 DSA、KDA、Gated DeltaNet；
   稀疏/线性模型没有传统 attention 的确定性 KV 形状，退路缓存、页表、
   连续批仍需适配（工程落地见串联阅读第一篇）。
