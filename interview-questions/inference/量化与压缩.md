# 量化与压缩

> 推理部署模块第二篇。量化题在推理岗是"高"频八股 + 算显存的延伸题，必须把
> FP16/BF16、PTQ vs QAT、GPTQ/AWQ/SmoothQuant/LLM.int8() 的原理差异和选型逻辑
> 说得像背手机号一样熟。本文按「为什么 → 精度格式 → 方法原理 → 选型 → 压缩其他
> 手段」组织，题目标注自 [高频面试真题汇总](../高频面试真题汇总.md#五推理部署)。

## 一、为什么要量化：三条省显存/省带宽的路

▶ 面试题：为什么要量化？量化的三个对象是什么？——**高频铺垫题**

[前一篇](./vllm与推理加速核心.md)说过：decode 是 memory-bound，瓶颈在**从 HBM 搬
数据**，搬的主要是两样东西——**权重**和 **KV Cache**。再加上 prefill 时打满算力
的**激活（activations）**，量化的战场就三条路：

| 路径 | 量化什么 | 直接收益 | 典型手段 |
|---|---|---|---|
| **权重量化** | 模型权重 W（W8A16、W4A16） | 显存砍半~1/4，decode 带宽砍半~1/4，吞吐翻倍量级 | GPTQ / AWQ / GPTQ-INT4 |
| **KV Cache 量化** | 每个 token 的 K/V cache | 长上下文/大 batch 的显存大头指数级省，batch 上限翻倍 | INT8/FP8 KV cache（vLLM/SGLang 内置） |
| **激活量化** | 层间激活矩阵 A（W8A8） | prefill/计算通路上也能吃 INT8 tensor core，prefill 提速 | SmoothQuant / LLM.int8() |

权重在前面是内存带宽命，KV cache 是容量命，激活是算力命。一个量化方案的"坐标"
就是「量了哪几条路、量化到多少 bit、误差怎么控制」。

## 二、精度格式扫盲：FP16 / BF16 / FP32 与 INT8/FP8

▶ 面试题：FP16 和 BF16 的区别？为什么训练用 BF16、推理有时 FP16？——**极高频八股**

```text
FP32:  [1 符号][8 指数][23 尾数]  范围大、精度高
FP16:  [1 符号][5 指数][10 尾数]  范围小（±65504），精度高，容易溢出
BF16:  [1 符号][8 指数][ 7 尾数]  范围和 FP32 一样，精度差，不溢出
INT8:  整数 -128..127，配 scale/zero-point
FP8 (E4M3/E5M2): Hopper/Blackwell 硬件原生支持，介于 INT8 和 FP16 之间
```

- **BF16 vs FP16 一句话**：BF16 "**范围像 FP32、精度像打折扣的 FP16**"；训练喜欢
  BF16 因为梯度不容易 underflow/overflow，免调 loss scale；推理在 quality 受控时
  FP16 也很常用（数值范围小没问题，权重激活都很温和）。
- **INT8 与 FP8**：INT8 动态范围小、要精心选 scale；FP8(E4M3) 是 Hopper 起
  硬件能直接算的浮点型，量化误差友好，**2026 年 FP8 权重 + 激活（W8A8）是
  线上生产越来越主流的选项**（DeepSeek 系、vLLM 原生支持）。

### 2.1 新派微缩格式：NVFP4 / MXFP4（2025-2026 新热点）

FP8 往下走，8 位单数已装不下权重分布，出现**块级微缩
（microscaling）**思想：几个数共享一个缩放因子，位宽压到 4-bit
同时保精度——这是与 INT4 均匀格点量化的本质代差：

| 格式 | 结构 | 硬件 | 要点 |
|---|---|---|---|
| **NVFP4** | 每 16 个权重共享一个 **FP8(E4M3) 缩放因子**，主体 E2M1 | Blackwell B200 Tensor Core 原生 | 浮点 scale 给离群值更大动态范围，**4-bit 下精度损失显著小于 GPTQ-INT4** |
| **MXFP4 / MXFP8** | 每 32 个元素共享一个 E8M0（纯指数）scale | 开放规范（OCP），AMD/微软/开源模型阵营 | GPT-OSS 系 MoE 版本已经在用它发布 |

**一句话理解代际**：INT4 是「整数量子化 + 分组零点」（格点均匀，
离群值硬砍）；FP4 系是「指数-尾数结构 + 块级浮点 scale」（分布
拟合强一档）——2026 年旗舰推理格式的收敛方向是后者。
面试记忆口诀：**位宽定成本、指数定范围、尾数定精度、块 scale 定
微缩格式的成败**。

与命名法的关系：`WxAy`（权重 x 位、激活 y 位）——
默认生产 W8A16（权重 INT8 激活 BF16，性价比之王）、高吞吐 W8A8
（H100 INT8/FP8）、极限 W4A16（GPTQ/AWQ g128 单卡塞大模型）、
旗舰 NVFP4 全链路（QAT/原生训练）。三笔账独立算：
**权重量化 ≠ KV 量化 ≠ 激活量化**，别用一个「量化后」笼统回答。

## 三、PTQ vs QAT：先分家再聊方法

▶ 面试题：PTQ 和 QAT 区别？——**高频开场**

| | PTQ（Post-Training Quantization） | QAT（Quantization-Aware Training） |
|---|---|---|
| 做法 | 训练完成后直接量化，最多用少量校准数据调 scale | 把量化伪节点插进训练图，带着量化误差继续训练/微调 |
| 成本 | 低（小时级、消费级 GPU 也能跑） | 高（要训练管线 + 数据） |
| 精度 | INT8 几乎无损，INT4 掉点 1 个点上下（看方法） | 同样 bit 下精度更好，可到 INT4 甚至更低 |
| 2026 主流 | **推理量化几乎全是 PTQ**（GPTQ/AWQ/SmoothQuant）+ 模型厂商官方出的 FP8/QAT 版 | 大厂 flagship 模型会用 QAT 发官方低 bit 权重（如 DeepSeek FP8） |

**答法要点**：工程师的默认解是 PTQ + 现成框架（AutoGPTQ/AutoAWQ/llm-compressor），
QAT 只有"官方目标就是极低 bit"或"精度验证过不了"时才上。

## 四、GPTQ：逐列贪心 + Hessian 误差补偿的数学直觉

▶ 面试题：GPTQ 原理？——**高频**

GPTQ 是 **weight-only INT4** 的标杆方法。两步直觉：

1. **逐列量化**：对权重矩阵一层一层来，每次量化**一列**权重到 INT4。
2. **误差补偿**：量化当前列产生的误差，**后面还没量化的列会按二阶信息
   （Hessian 的逆）调整自己**，把这一列造成的整体输出误差"摊"回去。

Hessian 近似怎么来？把每一层的量化当作"让这一层输出的均方误差最小"的优化问题，
目标函数是二次的，最优补偿量天然涉及 $(XX^T+\lambda I)^{-1}$ 这种二阶逆矩阵——
GPTQ 用 Cholesky 分解一次性算好，逐列复用，所以快（分钟~小时级完成一个 7B）。

记忆钩子：**「OBQ（Optimal Brain Quantization）的二阶框架 + GPU 友好的逐列实现」**。
效果口径（公开常用值）：INT4 GPTQ 一般在 7B 上掉点在 **1% 以内**（PPL 上浮一点点），
吞吐相比 FP16 提升 1.5~2 倍左右（量化 dequantize kernel 已很成熟）。

## 五、AWQ：激活感知的"保护 1% 重要权重"

▶ 面试题：AWQ 原理？为什么比 GPTQ 更稳？——**高频**

AWQ（Activation-aware Weight Quantization）的核心观察非常反常识但非常好讲：

- **不是所有权重都同等重要**——把权重均匀量化的方法会无差别伤害重要权重。
- 用一小撮**激活值**（用校准数据跑一层，看哪些输入通道幅值大）找出**对应
  "活跃通道"上的权重**，这些重要权重只占约 **1%** 左右（0.1%~1% 视层而异）。
- 做法：**不量化这 1%（保留 FP16）**，或者等价地先**把激活的尺度 scale 吸收进权重（per-channel scaling，重要通道放大 → 等效量化误差变小）**，再统一 INT4。

直觉类比：给地图上色，把重要城市标 100 层细节，其余沙漠 4 色就够了——看哪片
区域"人流量大"来决定上色精度。AWQ 的实测在 INT4 下对 GQA 模型、instruction-tuned
模型往往比 GPTQ 稳一点，vLLM 里 AWQ 的 marlin kernel 也优化得很好——**2026 年
AWQ-INT4 是线上最常见的低 bit 选型之一**。

GPTQ vs AWQ 一句话对比：

| | GPTQ | AWQ |
|---|---|---|
| 看的是什么 | 二阶统计（Hessian 逆） | 激活幅值（哪些通道活跃） |
| 保护方式 | 逐列误差摊回未量化列 | 约 1% 权重不量化/scale 保护 |
| 直觉 | 算学补偿 | 重点保护 |
| 工程 | 老牌、量化快 | 精度略稳、kernel 生态好 |

## 六、SmoothQuant：把激活的量化难度"转移"给权重

▶ 面试题：SmoothQuant 解决什么？为什么要做平滑？——**高频**（INT8 入门必问）

**INT8 的真正麻烦不在权重在激活**：激活里存在少量**outlier 通道**——某些通道的
幅值比其他通道大上百倍，量到 8 bit 后正常通道全被"挤扁"（0 或 1 个量化级），
误差爆炸。权重的分布反而平滑友好。

SmoothQuant 的做法只用一步数学：对每一对"权重 W、激活 X"，引入**per-channel
平滑因子 s**，把 X 除以 s、W 乘以 s（数学上 $(X/s)\cdot(sW)=XW$，结果不变）。
选 s 的原则是"刚好把激活的 outlier 压到和权重差不多平滑的程度"，即
$s_j = \max(|X_j|)^\alpha / \max(|W_j|)^{1-\alpha}$，α 通常 0.5。

## 七、LLM.int8()：混合精度的 176B 启蒙作

▶ 面试题：LLM.int8() 的思想？——**中**

BLOOM-176B 时代的代表作，是 SmoothQuant 的"前辈"。思想一句话：**outlier 通道不进
INT8，用 FP16 单独算，其余通道 INT8 算，最后相加**。离群维度只占总维度 ~0.1%
但贡献了大部分量化误差，单独走高精度通路就能保住质量。成本是 kernel 写两路、
工程上复杂，但它第一次示范了"176B 单机能临近 FP16 质量量进去"，是量化思路的
里程碑。2026 答法：提它是历史地位，今天的工程默认是 SmoothQuant/FP8 路线。

## 八、KV Cache 量化：长上下文时代的第二战场

▶ 面试题：KV cache 怎么量化？——**中高，随长上下文升温**

KV cache 在长上下文 + 大 batch 下会超过权重成为显存第一大头（算一遍：7B 模型
128K context、batch=32，FP16 时 KV cache 量级是几百 GB——[基础模块的公式](../llm基础/transformer与attention.md#四kv-cache-原理与显存估算)
套一下）。把每个 token 的 K/V 从 FP16 压到 INT8 乃至 INT4：

- **INT8 KV cache**：基本无损，vLLM/SGLang/TRT-LLM 都支持一键开启；收益量化为
  cache 显存减半 + decode 读 cache 的带宽减半，长 context 下 TPOT 改善可观。
- **INT4 KV cache**：略微掉点，GQA/MLA 模型的 cache 本来已小，是否值得看 case；
  商用 API 侧越来越多默认开到 FP8 KV（H100 上 E4M3 是免费午餐）。
- K 和 V 的量化敏感性不同——**V 更敏感**（误差直接污染输出），很多实现 K/V 用不同
  bit 或对 V 保守。面试提出来很加分。

## 九、选型决策表：INT8 / INT4 / FP8 该怎么选

▶ 面试题：量化选型 GPTQ/AWQ/PTQ/QAT？INT8/INT4/FP8 怎么挑？——**极高频**（爱奇艺/滴滴/字节）

| 场景 | 推荐 | 理由 |
|---|---|---|
| H100/B200 新卡，旗舰模型，线上生产 | **FP8 W8A8**（官方或 PTQ） | 硬件原生、几乎无损、吞吐翻倍，2026 默认答案 |
| A100/消费级 4090，想省显存拿 7B→24G 卡 | **AWQ-INT4** 或 **GPTQ-INT4** | 显存砍到 1/4、吞吐翻倍，INT4 PTQ 生态最成熟 |
| 对精度极敏感（医疗/金融），或要极限低 bit | **QAT**（自己训） | 同样 bit 下精度天花板 |
| Prefill 瓶颈大（长 prompt 业务）、INT8 tensor core 老卡 | **SmoothQuant W8A8** | 激活也 INT8，prefill 提速 |
| KV cache 是瓶颈（长 context + 大 batch） | 开 **FP8/INT8 KV cache** | 顺手一开的免费午餐 |
| 端侧 / 手机芯片 / CPU | **GGUF + Q4_K_M 等 k-quant**（llama.cpp 生态） | 端侧定制混合精度表 |

**答法套路**：先说目标（省显存？提吞吐？提质量？）→ 哪条路是瓶颈（权重/KV/
激活）→ 用什么硬件（有没有 FP8）→ 给个推荐 + 备选。把"决策树说出来"这一步
比背公式更拉分。

## 十、压缩的其他手段：一笔带过但要会说

▶ 面试题：除了量化还有哪些压缩？——**中**

- **蒸馏（Distillation）**：用大模型当 teacher 生成数据或教 logits，小模型接住了
  大部分能力。推理侧的好处是"直接换更小模型"（DeepSeek-R1 蒸馏的 Qwen-7B/1.5B
  是 2026 的常见落地方案）。
- **剪枝（Pruning）**：结构化剪枝优先（按层/头/FFN 通道整块删，如 LLM-Pruner、
  Sheared LLaMA）——非结构化稀疏需要稀疏算子支持，GPU 上收益难落地，2026 仍
  偏研究。
- **稀疏激活 / 量化后的进一步省**：如 W4A4 + 稀疏的 Wanda（weight + activation
  联合剪），提一下即可。
- **一句话定位**："量化是 uniform 压缩、工程收益最稳；剪枝/蒸馏是换模型，收益
  更大但动地基。"面试问"怎么把推理成本再砍一刀"时把这三个 + 投机解码 +
  更小的官方小模型一起说。

## 十一、高频追问清单（本主题）

| 追问 | 答题要点 |
|---|---|
| 为什么 INT4 权重量化几乎无损？ | 权重分布平滑 + 误差摊销方法成熟；且 decode 时间大头是搬权重，4 bit 直接省带宽因此**不仅无损还提吞吐** |
| 量化精度怎么验证？ | PPL（固话）+ MMLU/C-Eval 分数 + 真实业务评测集，三层都要跑 |
| FP8 为什么比 INT8 友好？ | 动态范围大，不需要精心调 scale；H100+ 硬件原生 |
| W4A16 和 W8A8 哪个快？ | Decode 段 W4A16 更快（搬的少），Prefill/矩阵乘段 W8A8 有 INT8 tensor core 更快；大 batch 高时也是 W8 优势 |
| KV cache 和权重量化同时用会冲突吗？ | 不冲突，不同对象；合用显存严重紧张场景（长 context）效果更好 |
| AWQ 保护的 1% 是固定的吗？ | 是经验量级（0.1%~1%），按层和校准数据不同；讲"约 1%"就够，不必精确 |
