## 一、压轴开场：MHA→MQA→GQA→MLA 一句话带过

注意力变体的主线只有一条：压缩 KV Cache。前几代动的都是 K/V 的头数，用
**单层单 token 的缓存字节数**写出一行账就能讲完（统一按 DeepSeek-V2 的头
配置 `n_h = 128`、`d_h = 128`、bf16 即 2 字节计）：

- MHA：K、V 各占 `128 × 128 × 2B = 32 KB`，每 token 缓存合 **约 64 KB 总账**。
  128 个头各自独立，表达力是上限，缓存量也是上限。
- MQA：128 个头共享一组 K/V，每 token 缓存缩到 **约 0.5 KB 量级**，解码是
  memory-bound 所以提速明显，代价是所有头抢同一份 K/V，质量掉得肉眼可见。
- GQA：折中方案，主流配置 8 组共享（`n_kv = 8`），每 token 缓存
  `2 × 8 × 128 × 2B` 得 **约 4 KB 一线**，几乎不掉点，是开源模型的默认答案。
- MLA：思路换了赛道——K/V 不是「共享出来」的，而是「压缩存进去、用时再
  还原出来」。cache 里存的不是任何头的 K/V，而是一个 512 维潜向量加一个
  64 维 RoPE 分量，每 token 仅 **约 1.13 KB 一块账**，比 GQA-8 再省 3.5 倍，比 MHA
  省约 57 倍，表达力却逼近 MHA。

为什么 MLA 可以不走「头共享」这条路？因为它把问题从「省几份 K/V」换成了
「K/V 能不能先编码成更短的信息」。答案在第二节的矩阵推导里。

## 二、低秩分解的完整推导

### 2.1 第一步：压缩——把 token 表示折叠进 512 维潜向量

对隐状态 `h_t`（V2 里维度 `d_model = 5120`），用一个下投影矩阵压到潜向量：

`c_t = W_DKV · h_t`，其中 `W_DKV` 的形状是 `d_c × d_model`，`d_c` 取 **512 维**。

512 对比的是 K、V 全称量：128 头 × 128 维 = 16384 维。也就是说，一个 token
的 K/V 信息被压进了一个**维度压缩约 28.4 倍的瓶顶**里。这个 `c_t` 就是
KV Cache 里真正要存的东西——不是任何某头的 K、V，而是它们的公共低秩底。

### 2.2 第二步：展开——用时再还原各头的 K/V

训练（以及「展开算」式推理）时，用两个上投影矩阵把潜向量还原回各头的 K、V：

- `K = W_UK · c_t`，`W_UK` 的形状是 `(n_h · d_h) × d_c`；
- `V = W_UV · c_t`，`W_UV` 的形状同样是 `(n_h · d_h) × d_c`。

关键认知：**各头 K、V 从不独立存进缓存**。真正落盘的是 512 维的 `c_t`，各头的
K、V 是 `c_t` 经过共享上投影「长出来」的。这不是 128 份 K/V 的共享——MQA
是所有头拿到同一份 K/V，MLA 是每个头拿到**同一低秩底经不同行块投影出的
不同 K/V**，各头依然有自己独立的注意力形态。这是 MLA 和 MQA 表达力差距的
根源，第六节的等价视角还要回来讲。

### 2.3 第三步：Q 侧对称压缩——省的是另一种钱

Q 同样被压缩：`c^Q_t = W_DQ · h_t`（压到 `q_lora_rank = 1536`），再展开
`Q = W_UQ · c^Q_t`。但这一步省的东西完全不同：

- Q 是瞬时量，每步算完即弃，因为 **Q 不进缓存账**，所以 Q 压缩对缓存量
  毫无贡献。
- 它省的是**训练显存与激活占用**：不压缩的话，`W_Q` 是 `(n_h · d_h) × d_model`
  即 16384 × 5120 ≈ 8000 万参数的大矩阵，前反两传都要背着它；压缩成
  `5120 × 1536 + 1536 × 16384` 两个小矩阵后，参数量降到约三分之一，反向
  传播时对应的激活占用同比例收窄。

答法要点：面试官问「Q 为什么也压缩」，正确答案是「省训练侧的大投影矩阵
开销，跟 KV Cache 无关」——把它归到缓存账里是说反了。

## 三、矩阵吸收：数学合法性与推理形态

### 3.1 合法性：一句话就是矩阵乘法结合律

注意力分数正常写法是 `score = q^T · K`。代入展开式 `K = W_UK · c`：

`score = q^T · (W_UK · c) = (q^T · W_UK) · c`

乘法是线性结合，括号想怎么搬家都行。于是 `W_UK` 可以**预合并进 Q 侧的
投影矩阵**——把 `W_UQ^T · W_UK` 离线算好存成一个矩阵，推理时 Q 侧一步投影
直接得到「面向潜向量空间的 query」，**全程不显式重建出任何头的 K 矩阵**。
注意力打分的维度
从 `n_h · d_h`（16384）降到 `d_c`（512）。

注意这里的形态改写：每个头的 query 名义维度 `d_h = 128`，吸收后被抬升到
512 维去和 `c_t` 做内积——**每头仍是独立注意力，只是打在 512 维潜空间里**。
这正是「MLA 不是 MQA」在打分层面的第二次确认。

### 3.2 输出侧：`W_UV` 被 `W_O` 吸收

输出投影同理。注意力加权求和阶段得到的是潜向量的加权和
`Σ softmax(score) · c_t`，然后：

`o = W_O · (W_UV · (Σ scores·c)) = (W_O · W_UV) · (Σ scores·c)`

`W_UV` 与 `W_O` 预合并成一个矩阵，V 同样无需显式重建。两端吸收合起来，
推理时的 MLA 注意力完全在 512 维潜空间里闭环：**打分与投影都在潜空间完成**——进 `(q^T·W_UK)` 打分，出 `(W_O·W_UV)` 投影，中间只见 `c_t`。

### 3.3 两种实现口径：展开算 vs 吸收算

工程上 MLA 有两条均合法、且数学等价的执行路径，面试官常追问二者的取舍：

- **展开算**：直接用 `W_UK`、`W_UV` 从 cache 里的 `c_t` 实时还原 K、V，然后
  走标准多头注意力。从实现视角看，这**等价于一个 `n_kv = 1` 的 GQA**——
  cache 读的是一份 512 维「KV」，展开复制给 128 个头用。好处是能直接复用
  现成的 FlashAttention 类 kernel；代价是展开要消耗 `2 · n_h · d_h · d_c`
  的算力，而且展开后的 K 要留在片上或写回，带宽消耗回到 GQA 形态。
- **吸收算**：不重建 K/V，如上两小节，预合并矩阵后直接在 `c_t` 上打分、加权、
  投影。好处是 cache 读写量保持 512 维，HBM 带宽最省；代价是 score 计算
  变成 512 维（比 `d_h = 128` 的 FlashAttention 内积更长），且吸收后的矩阵
  无法走标准注意力 kernel 的现成路径，需要专门的融合实现。

vLLM 侧的取舍一句话：**吸收算省显存带宽但 score 维度抬到 512，展开算吃
现有 kernel 红利但把省下的带宽又花回去一部分**——两种 backend 在推理引擎
里都存在，展开算日常可用作 fall-back（无需预合并、实现简单），吸收算是
MLA 生产部署的主推力。

## 四、RoPE 冲突与 decoupled RoPE

### 4.1 为什么 RoPE 塞不进矩阵吸收

矩阵吸收的前提是「`q^T · K` 里 K 可以整体写成 `W_UK · c`，从而把 `W_UK`
预先并给 Q 侧」。RoPE 恰好打碎这个前提：RoPE 是**逐位置的旋转矩阵**，记
作 `R(θ, pos)`，作用形态是

`score = (R_q pos · q)^T · (R_k pos' · K) = q^T · R^T(pos) · R(pos') · W_UK · c`

中间插着的 `R^T(pos) · R(pos')` 与查询、键的位置都有关，**它不能把括号
收进 `W_UK` 里**——一旦收进去，合并出来的矩阵就和位置耦合，推理每个新
位置都要重算一份合并矩阵，预合并的意义不复存在。RoPE 的相对位置性质说明
它必须留在打分环节逐位置执行，与「离线预合并」冲突。

### 4.2 DeepSeek 的解法：切 64 维单独走 RoPE

既然 RoPE 的分量不能参与吸收，干脆**不让它参与压缩**：在 K 侧额外保留一
个 `d_R = 64` 维的 decoupled RoPE 分量记作 `k^R`，专门负责携带位置信息：

- `k^R = RoPE(W_KR · h_t)`，它在所有 128 个头之间**共享**——头与头的位置
  结构本来就是同一套，共享无损；
- Q 侧对称地保留对应 64 维 `q^R`，打分变成两路相加：
  `score = (q^T·W_UK)·c + (q^R)^T·(k^R)`，前半段走低秩吸收通道，后半段
  走逐位置 RoPE 通道，互不干扰。

于是 KV Cache 里每个 token 存两块：**512 维的 `c_t`（无位置信息的低秩底）
加 64 维的 `k^R`（位置信息的载体）**，共 576 维。这就是 cache 账里那个
「512 + 64」的来历——漏掉 64 维是手撕题最常见的失分点。

## 五、Cache 账：白板可默写的数字锚

统一 bf16（2 字节），统一 DeepSeek-V2 头配置 `n_h = 128`、`d_h = 128`，
先写**单层每 token 口径**的三行账：

| 方案 | 每层每 token 缓存字节 | 算式 | 100 G KV 池可装 token 数（单层口径） |
|---|---|---|---|
| MHA | 约 64 KB（65536 B） | 2 × 128 × 128 × 2 B | 约 164 万 |
| GQA-8 | 4 KB（4096 B） | 2 × 8 × 128 × 2 B | 约 2621 万 |
| MLA | 约 1.13 KB（1152 B） | (512 + 64) × 2 B | 约 9321 万 |

三行账里最该张口即出的是两头：**MHA 64 KB 对 MLA 1.13 KB，约 57 倍的显存
压缩**（65536 ÷ 1152 ≈ 56.9），**GQA-8 则落在 4 KB 中间档**（MLA 对 GQA
再省约 3.6 倍，GQA 对 MHA 再省 16 倍）。100 G 一列是按单层口径把字节数除出来的
量级感，用于直觉校准；整模型账乘上层数，DeepSeek-V2 为 60 层 MLA。

换到整模型 + 真实硬件，拍一张生产场景账：80 G 卡、权重占 60 G、剩 20 G 给
KV 池——

- 单层口径下 `20 × 1024³ ÷ 1152 ≈ 1864 万 token`；
- 60 层整模型口径，每 token 缓存 `1152 × 60 ≈ 69 KB`，同一个 20 G 池装
  **约 31 万 token 的容量**，同配置换成 MHA 只装约 5000 个 token。**长上下文
  serving 从「几个并发」变成「一批并发」**，这就是 DeepSeek 推理定价能压
  到同行零头的结构性原因之一（MoE 稀疏激活是另一头，见串联阅读）。

## 六、与 MQA/GQA 的等价视角与局限

- **MLA 不是「更省的 GQA」**。展开视角下 MLA 虽可形式化写成 `n_kv = 1` 的
  GQA，但那 128 个头的 K/V 不是同一份复制的——各头的 `W_UK` 行块不同，
  每头的 K 仍独立。GQA 是「头数上砍、通道数不变」，MLA 是「通道数上压、
  头数上保」，省钱的杠杆不同轴。
- **低秩瓶顶是真实的表达约束**。512 维的 `c_t` 要装进原本 16384 维的 K/V
  信息，本质是对 K/V 联合分布设了秩 512 的上限。理论上，若任务所需的 K/V
  张成的子空间秩超过 512，MLA 严格不如 MHA。
- **DeepSeek 的补偿策略是把头做大**：`d_h = 128`、128 头的总量（16384 维）
  其实是同档模型里的「超配」配置，用更宽的低秩输入底 + 吸收后的 512 维
  打分通道，把表达力拉回 MHA 量级。论文评测口径上，V2 相对上一代
  Dense/MoE 基线的指标持平到反超——实践中 512 的瓶顶没被捅破。
- **训练-推理一致性一个坑**：训练时理论上也可以走吸收（对 `c_t` 直接打分，
  不需要显式重建 K/V 的激活），但实现与数值对齐都要为此额外设计——比如
  吸收后的矩阵决定了前反向路径与「展开」不一致时，显存/算力的收益会被
  融合 kernel 的成本吃掉一大块。面试一句带过即可：「训练的实现与吸收的
  推理实现需要专门对齐，否则会数值漂移」——这也是推理引擎给 MLA 做独立
  backend 的原因之一。

## ▶ 面试题

**Q1：矩阵吸收为什么合法？**

矩阵乘法结合律。`score = q^T · (W_UK · c) = (q^T · W_UK) · c`，把 `W_UK`
离线预合并进 Q 的投影矩阵（同理输出侧把 `W_UV` 预合并进 `W_O`），推理
就不需要显式重建 K/V，注意力直接在 512 维的潜向量 `c_t` 上闭环。一句话：
**线性变换的括号能搬，位置有关的旋转不能搬**（后者见 Q2）。

**Q2：RoPE 为什么不能吸收？**

RoPE 是逐位置旋转，`score` 里插着 `R^T(pos) · R(pos')`，这个矩阵和输入
位置耦合，不能离线吸收进 `W_UK`；强行吸收就得每个位置重算一份合并矩阵，
预合并的意义消失。解法是把 64 维 `d_R` 解耦出来单独走 RoPE——`k^R` 在各
头间共享、不参与低秩压缩，打分变成「低秩通道 + RoPE 通道」两路相加。

**Q3：MLA 的 cache 里到底存什么？**

每个 token 两块：**512 维潜向量 `c_t`（`W_DKV · h_t`，各头 K/V 的公共
低秩底）加 64 维 `k^R`（decoupled RoPE 分量）**，合计 576 维、bf16 下
1152 B/token/层。注意 `k^R` 在 128 个头间共享，不是每头一份——这是账上
「不是 576 × 128」的原因，也是「不是只存 512」的原因。

**Q4：为什么 Q 也要压缩？**

Q 不进 cache，省的不是 KV 显存，是**训练显存与激活占用**：不压缩时
`W_Q` 是 `(n_h·d_h) × d_model ≈ 8000 万参数`的大矩阵，压到 rank 1536 后
参数量降到约三分之一。答「省 KV 缓存」是本题最直接的反答。

**Q5：MLA vs GQA 表达力谁强？为什么 DeepSeek 敢用 MLA？**

理论上 MLA 是秩约束——`c_t` 最多 512 维，若 K/V 需要的秩超过 512 则弱于
MHA。但两点让它实操不输：① GQA 是 「头数砍到 1/16，各头共享 K/V」，MLA
是「头数保留 128，各头 K/V 来自同一低秩底的不同行块投影」——头级的表达
独立性强于 GQA；② DeepSeek 把头配置超配（128 头 × 128 维 = 16384 维，远
大于模型隐宽 5120），用宽低秩底抵消瓶顶约束。论文评测口径上，MLA 相对
同档 MHA 基线指标持平或反超，所以「敢用」是评测给出的，不是赌注。

**Q6（手撕）：给定 `d_c = 512`、`d_R = 64`、`n_h = 128`、`d_h = 128`，
算 cache 比。**

- MHA 单层单 token：`2 × 128 × 128 × 2 B = 65536 B = 64 KB`；
- MLA 单层单 token：`(512 + 64) × 2 B = 1152 B ≈ 1.13 KB`；
- 压缩比：`65536 ÷ 1152 ≈ 56.9`，即**约 57 倍**；
- 维度口径对照：`16384 ÷ 576 ≈ 28.4`（潜向量维度压缩比的另一表示）；
- 外推整模型：乘层数（V2 为 60 层），V2 每 token 整模型缓存约 69 KB。

**Q7：推理时「展开算」和「吸收算」差在哪？**

展开算把 `c_t` 实时还原成 K/V 走标准注意力 kernel，实现等价于 `n_kv = 1`
的 GQA，好用但展开了 16384 维的又一轮带宽；吸收算预合并 `W_UK`/`W_UV`
后进 512 维潜空间闭环，cache 读写最省但 score 维度从 128 抬到 512、无法
走现成 FlashAttention 路径。vLLM 两种 backend 都存在，吸收算生产部署
主推，展开算常用作 fall-back。

**Q8：MLA 和 MQA 本质区别是什么？**

MQA 是 128 头读**同一份 K/V 本尊**，MLA 是 128 头读**同一份潜向量、不同
投影出的不同 K/V**。后者保留了头级注意力形态的独立，只是 K/V 的「信息量」被
限进 512 维的共同瓶顶——「共享的是底，不共享的是投影」。这是面试官从
「那为什么不用 MQA」切入时的一句话杀招。

  的总层数 61 层与 V2 的 60 层差一层（前 3 层 dense），本文算账按 V2 的
  60 层写。
- 「吸收算/展开算」的 vLLM 实现描述为社区工程共识口径；具体到各版本 kernel
  与 backend 的取舍以 vLLM 源码与 release notes 为准，本文不做版本钉注。
- 「训练中不走吸收是对齐成本」一句按经典实现路径写，吸收训练的技术可行性
  在论文中提及，非本文核验重点。
- 评测「MHA 基线持平或反超」为 DeepSeek-V2 论文口径，未独立复现。
