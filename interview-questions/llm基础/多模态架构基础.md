# 多模态架构基础：VLM 三大流派、训练流水线与推理成本

> 先声明定位：本仓主线是文本 LLM / infra / agent，多模态不是主线，但多模态
> 面试（尤其字节系）常以这类题开场——"主流 VLM 有哪些流派？""图像特征是
> 怎么映射进 LLM 的？"。本文是**最小考点地图**：按「结构流派 → 训练流程 →
> 推理 infra → 面试追问」给到够用的答案即可，不做深入钻研，面试官深潜时
> 能接住第一轮追问就算达标。

## 一、结构三大流派：视觉信息怎么进 LLM

所有主流 VLM 要解决的是同一个问题：**ViT 吐出的是一堆 patch embedding，
LLM 吃的是词表维度的 token embedding，怎么把前者变成后者能消费的东西**。
围绕"中间这层怎么接"，形成三个流派：

| 流派 | 代表 | 视觉侧结构 | 图像 token 数 | 核心取舍 |
|---|---|---|---|---|
| 投影派 | LLaVA-1.5、MiniGPT-4 后期 | ViT/CLIP 编码器 + **MLP projector**，输出当「视觉 token」拼在文本前 | 大（576+，随分辨率线性涨） | 最简单、复用现成 LLM，业界事实标准 |
| Q-Former 派 | BLIP-2、InstructBLIP | 冻结 ViT + 冻结 LLM，中间学一组 **learnable queries**（32 个）做 cross-attention 压缩 | 固定很小（32） | 省 token、省算力，但压缩是信息瓶颈 |
| 原生/早融合派 | Qwen2-VL、Chameleon/Emu3 | 视觉与文本同一 token 化、同一主干联合训练 | 中等，可动态 | 能力上限最高，训练成本也最高 |

**LLaVA 系（投影派）**是当下的主流答案：拿一个现成训练好的 ViT/CLIP
把图切成 patch 编码，接一个轻量 MLP projector 把 patch embedding 线性
映射到 LLM 的 embedding 维度，然后当作一段「视觉 token」直接拼在文本
token 前面。它赢的原因极其朴素——结构最简单，LLM 主干完全不用动（甚至
可以冻结），只训练一个几 MB 的投影仪就能让 LLM "看见"。面试里讲一句
"视觉 token 占位拼接"，流程就讲清了。

**Q-Former 系（BLIP-2 派）**的思路是"压缩后再给"：ViT 和 LLM 两头都
冻结，中间学一个小的 Q-Former——用 32 个 learnable query 向量对几百个
patch embedding 做 cross-attention，把图像浓缩成 32 个 token 再喂给
LLM。好处是推理省 token（32 vs 576+）、训练两端不碰，缺点是信息瓶颈
明显：一张高分辨率细节图压到 32 个向量，细粒度内容（小人脸、小字）
很容易丢，这也是它后来被投影派和原生派挤下主流位置的原因。

**原生/早融合派**（Qwen2-VL、Chameleon/Emu3）把多模态当成一次的事：
视觉 token 和文本 token 在同一个序列里、同一个主干里联合训练，不是
"外挂编码器"而是"天生多模态"。这里的名词考点是 **M-RoPE**（Multimodal
RoPE，Qwen2-VL 提出）：普通 RoPE 只有一个一维位置轴，图像却是 2D
的、视频还有时间轴，M-RoPE 把位置拆成「时间 / 高 / 宽」三组，每组用
RoPE 频率的不同段编码，文本侧则三组数值相同退化成普通 1D RoPE——
**一句话：把 2D 图像和时间轴展平进 RoPE 的位置编码体系**。代价也很
直白：从头联合训练，算力和数据成本远高于只训投影的 LLaVA 路线。

## 二、训练流水线：对齐 → 指令 → 偏好

不管流派，VLM 的训练基本是三段式，面试问"LLaVA 怎么训练的"答这个即可：

1. **对齐预训练（alignment pretrain）**：冻结 ViT 和 LLM，只训中间的
   投影层（LLaVA 是第一代用单层线性、1.5 代换成两层 MLP）。数据是
   image-caption 图文对，目标是让投影层学会"看图说话"的粗对齐——
   把视觉特征映射到 LLM 已有的语义空间里。
2. **指令微调（instruction tuning）**：解冻 LLM（ViT 通常仍冻或用较小
   学习率），上视觉指令数据（视觉问答、详细描述、OCR、推理题），
   让模型学会按指令聊图。数据质量远比数量关键，LLaVA 的核心贡献之一
   就是用 GPT-4 造了 158K 高质量视觉指令数据。
3. **偏好优化（可选）**：和文本 LLM 一样接 DPO/RLHF，治理多模态特有
   的幻觉（编造图里没有的东西）。

一句总结：**先学"把图翻译成 LLM 能懂的向量"，再学"按人话指令回答关于图
的问题"，最后治幻觉**。各阶段冻结策略（冻谁、放谁）本身就是追问点。

## 三、VLM 推理的 infra 考点（infra 岗视角）

多模态落到 infra 面试，核心就是**图像 token 把序列拉长这件事的连锁反应**：

| 考点 | 一句话答案 |
|---|---|
| 图像 token 数怎么定 | 分辨率决定：(H/patch) × (W/patch)。LLaVA 336px、patch 14 → 576 token；高分辨率或动态切块动辄上千到几千 |
| prefill 成本 | 图像几百~几千 token 全进 prefill，prefill 远重于纯文本请求；prompt 里又是一个几乎不变的图像 token 段，可做前缀/块复用 |
| KV 显存 | 按 token 总数算，口径与文本完全一致——每 token KV 公式不变，只是 n 变大了（公式详见 [KV Cache 计算题](./README.md#3-kv-cache-显存本模块最硬的计算题) 与 [vLLM 与推理加速核心](../inference/vllm与推理加速核心.md)） |
| dynamic resolution tiling | 高分辨率图像切块成多个 tile，各自过 ViT 变 token：细节更好但 token 数 × tile 数，显存和 TTFT 跟着涨，是分辨率与成本的老权衡 |

给 infra 面试官的一句话形状：**VLM 推理 ≈ 文本推理 + 一段超长、可缓存
的图像 prefill**，瓶颈和优化手段（prefix caching、连续批处理、KV 显存
管理）都在现有文本侧框架的延长线上。

## 四、高频面试追问清单（本主题）

| 追问 | 答题要点（3-5 句版本） |
|---|---|
| LLaVA 的 MLP 投影和 Q-Former 的本质差别？ | 两者都是「视觉→词表维度」的连接器，但 MLP 投影是**逐 patch 的线性映射**，只改维度、不选信息，token 数跟 patch 数走；Q-Former 是 **compressor**，用少量 learnable queries 做 cross-attention 把几百个 patch 汇成 32 个 token，主动做了信息选择。所以前者保细节但 token 贵，后者省 token 但有信息瓶颈——追问"为什么现在主流是 MLP"：细节保真在多模态任务里更值钱，且 MLP 简单易训、算力成本可接受。 |
| 图像怎么一步步变成 token 进 LLM？ | ① 图像切成固定大小 patch；② 过 ViT/CLIP 编码器得到 patch embedding 序列；③ 过 connector（MLP 投影或 Q-Former）映射到 LLM embedding 维度；④ 把这串「视觉 token」当普通 token 和文本 token 拼接成一个序列，进 LLM 统一做 next-token 预测。关键直觉：进 LLM 之后图像 token 和文本 token **没有任何特殊处理**，这就是"多模态的尽头还是 next token prediction"。 |
| Qwen-VL 的 M-RoPE 在解决什么问题？ | 普通 RoPE 是一条一维位置轴，天然适合文本；图像是 2D（高×宽）、视频还有时间轴，硬塞进 1D 位置会丢失二维相对位置关系。M-RoPE 把位置拆成三份——时间 / 高 / 宽，各自用 RoPE 频率的一段编码，文本侧三份数值相同从而退化成标准 1D RoPE。作用是：同一套位置编码同时兼容 1D 文本、2D 图像和 3D 视频序列，且保留图像的二维相对位置信息。 |
| VLM 推理和纯文本推理成本差在哪？ | 差在序列里的图像 token 段：一张图几百到几千 token，prefill 长度、FLOPs 和 KV 显存都按 token 总数成倍放大，TTFT 显著变差；decode 侧和文本无异。工程对策也完全来自文本侧工具箱——图像 token 段几乎不变，前缀缓存收益极大；动态分辨率则要按业务权衡"细节好"和"token 数涨"的成本。唯一新增的组件是 ViT 前传，相对几千 token 的 prefill 通常不是大头。 |
