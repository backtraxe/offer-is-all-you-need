# RAG 权限控制：检索侧防线的三种方案与三个坑

> 本篇面向要把知识库从 demo 推向企业的读者。RAG 权限的核心难点一句话：
> **LLM 没有权限概念，检索到的内容它默认都是可说的**——所以防线
> 必须全部筑在检索侧，不能指望生成侧「自觉」。读完你会获得：
> 三道闸门的布局图、metadata 过滤/物理隔离/回源鉴权三种方案的
> 选择标准、以及权限变更延迟/混合检索漏闸/缓存泄漏三个高频事故点。

## 一、原则：三道闸门，过滤必须在检索时

```text
用户登录 → ① 身份解析（user → 部门/角色/组别）
         → ② 检索时过滤（权限条件先行，违禁块不进候选集）
         → ③ 生成与展示（引用溯源 + 空结果兜底话术）
```

铁律：**一旦违禁 chunk 进了 prompt，「请只基于允许的内容回答」
就是纸糊的**——模型可能引用、复述，甚至「我不能说的信息是……」
这种话本身就是泄露。

## 二、方案 A：Metadata 过滤（首选，80% 场景）

入库时每个 chunk 打权限标签，检索时把用户身份翻译成过滤条件：

```python
# 入库：chunk.metadata = {"acl": ["dept:finance", "role:vp"], "sensitivity": "internal"}
# 检索：
filter = {"must": [{"key": "acl", "match": {"any": user_groups}}]}
vector_db.search(query_vector, top_k=50, filter=filter)
```

三个工程要点：

1. **pre-filter 优于 post-filter**：先检索后过滤会把 top-k 洗掉大半
   导致召回不足，且 ANN 遍历仍途经违禁向量；
2. **标签用组别不用个人**（`dept:finance` 而非 `user:zhangsan`）——
   人员变动只调 AD/LDAP 组映射，不动库；
3. 各家载体：pgvector 是普通 WHERE、Qdrant/Milvus 是 payload filter、
   ES 是 bool filter + kNN。

## 三、方案 B：物理隔离（强隔离需求）

namespace/collection/索引按租户或密级分库，路由层按身份选库。

- 优点：隔离是物理的，过滤条件写错也不漏；
- 缺点：N 份库的运营负担 + 跨域共享文档要重复入库；
- 典型组合：SaaS 的 `tenant_id` 隔离 + 方案 A 做租户内细粒度。

## 四、方案 C：回源鉴权（最硬，权限不留库）

库房只存 doc_id + 向量映射、**不存正文**；命中后按**调用者身份**
回源系统取正文——SQL 的 RLS、SharePoint/Confluence 的原生 ACL、
联邦搜索都是这条线。

- 权限永远是源系统说了算，**权限变更即时生效，无同步延迟**；
- 代价是每次命中多一跳，且正文不落库意味着高光/预览要走源系统。

## 五、三个高频事故点（每个都被追问过）

**1. 权限变更延迟**：权限映射必须每次检索实时查（或短 TTL 缓存），
严禁「等全量重建」——员工上午被移出财务部，下午还能查到就是
审计事故。

**2. 混合检索漏闸**：向量路过滤了、BM25/rerank/缓存忘了一路 = 全漏。
尤其是 **query cache**——命中别人的缓存答案 = 绕过检索过滤。

**3. 生成层收尾**：引用溯源（每结论带 chunk 引用，合规可查）+
空结果兜底（「这个问题可能不在你有权访问的资料范围」而非硬答）+
可撤稿（库/缓存/日志引用三路抹除）。

## 六、Agent/MCP 时代的延伸

Agent 通过 MCP 工具访问数据时，信任链变长
（用户→agent→MCP server→数据系统）：

- **身份端到端透传**：server 必须以**用户身份**（on-behalf-of
  token exchange）访问下游，而不是拿一个服务账号超权限跑全部；
- **读权限过滤与写操作审批是两条独立防线**（写走
  [harness 权限六层](../agent/harness工程实战.md)）；
- 详见 [mcp与工具调用深度对比 第八节](../agent/mcp与工具调用深度对比.md)。

## 七、▶ 面试标准答（90 秒）

「第一原则：权限是检索问题不是生成问题——违禁内容绝不能进 LLM
上下文。主方案 metadata 过滤：入库打 ACL 标签（组别而非个人），
检索 pre-filter 生效；强隔离上 namespace 物理分库；最硬是权限
留源系统、命中后按调用者身份回源取正文。配套三件：权限映射
实时查、BM25/缓存同样过闸、引用溯源+空结果兜底+可撤稿。Agent
时代加一条：MCP 工具调用用 on-behalf-of token 透传用户身份，
读写权限分开管。」
