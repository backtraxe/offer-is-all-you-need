## 一、一句话主线：昇腾是唯一跑通"万卡预训练"全链路的国产栈，其余各家推理先行

国产算力不是一家公司一个生态，而是**四条路线并行**：

- **昇腾 = 全栈自研**：达芬奇架构芯片 + CANN 软件栈 + HCCL 通信 + MindSpeed
  加速库 + MindIE 推理，对标的不是 NVIDIA 一块卡而是整套 CUDA 生态位；
- **MUSA（摩尔线程）= CUDA 兼容层**：以 musify 源码级迁移 + torch_musa
  PrivateUse1 插件把迁移成本压到最低，生态策略是"跟随 DeepSeek 系开源栈"；
- **海光 DCU = ROCm/HIP 系**：借助 AMD 开源的软件栈做兼容，是四条路线里
  迁移成本最低的一支；
- **寒武纪 / 壁仞 = 自研指令集**：各自有一套 ISA 与编译栈，靠大客户有钱有
  量的场景落地。

为什么"推理先行"？因为推理只需要**复用现成 kernel + 量化**，算子覆盖面
需求小，vLLM/SGLang 的硬件插件机制把适配降级成"接 backend"的工程问题；
而万卡预训练要求**长稳数周 + 确定性计算 + 断点续训 + 通信库完备**，目前
只有昇腾有完整的公开证据链——两篇论文都来自华为自家 lab。

## 二、昇腾深挖：从 910 到 CloudMatrix 384，再到 CANN/MindSpeed 与论文实锤

### 2.1 硬件演进与超节点叙事

- **Ascend 910**（2019，达芬奇架构首发）→ **910B**（2023 年放量，算力与
  HBM 规格网上说法不一，本篇只写"300+ TFLOPS 级、64GB HBM"，**该规格口径
  未核实官方手册，**面试被追问主动说这句反而是加分项）→ **910C**（2025
  年放量，**双 die 封装** = 两颗 910B 合封成一颗）。
- **CloudMatrix 384**（2025-04 SemiAnalysis 深度报道）：384×910C 全互联
  超节点，整机 **300 PFLOPS dense BF16，约 2 倍 GB200 NVL72**；显存 3.6 倍、
  显存带宽 2.1 倍；代价是**功耗 4.1 倍**、每 FLOP 功耗 2.5 倍。跨 16 个
  机柜（12 计算 + 4 交换），scale-up 全靠光——**6912 个 400G LPO 光模块**。
  反推 **910C 单卡 dense BF16 约 780 TFLOPS**，约为单颗 Blackwell 的 1/3。
- **路线图**（华为 HC2025，2025-09）：950PR/950DT（2026，换装自研 HBM）→
  960（2027）→ 970（2028，目标 **4 ZFLOPS FP4**）；同步发布的 **Atlas 960
  SuperPod 达 15,488 卡**（此数为发布会标题级核实，规格细节以官方手册为准）。

面试叙事锚必须记住一句话：**用 5 倍芯片、4.1 倍功耗换 2 倍算力——系统级
反超、单卡级落后；中国不缺电、缺单芯片密度，所以路线是堆料 +
光互联。**被问"国产卡能替代吗"时先报这句，再展开。

### 2.2 软件栈：CANN / torch_npu / HCCL / MindSpeed

- **CANN**：昇腾异构计算架构，当前配套版本 **CANN 9.1.0**（vllm-ascend
  v0.26.0 依赖口径，2026-09）。
- **torch_npu**：走 PyTorch **PrivateUse1** 插件式适配路径，90% API 透传，
  主仓库在 Gitee；模式决定了"换 backend 字符串就能跑"只是第一层。
- **HCCL**：对标 NCCL 的集合通信库，环境变量前缀 `HCCL_*` 与 `NCCL_DEBUG`
  排障套路一一对应（复用[通信与网络专题](./distributed-training/通信与网络专题.md)的全套方法论）。
- **MindSpore**：华为自研框架，政企客户存量多，社招面试考察频率低于
  PyTorch 路线。

**MindSpeed**（昇腾版 Megatron 加速库，Gitee 381★，2026-10 实测）是本篇
最重要的面试素材，它的特性表直接就是"昇腾亲和优化清单"：

- 配套矩阵 **MindSpeed 2.0 + Mcore 0.12.1 + CANN 8.2.RC1**；
- 已发布 ✅：TP/PP/VPP/CP（Ulysses + Ring Attention）/分布式优化器全套；
  FlashAttention / rms_norm / swiglu / **MoE GMM 融合算子**；
- **未发布 ❌：Transformer Engine、MLA、确定性计算、MC2 通信融合**——
  面试说"昇腾亲和特性有明确 released/未发布边界，不是 Megatron 全量平移"
  直接提现成度；
- 套件形态：MindSpeed-LLM（大模型）/ -MM（多模态）/ -RL（强化学习）。

与[多档 Megatron 篇](./distributed-training/megatron源码深度拆解.md)的串联：**架构同源**——MindSpeed
借 Megatron-Core 的模块化路径，把 kernel 替换为 NPU 亲和实现。被问"两者的
关系"一句话：Mcore 管并行编排，MindSpeed 管算子与通信落到 NPU。

### 2.3 论文级训练实锤（面试金句）

两篇 arXiv 论文构成国产卡"能训大模型"的公开证据链：

- **Pangu Ultra 135B dense：8192 卡、13.2T token、MFU>50%（arXiv
  2504.07866，2025-04）**；
- **Pangu Ultra MoE 718B：6144 卡、MFU 30.0%（arXiv 2505.04519，2025-05）**。

同一软件栈、同一硬件代际，dense 50% vs MoE 30% 的同栈对照是绝好案例：
**MoE 的 AlltoAll/EP 通信是国产卡当前最大短板**（对应 MindSpeed 里 MC2
通信融合未发布）。被问"国产卡训 MoE 行不行"，用这组数字回答比任何定性
都强。

### 2.4 采用面可靠性分级（不要乱引用）

- **可靠**：华为官方发布（Pangu 论文、HC 大会路线图）；昇腾*推理*适配与
  MT-* 移植仓库（代码可查）；
- **公司官宣、无第三方验证**：讯飞星火训于"飞星一号"昇腾集群；
- **纯传言：DeepSeek 训练用昇腾**——目前没有任何可校验证据，面试说"这是
  未核实传言"是加分不是减分。

## 三、MUSA 深挖：CUDA 兼容层路线的极限

### 3.1 路线本质：把迁移做成"改字符串"

- **torch_musa**：同样走 PrivateUse1 插件，PyTorch 模型**改 backend
  字符串**即可跑（概念上）；
- **musify**：源码级自动迁移工具，把 CUDA kernel 翻译成 MUSA 版本；
- **MT- 前缀仓库群**：MT-DeepEP / MT-flashMLA / MT-DualPipe /
  MT-TransformerEngine / Megatron-MUSA-Titan——**这是生态跟随 DeepSeek 系
  开源栈的直接证据**，被问"摩尔线程生态怎么打"就举这组仓库；
- **MCCL**：对标 NCCL 的通信库，**目前仅在 S4000 平台提供**（面试冷知识：
  S3000 用户拿不到多卡集合通信，单机单卡推理是它的甜区）；
- **torchada**（43★）：号称 CUDA 脚本不用改直接跑——**热度极低**，说明
  社区主流仍是 musify 显式迁移路线。

### 3.2 硬件与时间线

- **MTT S4000**（官网实测规格）：48GB 显存、768GB/s 带宽、**MTLink
  240GB/s** 机卡互联（支持 2/4/8 卡）、PCIe 5.0、整卡 450W，支持
  FP64→INT8 全精度档；厂商宣称 KUAE 千卡集群线性度 **91%——宣称值，
  未见第三方复测**。
- **S5000：官网未见公开规格页**，写作与面试都不要编数字。
- 时间线：2023-10 被列入实体清单 → **2025-12-05 科创板上市（688795）**，
  募资超 10 亿美元、**首日 +468%，**DeepSeek 梁文锋为最大机构投资者 →
  **2026-08 宣布寻求港股二次上市**。

### 3.3 生态热度一句话（收尾金句）

**torch_musa 519★ vs vllm-ascend 2945★**（2026-10 GitHub 实测）——
"供应商 ≠ 生态，生态成熟度看 GitHub 活跃度：昇腾适配仓 star 数是 MUSA
的 5.7 倍"。被问选型时这句话收尾，比"看场景"敷衍回答好一个数量级。

## 五、引擎适配现状表：推理插件机制成熟，训练证据链只有昇腾

| 栈 | 热度（2026-10 GitHub） | 进度与依赖 | 定性 |
|---|---|---|---|
| vllm-ascend | **2945★ / 2416 fork** | v0.26.0rc1（2026-09）；源自 vLLM RFC#11162 硬件插件机制；支持 LLaMA-Factory/verl/TRL；要求 **CANN 9.1.0 + PyTorch 2.10 + torch_npu 2.10.0.post4** | 生态标杆 |
| SGLang main | 主仓内置 | `hardware_backend/` 含 **npu 与 musa 一等公民后端**（attention/moe/quantization/KV offload 完整子目录） | 不等插件，直接合主干 |
| MooreThreads/vllm-musa | 127★ | v0.28.0-dev 跟 V1 引擎 | 热度差一个数量级 |
| MindIE | 无开源仓 | 昇腾闭源推理引擎，随 CANN/Atlas 分发 | **闭源 SDK 集成而非开源贡献** |

主线结论：vLLM RFC#11162 后的**硬件插件机制**让推理适配变成"接
backend 工程问题"——这就是"推理先行"的机制原因；训练要万卡长稳数周
+ 确定性 + 断点续训 + 完备通信库，公开证据链只有昇腾（Pangu 双论文）。
面试被问"为什么国产卡推理落地快于训练"，把这四个词报出来。

## 六、面试答法骨架：四段模板

### 6.1 "你们做 CUDA→CANN/MUSA 迁移大概什么成本？"

按三层拆分，每层给一个可量化的指标：

1. **框架/API 层**：torch_npu / torch_musa 换 backend 字符串，80% 代码
   不动——量化为"代码改动行数占比"；
2. **算子层**：缺算子用 aclnn / muDNN 补齐，热点（attention / rms_norm /
   swiglu / MoE GMM）换厂商融合算子——**MindSpeed 特性表就是现成清单**；
   量化为"op 覆盖率打表"；
3. **通信层**：NCCL→HCCL/MCCL，并行策略原样搬，**重点回归 AlltoAll/EP
   性能**——接 Pangu dense 50% vs MoE 30% 的案例，说明这正是未知数的
   大头。

排障套路复用：`HCCL_*` / `MCCL_*` 日志环境变量类比 `NCCL_DEBUG`。人月
估算思路：op 覆盖率打表（1-2 周）→ 通信库回归（2-4 周）→ MFU 对齐目标
（4-8 周），合计**小团队 1-2 个季度**完成一个主力模型的迁移对齐。

### 6.2 "国产卡性能到底差多少？"

统一用 MFU 锚同模型同规模对比，别混口径：

- dense 训练 **MFU>50%（arXiv 2504.07866）**是论文级数字，不低于多数
  A100/H100 公开实践的 MFU 区间——**短板不在"能不能训"，在 MoE 与
  生态富集度**；
- 再报两个硬件锚：单卡 **910C ≈780 TFLOPS dense BF16 ≈ 1/3 Blackwell**
  （SemiAnalysis 2025-04 反推）；系统账 CM384「300 PFLOPS 算力 ≈ 2×
  GB200 NVL72，功耗 4.1×，6912 个 400G LPO」。

### 6.3 "为什么推理先落地？"

三句话：**推理 = 复用现成 kernel + 量化，算子覆盖面需求小；vLLM/SGLang
硬件插件机制把适配变"接 backend"工程问题；训练要求长稳/确定性/断点续训，
门槛高一个数量级**。

### 6.4 "H100 禁令你们怎么办？"——三层展开

1. **算力供给层**：报 CM384 的量级与功耗账，说明"替代存在于系统级，
   不存在于单卡级"；
2. **迁移成本层**：用 6.1 的三步给出估算模板——op 覆盖率打表 → 通信库
   回归 → MFU 对齐目标；
3. **节奏层**：推理先行（vLLM/SGLang 插件成熟，1 个季度可见效）、训练
   跟随（昇腾有证据链，MoE 短板需评估）。
