## 一、直觉与主线

一句话直觉：**预训练 loss 只认 token 分布，数据工程就是你在给模型投票——投给谁，
它就在谁的分布上表现好。**

2023 年以前，数据工程约等于「写清洗规则」：Gopher/C4 规则族、fastText 质量分、
MinHash 去重，工程上做完就完了。2024 年 FineWeb-Edu 和 DCLM 两个工作把它改写成了
另一个词——**分类器驱动的重采样**：FineWeb 的规则过滤链从 CommonCrawl 留下
约 15T token，但真正的大头增益在第二步，用 Llama-3-70B-Instruct 标注 50 万条样本、
蒸馏出一个 BERT 级教育质量分类器，再把全库砍掉约 92%（阈值 3，留下 1.3T），
这部分才是 FineWeb 到 FineWeb-Edu 的主要增益来源（官方 dataset card，2024）。
DCLM 的 7B 冠军配方核心同样是分类器——fastText（OH2.5+ELI5 正例）——而不是更新
的规则（DCLM 官方，2024）。**规则负责删垃圾，分类器负责选精华**，已经是 2024 后
所有头部 pipeline 的共识：Nemotron-CC（NVIDIA，arXiv:2412.02595）与 Qwen3 同理。

这条主线带来三个连锁反应：

1. **激进过滤和长 token 预算是一对真矛盾**。Nemotron-CC 论文（2024-12，ACL'25）
   点名 FineWeb-Edu/DCLM「remove 90% of data」导致数据不够喂 15T 级训练；它的解法
   是分类器集成加合成改写（synthetic rephrasing）来保留量，全量 6.3T 数据里唯一
   真实 token 是 DCLM 的 4 倍。**面试时说「过滤越狠越好」，会被这条追问到死。**
2. **课程式多阶段预训练取代静态配比**。Qwen3 三阶段（30T 通用 → 约 5T 推理增强加
   加速 LR 衰减 → 长上下文 4096 外推到 32768）是 2025 主流形态；实例级配比靠小代理
   模型打细腻标签做消融走出来，不再拍百分比（Qwen3 技术报告，2025-05）。
3. **合成数据的天花板由 teacher 决定，不在数量**。Magpie 只给 Llama-3-Instruct 左半
   chat template，零种子自生成 4M 指令、筛出 300K，8B-Base 纯 SFT 就打赢了
   「SFT 加 UltraFeedback DPO」组合，部分任务追平官方用 10M 数据训出的 Instruct
   （Magpie，ICLR 2025）。

## 二、清洗五件套（以 FineWeb/datatrove 为模板）

「五件套」是面试里对「一条 CC 数据 pipeline 讲讲」的标准拆法：URL 过滤、文本抽取、
语言识别、质量过滤、去重。每一件都有标准答案和可追问点。

### 2.1 URL 过滤

UT1 成人黑名单加子词黑名单（如 url 里含特定词的站整站丢）。这是整条链上**最便宜
的一刀**：一行 join 就能完成巨量级降落，成本几乎为零，所以永远放第一件。
RedPajama-V2（30.4T token，2024）的做法更工程化：把 ut1_blacklist 做成**质量信号
列**而不是硬删——信号随行存储，阈值留给下游配方决定，避免了「上游替下游做决定」
（RedPajama-V2 官方）。

### 2.2 文本抽取

WARC 里的 HTML 转正文，主流两个库：trafilatura（datatrove 默认）与 resiliparse
（DCLM 用）。**抽取器是隐藏变量**：两者对代码块、表格、列表的存活率系统性不同，
差异会直接传导到下游指标；换抽取器之后旧的质量分数不可复用，消融得从抽取重跑。
答应试时提这一句，就是把「做过」和「背过」区分开的细节。

### 2.3 语言识别

fastText-176 是标准件（GitHub 26.5k 星，但 2024-03 后实质停更，工具已固化——
停更不是问题，没人再改它）。FineWeb 的阈值是语言分大于等于 0.65（官方）。语言分
同时干两件事：语种划分、以及隐式的低质信号（一堆乱码语言分必低）。

### 2.4 质量过滤：规则兜底层与分类器层

两层，缺一不可：

- **启发式规则层**：Gopher/C4 规则族——行长、词长、重复 n-gram 比例、符号率、
  大写率等几十个布尔条件。优点是便宜、可解释；缺点是只能删垃圾，选不出精华。
- **质量分类器层**：fastText 时代的问法是「像不像 Wikipedia/OpenWebText 正例」；
  2024 后升级成 **LLM 打分 → 蒸馏小模型 → 全库打标**的 FineWeb-Edu 范式：
  Llama-3-70B-Instruct 按 0-5 additive rubric 标 50 万条，蒸馏成
  Snowflake-arctic-embed 的 BERT 回归器（F1 约 82%）扫全库（官方，2024）。
  成本锚记住这个数：给 15T token 打一遍教育质量分约 **6,000 H100 小时量级**
  （FineWeb-Edu card，2024）。阈值选 3 还是 2 不是拍脑袋：阈值 3（留 1.3T）偏向
  MMLU/ARC，阈值 2（留 5.4T）偏向 HellaSwag/PIQA——「质量」不是单一标量，
  **阈值选的是两个评测族之间的 trade-off 交点。**

### 2.5 PII 与「什么过滤不能做」

FineWeb 只做 email 和公网 IP 的正则替换，电话号码因为误报率太高直接放弃；并且
**明确不做** Wikipedia 相似度型 ML 过滤和毒性分类器——官方引用的文献理由是这两
类过滤会系统性剔除方言内容、对特定人群误伤（FineWeb 官方，2024）。讲出「什么过滤
不能做」的边界与理由，是这条追问线的加分点，比会背规则高级。

## 三、去重：免费能力里最贵的一步

Lee et al.（ACL 2022）给了去重的全部动机数字：C4 里有一句 61 词的句子重复了
6 万以上；**超过 1% 的模型输出是对训练语料的逐字抄写**；训练集与验证集重叠超过
4%；去重之后模型记忆化输出**降约 10 倍**、收敛还更快（Lee et al.，ACL 2022）。
所以去重被称为「免费的能力提升」——但实现成本全在工程侧。

### 3.1 三档实现

- **Exact 去重**：哈希全文，线性、便宜，先做。
- **Near-dup**：shingle（5-gram）→ MinHash 签名估 Jaccard → banded LSH 建桶候选
  对。FineWeb 参数：5-gram、14×8=112 个 hash，**逐 dump 去重**（官方）；
  RedPajama-V2：128 个 hash 分 band，导出 Jaccard 0.7/0.8/0.9/1.0 四档签名——
  band 数越多阈值越高、漏检越多，三档签名一次算出当元数据资产随行存储（官方，
  2024）。
- **Span 级**：suffix array 找精确子串，可解释但难分布式，只在高价值子集上做。

两个反直觉结论，都是面试钩子：

1. **FineWeb 逐 dump 去重比全局去重效果好**——全局去重会保留「最早出现的那一份」，
   杀掉各 dump 里时间最新的副本，等于让模型学旧版本的信息；逐 dump 自治反而更新鲜
   （FineWeb 官方）。
2. **DCLM 链路不用 MinHash，用 Rust 实现的 BFF（Bloom filter family）**——百亿
   文档级去重的痛点在吞吐与内存墙，不在精度理论（DCLM 官方）。

### 3.2 分布式落地三要素

1. **Sharding 稳定**：FineWeb 按 dump 分桶、分桶自治去重，把全局 join 局部化；
2. **LSH 内存墙**：RedPajama-V2 的 polars LSH 实现在单机 64 核、500GB 内存上
   只敢压 2 亿文档（官方实测），所以百亿级必须分桶加单机内并行，横向扩机器而
   不是纵向调参；
3. **签名列当资产**：MinHash 签名重算成本高到不允许二次计算，RedPajama-V2 直接
   把四档阈值签名存成列，随数据流转。

## 四、配比与课程：从静态百分比到课程式三阶段

直觉记住一句：**配比就是「你希望模型在谁的分布上表现好」**——loss 对 token 没有
品味，只有分布。

2023 时代是静态百分比：Llama 系大概 67% CommonCrawl、15% C4、4.5% Github 这类
固定配方。2025 后转向课程式多阶段，Qwen3 是标准范本（技术报告，2025-05）：

| 阶段 | 内容 | 口径 |
|---|---|---|
| S1 通用 | 30T token、4K 上下文 | 打底胚子 |
| S2 推理增强 | 约 5T，STEM/代码/推理占比拉高，同时加速 LR 衰减 | 高密度收尾 |
| S3 长上下文 | 4096 分两阶段外推到 32768 | 能力补课 |

支撑这套配比的工程有两件：

- **实例级消融**：Qwen3 给 30T 以上 token 打教育价值、领域、安全等多维标签，用小
  代理模型做实例级配比消融再外推；学术对应物是 DoReMi、Data Mixing Laws、RegMix。
  为什么实例级优于数据源级：一个「数据源」内部异质到不可用单一权重描述，域间还
  互相污染，实例级标签把决策单元从「源」细到「样本」。（Qwen3 官方）
- **规模化蒸馏进预训练**：Qwen3 36T token、119 种语言（Qwen2.5 是 29 种）；
  Qwen2.5-VL 从 PDF 抽取贡献「万亿级」文本，Qwen2.5-Math/Coder 合成「万亿级」
  pretrain token——合成数据不再只留在 SFT 阶段（Qwen3 官方）。

两条经验共识：代码占比稳步上调（推理反哺，Qwen3/DeepSeek-V3 都在推理阶段加
code+STEM）；多语言是「加量但防英语退化」。上采样策略：Wikipedia/arXiv/书籍这类
高质源跑 2-4 个 epoch，长尾源 1 个 epoch。但 Nemotron-CC 给了最重要的边界警告：
**激进过滤后量撑不起 15T 级预算时，宁可「保留量加合成改写」，也不要对低质数据多
轮复训**——复训轮次一多，低质数据的害处比稀释更糟（Nemotron-CC，arXiv:2412.02595）。
量化证据：8B@1T 高质量子集上 MMLU 比 DCLM 高 5.6 分；8B@15T（其中 7.2T
Nemotron 数据）MMLU 高 5 分、ARC-C 高 3.1 分，反超 Llama3.1-8B（官方）。

参照物：DeepSeek-V3 用 14.8T token 训出 671B（激活 37B），全训练 2.788M H800
小时、**全程无不可恢复 loss spike**（arXiv:2412.19437）——数据与配比稳到这个
程度，本身就是数据工程的最终验收指标。

## 五、合成数据主线 2022→2026

五步走完法，每步回答一个特定问题：

1. **Self-Instruct（2022）**：175 条种子指令自举扩库，GPT-3 在 SuperNI 上提升
   约三分之一，距 InstructGPT-001 只差约 5%。确立了「种子 → 生成 → 过滤 → 微调」
   的循环骨架。
2. **Evol-Instruct（2023，WizardLM）**：种子多样性饱和后，用深度演化（加约束、
   加推理步）与广度演化（换主题、换风格）拉高复杂度上限。
3. **Self-Reward / 自批判（2023-2024）**：模型自己打分筛自己的输出，把「过滤」
   也合成化。
4. **Magpie（2024，ICLR 2025）**：只给 Llama-3-Instruct 左半 chat template，模型
   自回归直接吐出用户指令——**零种子**抽出 4M 条、筛 300K；8B-Base 加 Magpie 纯
   SFT 打赢「SFT 加 UltraFeedback DPO」，部分任务追平官方用 10M 数据加 SFT 加
   反馈训出的 Instruct。含义很重：**指令数据的边际成本已经趋近电费**，瓶颈在
   teacher 能力与筛选器，不在数量。
5. **大规模蒸馏（2025-2026 收敛态）**：合成 token 直接进入预训练胚子（Qwen3 的
   万亿级），官方报告明写蒸馏在小模型上显著优于 RL——**蒸馏在工程上压缩的是
   RL 的试错成本**，一步前向换 N 次采样。

### 5.1 数据飞轮

模型生成 → 人工/LLM 筛 → 训练 → 更强模型回头看旧数据重新筛。关键认知：**飞轮每
转一圈，旧数据不是资产而是负债**——上一代的分数、标签、取舍全部过时。Qwen3 的
多维标注系统就是把「重新筛」的成本摊薄成一次扫库，为再筛预留接口。

### 5.2 Model collapse 的边界

塌缩成立需要三个前提同时满足：**纯合成闭环、多代迭代、无新真实数据**——分布尾部
一代比一代瘦，最后学到自己的话术。它不是「用合成数据」的病，是「纯合成闭环」的
病。工程安全线三条：

1. 预训练里合成数据主要作用于高质子集、推理阶段、长上下文补课，不进全量胚子；
2. 用合成改写（rephrasing）真实数据而不是纯生成——改写保留真实分布的形状，
   Nemotron-CC 的 8B@15T 验证这条路能撑起长 token 预算（arXiv:2412.02595）;
3. 每次迭代混入新真实数据、保留人审抽检比例，代际标签做隔离。

## 六、SFT 与偏好数据

### 6.1 多样性 vs 质量：答案随规模翻转

这是 SFT 数据最核心的 tension：**千条级质量决定一切，十万条级多样性成为天花板。**
小数据阶段，一条坏样本的破坏力是占比级；到了十万条，覆盖分布的多样性决定模型学
到的指令空间形状，再提高单条质量边际收益递减。过滤组合按顺序：启发式规则 →
LLM judge 质量分 → 指令聚类去重、去近重复（控制题型分布）→ 长度截断。

### 6.2 Rejection sampling（RFT/BoN）：把 RL 信号前置成 SFT 资产

对同一 prompt 采 N 条 → verifier / reward / 单测过 filter → 只留「通过且多样」
的样本回灌 SFT。它同时干三件事：给 SFT 数据加了可验证质量的下界、给 RL 冷启动
一个好分布、副产品天然是 chosen/rejected 偏好对。Qwen3 报告明确走「long CoT
cold-start finetuning，然后 RL focusing on math/coding」这条线（Qwen3 官方，
2025）——rejection sampling 就是连接两段的那座桥。

### 6.3 偏好数据两条供给线

- **真人反馈**：长尾偏好真实，但贵、慢、标注一致性低；负责高风险域和对 judge 的
  周期校准。
- **AI feedback / RLAIF**：便宜几个数量级，但被 judge 偏置锁死——长度偏置、
  流利度偏置、judge 自亲和（同族模型生成加同族模型打分系统性推高自恋分）。

工业界混合姿态：AI 反馈负责量下限，真人抽检校准 judge，真人负责高风险域。DPO
时代的离线偏好对实际是「强模型产 chosen、弱模型产 rejected」构造，**成本等于
两次生成加一次打分**——这就是 distilabel（3.4k 星，2026-10 仍活跃）活着的原因。

## 七、数据评估：消融是唯一被信任的方式

1. **消融设计是唯一被信任的评估**。固定小模型、固定 token 预算、只换数据——
   Qwen 系内部口径是小模型（1.8B 级）、消融预算 27B token、对照组 350B；基准要
   满足「高信号三准则」：方差小、随训练单调上升、能区分已知优劣的数据。DCLM 把
   这套制度化了：模型、代码、评测全部固定，只比数据配方，53 个下游评测，候选池
   240T（官网口径；README 口径大于 300T）未过滤 CC token。成本锚一整行背下来：
   400M-1x 是 26、1B-1x 是 240、7B-1x 是 3,700、7B-2x 是 7,300 H100 小时
   （7B-2x 为 276B token、1.1e22 FLOPs，DCLM 官方）。效果锚：DCLM-BASELINE
   7B@2.6T MMLU 63.7、CORE 57.1（v1），接近 Llama3-8B 的 MMLU 66.2——后者用了
   15T 闭源数据。
2. **Perplexity 只对分布内（ID）数据可靠**。拿某数据集的 PPL 跨分布比较数据质量
   会系统性误导，别用。
3. **Data attribution / influence 函数是 debug 工具不是生产线**。定位「哪个样本
   害了这次 eval」很好用，但对 15T 全库做归因的开销远超重训，不是 pipeline 常规步。
4. **评测口径本身会漂移**。DCLM 在 2025-09 修了 CORE 评测 bug（v1 到 v2，57.1
   变 56.0），**新旧分数不可直接比**——自建 pipeline 必须 version pin 评测代码、
   结果存双口径，否则跨年结论全是空的。

## 八、工程 Infra：三档生态位与 GPU 打标

### 8.1 三档生态位（2026 已定型）

| 工具 | 星数（2026-10 实测） | 生态位 |
|---|---|---|
| datatrove（HF） | 3.4k | CommonCrawl 系公开数据的事实标准：pipeline block 抽象、Local/Slurm/Ray/HF Jobs 多 executor、低内存、completion marker 断点续跑 |
| Ray Data | 44k | 异构多源、与 GPU 训练同栈；DCLM 的 filter/去重/tokenize+shuffle 完整实现就是 Ray |
| Spark | 44k | 存量数仓出身，和 GPU 推理缝合最别扭 |

选型题别站队，论证生态位：CC 系公开数据用 datatrove；大厂异构多源选 Ray（因为
打标要 GPU）；数仓存量改造才是 Spark。

### 8.2 「清洗 pipeline 里嵌推理」是一等公民

GPU 打标环节，datatrove 的 InferenceRunner 原生支持 vLLM/SGLang/OpenAI 兼容
端点，带 sqlite 请求缓存去重、断块续写。设计上承认两件事实：打标钱比清洗钱贵
几个量级（6,000 H100 小时锚），**judge 版本必须冻结进数据版本号**——同一批数据
换个 judge 重打，等于换了一批数据。

### 8.3 文件格式与并行度

任务并行度等于文件数：**多个中等文件远好于单一大文件**，分桶输出的 shard 大小
本身就是调参项。前期把 10T 数据写成少数几个大文件，后期任何重跑、补跑、抽样都
要付整个 shard 的代价。「中等文件加完成标记」不是习惯，是省钱的架构决策。

## 九、工程议题八条

1. **激进过滤的「量」墙**：分类器砍九成在 1-3T 训练收益明确，10T 以上直接断粮；
   解法是替换信号源（集成分类、合成改写），不是放松阈值。
2. **抽取器是隐藏变量**：换抽取器后旧质量分数不可复用，消融入口要从抽取重跑。
3. **去重颗粒度三难**：全局 near-dup 最贵且不一定最优；doc-level MinHash 漏
   span 级抄袭；suffix array 精确但难分布式。落点：句级 exact 逐 dump 加
   doc-level MinHash 逐 dump 够用，span 级只在高价值子集做。
4. **LLM 打标成本惊吓**：全库打标不可能频繁重跑，标注 → 蒸馏小模型 → 批量扫描
   是唯一可支付路径。
5. **Judge 自亲和与飞轮退化**：同族生成加同族打分推高自恋分；止血靠跨族 judge、
   周期引入新真实数据、代际标签隔离。
6. **PII 合规最小可用线**：正则只稳 email/IP；要过 GDPR/个保法得 NER 级方案，
   合规深度和过滤成本同向涨。
7. **任务并行度不等于集群核数**：文件数决定并行度，写文件阶段就定死了后期成本
   曲线。
8. **评测口径会漂移**：version pin 加双口径存档，否则跨年对比全是伪结论。

## 十、▶ 面试题

**Q1（极高频）预训练数据你怎么配出 36T？**
浅层：静态百分比加几个高质源上采样。中层：课程式多阶段——Qwen3 的 30T 通用 →
5T 推理增强（配合 LR 加速衰减）→ 长上下文外推；为什么要先通用后专项：LR 末段喂
高密数据，等价于把最值钱的信息放在「记得最牢」的训练尾声。深层：配比怎么定——
小代理模型扎实例级标签做消融外推（DoReMi/RegMix 学术对应）；实例级优于数据源级，
因为源内异质、域间互相污染。

**Q2（极高频）MinHash 去重原理和参数怎么调？**
浅层：shingle（5-gram）→ 多哈希取 min 构成签名 → 签名估计 Jaccard → banded
LSH 建桶，只在同桶内精算。中层：band 数与每 band 行数控制阈值曲线——band 越多
阈值越高、漏检越高；RedPajama-V2 一次算 128 hash 导出 0.7/0.8/0.9/1.0 四档签名
存成元数据列。深层：百亿级分布式——LSH 内存墙（polars 单机 64 核/500GB 只敢压
2 亿文档）决定分桶自治；FineWeb 逐 dump 去重反而胜过全局去重，因为全局保留最旧
副本；DCLM 用 Rust BFF 替代 MinHash，说明瓶颈在吞吐不在精度。

**Q3（高频）fastText 质量分类器和 LLM judge 差在哪？**
浅层：成本与能力代差。中层：FineWeb-Edu 范式三段——Llama-3-70B 标 50 万条 →
蒸馏 BERT 回归器（F1 约 82%）→ 扫全库；成本结构是打标一次约 6,000 H100 小时级，
所以全库打标不可能频繁重跑，judge prompt 冻结进数据版本号。深层：阈值 3 与 2 在
MMLU/ARC 与 HellaSwag/PIQA 之间的 trade-off，说明「质量」不是单一标量，阈值选得
是评测族而不是「质量」。

**Q4（高频）激进过滤一定好吗？**
2025 后的反转口径：Nemotron-CC 全量数据唯一真实 token 是 DCLM 的 4 倍，8B@15T
反超 Llama3.1-8B。直觉结论：**过滤强度大约与训练 token 预算成反比**——预算越长
越需要量，信号源要换成集成分类与合成改写，而不是放松阈值。能说出这个函数形状就
是高分。

**Q5（高频）合成数据会不会让模型越训越差？**
浅层：model collapse。中层：塌缩成立三前提——纯合成闭环、多代迭代、无新真实
数据；Magpie 300K 追平 10M 官方数据说明瓶颈在 teacher 和筛选，不在数量；改写式
（rephrasing）保留真实分布形状是安全折中。深层：数据飞轮每转一圈旧数据变负债，
重新筛的成本要靠多维标注系统摊薄。

**Q6（中高）设计一次数据消融要多少钱、怎么做才可信？**
浅层：固定模型与预算、只换数据。中层：高信号三准则——低方差、单调、区分度；
DCLM 成本表当锚（1B-1x 是 240 H100 小时）。深层：评测口径漂移的元问题（CORE
v1 到 v2），version pin 加双口径存档。

**Q7（中高）SFT 数据多样性 vs 质量怎么权衡？**
浅层：质量优先。中层：答案随规模翻转——千条级质量决定一切，十万条级多样性定
天花板；指令聚类控制题型分布。深层：rejection sampling 把 RL 信号成本前置成
SFT 数据资产，chosen/rejected 副产品同时喂 DPO。

**Q8（中）PB 级 pipeline 选 Ray 还是 Spark？**
考点不是站队是生态位论证：CC 系公开数据 datatrove；异构多源、要嵌 GPU 打标选
Ray；数仓存量选 Spark。能补 LSH 内存墙与文件分片调优（并行度等于文件数）的，
区分「做过」和「背过」。

## 口径与未核实说明

- 常见但未亲自核实的数字（引用前建议自核）：Self-Instruct 52K、Evol-Instruct
  70K、LIMA 1,000、Deita 6-10K、UltraFeedback 64K、Nectar 183K、The Stack v2
  约 900B/67.5TB、SlimPajama 627B。
- 口径冲突并存：DCLM 候选池官网 240T 与 README 大于 300T 并存；FineWeb 15T
  （v1.0）与 18.5T/50.4TB parquet（v1.4，2025-07）并存；DCLM CORE v1 与 v2
  分数不可直接比。
- 社区/自媒体口径未当事实用：网传各家「代码占比 20-30%」「中文多语言配比表」
  均无官方技术报告背书，一律未引。
- 成本数字均为官方自称口径（6,000 H100 小时、7,300 H100 小时、2.788M H800
  小时），不含失败重试与外围实验，实际预算按 1.5-3 倍打。
- GitHub star 数为 2026-10-11 实测快照（datatrove 3,379、Ray 44,005、Spark
  44,165、fastText 26,524、DCLM 1,475、Dolma 1,557、OLMo 6,698、distilabel
  3,416、Magpie 887），半年后引用建议重跑。
