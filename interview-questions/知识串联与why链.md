## 〇、答题方法：一点的答案在上下游

任何一个知识点被问到，标准动作是向链上各走一步：
**上游 = 它为什么存在，下游 = 它逼出了什么问题**。比如被问
"什么是投机解码"，及格答案是"draft 小模型猜、大模型验证"，
优秀答案是"它存在是因为 decode 是访存瓶颈（上游）；它逼出的
问题是接受率、draft 显存、和 prefix cache 的互斥（下游）"。
下面五条链，就是你上下游的各个站。

## 链 A · 推理成本：一切从"decode 是访存瓶颈"开始

| 面试官追问 | 因为 | 所以工程上 | 深入文档 |
|---|---|---|---|
| decode 为什么比 prefill 慢？ | 每个 token 要读全部权重，算术强度极低 → memory-bound | 提算术强度是唯一出路 | [vLLM 与推理加速核心](./inference/vllm与推理加速核心.md) |
| 为什么要 KV Cache？ | 不缓存则每步重算历史 K/V，O(n²) 变 O(n³) | 用显存换计算 → KV 本身成新瓶颈 | [长上下文与 KV 体系](./inference/长上下文推理与kv体系.md) |
| KV 太大怎么办？ | 显存=单价×并发×上下文−前缀去重 | GQA/MLA 压单价、prefix cache 去重、分级存储 | [显存计算专题](./显存计算专题.md) |
| 为什么要连续批处理？ | memory-bound 时 batch 越大算术强度越高 | 不 padding、滚动进出 → 吞吐翻倍 | 同上 |
| 为什么还要 PD 分离？ | prefill 是算力活、decode 是访存活，混部互相干扰 SLO | 拆角色、按 TTFT/TPOT 分别定容 | [推理服务 SLO 与运营](./inference/推理服务slo与运营.md) |
| 为什么还要投机解码/量化？ | 串行 decode 一个头只有一条流水线；权重每步全读 | 小 draft 猜+大模型并行验；INT8/FP8 砍带宽 | [量化与压缩](./inference/量化与压缩.md) |

**链尾收口**：链 A 的所有方案都在 trade 同一样东西——用额外显存、
额外计算或精度损失换"少读几遍权重"。面试时把这一句放在段首，
后面的方案全是它的展开。

## 链 B · 长上下文与结构：一切的根是 attention 的 O(n²)

| 追问 | 因为 | 所以 | 文档 |
|---|---|---|---|
| 上下文加长为什么贵？ | attention 分数矩阵 n×n，KV 随 n 线性涨 | 计算与显存双杀 | [Transformer 与 Attention](./llm基础/transformer与attention.md) |
| 为什么 GQA/MLA 有效？ | KV 头数远小于 Q 头数不损质量；MLA 把 KV 压成低秩 | 显存单价降一个量级 | 同上 |
| 为什么还要稀疏/线性注意力？ | KV 压缩有下限，n 还在涨 | NSA/MoBA 稀疏化、Mamba/线性递推压成 O(n) | 同上（降成本一节） |
| 为什么 hybrid 成主流？ | 纯线性层在精确检索上稳定掉点 | 大部分层省算力+少数全注意力层兜精度 | 同上 |
| 既然能百万上下文，为什么还要 RAG？ | 长上下文成本高、海量知识塞不进参数 | 检索显式注入+引用可追溯 | [RAG 全链路](./rag/rag全链路.md) |

**链尾收口**：B 链给 A 链提供了"KV 单价"这个旋钮——两个模块
在显存公式上会师；B 链的终点（RAG）正是应用模块的起点。

## 链 C · 训练：一切的根是"训练显存 = 参数量 × 16 字节"

| 追问 | 因为 | 所以 | 文档 |
|---|---|---|---|
| 为什么单卡训不动？ | AdamW 每参数 16B（权重+梯度+主权重+m+v） | 7B 全参就 112GB+ | [LLM 基础模块导读](./llm基础/README.md) |
| 为什么 ZeRO？ | 同一份状态被每张卡冗余存一遍 | 参数/梯度/优化器分片，通信换显存 | [ZeRO 与显存优化](./distributed-training/zero与显存优化.md) |
| 为什么还要 3D 并行？ | 显存分片到头后，算力也要分 | TP 切张量 / PP 切层 / DP 切数据 | [三维并行](./distributed-training/三维并行.md) |
| 为什么通信决定扩展效率？ | TP 逐层 allreduce、EP 逐层 all-to-all，弱网就饿死算力 | 拓扑感知、通信计算重叠、NCCL 调优 | [训练框架与稳定性](./distributed-training/训练框架与稳定性.md) |
| 为什么 MoE 让通信更难？ | 专家散落多卡，token 要跨卡路由 | EP + EPLB 负载均衡；深链到推理侧 EP | [MoE 架构](./llm基础/moe架构.md) |
| 为什么数据/配比要工程化？ | Scaling 里 D 的质量与配比是独立变量 | 六步流水线+退火段高质量 | [数据工程专题](./训练与对齐/数据工程专题.md) |

**链尾收口**：C 链与 A 链是同一枚硬币——训练守"通信换显存"，
推理守"显存换算力"；[负载均衡专题](./负载均衡专题.md) 的六层
地图把两端的均衡问题统一了起来。

## 链 D · Agent 上下文：一切的根是"上下文是唯一的工作记忆"

| 追问 | 因为 | 所以 | 文档 |
|---|---|---|---|
| 为什么需要工具调用？ | 模型只有文本没有行动 | schema 注入+协议化返回 | [工具调用与 MCP](./agent/工具调用与mcp.md) |
| 为什么还要 MCP？ | 每工具一套私有集成无法生态化 | 标准协议换供应商中立；代价是权限与投毒面 | [MCP vs 工具调用深度对比](./agent/mcp与工具调用深度对比.md) |
| 为什么上下文要"工程化"？ | token 贵+注意力稀释+硬上限 | 一切都是消息；分层预算 | [记忆与上下文工程](./agent/记忆与上下文工程.md) |
| 为什么压缩会影响推理成本？ | compaction 重写前缀 → prefix cache 命中归零 | 压缩策略同时是 token 账与延迟账 | 同上（§3.6） |
| 为什么要分层披露 skill？ | 全量工具 schema 常驻烧预算 | 索引常驻/命中读正文/脚本只回输出 | [Agent Skills 详解](./agent/agent-skills详解.md) |
| 为什么安全是系统问题？ | LLM 词元层不区分指令与数据 | 最小权限+外泄信道控制+HITL | [Agent 安全与防护](./agent/agent安全与防护.md) |
| 为什么需要 trace/eval？ | 不确定系统无回归测试 | 确定性回放+span 归因 | [Harness 工程实战](./agent/harness工程实战.md) |

**链尾收口**：D 链的每个"压缩/注入"决策都最终落到 A 链
（token 账本）与 B 链（注意力稀释）——**Agent 工程本质是
推理成本工程 + 信息管理工程的乘积**。

## 链 E · 能力来源：一切的根是"loss 随变量走幂律"

| 追问 | 因为 | 所以 | 文档 |
|---|---|---|---|
| 为什么越训越大有效？ | L=E+A/N^α+B/D^β，长尾难样本逐档被削 | 预算可外推分配 | [Scaling Law 与范式迁移](./训练与对齐/scaling-law与范式迁移.md) |
| 为什么配比 D≈20N？ | 同算力下"大模型欠喂"劣于"小模型喂饱" | Chinchilla 翻案 | 同上 |
| 为什么喊数据墙？ | 按 20N 外推，自然文本 10-30T 见底 | 合成数据+质量过滤+配比课 | [数据工程专题](./训练与对齐/数据工程专题.md) |
| 为什么转向 RL？ | 预训练便宜变量见顶 | RLVR 独立 scaling 曲线、o1/R1 范式 | [RLHF 与对齐](./训练与对齐/rlhf与对齐.md) |
| 为什么 test-time compute 接棒？ | 不训练：让模型多想也涨能力 | 思考链变长 → 推理成本陡增 | [决策模型与 Jev](./agent/决策模型与jev.md) 等 |
| 为什么 RSI 引人注目？ | 若模型能改进生产下一代模型的环节，曲线自我加速 | DGM/AlphaEvolve 只到"改脚手架"层 | [RSI 递归自我改进](./agent/rsi自我改进.md) |

**链尾收口（关键闭环）**：E 链的终点「思考 token 变多」一头
扎回 A 链「推理成本」——**能力范式的每一次迁移，最后都是
推理引擎的一次新需求**。这就是"训练的人要懂推理、推理的人要
懂训练"的真正原因。

## 三条贯穿主线（把五条链再压缩成三句话）

1. **成本守恒**：显存、算力、通信、精度，只能互换，不能白拿。
   A 链换显存、C 链换通信、B 链换精度、D 链换 token——
   所有优化都在这个三角里选边。
2. **信息守恒**：能力没有免费来源。参数记忆（训练）、外部检索
   （RAG）、上下文注入（prompt/工具返回）三条通道互相替代，
   选谁取决于"这条信息用几次、要不要可追溯"。
3. **信任守恒**：自动化每多一分，确认、权限、审计就要补一分。
   Agent 的工具自由度与安全预算永远同增减（D 链），训练数据
   的"省事"也要用去污染和评测审计找回来（C/E 链）。

## 自测玩法

随机抽链上任一点，限时 60 秒说出：它的上游（为什么存在）、
下游（逼出什么）、以及与另外四条链的一个交叉点。说不出
交叉点的那条链，就是你下一轮复习的主页。
