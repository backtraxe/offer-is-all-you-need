## 一、直觉一句话：端侧的天花板是带宽，不是算力

手机跑 LLM，和新干线过乡间小路是一个道理。数据中心 H100 级 GPU 有 3 TB/s
级 HBM，到端侧全部换成 LPDDR：手机 SoC 统一内存架构下，CPU/GPU/NPU 共享
一条几十 GB/s 的总线。真问题被放大了一个数量级。

为什么是带宽而不是算力？LLM decode 是自回归的：**每吐一个 token，都必须
把整份模型权重从内存完整读一遍**。于是有数学下限：

```
decode tok/s ≈ 内存带宽 ÷ 模型权重字节数
```

口算两个常考题：

- **iPhone 16（A18，带宽 60 GB/s，官方 spec 表 2024）** 跑 3B 的 Q4_K_M
  （≈1.8 GB），理论上限约 **三十 tok/s**，实际落地 **八到十五 tok/s**
  （推导值，非受控实测）；
- **M4（带宽 120 GB/s）** 跑 8B 的 Q4_K_M（4.92 GB），理论上限约
  **二十四 tok/s**——这一个式子就解释了「Mac mini 跑 8B 尚可、手机跑
  7B 普遍难受」。

对照带宽供给端：Android 旗舰 LPDDR5X-8533 在 64-bit 总线下约 **六十八 GB
每秒**（JEDEC 标准推导，2021–2024）；三星为天玑 9400 验证的
LPDDR5X-10700 到约 **八十五 GB/s**（Samsung newsroom 2024-07）；LPDDR6
规范 JESD209-6 已发布，**速率 10.6–14.4 Gbps/pin**，2027 年起旗舰搭载（JEDEC
官方 2025-07）。带宽在涨，但一年一代的斜率远慢于模型能力发育的斜率——
**端侧 decode 天然是个位数到两位数 tok/s 的游戏**，这个判断 2027 年前不
会变。

## 二、硬件面：TOPS 与带宽的真实分工

### 2.1 40 TOPS 是产品认证线，不是工程线

2024-05 微软给 Copilot+ PC 定的门槛是 **NPU 不低于四十 TOPS**（官方），
芯片厂立刻把它变成营销三件套：

| 平台 | NPU 算力 | 口径 |
|---|---|---|
| Snapdragon X Elite | 45 TOPS | 高通官方博客 2024-06 |
| Core Ultra 200V | 48 TOPS | 媒体汇总多源一致 2024 |
| Ryzen AI 300 | 50 TOPS | 媒体汇总多源一致 2024 |
| Apple M4 / A18 | 38 TOPS | Apple Newsroom 经 Wikipedia，官方 2024 |
| Dimensity 9500 | ≈100 TOPS | 媒体含 Counterpoint 分析师 2025-09，**官方未公布精确值** |
| Snapdragon 8 Elite Gen 5 | 官方不再公布 TOPS，仅称同比 +37% | 官方口径转述 |

注意两个信号：一是联发科、高通先后**停止公布 TOPS 精确值**；二是
2026-09 微软开始收窄 Copilot+ PC 品牌（官方措辞收窄为「简化/重定位 AI
负载」，「弃用品牌」是媒体归纳口径，Windows Central / PCWorld 2026-09）。
「端侧 NPU 卖 PC」的叙事**没有兑现为杀手级应用**——这是面试里产品判断题
的核心证据（见第七节 Q8）。

### 2.2 TOPS 的真实分工：NPU 吃 prefill，GPU 吃 decode，CPU 兜底

prefill 是大矩阵乘，compute-bound，NPU 的 40–100 TOPS INT8 有用武之地；
decode 是 bandwidth-bound，batch=1 时计算密度极低，NPU 常因利用率低、
SDK 对新模型架构支持滞后而**反而不如同 SoC 上的 GPU**。现实格局：

- 高通手机上主流是 **llama.cpp 的 OpenCL/Adreno 后端或 QNN 后端**；
- iOS 上是 **Metal / Core ML** 栈；
- 「NPU 全链路跑 LLM」只在厂商系统级功能里真正落地（Apple
  Intelligence、Galaxy AI、Gemini Nano），第三方 App 基本摸不到。

带宽侧的另一个锚：A18 带宽只有 **60 GB/s 封顶**，而 M4 Pro 273、M4 Max
546 GB/s（Apple 官方 2024）——同一家芯片，手机与桌面差近一个数量级，这正是
「端侧」和「工作站本地」要分开讨论的原因。

## 三、模型侧：不是「小 7B」，是「够用 3B」

2025–2026 端侧主力尺寸收敛到 0.5B–8B，且**有效尺寸还在变小**：

- **Apple 官方端侧模型只有约 3B，且 2-bit 量化**（WWDC25 官方视频原话
  「each quantized to 2 bits」），iOS 26 起通过 Foundation Models
  framework 开放给第三方 App（Apple Newsroom 2025-09）；
- **Gemma 3n** 用 PLE（Per-Layer Embedding，内存外置）把 5B/8B 参数的
  动态内存压到 **2 GB / 3 GB**（E2B/E4B），首 token 比 Gemma 3 4B 快约
  1.5×（Google Developers Blog 2025-05，**官方宣称**）；
- **LFM2**（350M/700M/1.2B，10T tokens，2025-07）CPU 上 decode/prefill
  比 Qwen3、Gemma 3 快 2×（liquid.ai，**官方宣称**）；
- **SmolLM3-3B**（11.2T tokens，GQA+NoPE，64k 上下文，BFCL 92.3，HF
  官方模型卡 2025-07）证明 3B 档 tool calling 够用；
- **Qwen3 端侧档** 0.6B/1.7B/4B（另有 8B/14B/32B 与 MoE 30B-A3B，
  Apache 2.0，2025-04；2026-04 续出 Qwen3.6-35B-A3B）。

口诀：**端侧不是「小 7B」，是「够用 3B」这个新共识**。1–4B 在 tool calling、
summarization、改写、分类路由这些端侧真实负载上已经够用，剩下的交给云。

架构层的减法有三条已验证路线：

1. **PLE / 内存外置**（Gemma 3n）：参数名义上 5B/8B，热路径只占 2/3 GB；
2. **MatFormer 嵌套子模型**：一个 4B 内嵌一个 2B，按设备档位动态切片，
   不用存两份权重；
3. **混合架构**（LFM2）：门控短卷积 + 少量 GQA attention，KV cache 和
   计算同时降。

KV cache 在 1–4B 档叠了 GQA 之后不算大，但 32k+ 长上下文仍然是数百 MB
级，端侧同样需要 KV 量化（q8_0/q4_0）、滑动窗口、截断+摘要这套组合拳
（细算口径见 [显存计算专题](./显存计算专题.md)）。

## 四、量化：端侧的第一性优化

带宽是瓶颈，那么**把每个权重读的字节数砍半，decode 就近似翻倍**——这就是
量化在端侧是一等公民的原因（前提：反量化算子别吃掉收益）。

GGUF 档位是质量/体积/内存的三维权衡，8B 模型实测文件体积（bartowski
HF 卡，imatrix，Llama-3-8B，2026-10 页面实测）：

| 档位 | 体积 | 备注 |
|---|---|---|
| Q8_0 | 8.54 GB | 接近无损 |
| Q6_K | 6.59 GB | |
| Q5_K_M | 5.73 GB | |
| **Q4_K_M** | **4.92 GB（≈4.83 bpw）** | **社区默认甜点**：带宽占用减半，ppl 失真基本不可感知 |
| Q3_K_M | 4.01 GB | 引用性/数学任务可见退化 |
| Q2_K | 3.17 GB | 靠 imatrix 补救 |
| IQ2_XXS | 2.39 GB | 「surprisingly usable」（卡内原文），只适合验收宽松场景 |

工作点经验：主流是 **W4A16 这个端侧 GPU/NPU 工作点**；W8A8 只在 NPU 原生
INT8 路径才划算。KV cache 量化与权重量化**正交，通常一起开**。

失真评测要跑自家下游任务集，别只信 perplexity——**它对工具调用的 JSON
格式错误几乎不敏感**，ppl 增量不到 0.05 也可能功能性退化（数学链路断裂、
function call 格式漂移）。

与社区方案的对比是高频追问：Apple 的 2-bit 靠**训练感知**（蒸馏+低比特
微调/QAT，校准在训练时介入，见 Apple 官方论文 arXiv 2407.21075 /
2507.13575，adapter-per-feature 架构）；社区 IQ2 靠 **imatrix 重要性加权
的离线量化**。一个是训练时就把低比特纳入目标，一个是后训练补救——失真
控制差半个档位。

## 五、框架对决：选型 = 选阵营

2026 年生态收敛成两层，跨平台统一栈**依然不存在**：

| 层 | 玩家 | 数字锚（gh api 实测，2026-10） | 定位 |
|---|---|---|---|
| 底层引擎 | llama.cpp | 130,814 star，v0.6.0（2026-10-05） | 事实标准 CPU/GPU 引擎 + GGUF 格式 |
| 体验层 | ollama | 182,739 star，v0.40.3 | 统治 PC 体验层 |
| 编译式 | MLC-LLM | 23,229 star，**无正式 release**（滚动 main） | 性能好，接入新模型成本高 |
| Meta 系 | ExecuTorch | 5,088 star，v1.5.1（2026-09-23） | Qualcomm/MediaTek 后端在位 |
| Google 系 | MediaPipe / AI Edge Gallery / LiteRT | 37,227 / 24,915 / 3,485 star | Android 系统级路径 |
| Apple 系 | Core ML + Foundation Models | iOS 26 开放 3B 端侧模型 | 模型随 OS 更新，零下载零 API key |
| 国内 | MNN（阿里） | 16.2k star | Android 装机量实际更大，生态封闭感 |

权衡轴四条：**覆盖度**（llama.cpp 兜底，迭代最快但 NPU 支持弱）vs
**峰值性能**（平台私有栈 + NPU 后端）vs **新模型接入成本**（编译式慢于
JIT 式，MLC 无正式 release 版本号勿引用）vs **二进制体积与合规**。

结论话术：现实组合是 **llama.cpp 兜底 + 平台私有栈提速（Core ML /
MediaPipe / QNN），这是 2025–2026 的通行做法**。统一栈 2026 年仍未出现的原因是 NPU 私有
runtime 碎片化 + 算子支持滞后——每个厂商的 NPU SDK 都是半封闭花园。

浏览器/WebGPU 路线（web-llm 19.3k star、transformers.js 16.3k star）仍然
是 **demo 经济，不是产品路径**：WASM 无原生 int4 MAC、tab 内存硬上限、
WebGPU 驱动碎片化，实际能流畅跑的只有 **3B 以下 + 短上下文**。价值在零
安装 demo 和隐私叙事。

## 六、端云协同：形态终局，不是妥协

### 6.1 Apple 蓝图是事实标杆

2024 WWDC → 2026 三代模型走通的双层架构：**本地约 3B（2-bit）处理默认
请求 + 按请求分级路由到 PCC（Private Cloud Compute）**。PCC 的隐私是可
验证的：无状态（请求不落盘）、可审计镜像、硬件 attestation。开发者视角
是统一 API，路由由系统做。这与数据中心 PD 分离是同构思想：重计算且
不敏感的部分卸载，延迟敏感、隐私敏感的留本地。国内 Apple Intelligence
据报道接入本地版 Qwen（CNBC/Reuters 多条报道指向 2026-07，**部署细节未
官方确认**）。

### 6.2 路由三判据

哪些请求留本地？三个判据：

1. **隐私敏感度**：PII 不出设备，健康/财务/通讯数据本地优先；
2. **离线/延迟需求**：机上、弱网、实时交互（语音转写）必须本地能扛；
3. **成本结构**：端侧 token 边际成本为零但有能力上限，云端按量付费但
   能力无顶。

路由器实现两派：约 1B 分类器判断复杂度/敏感度，或规则+能力声明。工程上
常见混合：规则兜底 + 小模型打分。

### 6.3 Speculative decoding 在端侧反而更值

带宽瓶颈下，小模型 draft + 大模型 verify 能**摊薄每 token 的权重读取次
数**；且端侧 GPU 常跑不满带宽，额外计算成本近似免费。反驳点也成立：双
模型常驻内存与端侧内存稀缺矛盾——Medusa/EAGLE 类「单模型多头」是折衷
方案（加餐背景见 [蒸馏与剪枝专题](./蒸馏与剪枝专题.md) 与推理侧专题）。

## 七、工程坑：七个会咬人的细节

1. **发热降频是端侧性能第一杀手**：手机 SoC 持续 decode 数十秒就触发热
   墙，同设备跑分差可达 **三成以上**（社区实测口径，未做系统性实测核
   实）。对策：长生成拆 chunk、throttle 检测动态降 draft 长度、散热不
   良机型黑名单。金句：**端侧 SLO 不是 TTFT/TPOT，是 sustained
   perf/W（持续性能每瓦）**。
2. **电量与后台保活决定功能形态**：iOS 后台任务受限（LocalLLM 类 App
   退后台即停，社区通行认知），Android 要 foreground service 常驻。这
   是「离线端侧 Agent」难产品化的隐性原因。配套要求：生成中断/断点续
   跑（KV cache 落盘）。
3. **模型下载与更新是真基建问题**：2–4 GB 模型过不了应用商店体积限制。
   通行做法是首启按需下载 + CDN 分块 + 断点续传 + 完整性校验。最优雅的
   是 Apple Foundation Models：模型随 OS 更新、第三方零下载零 API
   key——代价是锁在约 3B 能力和平台节奏上。
4. **网页端就是 demo**：价值在获客与隐私叙事，别按产品路径做架构。
5. **端侧与嵌入式不是同一个问题**：嵌入式 RAM 只有几百 MB——要么 1B
   以下（Gemma 3n E2B、LFM2-350M），要么 4 bit 以下 + mmap 按页加载
   （llama.cpp 的 mmap 是关键特性）。车载/IoT 的主流答案是「端侧小模
   型做唤醒和路由 + 云上大模型」。
6. **跨平台成本没有银弹**：每接一个平台私有栈，就是一份独立的模型转
   换、算子对齐、回归测试成本。
7. **量化失真按任务分层**：Q4_K_M 甜点、Q3_K 引用/数学退化、Q2 只适合
   宽松验收——验收集必须含自家真实负载，不能只跑 ppl。

## 八、▶ 面试题（带频率标注）

**Q1（极高频）为什么手机 NPU 50 TOPS 跑不动 8B LLM？**
拆 roofline 的 compute-bound 与 memory-bound 两侧：decode batch=1 计算
密度极低，tok/s ≈ 带宽 ÷ 权重字节数，50 TOPS 只加速 prefill。加分项：
区分「NPU 利用率」与「NPU 峰值」，指出 batch=1 下 NPU 利用率常常极低。

**Q2（高频）GGUF 的 Q4_K_M 是怎么量出来的？Q4_K 和 Q4_0 本质区别？**
superblock 结构 + 组内 scale（FP16 二级量化）；K 量化随层重要性混合位
宽，所以 Q4_K_M ≈ 4.83 bpw 不是纯 4 bit。督问情景：给 8B 模型与 68 GB/s
带宽估 Q4_K_M 理论 decode 上限——考「体积数字（4.92 GB 实测）+ 带宽公
式」的工程直觉（约 14 tok/s）。

**Q3（极高频）设计端云协同路由系统：哪些请求留在本地？**
三判据：隐私敏感度（PII 本地）、离线/延迟需求、成本（端侧边际成本为零
但能力有上限）。深问路由器实现：约 1B 分类器 vs 规则+能力声明；以
Apple on-device + PCC 为参照系，追 PCC 如何做到可验证隐私（无状态、可
审计镜像、硬件 attestation）。

**Q4（高频）端侧 KV cache 长上下文爆了怎么办？**
KV 量化（q8_0 → q4_0）、滑动窗口、截断+摘要、cache-type-k/v 配置。深一
步：PagedAttention 在端侧收益是否成立——端侧几乎无并发，continuous
batching 的边际收益小，与 DC 视角对照着答很出彩（对照
[inference/vllm与推理加速核心](./inference/vllm与推理加速核心.md)）。

**Q5（高频）App 选型推理框架：llama.cpp / MLC / ExecuTorch / Core ML 怎
么权衡？**
四轴：覆盖度（llama.cpp 兜底）、峰值性能（私有栈 + NPU 后端）、新模型
接入成本（编译式慢于 JIT 式）、二进制体积与合规。追问：为什么统一跨平
台栈 2026 仍未出现（NPU 私有 runtime 碎片化 + 算子支持滞后）。

**Q6（中频）2-bit 量化（Apple 3B）失真怎么压回去？和社区 IQ2 有什么不
同？**
社区 IQ2_XXS 靠 imatrix 重要性加权；Apple 是训练感知：蒸馏 + 低比特微
调/QAT，校准在训练时介入。追：为什么 perplexity 不能说明任务失真
（tool calling JSON 错误率、数学链路断裂，ppl 增量 <0.05 也可能功能性
退化）。

**Q7（中频）端侧 speculative decoding 比在数据中心更划算，论证或反驳。**
论证：端侧 GPU 带宽常不饱和，draft+verify 额外计算近乎免费，摊薄每
token 权重读取次数。反驳：双模型常驻内存与端侧内存稀缺矛盾，Medusa/
EAGLE 单模型多头是折衷。

**Q8（中频）AI 手机换机潮为什么到 2026 年没兑现？**
产品判断题。Copilot+ PC 品牌收窄是标志性证据；驱动因素：40–100 TOPS
营销 vs 60–68 GB/s 工程现实、系统级 AI 挤压第三方空间、端侧能力距生成
质量场景有差距。深问：什么时候出现真杀手级——**隐私敏感 + 高频低延迟 +
云上做不起的交集**：实时语音转写（参见
[语音与voice-agent专题](./语音与voice-agent专题.md)）、无障碍辅助、本
地知识库粗筛层。

## 九、口径与未核实说明

- 手机端 tok/s 实测区间（iPhone 约 8–15、Mac M4 约 15–24）为**推导值**
  （带宽/体积公式），无受控条件系统性实测；对外只说「个位数到两位数」
  或反推理论上限。
- Dimensity 9500 ≈100 TOPS：官方未公布精确值，第三方口径；Snapdragon 8
  Elite Gen 5 官方不披露 TOPS 仅称 +37%（自媒体「80 TOPS」来源存疑，
  已弃用）。
- 「iOS 退后台即停」「tab 内存 2–4 GB 上限」为社区通行认知，未取第一
  手条款。
- MLC-LLM：GitHub 无正式 release、PyPI 状态未查到，**版本号勿引用**。
- Copilot+ PC 弃用：官方措辞收窄为「简化/重定位 AI 负载」，「彻底弃用
  品牌」是媒体归纳口径。
- Apple 中国区 Apple Intelligence 集成 Qwen：CNBC/Reuters 2026 多条报
  道指向 2026-07，部署细节（端侧 vs PCC 范围、区域限定）未官方确认。
- Apple 端侧 3B 2-bit：WWDC25 官方视频原话「each quantized to 2
  bits」；训练工艺细节来自 Apple 官方论文但未逐页重读核实。
- 天玑 9400 的 LPDDR5X-10700（≈85 GB/s）与 LPDDR6 时间表分别为三星
  newsroom 与 JEDEC 官方口径；68 GB/s 为 JEDEC 标准推导值。
- Gemma 3n「1.5× 首 token」、LFM2「CPU 2×」均为**厂商官方宣称**，引
  用须显式标注。
- 发热降频「跑分差 30%+」为社区实测口径，未做系统性实测核实。
