## 一、直觉一句话

**蒸馏是把大模型「已经会的东西」搬运进小模型，剪枝是把超配的参数砍回够用。**
两者回答的问题不同：蒸馏决定「模型是谁」（能力上限），剪枝与量化决定
「部署多便宜」（结构与数值保真）。2026 年的工业默认生产线是「蒸馏 + 量化」
组合拳：剪枝没有消失，但它的主流形态收缩到了 2:4 半结构化与非生成场景，
纯剪枝交付主力生成服务的案例几乎没有。搞清楚「每条线解决什么问题、数字
边界在哪」，就是这一篇要交付的东西。

## 二、蒸馏四层谱系：信号由稀到密

把 2023 年以来的 KD 工作按「teacher 给学生多少信号」排一个轴，就是四层
谱系。面试里被问「蒸馏有哪些做法」，按这个轴答就不会乱。

### 2.1 响应级 / 序列级 KD（SeqKD）：信号最稀，2025 后的事实标准

只拿 teacher 采样出的最终文本（含 CoT）当 SFT 语料，student 做普通监督
微调。DeepSeek-R1 的六档蒸馏全是这个路子（800k 样本，官方口径）。

- 优点：黑盒可用（只要 teacher 能采样）、数据可离线生产、跨机构可复现；
  训练侧就是标准 SFT，不需要碰训练框架。
- 缺点：信号最稀——每个 token 只学到「teacher 最终选了什么」，学不到
  「teacher 在其他候选上给多少概率」；容易学风格不学知识（见 §6.2）。

### 2.2 logit KD（白盒）：逐 token 对齐完整分布

经典做法是对齐 teacher 与 student 的完整 next-token 分布，前向 KL
（forward KL）是默认目标。MiniLLM（arXiv:2306.08543，ICLR 2024）指出
forward KL 是 mass-covering 的：学生被迫给 teacher 的低概率区也分配概率
质量，表现在生成上就是偶尔蹦胡话；换成 reverse KL（mode-seeking）更稳。
但 reverse KL 的期望在学生分布上取，必须让学生先自己采样轨迹——**数学上
就直接导出了 on-policy 蒸馏**（§3.4）。Thinking Machines（下称 TM）的
复现博客选的就是 per-token reverse KL，卖点三条：KL 不可 hack、
mode-seeking、缓解 exposure bias。

### 2.3 feature / hidden KD：LLM 时代基本退场

对齐中间层 hidden state / attention map，是 BERT 时代的传统（PKD、
TinyBERT 一脉）。LLM 时代很少主创：老师学生各层宽度不一样对不齐，
对齐层的选取也没有共识，工业界收敛成「只对 logits」。面试被问到能说出
「为什么 feature KD 在 LLM 上不火」就算到位。

### 2.4 self-distill 与 cross-tokenizer：一端已实用，一端还是前沿

- **自蒸馏（self-distill）**：拿自己的老 checkpoint 当 teacher，恢复被后续训练
  （通常是 RL）训丢的行为。TM 的 personalization 实验是硬数字：模型经
  RL 后 IF-eval 从 83% 掉到 45%，用老 checkpoint 自蒸馏蒸回 83%。
  这是「蒸馏不只是压缩工具，还是行为修复工具」的证据。
- **跨 tokenizer（cross-tokenizer）**：真前沿。师生 tokenizer 不同，logit 维度和语义都对
  不上，研究线有 OT 对齐（2024-12）、byte-level（2026-04）、likelihood
  marginalization（2026-07），均未收敛成工业标准。工程回避方案两条：
  同家族师生（Qwen 蒸 Qwen、Llama 蒸 Llama），或者干脆只做 trajectory
  SFT（SeqKD 天然跟 tokenizer 无关）。

## 三、2025-2026 事实线：R1 谱系与 on-policy 蒸馏

### 3.1 R1 六档蒸馏：官方把「蒸馏胜过从头 RL」写进了论文

2025-01-20 前后 DeepSeek 发布 R1 / R1-Zero 与六档蒸馏模型
（arXiv:2501.12948；2025-09 登 Nature 645 期）。六档底座：
Qwen2.5-Math-1.5B / 7B、Llama-3.1-8B、Qwen2.5-14B / 32B、
Llama-3.3-70B-Instruct，全部用 R1 采样 **800k 样本**做 SFT（官方原话
finetuned with 800k samples curated with DeepSeek-R1）。

官方 README 原话（面试可直接引用）：reasoning patterns of larger models
can be distilled into smaller models, resulting in better performance
compared to RL on small models。配套的对照数字（官方表，2025-01）：

| 模型 | AIME24 pass@1 | 备注 |
|---|---|---|
| R1-Distill-Qwen-1.5B | 28.9 | 小档收益递减，蒸不动就是蒸不动 |
| R1-Distill-Qwen-7B | 55.5 | MATH-500 92.8 / GPQA 49.1 / LiveCodeBench 37.6 / Codeforces 1189 |
| R1-Distill-Qwen-32B | 72.6 | 反超 o1-mini |
| R1-Distill-70B（Llama-3.3） | 70.0 | 六档顶点 |
| QwQ-32B-Preview（对照） | 44.0 | 同为 32B 量级、从头 RL 路线 |

论文 Section 2.3.2 明说：基于 Qwen2.5-32B 从头做 RL 成本巨大且不及直接
蒸馏。**数字对「72.6 对 44.0」是「蒸馏 vs 从头 RL」最常被引的官方对照。**

### 3.2 R1-0528：teacher 变强的代价是想得更久

2025-05-28 发布 R1-0528：AIME25 从 70.0 提到 87.5，**平均思考长度从
12K tokens 涨到 23K tokens**。同期放出第二代蒸馏 R1-0528-Qwen3-8B：
AIME24 86.0（比 Qwen3-8B 原版 +10.0）、AIME25 76.3。注意隐形成本：
teacher 变强靠想更久，学生照单全收——§6.5 展开。

### 3.3 社区复现数据集线：讲项目用的标准素材

R1 蒸馏数据没开源，社区沿着「自己造 R1 风格轨迹」接力（创建时间均为
HF API createdAt 实测）：

- OpenThoughts-114k（2025-01-27）：第一波复现；
- OpenR1-Math-220k（2025-02-10）：220k 题、每题 2-4 条 R1 轨迹、
  验证器（math-verify）筛过；
- OpenThoughts3-1.2M（2025-05-28）：120 万条、QwQ-32B 生成。

社招讲「我复现过推理蒸馏」时，这条线就是最常被追问的数据背景。

### 3.4 on-policy 蒸馏锚点：GPU·h 数字对与 TM 复现

2025-2026 年蒸馏的主轴从「off-policy 白嫖轨迹」迁到「on-policy 蒸馏」。
锚点数字对（Qwen3 技术报告 Table 21，经 TM 博客转引核实，非一级原文）：

- 同为 8B 学生冲 AIME24：从头 RL 要 **17,920 GPU·h** 才到 67.6；
- on-policy 蒸馏只要 **1,800 GPU·h**，且分数更高（74.4）。

TM 2025-10 的独立复现（数学域，Qwen 系师生）给了完整的工程手感：

- SFT-400K 起手把学生带到 AIME24 约 60%；on-policy 蒸馏只跑约 150 steps
  （77K prompts）就到 70%；
- 成本对比：相对全量 SFT-2M 全程，摊销 teacher 后约 **9 倍**，算全成本约
  **30 倍**，GPU·h 口径约 **18 倍**；
- LoRA 陷阱的量化：rank=32 的 LoRA 在大规模 SFT 上落后全参 13%，经
  on-policy 蒸馏收尾后差距缩到 6%；
- 自蒸馏修复：老 checkpoint 当 teacher 把 IF-eval 从 45% 蒸回 83%。

**一句话记住这组锚：蒸馏抄的是最终策略，RL 贵在搜索策略空间。**

### 3.5 蒸馏与 RL 的边界已经模糊：当光谱，不要二选一

把三种训练形态放一张表，是为「GKD 和 GRPO 有什么区别」这类追问准备的：

| 形态 | 轨迹来源 | 监督信号 | 信号量级 |
|---|---|---|---|
| SFT / off-policy 蒸馏 | teacher 固定轨迹 | 稠密、逐 token | O(N) bits，但分布外 |
| RL（PPO/GRPO） | 学生自己 rollout | 稀疏、结果标量 | O(1) bits |
| on-policy 蒸馏（GKD/MiniLLM/TM） | 学生自己 rollout | teacher 逐 token 反馈 | O(N) bits，且分布匹配 |

GKD（arXiv:2306.13649，ICLR 2024）第一次把「学生自轨迹 + teacher 逐
token 反馈」命名成 on-policy 蒸馏，并指出可与 RLHF 无缝混合。换句话说，
**on-policy 蒸馏等价于把 reverse-KL 当 reward 的 RL**：reward 稠密、
不可 hack（KL=0 当且仅当学生等于 teacher）、还不用训练奖励模型。黑盒
方向也有延伸——GAD（arXiv:2511.10643，2025-11）只拿文本不拿 logits 做
on-policy 对抗蒸馏，作者自报 Qwen2.5-14B 逼近 GPT-5-Chat（LMSYS-Chat
自动评；注意这是作者自评口径，未见大规模复现）。

## 四、剪枝三代

直觉先行：LLM 权重矩阵里大量权重接近冗余，砍掉一半 PPL 才涨一两个点，
参数超配严重。问题从来不在「能不能剪」，而在「剪完有没有人给你写快的
kernel」。三代技术对这个问题的回答各不一样。

### 4.1 非结构 one-shot（2023）：SparseGPT 与 Wanda

SparseGPT（arXiv:2301.00774，ICML 2023）：OBS 家族二层近似、逐层重建，
OPT/BLOOM-175B 单卡 4.5 小时一次性剪到 50%，60% 非结构稀疏时 PPL 上升
可忽略；原生支持 2:4 / 4:8 与「稀疏 + 4-bit」联合。Wanda
（arXiv:2306.11695，ICLR 2024）把重要性判据改成 |W|×||X||，连权重更新
都省了。精度对照（WikiText2 PPL，原文口径）：

| 模型 | dense | 50% 非结构（magnitude） | SparseGPT | Wanda |
|---|---|---|---|---|
| LLaMA-2-7B | 5.12 | 14.89（已崩） | 6.51 | 6.42 |
| LLaMA-2-70B | 3.12 | — | 3.98 | 3.98 |

加速侧：CPU DeepSparse 引擎上 40%/50%/60% 稀疏对应 1.57×/1.82×/2.16×。
硬伤：非结构稀疏 GEMM 没有足够快的通用 kernel，NVIDIA 稠密生态吃不到
这 60% 的稀疏。**所以非结构剪枝的主要价值是显存减半的理论空间，以及
「剪枝 + 量化可联合」的可行性证明，不是端到端加速。**

### 4.2 结构化剪枝（2023-2024）：LLM-Pruner 与 SliceGPT

- LLM-Pruner（arXiv:2305.11627，NeurIPS 2023）：按耦合结构组剪 20%
  参数，LLaMA-7B 零-shot 保留 89.8%，LoRA 恢复（3 小时、50K 数据）后
  回到 94.97%；Vicuna-7B 92.03%。
- SliceGPT（arXiv:2401.15024，ICLR 2024）：用 RMSNorm 的计算不变性砍
  嵌入维度，砍 25% 参数 + 嵌入后，LLaMA-2-70B / OPT-66B 零-shot 保 99%、
  Phi-2 保 90%；LLaMA-2-70B 推理计算量降到 64%（24GB 消费卡）/ 66%
  （A100）——「24GB 消费卡跑 70B」是它的招牌卖点。

坑在口径：**保留率 95% / 99% 全是零-shot 选择题口径**，生成任务和长
CoT 的掉点远比表格难看；且剪完的不规则形状在 TensorRT / cuBLAS 要额外
调教。2026 的现实是：几乎没有线上大模型用纯结构化剪枝交付主力生成服务，
它的舒适区在非生成场景（embedding、分类、rerank）。

### 4.3 2:4 半结构化：硬件给的理论上限，生态没接住

Ampere 起的稀疏 Tensor Core 原生支持 2:4 结构稀疏（每 4 个权重 2 个非
零），理论 GEMM 加速 2×。SparseGPT 论文 Appendix E 的官方实测（OPT-175B
三个大 GEMM 形状，CUTLASS 对 cuBLAS，bs=2048 tokens）：per-layer 加速为
**层内 1.54 到 1.79 倍**；端到端扣掉 attention 等不吃稀疏收益的部分会再打折，
论文没有给端到端官方数字，引用一律按「低于层内、官方未给出」表述。

精度端 2:4 比 50% 非结构掉点明显多：LLaMA-2-7B 上 Wanda 2:4 是 11.02
（SparseGPT 2:4 为 10.17），而 50% 非结构才 6.42；70B 上 2:4 是 5.16
对 SparseGPT 的 5.40。**越小的模型越受不了 2:4 的硬约束**，所以 2:4 多
见于 70B+ 或多模态 / 视觉 backbone。工程现实：N:M 稀疏在 vLLM / SGLang
主流 serving 栈仍不是默认路径，生态热度远低于量化。面试金句：
**半结构化 2:4 是硬件给的理论上限、生态没接住的典型。**

## 五、压缩组合生产线：distill → (prune) → PTQ

### 5.1 为什么是「先蒸馏、再量化」

2025-2026 的默认生产线没有悬念：R1 六档蒸馏、R1-0528→Qwen3-8B 都是先
出 BF16 蒸馏权重，社区再做 GPTQ / AWQ / FP8 / NVFP4。顺序的理由：

1. **蒸馏决定「模型是谁」，量化决定「部署多便宜」**：前者伤能力上限，
   后者伤数值保真，性质不同，串联时误差近似相加。
2. **不要把量化塞进蒸馏之前**：teacher 与学生要在 BF16 下对齐分布，量化
   噪声会污染 KL 目标——先把数值噪声引进来再谈对齐是本末倒置。
3. 剪枝插在中间且可选：SparseGPT 原生支持 50% 稀疏 + 4-bit 联合，剪枝
   与量化的联合有论文背书。
4. **蒸馏是 QAT 的廉价替代**：「换个更强 teacher 重蒸一遍」通常比搭一套
   QAT 设施便宜；精度出了问题再升级 QAT。

标准组合答案：distill → (prune) → PTQ，精度不达标再升 QAT。交叉审题模板
——「7B 上线、精度要接近 32B」：同家族强 teacher 蒸 7B → GPTQ/AWQ
W4A16 或 NVFP4 → PPL + 业务集双重评测。

### 5.2 与量化专题的分工

PTQ/QAT 的方法谱系、GPTQ/AWQ 的算法差、FP8/NVFP4 的数值口径全部在
[量化与压缩](./inference/量化与压缩.md)，本篇不重复；这里只负责回答
「量化在压缩流水线里站哪一格」。

### 5.3 工程 pipeline 五步：蒸一个垂直域 7B 推理模型

1. **选师生对**：同家族同 tokenizer 是默认前提；尺寸比 4-30× 都有先例
   （R1 拿 671B 蒸 1.5B 是 400× 也蒸得动，但小档收益递减，1.5B 档
   AIME24 只有 28.9）。跨家族直接放弃 logit KD，退到 trajectory SFT。
2. **teacher serving 造数据**：成本大头是 teacher 推理而不是训练。锚点：
   R1 800k；OT3 1.2M；TM on-policy 阶段只有 77K prompts 又涨了十个百分点。
   工程上走 vLLM / SGLang offline batch（PD 分离、大 batch），teacher
   可以用 FP8 / NVFP4 serving 版省一半成本（注意量化 teacher 的分布漂移
   会传给学生）。
3. **数据配比与质量门**：R1 的 800k 混了推理与非推理数据；纯轨迹数据过
   验证器（OpenR1-Math-220k 用 math-verify）；TM 内部配方的口径是混入
   至少 30% 通用 chat 背景数据防遗忘。
4. **训练两段**：off-policy SFT 打底（全参优选；LoRA 高 batch 落后，TM
   实测 rank=32 落后 13%）→ on-policy 蒸馏收尾（reverse KL；LoRA 差距
   收窄到 6%）。
5. **评测与迭代**：pass@1 报均值要对齐口径——R1 官方是 temperature 0.6、
   top-p 0.95、64 次采样估 pass@1；盯思考长度，teacher 从 12K 涨到 23K
   tokens 会直接推高学生的输出长度与服务成本。

## 六、工程议题八条

1. **teacher serving 成本常超训练成本**：on-policy 每 step 要对学生
   rollout 调 teacher forward 取 logprobs，teacher 是 235B / 671B 就是
   常驻推理集群。对策：离线批处理、logprobs 只取 top-k 存盘、FP8/NVFP4
   serving 版 teacher。
2. **学生学风格不学事实**：The False Promise of Imitation（Gudibande
   et al., 2023）——off-policy 蒸馏连 teacher 的自信口吻和幻觉一起抄。
   对策：验证器筛轨迹 + on-policy 让学生暴露自己的错误分布。
3. **分布失配 / compounding error**：off-policy 轨迹中学生永远走不进
   teacher 没去过的状态，长 CoT 尤其明显。共同答案是自己 rollout、
   teacher 逐 token 打分；代价是实现「半个 RL 训练栈」，基础设施门槛跟
   RL 一样高。
4. **tokenizer / 架构错配**：跨家族只能退化 trajectory SFT 或做
   OT / byte-level 研究方案；MoE → dense（R1 671B-MoE 蒸 Qwen dense）已
   证实可行，反向 dense 蒸 MoE 没有公开成功范式。
5. **思考长度失控是蒸馏的隐性成本**：teacher 变强靠想更久（12K → 23K
   官方口径），学生照单全收，服务成本与首 token 延迟全涨。标准答：省了
   参数量与显存，没省输出 token 数。
6. **结构化剪枝的「评测幻觉」**：LLM-Pruner / SliceGPT 的保留率是零-shot
   选择题口径，生成任务掉点敏感；落地点在非生成场景，生成主力走蒸馏 +
   量化。
7. **多教师混合与合规**：混多 teacher 轨迹要管风格冲突（分布多峰）、
   数据去重配比（按任务分层抽样）与 license——OpenAI / Anthropic 的 ToS
   禁止蒸馏其模型，DeepSeek-R1 是 MIT 明文允许商用与再蒸馏。合规问题在
   北美 infra 面已被问过。
8. **LoRA 蒸馏的陷阱**：LoRA + 大规模 SFT 掉 13%，on-policy 蒸馏可追回
   至 6%（TM 实测）；且蒸馏数据分布窄时，LoRA「忘得少」的特性反而是坏
   事——新知识也学不进去。

## 六·增、A2 速记：OPD 谱系

- **#187 反向 KL → GKD/DistiLLM/AOPD → 特权信息自蒸馏**：Rock Token
  **18%**；占 **40%** 优化带宽；误差从 **O(εT²) 降到 O(εT)**。
- 面试点：OPD 不是单一算法，而是一条「用教师分布做 dense reward」的
  谱系；越往后越强调特权信息与长程 credit。

## 七、▶ 面试题 8 条（全收）

**Q1【极高】R1 为什么不直接对小模型做 RL，要蒸馏？**
官方口径 + 数字对：AIME24 上 R1-Distill-Qwen-32B 得 72.6，QwQ-32B-Preview
从头 RL 只有 44.0；成本侧 Qwen3 的对照是 17,920 对 1,800 GPU·h。原理上
RL 的价值在「发现新策略」（R1-Zero 证明纯 RL 能涌现反思行为，但可读性
差、中文混杂），蒸馏的价值在「搬运已知策略」，分工不同；小模型从头 RL
既贵又不如蒸。（§3.1、§3.4）

**Q2【高】forward KL 和 reverse KL 蒸馏差在哪？**
forward KL 是 mass-covering：学生会给 teacher 的低概率区分配概率质量，
是间歇性胡话的源头；reverse KL 是 mode-seeking，且它的期望在学生分布上
取，数学上必须 on-policy——off-policy 数据估不了 reverse KL。深追一个
是 MiniLLM 把 reverse KL 做成长序列蒸馏的默认目标，二是 TM 选 per-token
reverse KL 的理由（KL 不可 hack、缓解 exposure bias）。（§2.2）

**Q3【高】GKD / on-policy 蒸馏和 GRPO 的边界在哪？**
都是学生 rollout + reward 更新；差别在 reward 密度（逐 token 的 KL 是
O(N) bits，结果标量是 O(1) bits）与是否需要显式 reward model。TM 的一句
话转换：把 RL 里 KL regularizer 的 reference model 换成强 teacher，就是
on-policy 蒸馏。reward hacking 角度：KL 型 reward 不可 hack，KL=0 当且
仅当学生等于 teacher。（§3.5）

**Q4【高】SparseGPT 60% 稀疏几乎不掉点，为什么业界不大规模用剪枝？**
分三档答：非结构稀疏没有通用快 kernel（1.57-2.16× 只在 DeepSparse）；
2:4 有硬件但生态没进 vLLM/SGLang 主链路，且 7B 档掉点大（11.02 对
6.42）；结构化保住的是零-shot 选择题，生成与长 CoT 敏感。结论：2026 年
「蒸馏 + 量化」才是工业默认，剪枝活在论文与非生成场景。深追问理论实测：
2:4 理论 GEMM 2×，SparseGPT 实测层内 1.54-1.79×，端到端更低（attention
不吃稀疏收益）。（§4）

**Q5【高】设计一条把 671B 教师蒸到 7B 上线的 pipeline，成本项有哪些？**
teacher 离线 batch serving（成本大头，可 PD 分离 + FP8/NVFP4 teacher）→
验证器筛轨迹 → SFT 打底 → on-policy 收尾（150 steps / 77K prompts 量级）
→ PTQ → 业务评测。深追数据量怎么定：800k 是 R1 官方锚；scaling 是
log-linear，后期靠 on-policy 而不是堆 prompt。（§5.3）

**Q6【中高】蒸馏模型怎么合规？能不能蒸 GPT-5 / Claude？**
OpenAI / Anthropic 的 ToS 明确禁止用输出蒸馏竞争模型；DeepSeek-R1 是
MIT 协议明文允许商用与再蒸馏；黑盒 GAD 类技术可行但法律风险自担。深追
「怎么检测某模型是不是蒸了某 teacher」：输出分布水印 / 风格指纹，开放
问题，无工业标准。（§6.7）

**Q7【中】跨 tokenizer 蒸馏怎么办？**
三条路：只蒸文本轨迹（SeqKD 最常用、天然与 tokenizer 无关）；logit 对齐
研究线（OT、byte-level、likelihood matching，未收敛）；工程回避（同家族
师生）。深追 MoE teacher 蒸 dense student 的坑：无官方结论，可从「老师
每次只激活 37B / 671B，学生学的是条件路由后的平均行为」展开。（§2.4、
§6.4）

**Q8【中】先剪枝还是先量化 / 先蒸馏？**
顺序题：能力操作（蒸馏）在前、数值操作（PTQ）在后；剪枝在两步之间，
SparseGPT + 4-bit 可联合；QAT 是数值操作前置训练化的特例。深追误差怎么
叠加：每步独立评 PPL + 业务集，误差近似相加，组合超预算就回退更高 bit。
（§5.1）
