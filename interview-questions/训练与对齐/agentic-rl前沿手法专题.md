# Agentic RL 前沿手法专题：Search-R1、ReTool 与 On-Policy Distillation

> **面向**：已读过本仓 [agentic-rl专题](./agentic-rl专题.md)（多轮
> credit assignment 与工业配方）、想再往下一层看「环境交互协议到底怎么
> 设计」的读者。本篇只讲三个手法，每个都是从零实现视角拆开：检索环境
> （Search-R1）、代码执行环境（ReTool）、教师在线指导（OPD）。
>
> **读完获得**：① observation mask 为什么是所有 tool-RL 的必修课；
> ② 三手法的环境接口/奖励源/代表数字一张对比表；③ 一条「为什么 mask」
> 起手的面试追问链与参考答法。
>
> **口径说明**：数字均引自一手出处（arXiv 摘要与 Thinking Machines
> 官方 blog，2025），文末列 URL；论文口径是「作者自报」，不代表独立复现。

## 一、为什么单讲这三个

[agentic-rl专题](./agentic-rl专题.md) 回答的是「多轮轨迹上
credit 怎么分、各家工业配方怎么选」，偏顶层。面试到了 2025-2026 年
开始往下钻一层：**环境和模型之间的接口协议长什么样**。这三个手法恰好
覆盖了 agentic RL 的三类环境接口：

- 检索环境：模型发 query，搜索引擎回文档（Search-R1）
- 执行环境：模型写代码，沙箱回运行结果（ReTool）
- 教师环境：模型走一步，教师当场对这一步打分（OPD）

三者看似不同，工程上共享同一条主线：**环境里进来的 token 不能让模型
学着背，要学的是「怎么用」它们**。这就是 observation mask，也是全篇
的题眼。

## 二、Search-R1：把搜索引擎变成 RL 环境

### 2.1 协议长什么样

Search-R1（arXiv:2503.09516，2025-03，UIUC 等）把检索嵌入推理循环：
模型在推理过程中可以发出被 `<search>` 与 `</search>` 包裹的查询，
系统检测到闭合标签后暂停生成、调真实搜索引擎、把返回的 top 文档塞进
 `<information>` 与 `</information>` 之间拼回上下文，模型继续推理，
可以多轮调用，最后用 `<answer>` 给出最终答案。本质是一台**多轮
rollout 状态机**：生成态 ↔ 检索态交替，检索结果作为环境
observation 注入轨迹。

### 2.2 observation mask：环境 token 不算 loss

训练时的关键工程点就一条：**检索回来的文档 token 全部 mask 掉，不参与
loss 计算**。模型自己生成的 token（推理、query、answer）照常算梯度。

为什么必须 mask？三个理由层层递进：

1. 检索内容是**环境写的，不是策略写的**——对它算策略梯度在数学上
   就不成立（这些 token 不是从 π_θ 采样的）；
2. 不 mask 等于让模型**背检索结果**，梯度会把概率推向复述文档，
   学不到「该什么时候搜、搜什么」；
3. 检索文档又长又杂，不 mask 会让 loss 被大量无关 token 稀释，
   训练不稳。Search-R1 论文把 retrieved token masking 列为稳定
   RL 训练的两个关键设计之一（另一个是简单的 outcome-based 奖励）。

### 2.3 奖励与成绩

奖励走最简路线：**outcome-based**，只看最终答案对不对（EM/F1 规则
判定），不给过程奖励、不用神经网络 RM——检索场景下过程奖励极易
reward hacking。论文口径的成绩：在 7 个 QA 数据集上，相对同设置的
RAG 基线平均提升 **7B 约 41%、3B 约 20% 的相对提升（论文摘要口径）**。
注意这是「相对提升」，不是绝对准确率涨 41 个点——面试别夸大。

## 三、ReTool：代码解释器作为环境

### 3.1 冷启动 + RL 两段式

ReTool（arXiv:2504.11536，2025-04，字节）瞄准的痛点是：纯文本推理
模型（如 R1 式长思考）在几何推理、精确计算、复杂方程求解上吃亏——
这些恰恰是代码解释器的主场。做法分两段：

1. **冷启动 SFT**：合成「代码增强的长推理轨迹」（自然语言推理中
   插入 `<code>` 调用与执行结果），先教会模型调用格式与场景；
2. **RL 阶段**：rollout 中允许真实多轮执行——模型生成 ` ```python `
   代码块后沙箱真实运行，输出回填到 ` ```output ` 块里，模型接着
   推理；奖励只看**任务最终结果**（数学答案对错），不设计工具调用
   本身的过程奖励。

与 Search-R1 同构：执行输出同样是环境 observation，同样要在 loss
里 mask 或隔离——模型要优化的是「何时写代码、写什么代码」，不是背
运行结果。

### 3.2 论文口径的数字与涌现

论文（字节自报口径，AIME 数学奥赛基准）：

- ReTool-32B 用 **400 步** RL 达到 **67%** AIME 准确率；同起点纯
  文本 RL 基线用 **1080 步**只到 **40% 这一档**——工具集成后样本效率
  和上限双高；
- 延长训练设置下 ReTool-32B 达 **72.5% 的水平**，论文称超
  o1-preview **27.9%（相对幅度）**；
- 涌现出**代码自我纠正**行为：模型会在执行报错或结果异常时主动
  改写代码重试——这是 outcome 奖励下无人为设计、自己长出来的
  「工具使用策略」。

面试里这组数字的价值不在背诵，在于说明一个判断：**给模型一个可验证
的执行环境，outcome-based RL 自己就能学会工具策略**——不需要人工
标注「这一步该不该调工具」。

## 四、OPD：On-Policy Distillation，教师在线批改每一步

### 4.1 它补的是哪条缝

后训练的两条老路各有硬伤（Thinking Machines Lab「On-Policy
Distillation」，Connectionism blog，2025-10）：

- **RL（on-policy，奖励稀疏）**：学生自己 rollout，但每个 episode
  只教 O(1) bits 的信息——知道答案错了，不知道错在哪一步；
- **离线蒸馏 / SFT（off-policy，信号密集）**：逐 token 都有监督，
  但学生学的是**教师访问的状态分布**；学生一旦犯了教师从不犯的错，
  就跑出训练分布，误差复利累积（compounding error）。

OPD 的拼法：**学生自己 rollout（on-policy），教师对学生轨迹里
的每个 token 现场打分（dense reward）**。下棋类比：RL 是没教练
自己下完才知道输赢；离线蒸馏是看大师下棋，但那些局面新手根本
下不出来；OPD 是大师坐在旁边给你的每一步当场评级。

### 4.2 机制：per-token reverse KL 当 advantage

学生对 prompt 采样完整轨迹；教师对**同一条轨迹**算每个位置的
logprob（教师只需一次前向，不用自己采样）；逐 token 的
reverse KL（学生分布对教师分布）取负就是该 token 的 advantage，
然后直接复用 RL 的 importance-sampling loss 更新——伪代码里就是
把 RL 实现中的 KL 正则模型换成教师模型，近似一行改动。
discount 取 0：只优化当前 token，不折现未来。

reverse KL 的三个好性质，面试可直接答：

1. **不可被 hack**：KL 低当且仅当学生在该状态的行为从教师视角
   看是高概率的——奖励模型会被 hack，教师分布不会；
2. **mode seeking**：收敛到教师的那一个具体行为模式，而不是在
   多个次优选项上摊平均（这正是蒸馏相对 RL 想要的性质）;
3. **dense**：每个 episode 教 O(N) bits（N = token 数），
   对比 RL 的 O(1) bits——这是效率差距的信息论解释。

### 4.3 数字与「廉价版 RL」的定位

- Qwen3 技术报告表 21（转引口径）：同起点 SFT 模型上，RL 用
  **17,920 GPU 小时**到 AIME'24 **67.6% 的成绩**；on-policy
  distillation 用 **1,800 GPU 小时**（**约十分之一成本**）到
  **74.4% 的高度**；
- Thinking Machines 复现实验：从 400k 条 SFT checkpoint 出发，
  **约 150 步** OPD 把 Qwen3-8B-Base 的 AIME'24 从 60% 拉到
  **70% 一线**；与 SFT-2M 外推相比基线成本降 **9x（数据集现成）**
  至 **30x（含教师采样成本）**；反向实验中，把 RL 训好的教师蒸回
  base 模型，**7-10x 更少梯度步**、累计算力省 **50-100x 的量级**；
- 增值用法：把「更早版本的模型自己」当教师，OPD 可以在新知识
  midtrain 造成遗忘后**恢复指令遵循行为**（官方实验中 IF-eval
  从 79% 恢复到 83%，且知识不掉）——所以它也是持续学习工具。

「廉价版 RL」的说法成立但要记住边界：OPD 的天花板是教师，它没有
RL 那种**探索出新策略**的能力——官方自己的解读是「RL 在语义
策略空间里搜索，OPD 是把搜到的最终策略快速刻下来」。所以合理
配方往往是 RL 在前探路、OPD 在后固化。

### 四·增、TurnOPD：长程多回合下 OPD 的两道错配与回合级预算（混元 hy3，2026-10）

口径：腾讯混元 hy3 系技术文章（公众号解读帖全文转录，官方一手未
读）。标准 OPD 单侧 rollout、逐 token 反向 KL，搬到长程多回合任务
会撞两道错配——

- **外部错配：固定 rollout 深度浪费算力**。逐回合看平均反向 KL，
  信号严重前载——早期回合很大、20 到 30 步内快速落入低噪长尾，
  固定深度把预算花在信号不可靠的深处。
- **内部错配：轨迹级归一化让深层挨饿**。KL 损失份额由 token 数与
  该处 KL 共同决定，ALFWorld-4B 上仅回合 0 就吃掉约四分之一预算、
  前三回合近半，最深的第三回合只分到 3.6%-4.5%。
- **「污染-压缩」让深层 KL 不可信**：自回归上下文越长，越多
  next-token 分布被强制决定（重复串、格式约束、复制实体），测得的
  KL 衰减可能只是压缩加剧、不是策略分歧消失；失败轨迹刻板模式更
  强、强制比例系统性更高——失败轨迹的 KL 反而更低，深层 KL 不是
  干净的成果预测信号。
- **两个预算控制器**：自适应 rollout 深度 H* 取效率臂与覆盖臂之
  大——效率臂把跨回合反向 KL 视作存活者加权的蒸馏质量分布，监督
  集中浅层时保持浅、纠错尾巴延伸到深层时自动加深；覆盖臂盯成功
  条件下的回合覆盖。KL 聚合从 token 级向回合均衡监督逐步迁移。
- **数字**：ALFWorld、WebShop、Multi-Hop Search 同等时钟预算准确率
  全面占优，训练最高 2.29 倍（4.42h 到 1.93h）。
- **接法**：与上文「RL 在前探路、OPD 在后固化」连读——长程 agent
  的固化阶段要按回合重做预算；面试一句型答案：**监督单位从扁平
  token 位置改成回合条件的决策**。

## 五、三手法对比表

| 维度 | Search-R1 | ReTool | OPD |
|---|---|---|---|
| 环境类型 | 搜索引擎（检索） | 代码解释器（执行） | 教师模型（在线评分） |
| 交互轮次 | 多轮检索穿插推理 | 多轮执行穿插推理 | 单侧 rollout，逐 token 评分 |
| 模型要学的事 | 何时搜、搜什么 | 何时写码、写什么 | 每一步向教师分布靠 |
| 环境 token 处理 | 检索文档全 mask | 执行输出隔离/mask | 教师只算 logprob，不进 loss |
| 奖励源 | 最终答案 EM/F1 | 最终答案对错 | 逐 token reverse KL（dense） |
| 出处 | arXiv:2503.09516（2025-03） | arXiv:2504.11536（2025-04） | TM Lab blog（2025-10） |
| 代表数字（自报） | 7 数据集相对 RAG +41%/+20%（7B/3B） | AIME 67%@400步 vs 40%@1080步 | 约 1/10 RL 成本到 74.4% AIME |

共性一眼可见：**环境进上下文的 token 一律不进 loss，奖励一律
朝着「结果可验证」或「分布不可 hack」设计**。这两句是 tool-RL
工程的总纲。

## 六、面试怎么考：一条追问链

1. 「Search-R1 为什么要把检索内容 mask 掉？」——见 2.2 三条理由，
   追问「不 mask 会出什么现象」（背文档、梯度被无关 token 稀释、
   loss 曲线噪声大）。
2. 「ReTool 涌现出代码自我纠正，说明什么？」——outcome 奖励 +
   可验证执行环境足以让工具策略自发涌现，不需要过程标注；追问
   「那冷启动 SFT 还必要吗」（必要，先教格式与调用意图，RL 阶段
   才站得起来）。
3. 「OPD 和 GRPO 能叠加吗？」——能：OPD 的逐 token 分是 dense
   信号、GRPO 的组内基线是稀疏 outcome，两者一个管「每步对不对」
   一个管「整局成不成」；官方也点名「逐 token 蒸馏奖励与序列级
   环境奖励结合」是未来方向。
4. 「OPD 有什么天花板？」——学生超不过教师；没有探索新策略的
   能力。RL 探路、OPD 固化是更合理的组合。
5. 「reverse KL 为什么不可 hack？和普通 RM 打分差在哪？」——
   RM 是学出来的近似，存在 OOD 高分漏洞；教师 logprob 是真实
   分布，KL=0 当且仅当行为一致。

## ▶ 面试题

**Q1（极高频）友善的面试官：Search-R1 训练的 loss 里，检索回来的
文档要算进去吗？为什么？**

参考答法：不算，全部 mask。两条核心：① 这些 token 不是策略采样
出来的，对它们算策略梯度数学上不成立；② 不 mask 模型会把梯度
花在背检索结果上，学不到检索决策本身。补一句工程观察：mask 也是
训练稳定性的来源，长文档会稀释有效梯度。

**Q2（高频）：outcome-based 奖励在检索 RL 里够用吗？为什么不用
过程奖励？**

参考答法：够用且更稳。检索场景的过程信号（这步搜得好不好）很难
客观标注，用神经网络 RM 打过程分容易被 hack——模型学会让 RM
高兴而不是真答对。Search-R1 用最简单的 EM/F1 结果奖励反而稳住
了训练，这个「奖励设计宁简勿滥」的判断与 rlhf与对齐 里 reward
hacking 一节一脉相承。

**Q3（高频）：ReTool 冷启动那段 SFT 是干什么的，直接 RL 行不行？**

参考答法：冷启动用合成的代码增强推理轨迹教会模型两件事：调用
格式（` ```python ` / ` ```output ` 协议）和「什么时候值得动笔算」
的直觉。直接 RL 不是不行，但 base 模型的有效调用率太低，
exploration 大部分浪费在格式错误上，冷启动把这些学费省掉。

**Q4（高频）：OPD 的 advantage 是什么？为什么可以用 RL 的
loss 训练？**

参考答法：advantage = 负的逐 token reverse KL（学生 logprob −
教师 logprob 的期望形式）。它和策略梯度天然同构——RL 本来就在
优化奖励诱导的序列级 reverse KL，把 RM 换成教师分布后，可以直接
复用 importance-sampling 的实现，官方伪代码就是「把 KL 正则模型
换成教师」一行改动。

**Q5（中频）：OPD 和离线蒸馏（蒸 teacher 轨迹做 SFT）差在哪？**

参考答法：状态分布。离线蒸馏学的是教师访问的状态——学生犯了
教师不犯的错就出分布，误差复利；OPD 在学生自己访问的状态上
打分，「学生犯自己风格的错，就在自己的分布上被纠正」。当然代价
是要在线采样 + 教师逐 token 前向。

**Q6（中频）：给你一个场景：想要个小模型学会公司内部的工具链，
但没有环境奖励。你选 RL 还是 OPD？**

参考答法：优先看有没有强教师。有（大模型会这套工具链）→ OPD，
dense 信号成本低且不可 hack；没有合格教师、但有可验证结果
（工具调用是否达成业务目标）→ outcome-based RL；两者都有 →
OPD 冷启动 + RL 收尾是常见配方。

**Q7（中频）：ReTool 论文里 67% vs 40% 的对比能说明「工具 RL
全面碾压文本 RL」吗？**

参考答法：不能，只能说明在 AIME 这类「计算密集、可执行验证」
的任务上工具环境上限更高。它没覆盖检索依赖型、开放生成型任务；
而且 40% 的文本基线用了更多步数（1080 vs 400），说明的更多是
**样本效率差距**。面试答数字顺手带上这个限定，显得读过论文。
