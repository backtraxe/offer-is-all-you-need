# LoRA 与参数高效微调详解

> 训练与对齐模块第二篇。LoRA 原理是 Top 20 榜单第 3 的极高频题（美团/字节/
> 快手都考），问到必问"低秩矩阵怎么初始化、为什么"。本文按「直觉 → 公式 →
> 显存拆账 → 超参与坑 → 全家桶对比 → 工程落地」组织，题目标注自
> [高频面试真题汇总](../高频面试真题汇总.md)。

## 一、LoRA 原理：低秩分解公式

▶ 面试题：LoRA 原理？与全量微调区别？——**极高频**（美团/字节/快手）

直觉先行：全量微调时，权重的变化量 ΔW 是一个 $d \times d$ 的大矩阵。但
LoRA 的作者发现：**微调带来的「有用更新」本质是低秩的**——模型已经在预训练里
把大部分能力学好了，微调只是在原参数空间的少数几个方向上做修正，这些修正
方向的张成空间维度远小于 $d$。

那就别学一个 $d \times d$ 的 ΔW 了，直接把它**分解成两个小矩阵的乘积**：

```text
  W' = W₀ + ΔW = W₀ + B·A

  W₀ ∈ R^{d×k}   <- 冻结，不动
  B  ∈ R^{d×r}   <- 可训练
  A  ∈ R^{r×k}   <- 可训练
  r << min(d, k)，一般 8~64
```

前向时变为两条支路：

$$h = W_0 x + \frac{\alpha}{r} \cdot BAx$$

其中 $BAx$ 这条支路的参数量是 $r(d+k)$，相比全量 $d \times k$ 小 $r/d$
倍——$d=4096$、$r=16$ 时参数量只有全量的 0.4%。$\alpha/r$ 是一个缩放系数
（等价于调整 LoRA 支路的学习率），这就是 LoRA 超参里 `alpha` 的由来。

再品一遍为什么有效："**预训练已经把能力写进 W₀ 了，微调只需在少数方向上
纠偏，所以 ΔW 的本征秩很小。**" 这也是 LoRA 和 SVD 思路相通的地方。

## 二、初始化：A 随机、B 置零，为什么不能都随机

▶ 面试题：LoRA 低秩矩阵怎么初始化？为什么不是两个都随机？——**极高频**
（字节/美团必追问）

官方实现（Microsoft 原版 + PEFT）：

- **A 用高斯/Kaiming 随机初始化**（每个分量 rᵢ ~ N(0, σ²)）——打破对称性、
  供训练信号。
- **B 置零**——让初始时刻 $BA = 0$，即 $\Delta W = 0$，**模型在一开始和
  未微调前的行为完全一致**。

反过来问：为什么这俩必须一个零、一个随机？

- **两个都随机**：$\Delta W = BA \neq 0$，相当于在 pretrained 权重上叠加了
  无意义的随机噪声，一开始的模型行为被扰动，第一阶段的训练要先"把噪声纠正
  回来"再学真实任务——浪费且容易学歪。
- **两个都置零**：梯度对称，$BA$ 的 Jacobian 为零矩阵，什么也学不动。

一句话答法："**随机初始化负责打破对称学出内容，零初始化负责保证初始
ΔW = 0、不扰动原模型；两者缺一不可。**" 有些变体（DoRA / PiSSA）会用
SVD 初始化得更聪明，但核心不变：初始 ΔW 从 0 出发。

## 三、LoRA vs 全量微调：显存拆账

▶ 面试题：LoRA 与全量微调区别？显存差多少？——**极高频**（字节/滴滴计算题）

训练显存三块账（BF16 + AdamW + 混合精度）：

| 项 | 全量微调 | LoRA |
|---|---|---|
| 权重（主权重 + grad + m + v） | 16 字节 / 参数 | 主权重按 LoRA 参数量算 |
| 优化器状态（AdamW m/v） | $2 \times 4 = 8$ 字节 / 参数 | 只按低秩参数量算，量级 ~1% |
| 激活值（前向保存） | 按层按 batch 按精度 | **基本不变**（主干还在算） |
| 梯度 | 主干也有 | 主干**没有**（冻结） |

拿 7B 参数、LoRA r=16、只挂 attention + FFN 全部线性层算算：

- 全量：$7 \text{B} \times 16 \text{B} \approx 112 \text{GB}$，还没算激活，
  单卡（哪怕是 H100 80G）都下不来。
- LoRA：可训练参数约 20M~50M（占 ~0.5%），主权重 + 梯度 + AdamW 状态只
  按 LoRA 量算约 0.5 GB 级别；主干 BF16 权重 14 GB 冻结放置，梯度不占主干。
  总账：14 GB 权重 + ~1 GB LoRA 状态 + 激活/梯度检查点，单张 24 GB 消费卡
  （配合梯度检查点、batch 调小）就能跑。

**关键洞察**：LoRA 省的不是模型推理显存（主干一样在算），而是**训练时的
优化器状态和主干梯度**——这两块是全量微调里最大的头。

> 常见误区：很多人觉得 LoRA 省的是"模型本身的显存"。其实 W₀ 该占多少还
> 占多少，LoRA 省的是 AdamW m/v 和梯度——思考一下为什么系统化岗位会追问
> 这个，就是要分清"哪一块显存被砍掉"。

## 四、QLoRA：再砍一刀显存

QLoRA（Dettmers 2023）把 W₀ 再压到 4-bit，三件武器：

1. **4-bit NF4 量化**主干权重（Normal Float 4，对正态分布数据信息论最优的
   4-bit 数据类型）。
2. **Double Quantization**：对量化常数本身再量化一次，再多省一点。
3. **Paged Optimizer**：防止梯度 checkpoint 时优化器状态瞬间挤爆显存，
   自动换到 CPU 内存再换回来。

结果：7B 模型 SFT 能跑到 24GB 卡（NLG 论文口径），65B 能跑到 48GB 单卡。
LoRA 支路仍是 FP16/BF16 计算，主干 4-bit 只参与前向——**推理精度和 BF16
主干 LoRA 基本持平，这就是 QLoRA 的最大卖点**。

## 五、LoRA 超参与常见坑

▶ 面试题：LoRA 的 r、alpha、target_modules 怎么设？——**高频**

### r（秩）：15~64 是常用带

- r 小（4~8）：应付简单格式对齐，显存极省，过拟合风险低。
- r 大（64~256）：学复杂领域行为/代码模式；r > 256 基本超过收益拐点。

### alpha：控制 LoRA 支路学习强度

- 官方实现 $h = W_0x + (\alpha/r) BAx$，所以**调 alpha 等价于对学习率做
  缩放**。常见经验：$\alpha = 2r$ 或 $\alpha = r$，保持 $(\alpha/r) = 1\sim2$。
- 追 alpha 本质：**「想让 LoRA 支路相对于学习率 lr 走多快」**。

### target_modules：挂哪些层

- 最简单：只挂 attention 的 `q_proj/v_proj`（省显存）。
- 常用稳妥：attention 全部 + FFN 的 `gate/up/down`（QLoRA 原文建议的全线性
  层方案，几乎不掉点，显存多花 20-30%）。
- 不要挂：embedding 层、LM head（参数量大、收益低、容易过拟合）。

### 常见坑清单

| 坑 | 答法 |
|---|---|
| 学习率太小 | LoRA lr 比全量大一个数量级：全量 1e-5 → LoRA 1e-4。主干冻结，权重要靠 LoRA 学到东西，lr 不可同步缩小。 |
| 只加 attention | 学不出"领域行为"，只学了"领域注意力分布"；FFN 是 FFN 是记忆库，领域术语码在 FFN 里。 |
| r 拍太大 | 过拟合、显存爆炸反而掉点；采样小网格扫 r 再定。 |
| 不 mask instruction | SFT 只对 response 算 loss；全序列 loss 会让模型学预测用户 query，行业 imbalance。 |
| dtype 混用 | merge 时 BF16 ↔ FP16 不对齐，推理侧掉点 2-3pt 还找不着原因。 |

## 六、Full SFT / LoRA / QLoRA / Adapter / P-Tuning 对比表

▶ 面试题：Full SFT vs LoRA/QLoRA/Adapter/P-Tuning 对比？——**高频**

| 方案 | 可训练参数占比 | 主干显存 | 复杂度 | 顶会年份 | 典型场景 |
|---|---|---|---|---|---|
| Full SFT | 100% | 全部 ×16 字节 | 简单 | 2022 | 算力充足、垂域彻底深度定制 |
| Adapter | ~1%-3% | 全量加载 | 模块插进 FFN 之后 | 2019 | BERT 时代经典 |
| Prefix/Prompt-Tuning | 万分之几 | 全量加载 | 加可学前缀 token | 2021 | NLU/NLG 轻定制 |
| P-Tuning v2 | ~0.1%-1% | 全量加载 | 每层加 prefix 键值 | 2022 | 对齐 + 少量算力 |
| **LoRA** | ~0.1%-1% | 全量加载 BF16 14 GB/7B | 加一个低秩支路 | 2021 | 主流默认 |
| **QLoRA** | ~0.1%-1% + 主干 4-bit | 主干 ~4 GB/7B | LoRA + 量化 | 2023 | 单卡微调大模型 |

答法要点：**LoRA 和 QLoRA 是目前唯一"参数高效 + 实现简单 + 效果接近
全量"同时成立的方案**，Adapter 和 P-Tuning 已被边缘化但概念题还要能讲。

## 七、合并推理与工程部署

▶ 面试题：LoRA 推理要不要拆开算？部署注意什么？——**中高**

**两条路线**：

1. **合并（merge）**：$W' = W_0 + (\alpha/r) BA$，把 LoRA 权重合并回主干，
   **推理零额外开销**——一次前向，一次矩阵乘。vLLM / SGLang 加载
   HF 格式权重时就是这条路线，**正式上线首选**。
2. **不合并（分离计算）**：前向同时算 $W_0x$ 和 $BAx$ 再相加。
   用在**多 LoRA 在线切换场景**——同一份 $W_0$，挂上不同租户的 adapter
   动态换载。vLLM 0.4+ 原生支持 multi-LoRA serving。

**坑位提醒**：

- merge 时一定先转 BF16/FP16 主权重再合并，**不要在 8-bit/4-bit 量化之后
  再 merge** ——量化主干上叠低秩精度损失不可控。
- LoRA 权重文件很小（几十 MB），方便多租户管理，但**合并后的 W' 就是完整
  模型权重**，占用等于全量模型。
- KV Cache、推理引擎、量化 的坑不变——合并后的 LoRA 模型从推理视角
  和全量微调模型**完全等价**，这条也是面试："LoRA 推理成本跟全量微调
  推理成本是一样的哦。"

## 八、高频追问清单（本主题）

| 追问 | 答题要点 |
|---|---|
| LoRA 能降到多少显存？ | 主干不动，优化器状态 + 主干梯度 ≈ 砍零；可训练参数降到 ~0.5%。7B 全量 112 GB → LoRA 消费卡可跑。 |
| r 理论上限多少？ | $r \le \min(d, k)$；实证上两条线性层的有效秩在几十量级就到头，再大收益饱和。 |
| LoRA 和 Prompt-Tuning 谁强？ | LoRA 参数量更少且改的是权重，能学到领域行为；Prompt-Tuning 只是 prefix 级软提示，学得浅、可控性差。LoRA 是主流默认，Prompt-Tuning 只剩概念题价值。 |
| DoRA / PiSSA 听过吗？ | DoRA 解耦权重的模长和方向先学方向，PiSSA 用 SVD 初始化 LoRA 起点更好——提
  一句体现跟进，深挖不会。 |
