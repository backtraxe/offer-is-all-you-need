## 一、主线直觉：蒸馏不是算法，是生产线

一句话：**蒸馏在现代 post-training 里不是一个算法，而是一条「教师巡检 +
数据造厂 + 学生装配」的工业化流水线**——教师模型通过拒绝采样
（rejection sampling）批量生产带验证的轨迹，经过质量 / 去重 / 去污染过滤
后当 SFT 语料喂给学生，再按需叠一段 on-policy 蒸馏收尾。RL 在这条线上只是
偶发出现的「质检提升工位」，不是主体。

这个视角为什么是 2025–2026 的面试主线，因为它回答了三个最常被问的问题：

1. **钱花在哪儿**：DeepSeek-V3 全训约 **2.788M H800 GPU·h（2025-02
   口径）**，R1 整套后训练只花 **147K GPU·h（arXiv v2, 2026-01）**，而这
   147K 里造 80 万条教师轨迹只花了 **5K GPU·h，约为纯 RL 工位的二十分之一**
   ——产线的每一环成本差两个数量级，组织方式直接决定预算。
2. **蒸馏和 RL 是不是二选一**：不是。产线上两者是**串联**：先用便宜的
   「搬运」（蒸馏把教师已知策略灌进学生）把上限填到八成，再用 RL 做增量
   搜索。Qwen3 的技术报告把这件事写成了官方结论——8B 学生组，在
   off-policy 蒸馏之上再花 **1,800 GPU·h 做 on-policy 蒸馏，AIME24 到
   74.4**，同样起点接 RL 要 **17,920 GPU·h 才到 67.6（Qwen3 TR,
   2025-05）**。
3. **在哪里炸**：递归吃自己数据会能力坍缩、教师垃圾轨迹会原样遗传、
   评测集污染会让所有分数不可信——这三坑每一坑都会让整条产线返工，所以
   过滤与去污染是产线的默认数据门，不是可选件。

## 二、机制拆解：五段产线

以 DeepSeek-R1 / Qwen3 公开口径为骨架，标准产线分五段。

### 2.1 选师生对与原料库

源头是一个**带可验证答案的 prompt 池**：数学有标准答案、代码有
test case。Qwen3 的冷启动数据先过两阶段过滤——用 Qwen2.5-72B-Instruct
删掉**不可验证**的 query，并且**删掉 72B 模型不用 CoT 就能答对的题**
（Qwen3 TR §4.1, 2025-05）。第二刀的意义是只做「非想不可」的难样本：
教师不用思考就答对的题，长链轨迹没有信息量，蒸馏等于灌噪声。这是
「困难样本挖掘」目前最标准的公开做法；同时 Qwen3 用 72B 给每题标
domain，保持域平衡。

师生对的选择另有一本理论账：teacher 不是越强越好，capacity gap 过大时
学生吃不下。Apple 等的工作把师生算力分配做成了显式 Scaling Law
（Distillation Scaling Laws, ICML 2025）——**只有当 teacher 已经存在、
或要服务多个学生摊销成本时，蒸馏才划算；为一锤子单个学生从零训
teacher，通常直接监督学习更便宜**。

### 2.2 冷启动 SFT：短链塑形，别喂太饱

少量高质量长 CoT 对学生（或 RL 的 actor）做格式塑形。R1 与 Qwen3 都
明说此阶段要**样本数与步数最小化**：冷启动的作用只是装格式与风格，
训练过度会压缩后续 RL 阶段的探索空间（R1 §B.3.2 / Qwen3 §4.1）。
面试里被追问「冷启动数据放多少合适」，标准答法是「够装格式即可，
多了是负资产」。

### 2.3 中段 RL 工位（边界外，一句话带过）

R1 的推理 RL 把院内 AIME24 从 70.1 推到 85.1；这一段的训练机制、显存
与调度细节属于 RL 专题。本篇只需要记住一个身份：RL 工位是产线上
**给数据厂提供更强母体**的环节，而不是产线的终点。

### 2.4 拒绝采样造数据：产线核心

从中段 checkpoint 对每个 prompt 采样 N 条轨迹，规则验证器（答案对错 /
测试用例）留下正确样本；规则判不了的题用 generative reward model 当
裁判（R1 用 DeepSeek-V3 做裁判）。过完正确性再过风格门：语言混杂、
超长段落、CoT 中混入代码块全部剔除（R1 §B.3.3）。Qwen3 的响应过滤
是六条规则，其中第 6 条专门砍掉「与验证集疑似相似」的轨迹——
**去污染被写死在产线数据门的默认位置**。

产量口径（R1 arXiv v2, 2026-01）：推理轨迹 **600k** + 非推理样本
**200k** = **800k** 一大桶。非推理部分直接复用 DeepSeek-V3 的 SFT
管线并混入软件工程数据，简单 query 不给 CoT。也就是说推理数据占约
七成半，剩下四分之一是防遗忘的通用面——配比不是拍脑袋，是「防一头
独大」的防腐设计。

### 2.5 蒸馏 SFT 与 on-policy 收尾

学生侧先做普通 SFT：R1 六档学生（1.5B–70B）统一 **2–3 epochs、
batch 64、seq 32,768**（R1 原文）。Qwen3 在此基础上再加一段
**on-policy 蒸馏**：学生自采样，对齐 teacher（Qwen3-32B 或
235B-A22B）的 logits、最小化 KL。off-policy 解决「教师写啥学生背啥」，
on-policy 解决「学生自己造的分布教师怎么管」——后者把分布失配直接从
训练循环里消掉，这是它比接 RL 便宜十倍还能多拿分的机制解释。

整条数据流串起来就是：

```text
prompt池(带答案) → 72B初筛(可验证/够难/域标注) → teacher对每题采N条
→ 验证器留正确 → 风格过滤六条规则 → 与通用SFT混合配比
→ 学生SFT → [可选 on-policy蒸馏] → 评测量化
```

## 三、数字锚：三本成本账

### 3.1 R1 产线总账（arXiv v2, 2026-01，Table 7）

- R1-Zero（基座直接 RL）花掉 **101K H800 GPU·h**；
- 造 800k 蒸馏数据：**只花 5K GPU·h**；
- R1 本体 RL（512 张 H800 约 80 小时）花掉 **41K GPU·h**；
- 三者合计 **147K GPU·h**，按 2 美元每卡时租价约 **29.4 万美元**。

金句记好：**用拒绝采样造八十万条教师轨迹，成本只有纯 RL 工位的二十分
之一**。反过来说，「teacher 推理成本常超学生训练成本」这句业内常谈在
R1 口径下也是成立的（造数据 5K vs 学生侧 SFT 的训练算力），但「蒸馏产
线贵」是相对整个蒸后训的便宜而言——后训练 147K 只占 V3 全生命周期的
约 5%，而这 5% 里数据制造又只占约 3.4%。

### 3.2 蒸馏 vs RL 的官方对照（Qwen3 TR, 2025-05）

- 小模型全线蒸馏 = 四阶段产线 GPU·h 的 **十分之一**（官方自称，未逐项
  拆分，引用时带这个标签）；
- 8B 学生冲 AIME24：off-policy 蒸馏到 55.0；在此之上接 RL 要
  17,920 GPU·h 到 67.6；换 on-policy 蒸馏只要 1,800 GPU·h 到 74.4。

同一起跑线，on-policy 蒸馏**花十分之一的算力、多拿 6.8 分**——这是
「蒸馏 > 先 RL」目前最硬的一张表。

### 3.3 蒸馏 > 小模型从头 RL（R1 v2 Appendix F）

R1-Distill-Qwen-32B 的 AIME24 得 **72.6**，对照 QwQ-32B-Preview 的
**50.0**、对照同一基座 Qwen2.5-32B 从零 RL（自训 32B-Zero）的
**47.0**——蒸馏用搬运达成了搜索达不到的高度，且便宜得多。**口径勘误
注意**：姊妹篇与不少二手材料引用的 QwQ 对照分 **44.0 是 arXiv v1 口径，
v2 已改为 50.0**，且 v2 新增了自训 32B-Zero 的 47.0 这一对照；引用统一
以 v2 为准，被追问「你怎么知道是这个数」时能说出版本差异即过关。

另有一个反向锚：六档学生里 **1.5B 档 AIME24 只有 28.9**，收益递减——
capacity gap 大到一定程度，蒸不动就是蒸不动。

## 五、工程实践：坑位与硬门

### 5.1 思考长度是隐性成本

V3 论文在讲蒸馏 R1 能力时明写要「carefully maintain the balance between
model accuracy and generation length」——教师变强很大程度上靠**想得更久**，
学生照单全收，推理服务成本与首 token 延迟一起上涨。蒸馏不是免费午餐，
链长是会遗传的，产线上必须给「生成长度」设预算项（R1-0528 在这点上的
教训详见姊妹篇 [推理模型训练专题](./推理模型训练专题.md)）。

### 5.2 配比与混合是防腐设计

R1 的 800k 里约四分之一是非推理数据；Qwen3 用 72B 给每题标 domain 保持
域平衡；简单 query 不给 CoT。三条配方的共同目标是防「一头独大 + 灾难性
遗忘」：纯推理轨迹灌出来的学生会在开放问答与安全边界上退化。

### 5.3 风格过滤是硬门，不是可选项

R1 剔除语言混杂、超长段落、CoT 混入代码块；Qwen3 六条响应过滤覆盖重复、
无推理地猜测、思考与总结不一致、文风突变。**教师垃圾轨迹会原样传给学生**
——这就是教师偏差继承的机制本体，过滤门是产线上唯一能在数据造完前拦下
偏差的位置。

### 5.4 去污染进数据门

Qwen3 第 6 条规则专门砍与评测集相似的轨迹；Tülu 3 把 decontamination
当产线标配写进报告。去污染不是「良心底线」层面的选项，而是**产线输出物
分数可信度**的前置条件——一旦下游发现污染，整条产线数据要回炉重造。

## 六、失败模式三坑

### 6.1 能力坍缩（Model Collapse）

Oxford/Cambridge 等的工作（Nature 631:755–759, 2024-07-24）给出理论
母本：递归地用模型生成的数据训练下一代模型，**分布尾部先消失、方差
塌缩**，前几代看起来没事，几代之后能力不可逆地退化。实验里当管线每次
保留约 **10** 个百分点的原始真实数据时，退化降为「轻微」。对策因此是
结构性的：蒸馏产线必须始终混真实 / 通用数据（第四节配比条的另一面），
不能让「师生闭环」变成「自产自销闭环」。

### 6.2 教师偏差继承

教师的所有系统性偏差——啰嗦、特定文风、对某类题的偏好、甚至错误——
都会随轨迹完整遗传给学生。机制链条是：垃圾轨迹 → 三低分裁判放行 →
学生 SFT 学得原样。对策就是那几道门：风格六条、裁判模型、去重、以及
最终件的**小学生消融**（把数据喂小一档学生看分数，绝不只看教师分数下
数据——这是 Tülu 3 传承下来的方法学）。

### 6.3 基准污染

两个层面的坑。其一是**泄题型**：蒸馏轨迹与评测集相似，分数虚高——
Qwen3 第 6 条规则为此存在。其二是**资源不对称型**：Cohere 等的
「The Leaderboard Illusion」（2025-04）披露，Meta 在 Llama 4 发布前
测试了 **27 个私有变体**去刷榜，Google/OpenAI 分别拿走了 Arena 约
19.2% / 20.4% 的原始数据，而 **83** 个开源模型合计只有 29.7%；额外的
Arena 数据可带来高达 **112** 个百分点的相对增益（作者自称保守估计）。
Llama 4 上线 LMArena 用的「experimental chat version」拿到 ELO
**1417**，与开放权重版本不是同一个模型——评测蒸馏产物时，先问测的
是不是同一个权重。

## 七、前沿变体：codistillation 把蒸馏左移到预训练

Llama 4 给了另一种形态，即 **codistillation**——不再等教师训完、后训练
再蒸，而是 Behemoth（288B active / 16 experts / 近 2T 总参；官方
2025-04-05 博客上标注仍在训、未发布）作为 teacher 与学生 Maverick
（17B active / 128 experts）**同步训练**，新增的蒸馏 loss 在训练中
动态加权 soft/hard targets，把 teacher forward 的计算成本摊销进
预训练。这是「蒸馏不是后训练专属、可贯穿训练全程」目前最大的公开
样本。面试里它常作为「蒸馏和预训练的边界正在消融」的证据点：信号
更早、成本结构不同（摊销而非一次性），但【教师偏差】与【污染】两
个坑在预训练期同样成立，只是过滤门更难加。

## 八、▶ 高频面试题

**Q1【极高频】为什么先蒸馏后 RL，蒸馏和 RL 在产线上是什么关系？**

串联而非二选一。成本账：R1 造 80 万条教师数据只花 5K GPU·h，R1-Zero
纯 RL 要 101K（v2 Table 7）；Qwen3 的 8B 组，on-policy 蒸馏 1,800
GPU·h 拿到 74.4，同起点 RL 要 17,920 GPU·h 才 67.6。原理账：蒸馏是
**搬运已知策略**（有教师答案可抄），RL 是**搜索新策略**（没有现成答案
只能靠奖励信号探）；产线先用便宜的搬运把上限灌到八成，再视预算用 RL
做增量。深度提示：能说出「蒸馏先定能力地板、RL 决定天花板突破」，
并给出任意一组 GPU·h 数字即满分。

**Q2【高频】小模型蒸馏的上限在哪？**

capacity gap。Distillation Scaling Laws（2025）把师生算力配比量化了：
teacher 不是越强越好，差距过大学生吃不下。实例：R1 六档里 1.5B 档
AIME24 只有 28.9，32B 档却有 72.6——同一批数据，容量决定转化率。
深度提示：追到「那怎么办」，答换更近的教师 / 课程式多档接力 / 等学生
档位。

**Q3【高频】蒸馏数据质量怎么评估？**

三层门 + 一个终检：可验证性（规则验证器，判不了的上生成式裁判模型）、
风格（Qwen3 六条：重复 / 无推理猜测 / 思考与总结不一致 / 文风突变 / 长
段落 / 代码混入）、去污染（与评测集相似度）；终检是**小学生消融**——
绝不只看教师分数。

**Q4【高频】蒸馏 vs RL 的成本，给个数量级？**

R1：后训练 147K GPU·h 里数据制造 5K（占约 3.4%）；vs R1-Zero RL 的
101K。Qwen3：蒸馏全线是四阶段产线的十分之一。再补边界：单学生 + 从零
训 teacher 时，监督学习通常更便宜（Apple, 2025）——蒸馏划算的前提是
**教师已存在或能摊销**。

**Q5【中高频】拒绝采样（RFT/RAFT）在产线上是什么位置？**

它是「中段产物反向变回 SFT 数据」的回路：中段 RL 出来的 checkpoint
对 prompt 采 N 条，只留验证通过的，回炉当 SFT 语料——R1 的 600k
推理数据就是这么来的。与 RL 的本质区分：拒绝采样**没有梯度更新，只有
选择**；RL 用奖励把概率推上去，拒绝采样把分布截断到正确侧。

**Q6【中高频】蒸馏有哪些失败模式？**

三坑连背：能力坍缩（递归吃自己数据，尾部先消失；混约一成真实数据可
明显缓解，Nature 631, 2024）；教师偏差继承（垃圾轨迹直通学生，对策是
风格过滤 + 裁判）；基准污染（Qwen3 第 6 条去污染规则；Llama 4 的 27
个私有变体刷榜案例）。深度提示：每坑能说清「机制链条 + 对策 + 出处」。

**Q7【中频】codistillation / 预训练期蒸馏是什么？**

Llama 4 Behemoth 与 Maverick 共训：教师边训边教，蒸馏 loss 动态加权
soft/hard targets，teacher forward 成本摊销进预训练。与常规后训练蒸馏
的区别：信号更早、成本从一次性变摊销；代价是过滤门更难前置。

**Q8【中频】评估蒸馏模型时注意什么？**

两条纪律：pass@1 的采样参数必须声明（R1 口径是 T=0.6 / top-p 0.95 /
64 次采样）；Arena 类开放评测要区分**定制版本与开放权重版本**（Llama 4
的 1417 ELO 是 experimental chat version，不是你下载到的那个模型）。

**浅档过关标准**：背得出主线一句话 + 两组锚（R1 的 800k 与 5K vs 101K、
Qwen3 的十分之一与 1,800 vs 17,920）。**深档**：能画五段产线图、指出每段
成本占比来源（v2 Table 7 / Qwen3 TR），并能讲 v1/v2 口径漂移与
Leaderboard Illusion 的方法论批判。

## 九、产线速记卡（三十秒复述版）

- 产线五段：选师生对与原料库 → 冷启动 SFT → （中段 RL 工位）→ 拒绝
  采样造数据 → 蒸馏 SFT 与 on-policy 收尾。
- 数据三门：可验证性（规则 / 裁判模型）、风格（Qwen3 六条）、去污染
  （Qwen3 第 6 条是产线默认门）。
- 成本三角：造数据 **5K** vs R1-Zero RL **101K** vs R1 本体 RL **41K
  GPU·h**，合计 147K（v2 口径，2026-01）。
- 官方对照：Qwen3 8B 组 55.0 起步，RL 花 17,920 GPU·h 到 67.6，
  on-policy 蒸馏花 1,800 GPU·h 到 74.4；小模型全线蒸馏为产线
  GPU·h 的十分之一（官方自称口径）。
- 三坑一句话：递归自食会坍缩、教师垃圾会遗传、分数先问他污没污染。
