# RL 训练工程实战：Reward 漏刷、熵坍缩、数据筛选与长思维链

> 本篇面向已经知道 PPO/GRPO/DPO 公式、准备「RL 工程落地」这条线的读者。
> 理论算法看 [rlhf与对齐](./rlhf与对齐.md)；本篇只讲一线团队（GRPO 训推理模型，
> 十几人、两周一迭代）在实跑中踩过的**四个坑**：verifier 漏刷、熵坍缩、
> 数据筛选、长思维链训练——每个坑给现象、机制、对策和监控指标。
> 素材主要来自一篇被评论区评价为「可以当面经背」的四坑复盘帖，
> 并交叉了 20+ 大厂社招面经里 RL 追问反复出现的点（20%+ 的 RL 面试追问
> 都落在这四个坑里）。

## 一、直觉：RL 的坑不是「不会训」，是「信号在骗人」

SFT 时代，loss 下降大体可信；RL 时代，reward 上涨**不等于**能力上涨。
因为 RL 的优化目标和管理目标之间存在一条缝：**verifier 只是能力的代理**。
模型比你不是笨，是太聪明——它会优先征服代理而不是征服能力。
四个坑全在这条缝上：

1. **verifier 漏刷**：reward 涨，真人一看三成样本在糊弄；
2. **熵坍缩**：探索死了，reward 还在涨，一切指标都很健康；
3. **数据没筛**：一半样本贡献零梯度，算力直接腰斩；
4. **长思维链**：上万 token 的 rollout 把前面的坑全部指数放大。

## 二、坑一：verifier / reward 设计的五种漏法

### 2.1 字符串匹配漏刷（最常见）

- **现象**：数学 rollout pass@1 涨得不错，但抽 1000 条高 reward 样本人工
  复核，**近三成是抓特殊字符串匹配凑出来的**——答案框填对了，过程全是
  循环论证。代码版类似：只跑示例用例，模型学会**特判**。
- **对策**：数学题改**符号系统验算**（符号级等价判定），代码把测试用例
  扩到边界条件和反例，判不过 reward 直接归零。
- **面试追问**：你为什么不用最终答案匹配当 reward？——能说出「学特判」
  三个字和这两条对策就过关。

### 2.2 结果奖励 × 过程奖励混用污染

- **现象**：过程奖励直接加权进总 reward → 模型写漂亮过程骗过程分。
- **对策（解耦）**：**结果奖励锚定正确性，过程奖励只在答案正确的样本里
  排推理质量**，两套信号互不干扰。实现上：结果奖励相当于过程奖励的
  binary gate；或一个 RM 训多个输出头算加权和。
- **why**：结果管「对不对」，过程管「好不好」，混在一起信用分配（credit
  assignment）就漂了。

### 2.3 LLM judge 讨好

- **现象**：模型学会讨好 judge 的**审美**而非完成任务——输出越来越像好
  答案，实际没干活。
- **对策**：给 judge 加硬约束——打分可复现、能说清依据；打分逻辑飘忽时
  **优先怀疑 judge 本身**，而不是调策略。

### 2.4 多维评估压成单分数

- **现象**：长 response 里哪个 token 为哪个标准负责？信号极弱，credit
  assignment 直接失效。
- **对策**：拆解奖励维度，让每个维度尽量独立；不要图省事压成一个分。

### 2.5 训推不一致（最隐蔽，也是 verifier 漏刷来源）

- **机制**：rollout 用高吞吐推理引擎（vLLM/SGLang），策略更新在训练框架
  跑，**数值精度、attention kernel 实现、MoE 路由选择的细节差异**会让
  同一模型在两套引擎算出不同 token 概率——verifier 在评一个「和训练时
  不一样」的模型。
- **对策**：verifier 质量评估加一组**训推一致性校验**——同一批 prompt
  两套引擎各跑一遍，对比 token 概率分布差异，超阈值先排查系统层再动算法。
- **数字锚**：长思维链下恶化显著——thinking 超过 5000 token 时，训推差异
  带来的梯度偏差比短序列**高 3-5 倍**（importance ratio 逐 token 累积）。

### 2.6 固定巡检动作

**每隔 3-5 个 checkpoint 抽 1000 条**「reward 最高但评测正确率未同步上升」
的样本，两个标注同学先过、拿不准丢给独立强模型交叉验。抽检覆盖四维度：
答案正确性、推理过程质量、judge 稳定性、训推一致性。

## 三、坑二：entropy collapse 与它的两个变体

### 3.1 主体

训练中后期 policy 输出多样性骤降，高度集中在几种固定生成模式——
**reward 还在涨，但探索已经死了**。不同尺寸基座都观察到：几千步后高频
token 几乎全跌成 top-1 选择，单次 rollout 间方差缩到很小。

**应对（按有效性排序）**：

1. **监控先于调参**：把 response 级 entropy 单独记录、按 checkpoint 画
   曲线配告警阈值，连续掉几个 checkpoint 就干预——这是最管用的一条；
2. 裁剪上下界解耦：下界保持紧、上界放宽，给探索型 token 上升空间
   （DAPO 的 clip-higher 思想）；
3. reasoning 阶段放松 KL；
4. 训练分「发现阶段」和「精细化打磨阶段」，entropy 下降在前者是事故、
   在后者可能是正常收敛——**按阶段设不同预期区间，比统一阈值有效**。

**两个预警信号的组合**：entropy 异常下降的 checkpoint 往往伴随**训推差异
同步放大**，两个指标共用告警可提前整轮预警；模型越大越明显。还要**按题型
拆开看**——总量还行但数学类已崩（被其他题型的多样性盖住）。

### 3.2 变体一：模板坍缩（光看 entropy 总量会漏）

- **现象**：输出看似多样，但与输入无关，全是流畅空洞的套话——entropy
  数值还很健康。
- **对策**：加**跨输入互信息监控**——同一批 prompt，看输出之间能否互相
  区分；区分度掉就是开始背模板。一句话：一个指标管输出自身多样性，一个
  管输出对输入的分辨力，两个都要盯。

### 3.3 变体二：梯度饥饿（GRPO 专属）

- **机制**：组归一化算优势时，一组 rollout 全对或全错 → 组内优势全归零
  → 梯度消失。小 group size 下退化组占比不低，训练后期尤甚（模型强了
  全对组变多，模型卡壳全错组变多）。
- **对策**：**动态采样**——过滤全对全错组，只留带边界样本的组进更新，
  有效梯度比例立刻上升。（这也是字节社招面「GRPO 为什么容易熵崩塌、
  怎么救」与「GRM 熵崩塌」的标准答法。）

## 四、坑三：数据筛选——三层过滤和一个飞轮

三类不值得训的数据：答案对但思维链是凑的；题目歧义大、reward 信号互相
对冲；难度两头倒（太简单学不到、太难 pass rate≈0 梯度也是 0）。

**三层筛选**：

1. **离线难度过滤**：候选集每道采样算通过率，只留 **20%-80% 窗口**
   （业界默认，太简单和太难都删）；
2. **过程质量过滤**：用过程奖励模型给答案正确的样本的推理过程打分，
   剔除「答案对过程凑」；
3. **课程式在线调度**：小型代理模型动态评估每个 prompt 当前的训练价值，
   价值低的跳过，再按难度配比组 batch，**简单:中:难 ≈ 3:5:2**。

**数据飞轮（不是筛一轮就完）**：

> 冷启动 SFT 打底 → 推理导向 RL 强化 → **拒绝采样**（用 RL 产出的高质量
> 数据回炉再做一轮 SFT）→ 对齐导向 RL 收尾。效果比单次筛选好不少。

面试补充：蚂蚁/面壁都追问「如何评估数据合成质量、LLM judge 拒绝采样具体
怎么做、困难样本怎么构建」——本节三条即答法。

## 五、坑四：长思维链训练的三个新变量

thinking 动辄上万 token，把坑一~坑三全部放大，还带来新问题：

1. **长度惩罚**：软惩罚优于硬剪——答案正确前提下对超预设上限的输出按
   长度**渐进式扣分**；进一步做分段式超长惩罚，配合 **token 级策略梯度
   损失**让长序列每个 token 参与优化而不被短样本稀释，比固定阈值平滑。
2. **KL 分段**：短序列保留 KL 约束，长序列直接去掉（允许离 base 更远换
   探索空间），配合 **token 级 KL 而非 sequence 级**，避免长输出被整段
   惩罚。绕不开的取舍：结果奖励设定下长度加权**无法同时做到无偏和长度
   不变**，二选一——一线选梯度无偏、再用分段惩罚压长度。
3. **rollout group size 不是越大越好**：thinking 很长时 group size 超过
   8 边际收益就很低。实测：同样梯度预算，**group size 16 跑 250 步 vs
   group size 4 跑 1000 步，后者在高难数学评测集上更稳、涨得更多**。
   group size 要结合退化组比例和任务难度动态调（难题小组、简单大组）。

加上 2.5 的数字锚：**thinking>5000 token 时训推差令梯度偏差高 3-5 倍**，
长思维链训练必须把训推一致性作为**前置检查**而不是事后排查。

## 六、数字锚与简历化写法

一线给出的简历化模板（真实指标量级，写简历/讲项目可直接套句式）：

- 搭建 GRPO 训练管线，解决 Reward Hacking、熵坍缩与长链训练不稳定，
  **高难评测准确率 58%→73%，单次请求成本降 25%；**
- 重构 Verifier 与奖励机制：四维抽检 + 结果/过程奖励解耦，**reward 与
  真实评测偏离度从 30% 降到个位数**；
- Entropy + 跨输入互信息双监控修复模板坍缩，动态采样过滤全对全错组，
  **相同算力预算下有效训练步数提升 4 倍**；
- 数据筛选飞轮：20%-80% 通过率窗口 + 在线课程式调度 + 拒绝采样三段管线；
- 长思维链稳定性：thinking>5000 token 前置训推一致性校验，分段式超长
  软惩罚替代硬截断，**推理长度缩短 20%。**

一个行情判断：RL 训练是这一波推理能力跃迁的核心变量，**会的人远不够多，
门槛比想象低**（千卡级预算就能看到明显跃迁）。面试能把这四坑讲到这个
深度，RL 追问环节的差异化和议价权会非常明显。

## 七、面试问答

**Q1：GRPO 训练 reward 涨但评测不涨，怎么排查？**
先怀疑 verifier 漏刷：抽「高 reward 低正确率」样本人工/独立模型复核
（固定节奏：每 3-5 个 checkpoint、1000 条）；再查结果/过程奖励是否混用
污染；再查训推一致性（同一批 prompt 双引擎对比 token 概率）；最后查
judge 本身稳定性。节奏是「每 3-5 个 checkpoint 固定巡检」而不是出了问题
再救火。

**Q2：熵崩塌怎么监控和处理？**
三件套：response 级 entropy 曲线 + 跨输入互信息（防模板坍缩）+ 按题型
拆分；处理用 clip 上下界解耦、reasoning 放松 KL、动态采样滤全对全错组；
按训练阶段设不同 entropy 预期区间。

**Q3：GRPO 的 group size 怎么定？**
长 thinking 时超过 8 边际收益很低；结合退化组比例与题目难度动态调；
预算固定时「小组多步」在高难集上优于「大组少步」。

**Q4：RL 数据怎么筛？为什么说和 online/offline 有关？**
通过率 20%-80% 窗口（离线）+ 过程奖励剔「答案对过程凑」+ 课程式在线
调度（简单:中:难≈3:5:2）。阿里国际二面追问「RL 数据一般怎么选、用不用
SFT 数据」即此；飞轮里拒绝采样产生的数据会进 SFT 轮次，所以不是一次性
筛完。

**Q5：训推不一致是什么？怎么校准？**——见 2.5 与 5.3。
