## 一、主线直觉：知识写进参数，还是写进上下文？

一句话直觉：**大模型时代的「持续学习」已经从学术上的灾难性遗忘问题，
分化成四种工程形态，核心权衡只有一条——新知识写入「参数」还是写入
「上下文/外部存储」。**

写参数：一次训练，之后**每一次推理都免费携带新知识**，便宜地服务所有
请求；代价是更新有风险——新分布的梯度可能把旧能力冲掉（灾难性遗忘）。
写上下文/外部：RAG 检索、记忆外挂、提示词注入，**灵活、无损、可溯源、随
改随生效**；代价是每次请求都要花 token、花延迟，且模型并没有真的「学会」
——换个问法、换个组合可能就调用不出来。

[预训练与sft](./预训练与sft.md) 里那句「垂域续训要混 10%~30% 通用数据防
遗忘」是这个框架在「继续预训练」象限里的一条防线；本篇把四象限全部铺开，
讲清每个格子的代表方法、成本量级、失效模式和它们怎么叠加。记住生产现实：
**四者从不互斥，真实系统几乎都是「续训打底 + RAG/记忆补时效 + RL 反哺 +
评估闸兜底」的叠加态。**

## 二、四象限地图：持续学习的四种工程形态

两轴定位全篇：**写入位置**（参数 θ / 外部与上下文）× **触发时机**（离线
批式 / 线上推理时）。四个格子各有正统代表：

| 形态 | 写入位置 | 触发时机 | 代表方法 | 一句话代价 |
|---|---|---|---|---|
| 继续预训练/继续微调 | 全量参数 θ | 离线批式 | CodeLlama、DeepSeekMath、ChipNeMo | 有遗忘风险，要 replay + 回归评估 |
| 参数高效续接 | 增量参数（LoRA/adapter） | 离线批式 | LoRA 叠加、skill adapter | 服务侧要为多 skill 付钱 |
| 测试时训练 TTT | 临时参数副本（或隐状态内嵌权重） | 推理时、逐样本 | MIT TTT、TTT layer、Titans | 每个样本多花几步梯度的钱 |
| 记忆外挂 | 提示词 / KV / 向量库 / 图记忆 | 推理时读取 | RAG、Mem0、Letta | 每次都花 token 与延迟 |

### 2.1 继续预训练（参数 × 离线）：垂域能力的主干写入方式

把基座 checkpoint 放到垂域语料上**重新 warmup 学习率、cosine 衰减续训**，
这是「术语、推理习惯、领域先验」写进模型的唯一正经通道——RAG 可以给模型
喂事实，但喂不了「像芯片工程师一样思考」的分布。第三节给三个配方级案例。

### 2.2 参数高效续接（增量参数 × 离线）：物理隔离的防遗忘

不动基座、每接一个领域叠一个 LoRA/adapter，新旧知识在参数空间里**物理
隔离**，天然绕开遗忘。代价在服务侧：多 skill 意味着多 adapter 的加载、
路由和显存账（生产侧的 kernel 与服务化细节见
[多lora-serving专题](../inference/多lora-serving专题.md)；LoRA 本体见
[lora与参数高效微调](./lora与参数高效微调.md)）。

### 2.3 测试时训练 TTT（临时参数 × 线上）：把梯度推到推理时刻

对每个测试样本，现场用自监督 loss 反向传播一版**临时参数**，预测完丢弃。
它回答的问题是：ICL 把示例摆在上下文里「看」，TTT 把示例**用梯度写进
权重**再推理——对结构新奇的任务，前者存在补不掉的 gap。机制与数字见第
五节；架构化路线（TTT layer、Titans、HOPE）把「学习」直接做成前向传播的
一部分，也归这个格子。

### 2.4 记忆外挂（外部 × 线上）：时效与个性化的补位

向量库/KV/图记忆在推理时读写，**不改任何权重**，适合时效性高、量小、要
可溯源的知识，以及跨会话个性化。生产数字见第六节（Mem0 的延迟与成本
实测）。这个格子的存储架构归 agent 侧记忆专题
（[agent记忆产品化专题](../agent/agent记忆产品化专题.md)），本篇只把它
当「学习闭环里的一个写入选项」来比。

### 2.5 决策边界：RAG 还是续训？

被问「垂域落地走哪条」时的判据：

- **知识时效性高、量小、要可溯源** → RAG + 记忆外挂；
- **术语体系、推理习惯、领域先验漂移**（要「懂行」而不只是「知道」）
  → 继续预训练；
- 两者不是互斥选项：**续训教分布，RAG 喂事实**，生产里几乎总是组合使用。

## 三、继续预训练配方：三个教科书案例与成本锚

### 3.1 CodeLlama（Meta，2023）：续训范式的标准动作

Llama 2 基座 → 续训 **500B tokens 代码**（70B 版加码到 **1T tokens**），
数据约 85% 代码 + 从相关自然语言数据抽样约 **8% 的量**；CodeLlama-Python 再续
100B tokens（CodeLlama，arXiv:2308.12950，2023）。收益：HumanEval
**提升 4.3~8.3 个百分点**、MBPP **提升 1.2~6.4 个百分点**。

最有信息量的反事实实验：从零下同样数据配比训一个模型，最终 loss 只相当于
CodeLlama 7B 训到一半的位置——**续训比「从零重训同配比」省下约 240B
tokens 的训练量**（同上，2023）。这是「先通用基座、后垂域续训」路线经济
学成立的直接证据。

### 3.2 ChipNeMo（NVIDIA，2023）：1.5% 成本拿到垂域 SOTA

内部芯片设计语料 **23.1B tokens**，领域自适应预训练（DAPT）成本约为
**约为从头预训练 1.5% 的成本**（128 卡 A100，ChipNeMo，arXiv:2311.00176，2023）。
ChipNeMo-70B 在工程助手和 EDA 脚本两个用例上**超过 GPT-4，且通用能力
不降级**。论文把「通用不降级」部分归因于**小学习率**——这个归因和第三
方「replay 比例」经验是两条并行的防遗忘旋钮，别混为一谈。

### 3.3 DeepSeekMath（DeepSeek，2024）：代码基座到数学专精

从 DeepSeek-Coder-Base-v1.5 7B 继续预训 **120B 数学 tokens**（Common
Crawl 萃取）+ 自然语言与代码数据，MATH **达 51.7%（论文口径）**（无工具无投票；自
一致性 64 采样 **达 60.9%（同上）**，DeepSeekMath，arXiv:2402.03300，2024）。
「代码基座 → 数学专精」的配方后来被广泛复制——代码预训练给的符号操作
与长程依赖习惯，是数学推理的好底子。

### 3.4 数据流水线与旋钮

标准流水线：**基座 checkpoint → 构造垂域语料 ⊕ 通用 replay 混样 →
LR rewarm 到峰值 → cosine 衰减续训 → 三轴评估闸**（新垂域 / 旧垂域 /
通用套件）。关键旋钮三个：

1. **replay 比例**：公开配方只有 CodeLlama 续训阶段混 8% 相关自然语言、
   Instruct 阶段回混 6% 代码 + 2% 自然语言防代码能力回退（2023）；本仓
   既有文档的 10%~30% 是社区经验区间（口径见第九节）。比例与「垂域分布
   离通用分布多远」正相关，**定比例靠通用套件回归评估闭环，不是拍脑袋**。
2. **LR rewarm 幅度**：换数据分布后接着用原训练尾部的残余 LR 效率低；
   重新 warmup **短期推高 loss 属正常现象**（Thérien 等在 Pythia 410M
   上从 Pile 300B 续训 SlimPajama 297B 的实证，arXiv:2308.04014，2023），
   长期下游性能反而优于从头训练。**看到 loss 跳涨就 panic-rollback 是
   大忌**；配套上 optimizer 状态是否重置要慎重（经验上保留 momentum
   利于平滑，无统一结论，属工程估算）。
3. **续训 token 量级**：典型案例带 **2×10¹⁰ ~ 5×10¹¹ tokens**——
   ChipNeMo 23.1B（2023）、DeepSeekMath 120B（2024）、CodeLlama
   500B（2023），约占基座预训练量（Llama 2 为 2T tokens，2023）的
   **一到两成**，成本占一到几个百分点。

### 3.5 成本锚：为什么不能每次都全量重训

Llama 2 全家族预训练累计 **3,311,616 GPU 小时**（A100-80GB），其中 70B
单模型 **1,720,320 GPU 小时**、排放 **539 吨 CO₂e**（Llama 2，
arXiv:2307.09288，2023）。也就是说每来一个领域、每做一次月度数据快照就
全量重训，**光排队和电费就直接否决这个选项**；ChipNeMo 用 **约 1.5%
成本**拿到垂域收益的事实，把「续训 vs 重训」从偏好问题变成了算术问题。

## 四、灾难性遗忘：机理、处置顺位与测量姿势

### 4.1 LLM 版的遗忘机理

经典定义：学习新分布的梯度把权重拉离旧任务的最优区域。LLM 时代的表现更
微妙——**「能力退化」比「任务遗忘」更可见**：不一定是某个 benchmark 精度
崩了，而是通用 benchmark（MMLU 类）掉点、指令跟随变钝、格式变得不稳定。
Luo 等在 1B~7B 模型连续指令微调中确认遗忘普遍存在，且该规模区间内
**模型越大初始性能越好、相对遗忘越明显**（arXiv:2308.08747，2023）。

放大规模的直觉：当前 LLM **过参数化 + 数据多样性本身就在缓和遗忘**——
参数冗余足够大时，新知识的写入有「空地」可用。这正是工业上 replay 主导、
正则化边缘化的根本原因。

### 4.2 工业处置顺位

**replay（主流）＞ 参数高效增量隔离（次选）＞ 正则化（论文里有，生产里
少见）。**

1. **replay**：续训语料里混入通用/旧领域样本，让新梯度在旧数据流形上
   近似「零投影」——经验上这就是缓解分布漂移最有效的杠杆，且零侵入、
   与现有训练栈完全同构。CodeLlama 的 8% 与 Instruct 回混 6%+2% 是公开
   锚点（2023）。
2. **增量隔离**：LoRA 叠加把新旧知识放进不相交的参数子空间，遗忘在结构
   上不可能发生——代价前移到服务侧（多 adapter 路由与显存）。
3. **正则化**：下一小节说为什么不流行。

### 4.3 EWC 类正则为什么不进生产栈

EWC（Kirkpatrick et al.，DeepMind，PNAS 2017）给每个参数记一份 Fisher
信息，按「对旧任务的重要性」惩罚漂移。在 LLM 上不实用，三个理由：

- **存储与维护开销**：Fisher 是 O(参数量) 的常驻状态，且**每接一个任务
  就多要维护一份**——70B 模型一项任务一份 Fisher 就是一笔显存账；
- **任务边界不存在**：EWC 假设「任务 A 学完、有明确边界、开始任务 B」，
  而 LLM 续训面对的是连续数据流，边界本身就模糊，Fisher 对齐不到「旧
  任务」；
- **机会成本**：同样的显存/算力预算拿去做**数据 replay 收益更高、实现
  零侵入**，叠加过参数化本身已缓和遗忘——正则化的边际收益撑不起复杂度。

面试被追问时的收口：不是 EWC 理论错了，而是 **LLM 时代的遗忘问题被「数据
侧工程 + 参数冗余」廉价地解掉了大半**，剩下的小头不值得为它维护一套
重要性估计系统。

### 4.4 定量测量姿势

- 永远**保留一版 frozen 基座**当对照；
- 每版续训跑**三轴 diff**：新垂域套件（拿收益）、旧垂域套件（查前序能力
  没丢）、通用套件（MMLU/HellaSwag 类，查能力退化）；
- Luo 2023 的结论提醒：**在 1B 到 7B 区间，模型越大遗忘越显著**，别拿小模型
  消融外推大模型的防遗忘表现；
- 评估闸要进流水线而非事后补：旧垂域/通用掉点超阈值就回到配比调优，
  这是「定 replay 比例」的唯一正规姿势。

## 五、TTT 与测试时算力：把梯度推到推理时刻

### 5.1 MIT TTT 的机制（留一重建）

MIT 的 TTT（Akyürek et al.，arXiv:2411.07279，2024-11 v1 / 2025-03 v2）
做法：对每个测试样本，用「留一法重建 in-context 示例」构造自监督 loss
——把示例里每个输入输出对轮流遮住一个，让模型从其余示例学出重建它的
规律——反向传播**几步梯度更新一版临时 LoRA**，用它做预测，**预测完丢弃
临时参数**。配合数据增广（ARC 网格的旋转/翻转）自举出多个「训练集」，
对增广副本投票/集成。

一句话读法：**就是 ICL 让模型「看着」示例推理，TTT 让模型先「练会」示例再
推理**——后者对结构新奇任务能补上前者补不掉的 gap。

### 5.2 数字边界：两个数各是什么口径

- ARC 公开验证集：8B LM **单模型 53.0%（单跑口径）**（较精调基线最多 6 倍）；
  与程序合成**集成后 61.9% 约等于人类平均**。（同上，2024/2025）
- BBH 10-shot：**从 50.5% 提到 57.8%（官方口径）**。

面试高频坑：**这个 61.9% 是 TTT 加程序合成的 ensemble，不是纯 TTT
单模型数字**；把集成数说成 TTT 单独功劳，会被当场拆穿。

### 5.3 TTRL 与 Absolute Zero：无标注日志也能用

- **TTRL**（清华等，arXiv:2504.16084，2025-04）：在**无标注测试数据**上
  做 RL，用**多数投票当奖励**；Qwen2.5-Math-7B 在 AIME24 的 pass@1
  **提升约 211%（官方口径）**，且超越初始模型 maj@n 的上限，逼近用真值标签直接训练。
- **Absolute Zero**（清华/BIGAI，arXiv:2505.03335，2025-05）：零外部
  数据自我进化——同一模型**出题 + 解题**，代码执行器当可验证奖励源，
  零设置下代码/数学推理整体 SOTA。

这两篇把「自我改进」从叙事变成配方：**可验证场景（代码/数学）连标注都
不需要**，执行器或自洽投票就是奖励源。这也是线上日志回流的第三条路径
（第六节）的理论地基；RL 训练细节本身归
[agentic-rl专题](./agentic-rl专题.md)。

### 5.4 TTT vs ICL vs TTS：三种「测试时」各花什么钱

- **ICL**：不改权重，受上下文长度封顶；
- **TTT**：每样本花「增广副本 × 几步梯度」的钱，把示例写进临时参数；
- **TTS（test-time search）**：不改参数，花 token 搜索推理路径。o3 是
  典型：ARC Prize 官方口径（2024-12）公开验证集 **75.7%** 用
  **33.5M tokens（$2,680 / 100 题，高效档）**；要 87.5% 那档得用 **5.7B
  tokens（$456,000，低效档）**——约 **172 倍**计算差。

口径边界（重要）：ARC Prize 官方分析推测 o3 的机制是 CoT 自然语言
program search，**不属于参数更新型 TTT**——把它当 TTT 的例子会被纠正。
正确说法是：**两者是互补可叠加的两条线，都姓「测试时算力换
能力」**（o3 的 87.5% 那档本身也是搜索与某种自适应的组合，细节未公开）。

### 5.5 架构化路线：把「学习」做进前向

另一条线干脆把参数更新藏进架构：

- **TTT layer**（Sun et al.，arXiv:2407.04620，2024）：隐状态本身是一个
  小模型，前向传播的「更新规则」就是一步自监督学习；
- **Titans**（Google，arXiv:2501.00663，2024-12-31）：用 **surprise
  门控**的神经长期记忆模块，超出预期才写入；NIAH 在 **超 2M 上下文**上
  优于 Transformer 与现代线性 RNN 基线；
- **Nested Learning / HOPE**（Google Research，NeurIPS 2025，官方 blog）：
  把模型与优化器统一建模为**多层嵌套优化问题**，continuum memory system
  让不同模块按不同频率更新；自修改架构 HOPE（Titans 变体）在语言建模与
  长上下文记忆上优于现代 recurrent 与标准 Transformer。

**这是 2025 下半年大厂直接把 continual learning 当第一性问题的信号**：
记忆不再是数据侧的补丁，而是「进前向、梯度可学、遗忘可学」的正式组件。
2026-10 社区实测：TTT 主题 repo 持续活跃（ViTTT 视觉 TTT 394 star、ARC
Prize 2026 解法大量 hybrid DSL+TTT）——**TTT 是 2026 的科研/竞赛热点，
但尚未成为生产推理标配**（口径见第九节）。

## 六、生产闭环：线上日志回流训练的三条路径

### 6.1 三路径

线上 agent 日志 → 质量门（验证器通过率 / 质量分 / 采样与脱敏）→ 分流：

1. **蒸馏进 SFT 池**：小步快跑、周级发布，承接格式与高频失败模式；
   （生产线的拒绝采样与蒸馏细节见
   [post-training蒸馏生产线专题](./post-training蒸馏生产线专题.md)）
2. **合并入继续预训练语料**：低频大批量、季度级模型更新，承接分布漂移；
   回到第三节的续训配方，同样要过 replay 配比与三轴评估闸；
3. **在线 RL**：可验证奖励场景（代码执行、数学校验、工具调用成败）直接
   做 RL；TTRL 证明**无标注日志也能用多数投票当奖励**，Absolute Zero
   证明**出题权都可以交给模型自己**。

三条路径之后统一走**影子评测 → 灰度上线**，任何一版掉回三轴评估闸之外
就回滚——闭环图上「灰度上线」不是装饰，它是防遗忘在发布侧的最后一个
闸门（发布与回滚的系统化做法见
[llmops 与模型发布专题](../llmops与模型发布专题.md)）。

### 6.2 Sleep-time compute：离峰消化上下文

Letta 系的 Sleep-time Compute（arXiv:2504.13171，2025-04）：在离峰
「睡梦中」**预计算上下文表征**，测试时直接复用——同等精度下测试时计算
**省约 5 倍**；加大 sleep compute 在 Stateful GSM-Symbolic / AIME 上再
**分别提升 13% 与 18%（同口径）**；多查询摊薄后单查询成本**降 2.5 倍**。它是「写外部」
与「测试时算力」的混血：**把测试时的钱挪到空闲时段先花掉**。

### 6.3 记忆外挂的生产数字

Mem0（论文 2025-04 + 仓库 2026-10 实测 **67.0k star**）：对比全上下文，
**p95 延迟降 91%、token 成本省超 90%（论文数字）**，LLM-as-a-Judge 相对 OpenAI 记忆
方案**提升 26%（同上口径）**。Letta（**共 25.1k star**）+ sleep-time compute 是另一条
「离线消化上下文」路线。这两个数字是「写外部」象限在生产里站得住的
直接证据：大部分个性化/时效知识**不值得为它更新参数**。

## 八、▶ 面试题 8 条

**Q1【极高】为什么不能每次上线都全量重训？**
成本锚：Llama 2 70B 单模型预训练 **1,720,320 A100 GPU 小时**（2023），
每来一个领域或每月快照就重训，成本与排队直接否决；ChipNeMo 证明**约
1.5% 成本**即可拿到垂域收益（2023）。论证框架按三轴展开：成本、时效
（重训周期赶不上数据漂移）、回归风险（每次重训都是新的能力骰子）。（§3.5）

**Q2【极高】垂域落地走 RAG 还是继续预训练？决策边界？**
知识时效性高、量小、要可溯源 → RAG + 记忆外挂；术语体系、推理习惯、
领域先验漂移 → 续训；**两者不互斥，续训教分布、RAG 喂事实**。追问
「LoRA 呢」：多垂域并存、要防遗忘、服务侧能接多 adapter 时选增量隔离，
代价在多 skill 的路由与显存。（§2.5、§4.2）

**Q3【高】续训时 replay 比例怎么定？**
公开配方锚点：CodeLlama 续训混约 8% 相关自然语言，Instruct 阶段回混
6% 代码 + 2% 自然语言防代码回退（2023）；社区经验区间 10%~30%（口径见
第九节）。比例随「垂域与通用分布的距离」单调调整；**定比例靠通用套件
回归评估闭环：frozen 基座对照 + 三轴 diff + 掉点超阈回配比调优**——
不是拍脑袋。ChipNeMo 走的是另一条：小 LR 保通用能力而非大 replay
（2023）。（§3.4、§4.4）

**Q4【高】灾难性遗忘为什么在 LLM 时代用 replay 不用 EWC？**
三点：Fisher 是 O(参数量) 常驻存储且每接一个任务多一份；连续数据流下
任务边界本来就不清晰，重要性估计对不上「旧任务」；同样预算做 replay
收益更高、实现零侵入，叠加 LLM 过参数化 + 数据多样性本身已缓和遗忘
（Luo 2023 的 1B~7B 实证提示小模型区间遗忘仍普遍）。处置顺位收口：
**replay 主导 ＞ LoRA 物理隔离 ＞ 正则化边缘化**。（§4.2、§4.3）

**Q5【高】TTT 和 in-context learning 的边界？**
ICL 不改权重、被上下文长度封顶；TTT 把示例用梯度写进临时参数。MIT 论文
单模型 53.0% 较精调基线最多 6 倍，说明 ICL 对结构新奇任务存在补不掉的
gap；但注意口径——ARC **61.9% 是 TTT + 程序合成的 ensemble 而非纯 TTT**。
机制追问要能讲「留一重建」：把 in-context 示例轮流遮住一个、以其余示例
自监督重建，几步梯度更新临时 LoRA，预测完丢弃。（§5.1、§5.2）

**Q6【高】线上 agent 日志怎么回流训练？画闭环。**
日志 → 采样/脱敏/质量过滤（验证器通过率、质量分）→ 三分支：蒸馏数据池
进 SFT 小版本（周级）、汇入续训语料走季度级续训（要过 replay 配比与三轴
评估闸）、在线 RL；可验证场景连标注都能省——TTRL 多数投票当奖励、
Absolute Zero 执行器当奖励源；最后统一影子评测 → 灰度上线 → 掉点回滚。
（§6.1）

**Q7【中深】为什么 replay 有效？**
直觉：新梯度在旧数据流形上被「约束」——混样让每步更新同时在旧分布上
不离群，等价于经验重放缓解分布漂移；再往上可接 continual learning 理论
谱系（重放类 / 正则类 / 结构类三分）。工程呼应：replay 的「混入什么」
比「混多少」更难——垂域分布离通用越远， replay 越要包含真正通用的
那部分而非随便凑数（属工程经验，口径见第九节）。（§4.2）

**Q8【中深】Titans/HOPE 这类「记忆即架构」路线和标准 attention + 外挂
RAG 的本质差异？**
记忆是否进前向：Titans/HOPE 的记忆是模型内部组件，**写入与遗忘都是梯度
可学的**（surprise 门控决定写什么、CMS 决定各模块更新频率）；外挂 RAG
的记忆在数据侧，**读出质量依赖检索器**，模型本身对「该记什么」无学习
信号。前者天花板高但要重训架构，后者即插即用但学到的东西每次都要重新
「看」。2025 末 Nested Learning 把这条线升级成「把优化器也建模进嵌套
优化」，是大厂把 continual learning 当第一性问题的信号。（§5.5）

**深浅两档**：浅档——四象限 + 三组已核实数字（续训 500B/23.1B/成本
1.5%、1,720,320 GPU 小时、53.0%→61.9%）足以应付大多数厂；深档——要能
讲清 TTT 留一重建 loss、LR rewarm 实证（arXiv:2308.04014）、TTRL/AZR
的无标签奖励设计，以及 Nested Learning 对「持续学习进架构」的定位。
