## 〇、直觉：o1 留下的问题

2024-09 o1 证明了一件事：**更多训练期 RL 加更多测试期 thinking 就是更强推理**。
但它把配方完全封闭——DAPO 论文开篇就以这个黑盒立论。于是 2025 年整个行业只做
了三件事：**开源化、降成本、修副作用**。R1（2025-01）把四段式 pipeline 开源成
教科书，Qwen3（2025-05）、Kimi K2 Thinking（2025-11）、GLM-5（2026-02）沿同一
骨架各改各的比例；DAPO/GSPO 负责修副作用的稳定性半区；长度控制与 test-time
compute 接口则把「补丁」升级成「产品形态」。

## 一、主线一：冷启动 + RLVR 主循环

### 1.1 R1-Zero：纯 RL 能涌现什么，不能涌现什么

R1-Zero 直接在 base 上跑 GRPO 加规则奖励——数学用 is_equivalent 判对、代码用测
试用例判过，**没有任何 SFT 步骤**。结果官方口径写得很硬：**官方复盘级成绩 AIME24 pass@1 从 15.6 爬到 77.9、cons@16 达 86.7**（R1 Nature 版 2025），
自我反思、自我验证、策略切换在训练中途自发涌现，反思段的英文 wait 词频出现
著名的突变尖点，社区称之为 aha moment。超参几乎全公开：LR 3e-6、KL 0.001、temp 1.0、每题采 16
个样本、batch 512 题、共 10,400 步、1.6 个 epoch、ref model 每 400 步更换。

代价同样被官方写明：**可读性差、中英混杂、非推理域窄**。R1-Zero 从多语言 base
演化出中英混杂 CoT，用户看不懂推理过程——纯 RL 解决「能不能想」，不解决「想
得能不能看」。

### 1.2 R1 四段式 pipeline：上限活在 RL，下限靠 SFT

R1 的处方是四段式：**冷启动数千条 long-CoT SFT 定形 → 推理 RL → 拒绝采样再 SFT（600K 推理 + 200K 非推理）→ 通用 RL**。这套骨架后来被 Qwen3、GLM-5、
K2 Thinking 一路沿用，差异只在各阶段占比与 agentic RL 比重。

冷启动数据本身是个自举结构：R1-Zero 高温采样 → sympy/规则过滤 → V3 改写成人类
友好风格 → 人工校验。注意一个官方承认的尴尬事实：Dev1 阶段（冷启动 SFT 后）
AIME 相对 R1-Zero **反而回落**——SFT 给格式与先验，RL 给探索与 scaling，两者
各司其职，**上限活在 RL、产品下限靠 SFT**，这是面试里解释「为什么 R1 还要冷启
动」最干净的口径。

### 1.3 为什么长 CoT 场景 GRPO 胜出

别答「省 value model 显存」这种泛话。R1 Nature 版给了两条机制级论证：

- **部分轨迹的奖励不可预测**：长 CoT 中间含反思与推翻，value model 从任意前缀
  预测最终奖励近乎不可能，PPO 的 critic 在长链上学不动；
- **PPO per-token KL dense penalty 隐性惩罚长度**：KL 按 token 稠密扣分会压制
  CoT 增长，考察者的金句是「KL 的隐性长度约束在长 CoT 下是 bug 不是 feature」。

GRPO 用组内平均当 baseline、完全无 critic，正好绕开这两条。这就是「无 critic
范式」的官方背书，也是 DAPO、GSPO 一路改进都在 GRPO 系内的原因。

### 1.4 奖励侧定调：PRM 在一线配方里被弃用

Kimi k1.5 官方声明**不用 MCTS、不用 value function、不用 PRM**；R1 与 DAPO 都
用规则判定加 ±1 稀疏奖励。OpenAI 的 PRM800K（2023-05，800,000 条 step 级人工
标注，过程监督模型解出 MATH 子集 78%）之后没有公开大后续，PRM 主战场退到测试
期重排序与过程错误检测（ProcessBench）。当前务实方案是**混合验证**：可验证域
数学/代码用规则，不可验证域用判别式 RM 或 LLM-as-judge 给 outcome 分；R1 的切
法是 RL 留给规则奖励域，不可验证域退回 SFT 加数百步小 RL。

## 二、主线二：long-CoT RL 稳定性工程（DAPO/GSPO）

### 2.1 DAPO：把「不稳」拆成四个可诊断的故障模式

naive GRPO 在 Qwen2.5-32B 上 AIME24 只到 30。DAPO（2025-03）不给玄学，给消融
阶梯（AIME24 avg@32，官方复现级）：

| 修复项 | 阶梯分数 | 修的故障 |
|---|---|---|
| naive GRPO | 30 | 基线 |
| +Overlong Filtering | 36 | 截断样本奖励噪声 |
| +Clip-Higher（εlow=0.2/εhigh=0.28） | 38 | entropy collapse、探索枯竭 |
| +Soft Overlong Punish | 41 | 硬惩罚污染正确推理信号 |
| +Token-level Loss | 42 | sample-level 对长序列失效 |
| +Dynamic Sampling | 50 | 全对/全错组零梯度稀释 batch |

对比锚：R1-Zero-Qwen-32B 的 47 分，DAPO 用 50% 步数到 50。超参给全：batch 512
prompts × 16 样本，期望上限 16,384 加 4,096 软缓存等于 max 20,480，且
DAPO-Math-17K 的答案全部整数化——**验证器输入格式本身是 leaderboard 变量**。

### 2.2 GSPO：MoE 把 token 级比率变成噪声放大器

GRPO/PPO 的重要性比率是 token 级的，dense 模型上凑合能用；MoE 上逐层路由切换
会把 token 级噪声跨层累积，实测 RL 会崩。GSPO（Qwen 官方 2025-07）改用**序列
级重要性比率配序列级裁剪**，直接稳定 MoE RL，已用于最新 Qwen3 训练。记住口径：
**算法选型上 GRPO 仍是默认起点，MoE 大模型 RL 的工程稳定器已换成 GSPO 系**；
R1 团队用的大 clip 策略针对的也是同一项。

### 2.3 稳定性从算法层升级到系统层

GLM-5（2026-02）把 slime 异步 RL 基建摆上台面：generation 与 training 解耦，
再加异步 agent RL 算法。背景是同步式系统被长尾 rollout 拖死（DAPO 早就指出
generation 时间由长尾主导），R1-Zero 每步 rollout 8,192 条乘以最长 65K
tokens，推理侧吃满整个集群。**本质看 RLVR 是训练-推理混合负载调度问题**，2026
的标准答案是全面异步化加 partial rollout（k1.5 已用）。配套型号的账：GLM-5
从 355B-A32B 扩到 744B-A40B，预训练 23T 到 28.5T tokens 并集成 DSA。

## 三、主线三：长度控制三条路线

RLVR 训练中 response length 会自然增长（R1-Zero 官方曲线从 hundreds 到
thousands tokens，DAPO 把 response length 列为核心监控指标），但**长度涨不等
于准确率涨**，无约束膨胀直接吃掉 serving 成本——K2 官方明说思考模型解码长度
过大导致量化容易掉点，这是他们上 QAT 的直接动机。认知走完三段跳：**越长越强
→ overthinking 是病 → 长度要可控**。三条工业化路线：

1. **训练期塑形（改模型分布）**：DAPO 的 Overlong Reward Shaping 在 16,384 到
   20,480 间设软惩罚区间；L1 长度可控 RL（2025-03）把预算嵌进 prompt 训练；
   Kimi k1.5 的 long2short（2025-01）用长度惩罚加模型合并加短样本拒绝采样蒸馏，
   短 CoT 版报 AIME 60.8 / MATH500 94.6 / LCB 47.3（官方 2025-01）。
2. **采样期预算强制（改采样行为）**：s1 的 budget forcing（2025-01）用
   1,000 条 s1K SFT Qwen2.5-32B-Instruct 加解码期强制 Wait 或终止，MATH/AIME24
   超 o1-preview 最多 27%，budget forcing 外推 AIME24 从 50 到 57；Qwen3 的
   thinking budget、K2 Thinking 的 96K/128K 评测上限都是同源兜底。
3. **融合模式开关（改数据形态）**：Qwen3 的 thinking mode fusion 用 /think 与
   /no_think 混合数据 SFT，一个模型两个模式，产品形态层收口。

2025-2026 面试的正确表述：**长度本身是 RL 的 artifact 而不是 objective，最优
解是训练期让模型学会按难度自适应分配，采样期强制是兜底，模式开关是产品形态**。
终极追问「预算应该模型自己学还是用户给」，当前研究答案是按难度自适应。

**口径警戒**：流传的「12K→23K 长度膨胀系数」查无官方出处，判断大概率社区转
引，本仓禁用。引用长度一律用官方锚：**官方锚 R1-Zero 的 max len 32,768 → 65,536（8.2K 步处调整）**，以及 **K2 评测预算 96K/128K thinking tokens**。

## 四、主线四：test-time compute 与训练接口

test-time compute 正在从「推理技巧」变成「训练生效对象」，四个接口：

1. **BoN/拒绝采样回流 SFT**：R1 的 600K 推理 SFT 数据就是拒绝采样的产物，
   采样即数据管道。
2. **并行重试聚合**：K2 Thinking 的 Heavy Mode 用 8 路并行 rollout 加反思聚合，
   HLE 从 44.9 提到 51.0（官方 2025-11）。聚合器本身是模型能力，train an
   aggregator 是 2026 明显增量方向；错误独立性决定了并行采样比加长串行 CoT
   更划算。
3. **agentic 长程 RL**：K2 端到端训练出 think→search→browse→think→code 交
   错，200–300 次连续工具调用被训出来；test-time scaling 变成 **thinking
   tokens 乘以 tool calling steps 两条轴**。
4. **自洽性进入评测协议**：R1-Zero 的 cons@16 86.7 对 pass@1 77.9、K2 的 AIME
   avg@32——一线报告把「采多少次」写成评测协议的一部分，跨榜单比较必须先对齐
   预算与采样次数。TTRL（test-time RL）则是推理期即训练期的极端形态。

记忆金句：**纯采样技巧的上限，就是训练分布没见过的那部分**。

基准 2 倍以上，且随 RL 规模上升出现计划外 cyber 能力涌现——**post-training
的投入产出差已经超过很多团队换 base 的收益**。

## 六、三个特殊问题

### 6.1 可读性与语言混杂：alignment tax 的第一个公开实例

R1-Zero 从 multilingual base 演化出中英混杂 CoT。修复手段：冷启动强制语言一
致，加 Language Consistency Reward。官方量化了代价：**数学持平、代码略掉**—
—这是 thinking 范式下 alignment tax 的第一个公开实例，面试被问「语言一致性修
复有没有副作用」直接引这组数字。

### 6.2 安全与 reasoning 绕过

长 CoT 给了 jailbreak 新攻击面：思考段可以表层写着安全文字、中间推理照常越界。
R1 官方安全实测三档数字要背：**无风控 unsafe rate 高于 20%，风控后约 10% 但拒
答率升到约 25%，对比 o1 拒答率约 50%。**防御侧的新阵地是 deliberative
alignment（OpenAI 2024-12），让模型在思考链里显式引用安全政策。GLM-5.3 的
教训更尖锐：**能力发现和危险能力发现是同一条曲线**——RL scaling 起来后
cyber 能力计划外涌现，护栏必须跟着 RL 规模一起 scale。

### 6.3 思考过程蒸馏与压缩

R1 官方结论：**小模型蒸馏优于直接 RL**（800K 蒸馏集，2–3 epoch、ctx 32K、
batch 64、cosine 衰减至 1/10）；s1 用 1,000 条高质量长链 SFT 出超 o1-preview
的数学能力。2025 共识：**长链行为可被 SFT 高效转移，RL 的必要性主要体现在
base 第一次涌现和后续持续 scaling**。注意趋势反差：一线推理模型的思考长度反而
在拉长，压缩主要是中小模型和成本敏感场景的事。

## 七、工程议题

1. **Entropy collapse 是 long-CoT RL 的头号杀手**：GRPO 几步内熵崩塌、组内样
   本趋同；DAPO 的 clip-higher 加 dynamic sampling 是标准修复。监控口径：
   actor entropy 必须缓慢上升，横盘或下降即预警。
2. **长度管理是奖励设计问题，不是 max_tokens 问题**：对截断样本硬扣分会污染正
   确推理的奖励信号（DAPO 实测），正确做法是 overlong filtering 加软惩罚区。
3. **MoE 叠 RL 是双重不稳**：路由不均乘上 token 级比率跨层放大噪声，GSPO 的
   序列级比率是针对性解法；batch 内 expert 激活分布漂移要单独建监控。
4. **长 rollout 的系统账**：R1-Zero 每步 8,192 条乘以最长 65K tokens 推理侧
   吃满；同步系统被长尾拖死，2026 答案全面异步化加 partial rollout。
5. **无 critic 的边界**：GAE 在长链上失真支持无 critic，但多步 agent 任务完全
   无 critic 是否够用 2026 仍开放——GLM-5 的异步 agent RL 算法就在补这个洞。
6. **评测被预算与采样次数污染**：pass@1 vs cons@16 vs avg@32、96K vs 128K 预
   算，跨榜单可比性极差；K2 Thinking 自曝放开 HF 域名后 HLE 44.9 到 51.3，
   连数据泄漏口径都能左右榜单。**评测协议必须与训练预算对齐**。
7. **QAT 进 post-training**：K2 把 INT4 weight-only QAT 嵌进 post-training
   阶段、只量化 MoE，2 倍提速且榜单分在 INT4 口径报出——量化不再是部署科的
   事后项。

## 八、▶ 面试题（频率标注）

▶ 【极高频】R1-Zero 证明纯 RL 可以涌现推理，为什么 R1 还要冷启动？

答法：三个真实动机——可读性、语言一致、非推理域打底；代价是 Dev1 阶段 AIME
相对 R1-Zero 回落（官方承认，追加分）；结构洞察是冷启动数据本身来自 R1-Zero
采样加人改写的自举。收尾金句：上限活在 RL、产品下限靠 SFT。

▶ 【极高频】长 CoT 场景为什么 GRPO 优于 PPO？

答法：别答省显存。给 R1 Nature 版两条机制论证（部分轨迹奖励不可预测、KL
dense penalty 隐性压长度），接 DAPO 四个故障模式，再补 GSPO 对 MoE 的序列级
比率。能画出 GRPO 组内 baseline 的方差结构是加分项。

▶ 【高频】PRM 为什么死了/没死？

答法：pragmatic 面——step 级标注贵、容易 hack、rule-based 覆盖数学代码后没增
量；nuanced 面——BoN 重排序、ProcessBench 过程诊断、search-aware 训练里仍活
着。两枚锚：k1.5 原文「不用 MCTS/value/PRM」；PRM800K 后 OpenAI 无公开接力。

▶ 【高频】长度膨胀怎么控？

答法：三条路线各改什么——训练期塑形改模型分布、采样期预算强制改采样行为、模
式开关改数据形态。能报出 DAPO 软惩罚区间 16,384 加 4,096 的具体数字和 L1 的
prompt 内嵌预算法是强信号。终极追问「预算模型自己学还是用户给」答按难度自适应。
**禁答**：「12K→23K 膨胀系数」，改用官方锚 R1-Zero 32,768→65,536。

▶ 【高频】训练一个 agentic thinking 模型和普通推理模型差在哪？

答法：奖励从单点 is_equivalent 变跨 200–300 步轨迹级信号；真实工具调用进 RL
循环所以异步势在必行；上下文管理策略也要进入训练分布；引用 K2 端到端交错训练
与 GLM-5 异步 agent RL 两个落地锚。

▶ 【中频】test-time compute 和训练 compute 怎么换算/取舍？

答法：成本阶梯——R1 官方 distill 优于小模型直接 RL、s1 用 1,000 条 SFT 换
27%、K2 Heavy Mode 用 8 路并行换 HLE 加 6 分；再追为什么聚合器/验证器让并行
采样比加长串行 CoT 划算（错误独立性）。

▶ 【中频】thinking 模型的安全怎么做？

答法：R1 安全三档数字、风控拒答率-不安全率 trade-off、deliberative alignment
思路、GLM-5.3 cyber 涌现推出「RL scaling 要配套危险能力评测」。

▶ 【中频】GRPO 熵崩塌现场怎么救？

答法：先确认监控（actor entropy 横盘即预警），再上 clip-higher 放宽 εhigh
打开 explore 空间，dynamic sampling 滤掉零梯度组，必要时提 temperature；能讲
清 DAPO 消融阶梯从 30 到 50 每一跳修什么，就是完整答法。

▶ 【低频-追热点】K2 Thinking 为什么敢用 INT4 报榜？

答法：QAT 嵌在 post-training 阶段联合训练、weight-only 只量化 MoE 部分、2 倍
提速；根因是 thinking 模型解码长，量化噪声在长链累积，PTQ 事后量化掉点压不住。
训练配方部分一律答「官方未披露」。
