## 一、主线直觉：不训练，把多个模型的能力「焊」进一个模型

先回答一个问题：**不训练、不蒸数据、不花算力，能不能直接把多个模型的能力
合并成一个模型？** 答案是肯定的——前提是模型们**同源**（同一 base、架构
一致、tokenizer 一致）。主线直觉是「权重空间算术」：把微调前后权重之差
看成一个「能力向量」（task vector），对这个向量做加、减、稀疏化、选符号、
搜索组合，就能像做线性代数一样编辑模型能力。

先划定与三个近亲的边界，这是面试官最常先问的：

- **vs 蒸馏**：蒸馏（见 [post-training蒸馏生产线专题](./post-training蒸馏生产线专题.md)）
  是把教师的输出或中间层行为用训练灌进学生，**需要数据和算力**，但可以
  跨架构、跨 tokenizer；合并零训练成本，但只限同构同源模型。
- **vs 多任务训练**：多任务把数据混在一起重训，上限最高，但成本最大、
  且数据不一定拿得到（人家的 SFT 数据不会给你，模型权重却挂在
  HuggingFace 上）。合并在「数据不可得」场景是唯一可行路径。
- **vs 加权集成（ensemble）**：集成在**输出层**平均，推理成本 ×N；
  合并在**权重层**平均，**推理成本不变**——这是合并的商业卖点：
  线上只部署一个模型，拿到接近集成的效果。

顺带一提 [推理模型训练专题](./推理模型训练专题.md)的边界衔接：Kimi k1.5
的 long2short（长度惩罚 + 模型合并 + 拒绝采样，2025-01）只是「合并」在
RL 后处理里的一个用法，本篇把完整谱系讲全。

## 二、机制拆解（一）：Task Arithmetic 与任务向量

给定 base 权重 θ₀ 和微调后权重 θᵢ，任务向量定义为 **τᵢ = θᵢ − θ₀**。
合并公式就是一行线性代数：

```
θ_new = θ₀ + Σ λᵢ · τᵢ
```

Task Arithmetic（Ilharco et al., ICLR 2023，arXiv:2212.04089）证明了
这个向量有三种可用操作，背下来就是一道题：

1. **缩放（scaling）**：调 λ 控制能力强度，λ > 1 还能「增强」；
2. **取负（negation）**：θ₀ − τ 可以**抹掉**某种行为，比如去遗忘
   （unlearning）、移除某些拒答倾向；
3. **跨任务相加（addition）**：多个任务的 τ 相加 ≈ 多技能叠加，
   数学模型的 τ 加代码模型的 τ 得到一个两者都会一点的模型。

直观解释：微调是在 base 附近做的一小步「位移」，位移向量本身承载了任务
方向，多个位移的线性组合自然落在「都会一点」的方向上。这个解释引出了
两个必须回答的问题：位移相加会互相干扰怎么办（第三节），以及为什么
「平均」在几何上合法（第六节）。

## 三、机制拆解（二）：干扰、TIES 三步与 DARE / DELLA 稀疏

多个 τᵢ 直接相加时会出现**两类干扰**：

1. **冗余稀释**：大量幅度极小的参数互相稀释，平均后有效信号被冲淡；
2. **符号冲突**：同一个参数，模型 A 往 +2 更新、模型 B 往 −3 更新，平均得
   −0.5——离两个模型的意图都远，谁也服务不好。

### 3.1 TIES 三步（NeurIPS 2023）

TIES（Yadav et al., NeurIPS 2023，arXiv:2306.01708）是参数平均系里的
标准答案，三步必须能脱口而出：

1. **Trim**：每个模型只保留幅度 top-k% 的 Δ 参数，其余归零——砍掉冗余；
2. **Elect Sign**：逐参数用全模型投票选出唯一胜出符号——消灭符号冲突；
3. **Merge**：只对与胜出符号一致的参数做平均，不一致的丢弃。

为什么符号投票有效：冲突的本质是「同一个参数的更新方向不一致」，
投票把多目标优化里互相拉扯的方向先仲裁掉，再平均就不再互相抵消。

### 3.2 DARE：稀疏化先行（ICML 2024）

DARE（Yu et al., ICML 2024，arXiv:2311.03099）的观察更激进：SFT 的
Δ 参数**幅度极小**（论文报告在 0.002 以内）且高度冗余，于是**随机丢掉
九到九成九的 Δ 参数**，剩下的按 1/(1−p) 重标定（保持期望），原模型能力
基本不掉。先把每个 τ 稀疏化再加和，天然减少参数级冲突。DARE 的深层信息
是面试加分点：**即 SFT 对权重的改动是稀疏、小幅度、高冗余的**——
绝大部分「能力」集中在极少数参数的更新上。

### 3.3 DELLA：按幅度排序的丢弃（2024）

DELLA（arXiv:2406.11617）把 DARE 的「随机丢」改成 MAGPRUNE——按幅度
排序，**幅度越小丢弃概率越高**。论文报告在三模型合并上：**排序剪枝
DELLA 比 TIES 高 3.6 分、比 DARE 高 1.2 分、比不做干扰处理高 11.1 分
（2024）**。谱系到这里的演进逻辑很清晰：全量加和（Task Arithmetic）→
保大幅 + 投票（TIES）→ 随机稀疏（DARE）→ 幅度排序稀疏（DELLA），
每一步都在更精细地回答「哪些 Δ 参数值得保留」。

社区一脉里还有 SCE、Model Breadcrumbs、Twin-Merging、EMR-Merging 等
变体（mergekit 已内置，见第八节），本篇不落引用号，面试知道名字、知道
它们都在「选参数 + 仲裁符号 + 定系数」三件套上做文章即可。

## 四、机制拆解（三）：系数 λ 谁决定——四个层次

加权公式里的 λ 决定了每个源模型的「发言权」，四个层次从手工到自动：

1. **手调（linear / SLERP）**：linear 就是扫网格调 λ；SLERP 在球面上做
   插值，保持权重模长几何特性，适合**二模型**精细调合。经验：SLERP
   适合两模型，多模型时直接上 TIES / DELLA（社区共识，2023–2025）。
2. **Fisher 加权**（Matena & Raffel, NeurIPS 2022，arXiv:2111.09832）：
   用各参数的 Fisher 信息当精度矩阵做 Laplace 后验加权——Fisher 信息
   大的参数说明模型对它敏感、不该被别人稀释。代价：需要少量数据算梯度。
3. **RegMean**（Jin et al., ICLR 2023，arXiv:2212.09849）：仅对内部
   线性回归层，用 Gram 矩阵求**闭式解**融合，逐层进行、**不需要标签
   数据**——「最小二乘视角下，最优合并系数有解析解」。
4. **AdaMerging**（ICLR 2024，arXiv:2310.02575）：把未标注测试样本的
   **熵最小化**当代理目标，逐层学合并系数——合并后模型对测试分布越
   「自信」越好。**用熵做代理目标后逐层学系数，比 Task Arithmetic
   提升约 11%（2024）**。

四个层次的共同假设：合并系数应该有信息论或统计依据，而不是纯手气。
回答「λ 怎么定」时按这个层次递进，面试官会知道你读过谱系而不是只背了
mergekit README。

## 五、进化合并与层拼接：合并配方的自动化与另一个维度

### 5.1 进化合并（Sakana AI）

把「合并配方」本身当作搜索空间——层间权重怎么配、宽度怎么拼接、从哪个
初值开始——用 CMA-ES 自动化寻优，进化出**日语 + 数学**等跨域组合模型
（Sakana AI，arXiv:2403.13187，2024-03 挂出）。这个工作的象征意义大于
单次结果：**合并从手艺变成了可搜索的程序**，2025-01-27 正式发表于
Nature Machine Intelligence，是合并方向首个正刊级工作。代价是每代个体
都要评测，搜索成本全在 benchmark 回归上。

### 5.2 层拼接：passthrough / DUS / Frankenmerge

参数平均系之外还有一个维度：**不做平均，直接把两个模型的层叠起来加
深度**。SOLAR 10.7B 就是 Mistral-7B 做 depth up-scaling（DUS）再续训的
产物（Upstage，2023-12，arXiv:2312.15166，NAACL 2024 Industry），**曾
登顶 7B 档 Open LLM Leaderboard（2024 H2 口径）**，是「frankenmerge 能干
过同尺寸精调模型」的标志性证据。mergekit 的 passthrough 模式干的就是这
件事。层拼接不是「权重算术」，但面试时同属合并工具箱，别漏。

## 六、为什么能平均：LMC、盆地与 Git Re-Basin

这是「为什么同一个 base 微调出来的模型可以直接平均」的标准答案，也是
「为什么跨 base 不能 merge」的根因，两个问题其实是一道。

**线性模式连通性（Linear Mode Connectivity, LMC）**：同一 init、同一
预训练轨迹出发微调出的若干个解，落在**同一个低误差盆地（basin）**里，
两点之间连线（线性插值）中途 loss 不升高、没有 barrier——盆地是平的，
所以插值点和平均点都是盆地内的合法解。这就是「插回 base」「多模型平均」
在几何上合法的原因。

而**不同 init 独立训练**的模型落在不同盆地：神经网络有隐藏单元**排列对称
（permutation symmetry）**——交换同一层任意两个神经元（连同其行列权重）
函数完全等价，所以 SGD 从不同 init 出发会收敛到互差一个排列的解。直接
对位平均会把「神经元 1」跟另一个模型的「神经元 17」混在一起，瞬时毁掉
对应关系，loss 爆炸。

两条把绕开排列对称的工作线：

- **Entezari et al.（arXiv 首版 2021-10）**：提出猜想——排除排列对称性
  之后，所有 SGD 解在全空间中其实是连通的；
- **Git Re-Basin**（Ainsworth et al., 2022-09，arXiv:2209.04836）：
  先把两个独立训练的 ResNet 找一个最优排列对齐，**对齐后实现
  zero-barrier 连通**，再平均就合法了。

但对 LLM 规模而言，寻排列本身代价高、且只验证了较小模型，**工程现实仍然
是：跨 base / 跨 tokenizer 直接平均必炸**（社区与论文共识，2023–2025）。
面试话术：理论上排列对齐后连通（Git Re-Basin），工程上没人这么做，
都要求同源。

## 七、治「对齐税」：WiSE-FT / WARM / Model Stock

合并在 RLHF 时代的杀手级用法是**修复对齐税**（alignment tax：对齐后
通用能力下降 / 灾难性遗忘），三件套按时间线：

1. **WiSE-FT**（Wortsman et al., CVPR 2022，arXiv:2109.01903）：把
   base 与微调模型做线性插值，**多个分布偏移下精度提升 4–6pp、
   ImageNet 本体不降反升 1.6pp（CVPR 2022）**——「插回 base」是治灾难性
   遗忘的极简手段，一行代码、零训练。
2. **WARM**（Rame et al., 2024-01，arXiv:2401.12187）：权重平均多个奖励
   模型（weight averaging reward models）提高 RLHF 稳定性、抗 reward
   hacking，报告**胜率 79.4% 对单个 RM（WARM 2024）**。RL 后处理里
   合并 RM 已经成为工程惯例。
3. **Model Stock**（ECCV 2024，arXiv:2403.19522）：证明**只用 2 个微调
   模型**就能逼近权重空间的几何中心——不像 model soup 要炖几十个，
   2 个就足够稳。

配上 Kimi k1.5 long2short（长短模型权重平均后再拒绝采样，2025-01）这个
工业配方，「合并治对齐税」就是一条从 2022 到 2026 仍在沿用的完整故事线，
RL 方向面试必带。

## 八、工业案例与 mergekit 事实标准

### 8.1 mergekit：事实标准工具

mergekit（Arcee AI，2023 起）是目前合并领域的事实标准：**截至 2026-10
实测为 7,392 stars、794 forks，最近 push 2026-09-12，持续活跃**。README
列出 **事实标准 mergekit 内置 15 个方法族、约 21 个配置项（2026-10
手工点数）**：linear / SLERP / NuSLERP / MultiSLERP / Karcher /
TaskArithmetic / TIES / DARE / DELLA / Breadcrumbs / SCE / ModelStock /
NearSwap / ArceeFusion / passthrough，外加 MoE 化、多阶段 merge、LoRA
抽取、evolutionary scaling。

用法就是 YAML 声明配方：base_model + models + merge_method + parameters，
可逐层单独配权重、按层 block 切片；资源需求极低——**全程 CPU 可跑、
8 GB VRAM 起步即可加速（官方 README 原文口径）**，7B 级 3 模型 TIES 在
消费级机器上数分钟内完成（mergekit 官方 FAQ 口径，2024）。两个进阶玩法
值得单独记：

- **MoE 化**：把多个 dense 模型叠成一个 MoE，靠路由器取舍各「专家」，
  通常要少量激活数据算路由统计——dense 合并到 MoE 的桥梁；
- **LoRA 抽取**：反过来，从 SFT 模型与 base 的差值里抽出 LoRA——合并
  和 PEFT（见 [lora与参数高效微调](./lora与参数高效微调.md)）在这里
  接上了头。

### 8.2 DeepSeek-V2.5：现象级的「Chat + Coder 合体」（2024-09）

官方 HuggingFace 卡写明"combines DeepSeek-V2-Chat and
DeepSeek-Coder-V2-Instruct"，社区普遍认为是 Chat 与 Coder 两个同 base
模型的**权重合并 / 插值产物**（官方未明确确认，口径见文末说明）。
卡片上的合并后成绩：**合体后 AlpacaEval 50.5、ArenaHard 76.2、
HumanEval 89，高于两个源模型（2024-09 官方卡）**——「1+1 > 各自」的
现象级案例，是「代码模型 + 通用模型合并」的标准引用。

### 8.3 Kimi k1.5 long2short 与 SOLAR DUS

- **Kimi k1.5 long2short**（Moonshot AI，2025-01）：长链思考模型先训出
  长短两个版本，**权重平均**后再用短样本拒绝采样清洗——合并是官方技术
  报告里的正式步骤，不是社区 trick；
- **SOLAR 10.7B / DUS**（Upstage，2023-12）：层拼接商业化样本，
  **曾登顶 7B 档 Open LLM Leaderboard（2024 H2）**，证明不加参数也能
  涨档。

### 8.4 MergeBench：合并能力的边界（NeurIPS 2025 D&B）

MergeBench（Meta 等，2025-05，arXiv:2505.10833）用 Llama / Gemma
2B–9B、5 个域（指令、数学、多语、代码、安全）、8 种方法做统一评测，
三个结论直接可以当面试答案：

1. **合并对更强的 base 更有效**——底座差时合并救不回来；
2. **系数调优和稀疏化对知识保留帮助最大**——印证第三、四节的方法重心；
3. **合并后的模型与多任务训练仍有 in-domain 差距**——合并是低成本
   近似，不是上限替代。

## 九、工程实践与坑位清单

- **成本量级**：一次 7B merge 是可忽略的几分钟 CPU/GPU 时间，对照微调
  动辄数百 GPU·时——「合并 ≈ 免费午餐」叙事的地基。但**真正的成本在
  评测回归**：每个新配方都要跑一遍 benchmark，这部分开销远大于合并本身，
  Sakana 进化合并的搜索代价全砸在这里。
- **坑①：不同 base / 不同 tokenizer 直接平均必炸**。Llama-2 和 Llama-3
  都不行， vocabulary 都不一样，对位无从谈起（社区与论文共识，
  2023–2025）。
- **坑②：同源也会出现「能力互斥」**。多模型合并仲裁后普遍 slightly
  worse at all——每个域都比对应单模型略弱。TIES / DARE 能缓解但无法
  根除，MergeBench（2025）确认 in-domain 差距仍在。
- **坑③：方法选型错配**。SLERP 适合二模型精调；多模型时优先
  TIES / DELLA（社区共识）。
- **坑④：系数靠手气**。手调 = 扫网格；系统化做法是进化搜索（CMA-ES），
  代价是多次评测。
- **调优经验**：先 DARE / TIES 稀疏化五到九成（DARE 原文说九成甚至
  九成九都能保留能力），再线性加和；每加入一个源模型**单独验证其贡献**
  是否为正——能给负系数就反着加，做一次消融，确认这个源不是来捣乱的。
- **典型组合范式**（均在前面案例出现）：代码 + 通用（DeepSeek-V2.5）、
  双语跨域（Sakana 日语 × 数学）、多能力 SFT（MergeBench 5 域）。

## 十、选型三轴：合并 vs 蒸馏 vs 多任务训练

被问「给你两个模型怎么合体」时，按三轴展开，这是压轴题的标准框架：

| 轴 | 合并 | 蒸馏 | 多任务训练 |
|---|---|---|---|
| 成本 | **近零**（几分钟 CPU） | 中（要跑教师 + 训练学生） | 高（完整重训） |
| 上限 | 中（有互斥，MergeBench 确认差距） | 高 | 最高 |
| 数据 | 不需要 | 需要（合成或教师输出） | 需要原始配比数据 |
| 架构约束 | 必须同 base / 同架构 / 同 tokenizer | 可跨架构、跨 tokenizer | 同一次训练内一致 |
| 推理成本 | 不变（核心卖点） | 不变 | 不变 |

话术模板：**数据不可得 / 预算近零 → 合并；要跨架构迁移或追上限且有点
预算 → 蒸馏；手握全部数据且要榨干上限 → 多任务**。再补一刀：三者可
叠加——合并出的胚子再做蒸馏或多任务续训，不冲突。

## 十一、▶ 高频面试题

**Q1【极高频，浅档】什么是 task vector？Task Arithmetic、TIES、DARE
各自解决什么问题、关键差异？**
答：τᵢ = θᵢ − θ₀，是微调在权重空间的「位移向量」，可缩放、取负、相加。
Task Arithmetic 给出全量加减（ICLR 2023）；TIES 解决冗余稀释 + 符号
冲突，三步 Trim → Elect Sign → Merge（NeurIPS 2023）；DARE 利用 SFT
的 Δ 幅度小、高冗余性质，先随机稀疏再重标定（ICML 2024）。深档追问
DELLA 的幅度排序剪枝与三模型 +3.6 分的对比。

**Q2【极高频，浅档】为什么同一个 base 微调出来的多个模型可以直接平均？**
答：LMC——同源微调解落在同一低误差盆地，插值路径无 barrier，平均点是
盆地内合法解。加分项：提 permutation symmetry，说明不同 init 落不同
盆地是排列对称导致。

**Q3【高频，浅档】不同 base 的模型能不能 merge？为什么？**
直答：不行。理论线是排列对称 → Git Re-Basin（2022-09）寻排列对齐后
zero-barrier；工程现实是寻排列在 LLM 规模不划算，且 tokenizer 不同直接
无解——一律要求同源。

**Q4【高频，中档】合并 vs 蒸馏 vs 多任务训练怎么选？**
答三轴：成本（合并近零 < 蒸馏 < 多任务）、上限（合并有互斥差距，多任务
最高）、数据可得性（合并零数据，蒸馏要教师输出，多任务要原始数据）。
补架构约束一行，再补「三者可叠加」收尾。

**Q5【高频，中档】TIES 的三步是什么？为什么符号投票能缓解干扰？**
答：Trim 保 top-k% 幅度、Elect Sign 逐参数全模型投票选唯一符号、
Merge 只平均与胜出符号一致的参数。符号投票先把多目标互相拉扯的更新
方向仲裁掉，再平均就不会互相抵消。

**Q6【中频，中档】DARE「丢 90% Δ 参数还不掉点」说明了 SFT 的什么性质？**
答：SFT 对权重的改动幅度小（0.002 内）、稀疏、冗余高——能力集中在
极少数参数的更新上。追问可接 DELLA：既然冗余，就按幅度排序丢小的。

**Q7【高频，中档】RLHF 之后怎么「修」对齐税 / 灾难性遗忘？**
答四条：WiSE-FT 插回 base（分布偏移下 +4–6pp）；WARM 权重平均多 RM
提 RLHF 稳定性（胜率 79.4%）；合并 SFT 与 RLHF 后两个版本；
Kimi long2short 式长短模型 merge。本质是同一招：往盆地里拉。

**Q8【中频，浅档】mergekit 支持哪些方法、一次 merge 要花多少资源？**
答：15 个方法族（linear / SLERP / TIES / DARE / DELLA / ModelStock /
passthrough 等，引实时 README 口径即可，不要背死数）；7B 级 TIES 在
消费级机器数分钟，CPU 可跑、8 GB VRAM 起步（官方口径）。真正贵在每
配方的 benchmark 回归。
