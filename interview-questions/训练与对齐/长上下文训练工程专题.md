## 一、直觉：标称窗口是四件事的乘积

一个模型「标的」1M 上下文，和「真能用」1M 上下文之间隔着四个独立的工程问题，
它们各自都可能不及格：

1. **位置编码层面**：新位置（超出预训见过的位置范围）不能变成分布外输入——
   这是 PE 谱系（PI / YaRN / LongRoPE）要解的问题。
2. **数据层面**：模型必须在真长 token 上学到东西——长文档稀缺，训练里得有
   「长度课程」把短基座渐进拉长。
3. **系统层面**：注意力的算力随长度平方涨、显存结构随长度线性涨，集群扛不扛
   得住——这是 CP（Context Parallel）三兄弟的生意。
4. **评测层面**：PPL 平坦 ≠ 检索健在，标称窗口 ≠ 有效窗口——得换一套评测口径
   才知道做到哪了。

2025-26 年起，hybrid 架构（linear/RNN 状态 + 全 attention 混搭）把「窗口」的
成本结构整个改写，这构成篇末最后一条线。

一句话总纲：**窗口做长等于 PE 让新位置不出分布、课程让模型真学、CP 让集群
扛住、评测让你知道真假**。推理侧「稀疏注意力怎么省算、KV 怎么省存」的全部内容
见[长上下文推理与 KV 体系](../inference/长上下文推理与kv体系.md)，本篇不重复。

## 二、机制一：位置编码外插谱系

RoPE 本身的公式与性质（旋转、相对性、长程衰减）见[位置编码与 norm](../llm基础/位置编码与norm.md)，
本篇只引用结论：**要点是 RoPE 的位置信息编码在高维三角函数的相位里，没见过
的大位置等于模型没见过的新相位，直接进推理就是分布外输入**。谱系七年的演进，就是围绕
「怎么把没见过的大位置映射回模型认识的相位域」这件事不断换手法。

### 2.1 PI：内插生于「外推会爆炸」

PI（Position Interpolation，2023-06，arXiv:2306.15595，Meta Shang Chen /
田渊栋团队）做的是最朴素的一步：把位置索引线性缩放，m 映射为 m·L / L'——
想把 32K 塞进预训 4K 的窗口，就把所有位置除以 8。真正值钱的不是这一步操作，
而是它配套的理论比较：**内插的注意力分数上界比外推小约 600 倍（PI, 2023）**。
外推让位置相位落在训练区外，注意力 logit 可能剧烈漂移；内插把所有相位压回
训练区间内，等价于「在认识的坐标系里重新标刻度」。

工程数字同样朴素：**用 LLaMA 7B~65B 实测，微调不到 1000 步即达 32K（PI, 2023）**，
且不改架构、短窗口表现不受损。PI 是这个谱系的「原理性突破点」，后续所有
方法都在回答它的软肋——线性缩放把高频短波长维度也一起压了，局部精细位置
分辨率被牺牲。

### 2.2 NTK 系：把缩放揉进 base 频率

NTK-aware RoPE（2023-06，由社区 kaiokendev 在 r/LocalLLaMA 首发）换了个
视角：不改位置索引，改 base 频率本身，令 θ' = θ · s^(d/(d-2))。效果是
**2048 免微调外推到 8192（NTK-aware, 2023）**——连 PI 那 1000 步微调都省掉。
直觉是「高频维度保持局部、低频维度压缩全局」：短波长维度管附近位置，不许动；
长波长维度才承载远距离，可以压。

NTK-by-parts（bloc97 等，2023）把这个直觉做成分频段规则：明确按波长分带，
短波长带完全不动、只对长波长带插值。这一「分频段」思想是 YaRN 的直接母体。

### 2.3 ABF 与 Dynamic NTK：调 base 直接进工业预训

ABF（Adjusted Base Frequency，2023-09，arXiv:2309.16039，Microsoft，口号
「Train Short, Test Long」）做减法：直接把 RoPE base 从 10K 调大到数百 K，
配小步数微调，让短训模型泛化到长测。标志性落地是：**最有代表性的落地是 Llama-3 把 RoPE base 定在 500000，并引用
Xiong et al. 证明该值对 32K 有效（Llama-3, 2024）**——
ABF 思想正式进入工业级预训配置。

Dynamic NTK（emergent methods 提出，2023-11）走另一条路：按当前序列长度
动态计算缩放系数，免微调且对短长度零损失，后来固化成 HF transformers 的
dynamic rope_scaling 选项。代价是推理时长度分布变化大时行为不稳——线上
稳定性一般，训练侧很少作为主方案。

### 2.4 YaRN：分频 ramp 加温度修正成为工业标准

YaRN（2023-08，arXiv:2309.00071，ICLR 2024，Quesnelle 等）把前面几代的
经验收拢成一个标准件：按维度做 ramp 式分段插值（ramp-size 的连续过渡），
同时在 QK 内积上乘一个注意力温度系数 √t，修正大位置下 softmax 熵的漂移。
两组数字锚：**比 PI 省 10 倍 token（YaRN, 2023）**、**训练步数再省 2.5 倍
（YaRN, 2023）**；并且能外推到微调数据里从没出现过的长度。

工业采用面是谱系里最广的：**最硬的工业背书是 Qwen3 明文以 YaRN scaling_factor
四倍把 32K 基座用于 128K 评测（Qwen3, 2025）**，Nous Research 等一系列开源配方也以
YaRN 为默认件。面试问到「现在工业界用谁」，答 YaRN 系基本不会错。

### 2.5 LongRoPE 与 CLEX：把缩放系数变成可搜索的超参

LongRoPE（2024-02，arXiv:2402.13753，Microsoft 亚研）把「插值率」从手工
公式升级成搜索结果：不同 RoPE 维度、以及序列最前面几个 token，允许各自不同的
缩放率，沿 token 维度做进化搜索。三组数字锚：**免微调 8 倍外推 2048 到 16K
（LongRoPE, 2024）**；先在 LLaMA2-7B 上做 256K 微调 1000 步，再做第二次插值
冲到 **2048K 即两百万窗口（LongRoPE, 2024）**；最后一步易忽略——**回到 8K
微调以恢复短窗口表现（LongRoPE, 2024）**。这个「扩长再补短」的三步曲，本质上
是长度课程思想在 PE 层的预演。

CLEX（2023-10，arXiv:2310.16450，OpenBMB/面壁智能）走连续化路线：把 base
缩放做成关于长度的连续函数（logistic/ODE 式微分参数化），只在 4K 内训练，
推理时连续外推到 32K 以上。思路对齐「位置编码是连续信号」，但工业影响力远不
及 YaRN 系——知道存在、能答出题即可。

### 2.6 LongRoPE2：失效诊断从治标到治本

LongRoPE2（2025-02，arXiv:2502.20082，Microsoft）先回答「为什么旧方法修到
128K 还是崩」：**诊断结论是 RoPE 高维分量在长文上训练不足，导致 OOD 维度
（LongRoPE2, 2025）**——问题不在缩放公式不够好，在缩放完后有些维度依然没在自己的工作区间
见过训练数据。对策是整套流程的升级：

1. 用「needle 驱动的 PPL」（带检索目标的长文 PPL）做适应度，进化搜索重新
   标定 RoPE；
2. 混合上下文窗口训练——长序列用重标定 RoPE、短序列保留原始 RoPE，护短
   能力；
3. 数字锚：**用 LLaMA3-8B，仅 10B token 就扩到 128K 有效窗口（LongRoPE2, 2025）**，
   **比 Meta 官方 800B token 方案省约 80 倍（LongRoPE2, 2025）**，且 Meta
   按其方案达不到同样的有效长度；短窗口表现保留不低于 98.5%。

谱系主线一句话：**主线依次是 PI 证明内插优于外推 → NTK 系把插值搬进 base
频率 → YaRN 把分频插值加温度修正做成即插即用标准件 → LongRoPE 把缩放系数
变成可搜索的超参 → LongRoPE2 把失效归因到「高频维训练不足」这一诊断**。面试问谱系，按
这一句话展开，每一站都能掏数字。

## 三、工程一：长文数据工程

DE 层的核心矛盾一句话：**长文档天然稀缺、注意力成本随长度平方涨、短能力会
遗忘**——三条共同决定了「从头直接训 1M」在工程上几乎不可行，业界全部是
「短基座 → 渐进拉长 → 长文继续预训 → 长短混合 SFT」的课程路线。

为什么不能从头直接训长：其一，网页均值只有几百 token，百万级长文档在任意
语料里都是长尾；其二，注意力 O(L²) 的成本意味着若全量长训，约九成五的预算
花在并不增加通用能力的长程 token 上；其三，长文边际学习信号稀疏，均匀长训
下短指令能力退化（遗忘）。

### 3.1 长度课程：Llama-3 六阶段与 Qwen3 三段式

**Llama-3 的长上下文继续预训分 6 个阶段从 8K 渐进到 128K，合计约 800B
token（Llama-3, 2024）**。配合两个硬化标准，是这届课程设计的工业模板：

- RoPE base 固定为 500000（前述 ABF 口径）；
- 每一阶段的两条门控——**短上下文评测完全恢复**、**当前长度 NIAH 满分**，
  缺一不可晋级。

要点不在「分六段」这个数字，在门控的思想：每次拉长都必须用短窗评测证明
「没有买到长度赔了通用性」。

**Qwen3 预训三段式合计窗口从 4096 扩到 32768（Qwen3, 2025）**：S1 约 30T
token 训 4K 通用性；S2 约 5T 高质量 token（学习率加速衰减）；S3 是长上下文
阶段，以「数千亿 token」（hundreds of billions）32K 继续预训。官方分层口径：
dense 小模型标配 32K，4B 及以上标 128K；推理侧再叠 YaRN 四倍缩放后评 128K。
另两个可引用的横向样本：**另一条线是 GLM-4.5，在预训中后段做 32K 到 128K
的窗口扩展，书籍、代码仓库、长 agent 轨迹单独配比（GLM-4.5, 2025）**；**以及
MiniMax-Text-01 以 lightning 与 full 混合注意力让训练窗口达 1M、推理外推
4M（MiniMax-01, 2025）**——后者同时宣布「长训」与「hybrid 架构」两条线在 2025 年会师，详见
第六节。

### 3.2 长文来源与上采样：书加代码，三六九等

**ProLong 的结论第一条：书籍与代码仓库级拼接是最佳长文源（ProLong, 2024）**
——Books3 类的书均十万 token 级、含叙事长程依赖，repo-level code 含跨文件
依赖；而纯网页拼接成的「伪长文」几乎无效。

**LongWanjuan 按长程依赖结构把长文分三类（LongWanjuan, 2024）**：holistic
（整体组织，如书籍）、aggregated（聚合型，如论文合集/报表）有训练价值，
patchwork（拼凑无真实依赖）为负贡献——这给了「长文清洗」的可执行标准：不是
看长度，是看依赖结构。

上采样策略：长文按长度分桶（4K / 8K / 32K / 128K 各档），长桶按幂律欠采样
的反向比例上调，工业口径约上调 2~4 倍；但**短数据绝不能丢**——Llama-3 的
800B 长文继续预训里，主体仍是短数据，原因见下节证据链。

### 3.3 只训长会烂：四条一手证据

面试被问「为什么长短要混合」，证据链按这四条列，全是一手来源：

1. **LongRoPE 扩完长专门回 8K 恢复短窗口表现，不恢复则短任务塌（LongRoPE,
   2024）**；
2. **LongRoPE2 直接设计混合上下文窗口训练，长短用不同 RoPE 同时喂
   （LongRoPE2, 2025）**；
3. **Llama-3 每阶段门控硬性要求短上下文评测完全恢复（Llama-3, 2024）**；
4. **ProLong 结论一要求与高质量短上下文数据混合，结论三更反直觉——SFT
   阶段只用短指令数据也能拿到强长任务表现，长能力主要来自基座的继续预训
   （ProLong, 2024）**。

代价机理记两笔：均匀长训下，有效 batch token 数不变但注意力开销按平方上升，
GPU 小时成本爆炸，同一份预算学到的通用能力更少；同时长文边际学习信号稀疏，
模型出现短指令退化——这两条构成「必须短混」的成本解释。

### 3.4 长上下文 SFT 的配方件

**LongAlign 给出长上下文对齐的三件套（LongAlign, 2024-01）**：Self-Instruct
构造长指令数据；packing 加 sorted batching 加速；packing 内 loss 按序列重
加权，避免超长序列把 loss 稀释成「长文主导」。**数字是 LongBench-Chat 上比
基线高 30 个百分点（LongAlign, 2024）**。它与 ProLong 结论三放一起看，恰好给出
「SFT 长数据到底有没有用」的两端：构造好的长 SFT 有增益，但不是长能力的
主来源——继续预训才是。

## 四、工程二：训练系统工程（通信账与显存账）

系统侧的入门算力账（以 Llama-70B 级、d≈8192、80 层量级估算，本文作者按
公开配置折算）：每 token 每层 dense FLOPs ≈ 1.75 GFLOP，每 token 每层
attention 点积 FLOPs ≈ 4·L·d。代入三档长度：

- L=8K 时 attention 只占 dense 的 0.15，训练是 MLP 主导；
- **L=128K 时 attention 达到 dense 的 2.4 倍（估算同上）**；
- **L=1M 时 attention 达到 dense 的约 19 倍（估算同上）**。

结论：**进 1M 时代后，训练的主账单就是 attention 本身**。这同时是 CP 能回本的前提
——通信增量只要小于算力增量就是赚的，而 attention 算力这会儿足够厚。

### 4.1 CP 三兄弟：Ring / Ulysses / USP

上下文并行（Context / Sequence Parallel）把序列切块分到多卡。三家方案按
通信模式分野：

**Ring Attention（2023-10，arXiv:2310.01889，UC Berkeley）**：序列分块跨
设备，每卡持块，KV 块绕环轮转做 P2P 通信，与本地 attention 计算重叠。
理论上 token 数随设备数线性扩张。causal 注意力下首尾卡负载不均，用 ZigZag /
Striped 布局（前半后半对称分布）拉平。通信账硬核：**在 L=1M、P=64、GQA-8×128 时，单轮单向通信约 128MB
（Ring Attention, 2023）**；该轮本地块算力约 12ms
（按 16K×16K chunk、约 370 TFLOP/s 有效算力折算），H100 NVLink4 900GB/s
下通信只需约 142µs——通信被完全藏进计算里；即便跨节点单口 NDR IB 400Gbps
（50GB/s），也只需约 2.6ms，仍然 overlap 得住。

**DeepSpeed Ulysses（2023-09，arXiv:2309.14509，Microsoft）**：attention
前后各一次 all-to-all，把「按序列切」换成「按 head 切」，每层前向 2 次 A2A。
理论亮点是**序列长度与设备数同比扩大时通信量恒定，不随 L 膨胀（Ulysses,
2023）**；实验数字是**比既有 Megatron-SP 基线快 2.5 倍、支持 4 倍更长序列
（Ulysses, 2023）**。通信账的软肋也在这：单次 A2A 每卡发送量约 (L/P)·d×2B，
L=1M、P=8、d=8192 时约 2.15GB 一次——**关键是 Ulysses 度数被限在单机 8 卡
内的 NVLink 域（Ulysses, 2023）**，跨节点就吃到 IB 带宽墙。

**USP 统一序列并行（2024-05，arXiv:2405.07719，饿了么/北理工）**：把上面
两家做成二维混合——Ulysses 组内走机内 NVLink、Ring 组间走跨机 IB，按硬件
拓扑分层编排。数字锚：**在 2×8×A800 上训 LLaMA3-8B，208K 上下文做到 47% MFU（USP, 2024）**。至此「怎么按集群拓扑配 CP」有了工业级答案。

Megatron-LM 的 Context Parallel（NVIDIA，2023-11 起）是另一条主线：ring
P2P 加 causal load balancing，与 TP/SP/PP 拼成 4D 并行；2025 年起普遍支持
分层 CP 与变长序列。面试答「CP 有哪些」，三兄弟加 Megatron 共四个名字要齐。

### 4.2 带宽参照系：通信账背的这张表

以下全部是硬件公开规格，做通信账时必须能脱口而出：

- NVLink4 H100 为 900GB/s，NVLink3 A100 为 600GB/s，A800/H800 被限到
  400GB/s；
- IB HDR 200Gbps 约 25GB/s 每口，NDR 400Gbps 约 50GB/s 每口，每节点 8 卡
  8 口聚合 200/400GB/s；
- PCIe5 为 64GB/s。

**A2A 走 NVLink、Ring 跨 IB 这道拓扑题，就是 USP 混合设计存在的唯一理由**
——单机内部吃满 600~900GB/s 的互连做 all-to-all，跨机则用可重叠的环状
P2P 在 50GB/s 的窄口上轮转。

### 4.3 变长 packing 与负载均衡

- cu_seqlens 驱动的 varlen packing（FlashAttention 原生支持）配 best-fit
  decreasing 装箱，文档拼接边界的 cross-contamination 用 position_ids
  重置缓解；
- Ring 的 causal zigzag 布局消除尾卡闲等；
- MoE 层与 CP 联合调度时，专家负载与序列切块解耦（MiniMax-01 论文为此
  专门做了交叉并行策略）。

### 4.4 1M 上的显存账：CP 的本职是把长折成短

关键认知先立住：**关键是 FlashAttention 把 attention 激活从 O(L²) 压成 O(L)，
只存 softmax 统计量**——所以 1M 训练的显存账是全局线性的。真瓶颈是三块：(1)
参数加梯度加优化器状态是定值，(2) 激活随 L/P 线性涨，(3) Ring/Ulysses 的
通信 buffer。

**CP 的本质是把 1M 折算成 P 份 1M/P 长的短训**——CP=64 时，每卡 16K shard
的激活等价于训一个 16K 短模型，这正是 CP 的本职：

1. Ring 常驻两份收发 KV buffer，约 2×128MB×层数（可跨层复用）；
2. Ulysses 的 A2A 中间 buffer 按约 2.15GB×2 次×层计；
3. optimizer 状态（FP32 m+v，每参数 8B，70B 即 560GB）由 ZeRO-3 分片兜底。

长训里 CP / ZeRO / TP / PP 的 4D 组合没有银弹，先按「长度 × 模型规模」两个
轴把份额算出来再选型。推理侧的 KV 显存账、驱逐与多级存储见[长上下文推理与
KV 体系](../inference/长上下文推理与kv体系.md)，与本节的训练侧激活账是两套
口径，别混答。

## 五、评测口径：别被标称窗口骗

### 5.1 单针 NIAH 为什么塌：机理与骗局化

NIAH（Needle-In-A-Haystack）是 Greg Kamradt 2022-12 首创的简单检索测试，
2023-11 GPT-4 Turbo 128K 使其成为行业标准。它的问题在机理层面已经写死：
**长文困惑度由局部的短程 token 主导，窗口外 OOD 位置对整体 PPL 的扰动被
平摊**——把 RoPE base 直接拉大往往能给出平坦的长文 PPL 曲线，但检索能力
已经崩。PI 与 YaRN 原文都只把 PPL 当弱证据，RULER 与 ProLong 更是明确
「PPL 与单针 NIAH 不是可靠长上下文指标」。2025 年起的 LongPPL 一类修正
度量（关注长程关键 token）被提出作为替代，但社区共识仍是真实任务评测加
有效窗口口径。

**Gemini 1.5 宣称 1M 文本 NIAH 召回 99% 以上、多模态到 10M（Gemini 1.5,
2024-02）**——这是「单针虚高」最典型的工业样本：大海自在捞到针，不等于
在大海里能推理。

变体时代的针法分四类：多针（多个 k-v 分散检索，Multi-NIAH）、时序与多跳
追踪（RULER VT）、聚合统计（CWE/FWE 数众数）、Ancestral Trace（OpenCompass
NeedleBench 2024，需回溯家族链）。2024-04 RULER 起，单针时代正式结束。

### 5.2 四大基准的分工

- **LongBench 首个双语多任务长上下文基准，21 个数据集 6 类任务、均长约
  6711 英文词（LongBench, 2023-08）**——测的是「真实任务 10K 档」。
- **RULER 合成可控长度、4 类 13 任务，提出有效窗口定义（RULER, 2024-04）**
  ——测的是「窗口在多长崩塌」，有效窗口指在指定阈值（如 4K 基线质量）下
  仍达标的最大长度。
- **∞Bench 首个平均长度超 100K 的基准，合成加真实任务双语（∞Bench,
  2024-02）**——测 100K+ 深水区，结论是当年所有模型在 100K+ 都仍需
  显著进步。
- **LongBench v2 收 503 道多选题、8K~2M 词长（LongBench v2, 2024-12）**，
  人类专家限时 15 分钟答对 53.7%，o1-preview 得 57.7%，模型直接裸答最
  高 50.1%——把评测推进到「推理 x 长上下文」的复合深水区。

HELMET（2024-10，Princeton，59 模型系统评）给出模型选择器视角：RAG 型
任务对下游表现的预测力最强，可作快速迭代的代理指标——**结论是 NIAH 满分不能预测下游长任务
（HELMET, 2024）**，开源与闭源的差距随长度拉长。

### 5.3 标称与有效的一手落差数据

三组数字要背，分别对应 2024 上半年、2024 下半年、2025 的实锤：

- **17 个宣称 ≥32K 的模型只有一半在 32K 达标（RULER, 2024-04）**——
  标称与有效首次量化出落差；
- **流行 LLM 实际只利用了上下文的 10~20%（BABILong, 2024-06，NeurIPS
  2024 D&B）**，数据切分到 10M token，单事实 QA 用 RAG 也只有 60% 准确——
  1M 标称对应约 100~200K 的真实利用率；
- **Qwen3-235B-A22B 的 RULER 分从 4K 的 95.1 单调降到 128K 的 86.0
  （Qwen3, 2025）**，Qwen2.5-7B-Instruct 在 128K 只剩 55.1——即便 2025
  年顶级开源，也是「标称 128K、有效约 64~128K 的斜坡」。

最新代表案例是 **Llama 4 Scout 宣称 10M 窗口加 iRoPE（Llama 4，2025-04）**：
25% 层完全不加位置编码（NoPE）加推理时温度缩放；社区从 2025-04 起的
LiveBench 与长文复测普遍认为其有效窗口远低于标称——「标称膨胀」这一病
并未随 2025 年收敛，反而在 hybrid 时代换了新包装。

### 5.4 评测口径层面的答题模板

被问「怎么评价一个模型的长上下文能力」，按四层答：

1. 不用单一 PPL（短程 token 主导、易被骗）；不用单针 NIAH（已骗局化）。
2. 报有效窗口——在 RULER 上，缩到 4K 基线质量阈值下还能稳的最大长度。
3. 真实任务交叉——LongBench / LongBench v2 / HELMET 看下游长任务，
   BABILong 看 100K+ 真利用率。
4. 混合加合成长文上的训练侧验证——训练里就用带 needle 的 PPL 做适应度
   （借 LongRoPE2 思路），评测里用多针/VT/CWE 做过程监督。

## 六、2025-26 口径：hybrid 改写窗口的成本结构

新口径一句话：**当模型变成「linear/RNN 状态承载长期记忆 + 少量全 attention
层负责精确召回」的混搭，「窗口」的边际成本被结构性改写**。长期记忆由循环
状态以常数内存承载，精确召回只由 FA 层负责 O(L²) 或 O(L) 的局部账；评测
重心从「PPL 是否平」转到「全 attention 层的比例与跨层状态压缩」。

五个标志性节点，年份与数字都要带：

- **7:1 lightning 配 full attention 的 456B MoE，训 1M、推理外推 4M
  （MiniMax-Text-01, 2025-01）**——hybrid 长训最早的工业样本；
- **iRoPE 让 25% 层完全 NoPE 加推理温度缩放，宣称 10M/1M（Llama 4
  Scout/Maverick, 2025-04）**——有效窗口遭社区实测质疑（见 5.3）；
- **5:1 local 滑窗配 global 混搭，RoPE base 分档 10K(local)/1M(global)
  （Gemma 3, 2025-03）**——训练成本实体砍掉六分之五的 attention；
- **Gated DeltaNet 配 Gated Attention 3:1，原生 256K、YaRN 外推到 1M
  （Qwen3-Next, 2025-09）**——hybrid 成为基座架构的标志性节点；
- **KDA 配 MLA 3:1，1M 下 KV 缓存省 75%、解码吞吐 6 倍（Kimi Linear,
  2025-10）**——同配方下首次全面超过 full MLA（短、长、RL 三场景），
  宣告 hybrid 对 full attention 的性价比临界点已过；长上下文竞争的
  焦点此后正式定在「全 attention 层数」上。

外加一条让长上下文 RL 成为 2026 面试热点的成本锚：**用 lightning hybrid 在 1M
上下文上做长思考 RL，报 512×H800 训 3 周约 53.4 万美元（MiniMax-M1, 2025-06）**——hybrid 让「1M 上下文的 RL」从不可负担进入可报价区间。

对训练侧的含义直白说：**在 hybrid 时代，「窗口训练」的主战场不再是 PE 谱系外推，
而是怎么设计那一小撮全 attention 层的窗口长度与配比**。前面四节
（课程、长短混合、CP、评测口径）全部照用，只有 PE 谱系这条线的边际地位
在下降。

短篇也被广泛用于回答「为什么 hybrid 能在 1M 训得起」：linear 层的常数
内存加 O(L) 计算，把训推两端的成本曲线同时改斜；省下来的预算再投给
少数 FA 层做长窗训练，等效于把「窗口税」从全局收到局部。

## 七、▶ 面试题与高频追问

1. **PI 是什么、为什么内插比外推好？** 高频。答：位置索引线性缩放，内插
   注意力上界比外推小约 600 倍（PI, 2023），不改架构、LLaMA 7B~65B
   微调不到 1000 步到 32K，rotation 域连续性的代价被压回训练区间。
2. **YaRN 比 NTK 强在哪？** 高频。答：分频 ramp 过渡代替硬分带，加上
   注意力温度系数 √t 修 softmax 熵；比 PI 省 10 倍 token、步数省 2.5
   倍（YaRN, 2023）；工业落地面 Qwen 全系列以 YaRN 四倍缩放用满。
3. **为什么不能只训长文？** 高频。四证据链（LongRoPE 回 8K 补短 /
   LongRoPE2 混合窗口 / Llama-3 门控 / ProLong 短 SFT 反直觉）加成本
   机理两条（attention 平方账、长文边际信号稀疏）。
4. **Ring / Ulysses / USP 差在哪？** 2026 热点。答：通信量是否随 L 膨胀
   这一条先把 Ulysses（恒定）与 Ring（线性可分）分开；再答拓扑——Ulysses
   A2A 被限单机 NVLink 域，Ring 可跨 IB 藏通信，USP 做二维混合 47% MFU
   @208K（USP, 2024）；顺手背带宽表（NVLink4 900 / A800 400 / NDR 50
   GB/s）。
5. **PPL / NIAH 能不能证明长上下文能力？** 送分与翻车双高。答机理（局部
   token 主导平摊扰动）→ 反例（Gemini 1.5 单针 99% 虚高）→ 替代口径
   （RULER 有效窗口、HELMET NIAH 不预测下游、BABILong 只用 10~20%）。
6. **你怎么设计一个把 7B 窗口 4K 拉到 128K 的方案？** 综合题。路径给
   五步：ABF/YaRN 重标定 RoPE → Llama-3 式六段课程（约 1% 总 token 量
   级，每段短评恢复加 NIAH 满分门控）→ 书籍加 repo 长箱 2~4 倍上采样
   且主体仍为短数据 → USP 二维 CP 配 varlen packing → 以 RULER 有效
   窗口口径验收，辅以 HELMET 与 BABILong 交叉。

**追问兜底**：LongRoPE2 的诊断（高频维训练不足致 OOD 维度）、iRoPE/NoPE
加推理温度缩放的图谱逻辑、hybrid 下「有效窗口」口径重定义（Kimi Linear、
Qwen3-Next 以 FA 层比例定成本）、单针 NIAH 被 HELEMT 证伪后用什么做
快速迭代代理（答 RAG 型任务）。
