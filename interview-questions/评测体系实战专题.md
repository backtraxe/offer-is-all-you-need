# 评测体系实战专题：给业务从 0 搭一套评测

> **面向**：会被「给你们业务设计一套评测体系」「两个模型怎么选」
> 问住的读者；默认你已读过 [评测题专项](./评测题专项.md) 的三层
> 骨架，知道 pass@k / pass^k 的口径差异。
> **读完获得**：开工前的三个前提答案、从 0 到 1 的七步落地 SOP
>（每步给决策点与常见坑）、模型选型的完整路子、评测集健康度
> 三诊断，以及一道现场设计题的 90 秒提纲。
> **分工口径**：《评测题专项》讲「评测世界有什么」（口径、
> benchmark 地图、harness），本篇只讲「你的业务从 0 怎么做」；
> agentic 基准专题的「自建内部评测五要素」、评测闭环专题的
> 「judge 可信度工程」与「trace 扩评测集闭环」本文一律引用
> 不展开。本篇的样本配比、成本与抽检数字均为**示例构造**，只
> 演示决策方法，不是行业标准。

## 一、先回答三个前提问题：评谁、为谁评、花多少

搭体系之前先把三件事说死，否则做着做着就会变成分数崇拜。

第一个问题是**评谁**。三层对象对应三张完全不同的卷子：

| 评测对象 | 典型问题 | 对齐到评测题专项的三层骨架 |
|---|---|---|
| 基座模型 | 换底座后能力变没变 | 工具层：公共 benchmark 地图 |
| 单个 Agent 技能 | 订票、改写这类 tool call 准不准 | 工程层：任务四元组 + verifier |
| 业务任务端到端 | 用户的问题最终解决了没有 | 口径层：业务自定义成功率 |

最常见的错误是把三层混成一张卷子：拿基座模型分数推断端到端
体验，或者拿端到端分数给单个技能甩锅。**评谁没定清楚，后面
所有数字都是糊涂账**。

第二个问题是**为谁评**。同一套题，三个用途的严格度截然不同：

- **选型用**：一次性的相对比较，允许噪声大，但必须公平（同
  环境同判分），可以牺牲精度换速度；
- **回归用**：每次发版都跑，必须便宜、快、稳定，宁可漏报也
  不能误报，否则没人再信这套评测；
- **上线门禁用**：不过线不许发，必须保守、低误杀率，高风险
  样本的占比要适当提高。

第三个问题是**花多少**。评测自身就是个成本中心：LLM judge 按
token 计费，全量回归跑一次可能是几十到几百美元量级（示例口径）；
人工标注按条计费，均价更高。预算意识落到两个旋钮上——**judge
只判规则判不了的维度**，以及**抽检比例按风险分层**（高风险样本
100% 过 judge，低风险抽检 5%~10%）。先框住预算上限再谈覆盖率，
顺序不能反。

## 二、七步 SOP：从 0 到 1 的落地流程

### Step 1：目标定义——把「好不好」翻译成可测量的维度

「这个 Agent 好不好」不是一个可测量的问题。第一步是把体感翻译
成 3~5 个可判分的维度，每个维度先定判分口径，再造题：

- **正确性**：任务最终达成了没有（0/1）；
- **格式与契约**：输出是否满足下游消费的 schema 约束；
- **安全与合规**：是否越权、泄露、违禁内容（通常一票否决）；
- **时延与成本**：p95 时延、单次任务 token 花费是否过线。

决策点：维度数量克制在 3~5 个，维度互相独立、各自有明确的
「过了/没过」口径。每个维度配上**正反例样本**，团队先对齐再
动工。常见坑是把「文风」「聪明程度」这类没有判据的维度写进
去——写不出判据的维度，标注员和执行者都会自由发挥，最后
评测集沦为玄学。

### Step 2：样本来源——三条路按配比混着用

| 来源 | 优点 | 污染风险 | 示例配比 |
|---|---|---|---|
| 线上日志回放 | 最真实、覆盖长尾 | 可能混入训练数据泄漏 | 60% |
| 专家手写 | 最准、质量上限高 | 慢且贵、风格单一 | 25% |
| 强模型合成 + 人工筛 | 量大、造题快 | 合成分布偏移、风格同质化 | 15% |

决策点：线上回放为主轴，专家手写定难度天花板，合成题只用于
补覆盖缺口。常见坑有三个：一是合成题不筛直接用，分布和线上
差出几个量级；二是回放日志不脱敏，把用户隐私带进测试环境；
三是三个来源混在一个池子里不标来源标签，后面发现问题想剔除
一批都剔不掉。

### Step 3：分层与规模——统计功效口径必须会算

单一维度的样本池必然偏科，至少按**意图 x 难度 x 风险**三维
分层切保覆盖：意图保业务覆盖，难度保区分度，风险保门禁价值。

规模的统计口径用二项分布保守估计（取 `p = 0.5` 时用最大方差，
是最保守的下界）：

```text
n = z² · p(1−p) / e²
z = 1.96（95% 置信）, p = 0.5
e = ±5%  →  n = 1.96² × 0.25 / 0.05² = 384.16 → 385 条
e = ±3%  →  n = 1.96² × 0.25 / 0.03² = 1067.11 → 1068 条
```

这是把成功率当比例估计的最保守口径；方差更小（p 离 0.5 更远）
时实际所需样本更少。

「50 条 gold 集够吗」的答案是**看用途**：粗筛选型、快速看趋势，
50 条够用——385 条才能压到 ±5%，50 条的半宽约 ±14%（同公式
反推 `e ≈ 1.96 × √(0.25/50) ≈ 0.139`），但作为方向性信号完全
可用；上线门禁、发版判定则不够，噪声比决策阈值还宽。把这句
话讲清楚，比背出 385 这个数字更加分。

### Step 4：判分方式决策树——能执行就不用 judge

按输出形态自上而下选最强的判分器：

1. **规则断言**：输出是确定性答案（分类标签、枚举值、固定
   格式）——正则、schema 校验、exact match，成本为零，
   可信度最高；
2. **执行验证**：输出是代码、SQL、工具调用序列——丢进沙箱
   真跑，结果对就过。**exec 是最强 ruler**：跑出来的能就是
   能，跑出来挂的再漂亮也算挂；
3. **LLM judge**：只有开放式长文本才用——rubric 化打分、
   per-dimension 各一个 judge、上岗前先过人工校准回路，
   具体工程见 [评测与观测闭环专题](./agent/agent评测与观测闭环专题.md)
   第二节，本文不展开。

混合判分是常态：一次评测里格式走断言、取值走执行、自由文本
走 judge。**judge 拿不准的样本要有升级路径**：低置信度自动
转人工队列，人工裁决结果回流进 gold 集——这条兜底路径在
面试里主动讲出来，是「真的做过」和「只背过书」的区别。

### Step 5：三集分工——gold、主战、回归各有更新频率

| 集合 | 规模量级 | 用途 | 更新频率 |
|---|---|---|---|
| gold 集 | 几十条 | 定基线、判分器校准 | 低频，人工逐条审 |
| 主战集 | 几百到上千条 | 日常开发回归 | 两周级随迭代扩 |
| 回归集 | 持续注入 | 线上 badcase 不重复犯 | 高频，case 一出就进 |

三组集合互不替代：gold 集小而精、人工精选，是所有判分器和
judge 的校准锚；主战集走量，扛日常 CI；回归集是线上事故的
疫苗库——每个线上 badcase 修复后 48 小时内必须注回评测集，
否则同一场事故会在下个版本原样再来一遍。常见坑是把三集合
成一坨，更新一个维度就动了基线，分数对比失去参照物。

### Step 6：版本化——评测集也是 artifact

评测集要当软件管：数据集版本号、变更记录、修题走 migration，
旧代码在新版本题集上可重判——这与 agentic 基准专题「自建
内部评测五要素」里的环境快照、版本化迁移是同一套哲学，落地
到业务侧记得三件事：每次评测跑完把**题集版本与判分器版本加
环境镜像三元组**落盘；任何人改了题，diff 之外必须附变更说明；
报告的每个分数都必须能指回某个具体版本。没有
版本化的评测报告，三个月后没人敢信，包括写报告的人自己。

### Step 7：与线上指标校准——离线分数不是终点

离线分数涨、线上任务成功率不涨，先别庆祝也先别慌，按三步查：

1. **查离线集漂移**：线上真实流量分布变了（新渠道、新客群、
   新意图），老评测集还在测旧世界——重新采样线上流量，
   给主战集换血；
2. **查口径断层**：离线以「输出正确」判分，线上以「用户
   解决了问题」判分，中间隔着工具成功率、延迟、兜底策略
   一整条链路——把线上失败样本按失败原因分层倒灌回离线；
3. **查指标误用**：pass@1 当 SLA 用、pass@k 当上线质量报，
   口径错位必然背离——回到 Step 1 重定维度口径。

离线评测的意义是让线上的坏结果**提前在离线上出现**；当离线
和线上持续背离，坏的一定是评测体系，不是线上。

## 三、模型选型评测实战：给业务在两个模型间做决策

「A 模型和 B 模型选哪个」是面试里的高频设计题，完整路子：

- **别信公开榜**。公开榜测的是通用能力上限，你的业务分布、
  prompt 模板、工具链、判分方式和榜单完全不同，两个模型在
  自家业务上的相对排序经常和榜单倒挂；
- **50~200 条自有 gold 集先粗筛**——按 Step 3 的口径，这个
  量级的半宽在 ±10% 上下，压不死 3 个点的差距，但足够把
  明显不行的踹出去；入围的再扩量做精测；
- **线上影子 A/B 收尾**：灰度双跑对拍，同一份流量两边各出
  结果，按业务口径判优劣，排障口径与 [排障面试实战题库](./排障面试实战题库.md)
  的四段论呼应——先指标后假设，两边结果有分歧先固定输入
  重放，再怀疑模型差异。

选型的呈现方式是**成本-质量帕累托图**：横轴每千次任务成本，
纵轴自家口径的质量分，把所有候选模型 + 量化档 + 提示工程
变体都点上去。结论不是「选最高点」，而是**选预算线以上的
最优质量点**——右下角的模型再强，越过预算线就没有讨论
价值；预算线以下只能选离右上角最近的。这张图一画，选型
就从吵架变成读图。

## 四、评测集健康度体检：三个诊断

评测集和人一样需要年检，三个典型病灶及修复动作：

| 病灶 | 症状 | 修复动作 |
|---|---|---|
| 饱和 | 头部模型扎堆 95%+，区分度死 | 换血：提难度、加长尾、引入新意图 |
| 区分度崩 | 同批模型多次跑相关性低，噪声大于差距 | 扩容 + 固定随机种子 + 减 judge 方差 |
| 相关性背离 | 离线涨线上不涨 | 回到 Step 7，重构任务定义与采样 |

三者里最危险的是**区分度崩**——分数排序本身在抖，任何基于
排名的决策都是赌。体检动作不动产：每个版本发版前，用同一批
参照模型跑两遍，**两次跑分的排序相关性**低于阈值就先修评测
集，再谈模型分数。

## 五、现场设计题：「给我们的 XX 产品设计评测体系」

90 秒提纲版，背下来现场就能用：

1. **先对齐三层**：「先确认评的是基座模型、单个技能还是
   端到端业务任务」——一句话把评谁问回来；
2. **三个前提**：为谁评、花多少，用途决定严格度与预算；
3. **七步框架**：目标维度 → 样本三源配比 → 三维分层 + 385
   口径 → 判分决策树 → 三集分工 → 版本化 → 线上校准；
4. **收口**：「评测不是一次考试，是一套随业务生长的产线，
   失配靠回归集注入和在线校准持续矫正。」

常见追问清单：385 怎么算（背 Step 3 公式）；judge 和 rule
怎么选（背 Step 4 决策树）；gold 集 50 条够不够（按用途答）；
离线涨线上不涨怎么办（按 Step 7 三步查）；为什么不直接用
公开榜（第三节第一段）。被追问「能不能举个例子」，就把
Step 5 的回归集注入 48 小时规则讲一遍。

## ▶ 面试题

1. **「95% 置信、±5% 误差的 385 条怎么算的？」**——二项
   比例估计的最保守口径：`n = z²·p(1−p)/e²`，z = 1.96 对应
   95% 置信，取 p = 0.5 使方差最大，e = 0.05 代入得
   `3.8416 × 0.25 / 0.0025 = 384.16`，向上取整 385；误差
   收紧到 ±3% 时同公式得 1067.11 向上取整 1068。高分答法
   是补一句：p 离 0.5 更远时实际所需更少，385 是下界。
2. **「judge 还是 rule 怎么选？」**——按输出形态走决策树：
   确定性输出用规则断言，可执行输出（代码/SQL/工具调用）
   用沙箱执行验证，只有开放文本才上 LLM judge；judge 上
   岗前先过人工校准回路，低置信样本自动升级人工兜底。
3. **「gold 集、主战集、回归集有什么区别？」**——三集按
   规模/用途/更新频率分工：gold 集几十条、人工精选、定
   基线和校准判分器、低频更新；主战集几百上千条、扛日常
   回归、周双周级扩；回归集是线上 badcase 疫苗库，case
   出现即注入。合一池的代价是基线被污染，分数不可比。
4. **「离线涨、线上不涨说明什么？」**——三种可能按序查：
   离线集漂移（流量分布变了老集测旧世界）；口径断层（离线
   评输出对、线上评问题解决，中间链路吞掉了差异）；指标
   误用（pass@1 当 SLA、pass@k 当上线质量）。修复分别是
   换血重采样、分层倒灌失败样本、回到维度定义重定口径。
5. **「公开榜为什么不能直接引用？」**——公开榜的任务分布、
   prompt、工具链、判分方式和你的业务全部不同，自家业务
   上的相对排序经常和榜单倒挂；且榜单饱和与污染问题严重
   （详见评测题专项）。选型只能在自家 gold 集 + 影子 A/B
   上做，公开榜顶天当粗筛的第一轮信号。
6. **「评测集饱和了怎么办，直接换掉吗？」**——诊断先行：
   扎堆 95%+ 是饱和，修复是提难度、加长尾、引新意图；
   但先排除是不是区分度崩（噪声大于差距）或相关性背离。
   换血要走版本化：新版本号、变更记录、旧版本可重判，
   否则新旧分数无法对齐，换血等于把参照系也弄丢了。

## 口径与未核实说明

- **统计口径**：385 / 1068 为二项比例估计最保守公式
  `n = z²·p(1−p)/e²` 在 z = 1.96、p = 0.5 下，e = 0.05 /
  0.03 的 python3 实算结果（384.16 / 1067.11，均向上取整）；
  50 条样本的半宽 ±14% 为同公式反推（`e ≈ 0.139`），已标注
  为最保守口径。
- **示例构造声明**：文中的来源配比（60/25/15）、judge 成本
  量级、抽检比例（5%~10%）、三集规模量级、恢复注入的 48 小时
  建议，均为说明决策方法而构造的示例数字，非任何公司内部口径
  或行业标准——真实业务请按自身成本与流量重新定标。
