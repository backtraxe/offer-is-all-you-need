## 一、一句话主线：三层骨架

评测题是 2025H2–2026 AI infra 面试的高频区。所有题目都能装进同一个三层骨架：

- **口径层**：分数是怎么算出来的？pass@k 看上限、pass^k 看可靠性、avg@k 看期望、
  greedy 看可复现下限——**不还原采样口径，「准确率 80%」就是一句空话**；
- **工具层**：分数在哪份卷子上考的？静态集正在快速饱和并被爬进训练语料，社区的
  答案是**时间轴正交**（滚动采样、赛后新题、人工过滤子集）和
  **「难以求解但易于验证」** 的出题哲学；
- **工程层**：分数是怎么判出来的？独立沙箱、固定环境、自动判分、版本化落盘，
  外加 LLM-as-judge 的三类偏差控制。

前两层的接缝处有一句必须背下来的话：

> **没有还原采样口径、环境配置和评测子集，任何两个榜单分数都不可比。**

直接证据：「**GPT-5 官方披露其 SWE-bench 是在 n=477 子集上跑的**」——不是标准
500 题（openai.com/index/introducing-gpt-5，2025-08）。同一榜单名字下，子集不同、
环境不同、judge 不同，就是不同的考试。

## 二、口径层：任何「准确率」先问采样口径

### 2.1 pass@k：衡量上限的无偏估计量

pass@k 出自 Codex 论文（arXiv:2107.03374，2021）。对每道题独立采样 n 个答案、
其中 c 个正确，则：

```text
pass@k = E[ 1 − C(n−c,k)/C(n,k) ]   （按题取期望后求平均）
```

**1 − C(n−c,k)/C(n,k)** （arXiv:2107.03374）是「抽 k 次至少中一次」概率的无偏
估计——直接「跑 k 次看有没有对过」在小样本下是有偏的，这个是面试加分细节。

必须记住的对照组：Codex-12B 在 HumanEval 上，单 sample 只有 **28.8%，**每题
100 sample 的 pass 率则达 **70.2%** （同论文，2021）——**大 k 衡量的是能力上限，
不是上线质量**。temperature、top-p 显著改变结果，报分必须带解码配置，否则两个
pass@k 不可比。

### 2.2 pass^k：Agent 的可靠性指标

pass^k 由 τ-bench 提出（arXiv:2406.12045，2024）：同一任务跑 k 次**全部成功**
才算过——衡量的是一致性而不是上限。数字锚：GPT-4o 在 τ-bench retail 域上
**pass^8 < 25%** （arXiv:2406.12045），论文原话级结论「前沿 agent 的一致性极差」。

为什么对 Agent 而言它比 pass@1 更贴近线上：**一次失败即事故**。客服场景里
「八成概率答对」翻译成工程语言就是每天几百万次错误承诺。面试里把 pass@1 的
「期望成功率」和 pass^k 的「SLA 可靠性」区分开，是 2025 之后的高分答法。

### 2.3 avg@k 与 greedy vs sampling：期望、下限、复现

四把尺子排开，才是完整的采样口径：

| 口径 | 衡量什么 | 优点 | 代价 / 陷阱 |
|---|---|---|---|
| greedy ≈ pass@1 下界 | 确定性最优解 | 完全可复现 | 低估采样潜力，开放题不适用 |
| pass@1（采样期望） | 单次随机采样的期望 | 最接近真实使用一次的表现 | **pass@1（期望）≠ greedy 准确率**，业界常混用，面试要主动区分 |
| avg@k | 每题跑 k 次取平均 | 方差小、可报误差带 | 不反映上限能力，成本 ×k |
| pass@k | k 次至少中一次 | 能力上限 | 不是上线质量，需要多候选消费场景 |
| pass^k | k 次全对 | 可靠性 / SLA | 单一失败即零分，对任务方差敏感 |

avg@k 是数学/竞赛赛道的主流：MathArena 的协议就是**每题跑 4 次取均值**并同时
报误差带与美元成本（arXiv:2605.00674）。

### 2.4 LLM-as-judge：三种模式 + 三类偏差

主观题没法跑测试用例，只能用模型当裁判。三种模式：

- **pointwise**：按 rubric 打 1–10 分（MT-Bench / G-Eval 式），便宜但绝对分不稳定；
- **pairwise**：两个答案对比（Chatbot Arena 式，**24 万组** 众包配对投票起步，
  arXiv:2403.04132，Elo/Bradley-Terry 排名），稳定但成本翻倍；
- **reference-guided**：给 judge 标准答案协判，事实题首选。

三类偏差与对策（arXiv:2306.05685，2023）：

- **position bias**（先看到的有优势）→ 交换顺序双面裁判，取并集/均值；
- **verbosity bias**（偏爱长答案）→ rubric 限制篇幅含义、要求引用证据；
- **self-enhancement bias**（偏爱自家输出）→ judge 与被测模型脱钩，版本化固定。

GPT-4 judge 与人评的一致率 **超过 80%** （arXiv:2306.05685），约等于人与人之间
的一致性——这是用 LLM-as-judge 的合法性依据，但**必须配工程控制**：judge 模型
版本 + prompt 模板版本化、**5–10%** 人工抽检、多 judge 投票。

## 三、工具层：Benchmark 分区盘点

被问「知道哪些 benchmark」时的正确姿势不是背名字，而是**按污染风险和发展阶段
分区**——每区能给出一两个数字锚即可过关。

### 3.1 知识与推理（静态集：饱和快、污染重）

- **MMMU**（**11.5K 题**、30 学科，CVPR 2024 Oral，arXiv:2311.16502）：多模态
  专家级理解。GPT-4V 发布时 56%，GPT-5 已到 **84.2%** （openai.com，2025-08）——
  两年涨近 30 个点，快速饱和；
- **MMLU-Pro**（arXiv:2406.01574，NeurIPS 2024 D&B Spotlight）：加难度、选项从
  4 増到 10、剔除噪声题，模型普遍掉分 **16–33%，**prompt 敏感性从 4–5% 降到 2%
  ——这是「如何改造一个饱和 benchmark」的**标准案例**；
- **GPQA**（**448 题** 研究生级物化生选择，arXiv:2311.12022）：专家 65%（剔除
  错题后 74%）vs 非专家联网仅 34%、「写都写不对搜也搜不到」；GPT-5 pro **88.4%**
  （2025-08）。日常引用多用 Diamond 子集（198 题）；
- **HLE**（Humanity's Last Exam，**2500 题** 跨数十学科，CAIS+Scale，
  arXiv:2501.14249，已发 Nature 2025）：设计上「无法靠检索秒答」。Gemini 2.5 Pro
  发布分 **18.8%** （Google Blog，2025-03）；OpenAI Deep Research（带浏览+Python）
  **26.6%** （2025）。冷知识：OpenAI 在 GPT-5 博客脚注披露「HLE 早期版本与现版
  分数有出入」——**评测集版本化**的现成案例。

### 3.2 数学竞赛（动态新题：2025 后的首选口径）

- **AIME**（美国数学邀请赛，每年两场共 30 题，答案 0–999 整数）：题目每年全新，
  天然抗污染。GPT-5 无工具 **94.6%** （2025-08）；开源非思考标杆 Kimi K2
  **49.5%** （arXiv:2507.20534，2025-07）。**已接近饱和**；
- **HMMT**（哈佛-MIT 数学锦标赛）：被 MathArena 纳入动态新题来源（题量细节
  未一手核实，不列）；
- **MathArena**（ETHZ，arXiv:2605.00674）：评测平台化的标杆——只收**最新竞赛题**、
  每题跑 4 次报均值 ± 误差带和美元成本、缺失数据用 2 参数 IRT 补估。截至 2026-09：
  GPT-6.1 Sol **90.1% ± 2.3**（单题约 $0.55），GPT-6 Astra **88.0% ± 2.0**
  （约 $2.42），最佳开源 Qwen3.8-Max **56.1% ± 7.6**（约 $3.07）。
  金句：**分数、成本、置信区间一起报**。

### 3.3 代码：生成 → 工程 → agentic 三级

- **HumanEval / EvalPlus**：164 题手写 Python 函数级。EvalPlus（arXiv:2305.01210，
  2023）把测试用例扩充 **80 倍**后，各模型 pass@k 被下压 **19.3–28.9%** 且修正了
  排名——**「测试不足会虚高分数」的必引文献**；
- **LiveCodeBench**（LCB，arXiv:2403.07974，2024）：从 LeetCode/AtCoder/
  Codeforces 滚动采集新题（初始约 400 题，持续滚动），按题目发布时间戳与模型
  训练截止日对齐做**干净窗口**评测；版本滚动（v1–v6 不同时间窗），扩展自修复、
  代码执行、测试输出预测四场景。数字锚：Kimi K2 LCB v6 **53.7** 分
  （arXiv:2507.20534，非思考模型；官方榜当前头部未核实，行文只引此锚）；
- **LiveCodeBench Pro**（arXiv:2506.11928，2025-06）：Codeforces/ICPC/IOI 题
  + 奥赛奖牌队员逐行诊断。无工具时最强模型 medium 档 pass@1 仅 **53%、**hard 档
  **0%** ——**高分主要来自实现精度和工具增强，而非推理**，能把「编码器分」
  和「推理分」拆开问；
- **SWE-bench**（arXiv:2310.06770，2023）：12 个 Python 仓库、**2294 个**真实
  GitHub issue，patch 通过 FAIL_TO_PASS 测试算解出；发布时 Claude 2 仅 **1.96%。**
  家族成员：
  - **Verified**（500 题人工过滤，2024-08）：当前**事实标准**。官方榜第一
    **79.2%** （Sonar + Claude 4.5 Opus，swebench.com leaderboards.json，
    2025-12-05）；纯模型榜首 Claude 4.5 Opus **76.8%** （2026-02-17），
    Gemini 3 Flash 与开源 MiniMax M2.5 均 **75.8%。**两年从约 2% 涨到约 80%，
    即将饱和。Claude Sonnet 4.5 官方称 SOTA，具体数字以官方
    leaderboards.json 为准（社区常引约 77.2%，未一手核实）；
  - **Lite**（300 题降成本）、**Multilingual**（300 题 / 42 仓库 / 9 语言，
    Kimi K2 47.3）、**Multimodal**（480 题）；
  - **SWE-bench Pro**（Scale AI，2025-09）：更难、含商用代码库的扩展集
    （题量社区常引用约 1865 题，未一手核实，不推荐当事实引用）；
- **Aider Polyglot**：编辑/重构类 agentic 代码评测，GPT-5 **88%** （2025-08）。

### 3.4 Agent 与工具使用

- **τ-bench**（arXiv:2406.12045，2024）：retail + airline 两域，LLM 模拟用户 +
  域内 API + policy 约束；**判分 = 对话结束时的数据库状态 vs 目标状态**——不评
  轨迹评终态，这是极关键的设计思想（正确路径不唯一，评轨迹必误伤）。pass^k
  指标出处；
- **τ²-bench**（arXiv:2506.07982，2025）：telecom 双控域（Dec-POMDP，用户侧也
  有工具），组合式任务生成器。Kimi K2 **66.1** 分（arXiv:2507.20534）；
- **BrowseComp**（OpenAI，arXiv:2504.12516，2025-04）：**1266 题**「倒推式」
  出题——从冷门事实反向构造「难搜索、易验证」的题，提出 **asymmetry of
  verification**（求解难、验证易）的出题哲学。Deep Research **51.5%** vs
  o1 **9.9%** vs GPT-4o **0.6%** （GPT-4o+浏览也仅 1.9%）；人类标注员仅解出
  29.2% 自己出的题。彩蛋数字：64 次采样 best-of-N 可再提 **15–25%** ——
  测试期算力聚合的实证；
- **AgentBench**（THU，arXiv:2308.03688，2023）：**8 个环境**打包套件（OS/DB/
  KG/卡牌/Web 购物/网页浏览等），把「环境搭建」从被测方剥离——这是分数可比的
  前提；
- **OSWorld / GAIA**：Claude Sonnet 4.5 OSWorld **61.4%** （Anthropic，2025-09）；
  Deep Research GAIA 平均 **67.4%、**cons@64（64 次采样多数投票）**72.6%** （OpenAI，2025-02）。

厂商发布分速查（发布会口径，对照子集披露）：GPT-5 SWE-bench **74.9%**
（**n=477 子集**，2025-08）/ AIME 2025 94.6% / MMMU 84.2% / GPQA 88.4%；
Gemini 2.5 Pro SWE-bench **63.8%** / HLE 18.8%（2025-03）；Kimi K2 SWE-bench
**65.8%** / Tau2-Bench 66.1（1T 总参 / 32B 激活，arXiv:2507.20534）。

## 四、防污染与防作弊

### 4.1 污染检测三板斧（外加两件小众武器）

- **n-gram 重叠**：GPT-3 式 13-gram 碰撞判定，训练语料命中测试题即剔除——防不了
  **改写泄漏**（换个说法照样见过）；
- **Min-K% Prob**（arXiv:2310.16789）：取输入中概率最低 k% 的 token，其平均对数
  概率高于阈值即「见过」，配套 WikiMIA 检测集；升级版 Min-K%++
  （arXiv:2404.02936）在 WikiMIA 上 AUROC 提升 **6.2–10.5%；**
- **Time Travel**（arXiv:2308.08493）：引导式补全——按原文分段前缀让模型续写，
  能逐段精确复述说明见过，检测精度 **92–100%，**实证 GPT-4 在 AG News/WNLI/XSum
  上被污染；
- **Data Contamination Quiz**（arXiv:2311.06233）：把原文与三个词级扰动改写做成
  选择题，见过原文的模型会在选项间暴露偏好；
- **canary string**：评测集嵌入一段永不自然出现的随机字符串（BIG-bench canary
  前缀 26b5c67b-…），训练方用它过滤语料——「君子协定」式道标。

### 4.2 LCB 为什么抗污染：时间轴正交

模型能污染的只有**训练截止前**公开过的题目。LCB 持续采集截止日**之后**发布的新
题，按题目发布时间戳对齐模型发布日——时间成为不可作弊的正交轴。MathArena 只收
最新竞赛题同理。

代价也明示：维护成本高、题量有限、**跨时间不是同一套题**（AIME 2024 vs 2025
难度不齐——这正是 MathArena 用 IRT 模型做补估的原因之一）。

### 4.3 冲榜手段与社区反制

手段四连（面试要数得出名字）：

1. 评测集或改写样本进训练数据（直接污染）；
2. 针对 benchmark 风格做 SFT/RL **过拟合**（风格刷分）；
3. **挑子集 / 换口径报分**——正面例是 GPT-5 明确披露 n=477 子集，属合规披露；
4. judge 用自家模型 self-enhancement；**测试期隐藏算力**（parallel sampling 报成
   pass@1）；针对专项训练（OpenAI 自己注明 BrowseComp 分数是「专门训练过」的）。

反制清单：滚动新题、人工过滤子集（Verified）、公布全部 completion 供复跑、
统一 harness 官方复核、**要求开源预测与日志**（SWE-bench/experiments 仓库把每期
预测、日志、轨迹全量落盘开源，社区审计基础设施，最后更新 2026-09）、污染声明与
canary、Min-K% 事后审计。

## 五、工程层：判题沙箱与评测 harness

### 5.1 判题三级：IO 比对 → 断言注入 → 仓库级测试

- **竞赛级**（Codeforces 式）：标准化 stdin/stdout + 多测试用例比对；
- **函数级**（HumanEval）：注入测试断言验证函数行为；
- **工程级**（SWE-bench）：仓库级环境 + fail-to-pass 测试集，patch 必须让
  原失败测试转通过且不破坏既有测试。

沙箱四要点：**每题独立容器**（SWE-bench 逐 repo 官方 Docker 镜像锁定依赖——
可复现性的根基）、资源限制（CPU/内存/wall-clock 超时）、网络隔离、只读挂载 +
结果 artifact 落盘。

judge 三档：全对/全错；按测试用例部分分；LLM 与规则混合。EvalPlus 的结论在此
适用：**测试用例覆盖率直接决定榜单可信度**。另一个经典工程范式是 AlphaCode
（arXiv:2203.07814）：大规模采样 → 公开测试过滤 + 聚类去重 → 小集合提交，
「先广撒网再判题」。

### 5.2 ACI 与评测框架：接口是主要性能变量

SWE-agent（arXiv:2405.15793，2024）的核心概念 **ACI（Agent-Computer
Interface）**：为 agent 专门设计命令集、文件查看/编辑工具与返回格式。论文证明
**接口设计本身是主要性能变量**——GPT-4 在 SWE-bench 上从非交互约 0 到
**12.5%** pass@1，全部收益来自接口与脚手架。

由此引出评测设计的第一性公式：

> **任务成功率 = f(模型, 接口, 环境)** ——评测要做分变量归因，不能把接口收益
> 记到模型头上。

框架侧三个名字：inspect-ai（UK AISI）的 **dataset → solver → scorer** 三段式，
scorer 可插拔（exact match / model-graded / 工具执行结果）；AgentBench 把 8 个
环境打包托管；τ-bench 系列确立两个工程范式——**终态判分**（比对 DB 状态）与
**模拟用户**（LLM 扮演但受工具与状态约束保证保真度）。

### 5.3 可复现五件套（面试送分背板）

被问「评测平台工程上怎么保证可复现」，就是这五件：

1. **逐题容器化 + 依赖锁定**（SWE-bench 逐 repo Docker 镜像）；
2. **模型版本与解码参数写进结果元数据**（temperature/top-p/seed）；
3. **判分器开源可插拔**（inspect-ai 的 scorer 模式）;
4. **trajectory / completion 全量落盘开源**（SWE-bench/experiments 式社区审计）；
5. **多次运行报均值 ± 误差**（avg@4，MathArena 协议：分数 + 成本 + 置信区间
   三报）。

配套 trace 可观测性：每一题的完整 trajectory、prompt、模型版本、温度都要落盘，
否则无法回放审计——这既是评测工程，也是 agent 线上排障的同一条地桩。

## 六、▶ 面试题（十道背熟）

### 1. pass@k 和 pass^k 的区别？什么场景看哪个？——**高频**

pass@k 看**上限**（k 次至少中一次，适合有多候选消费场景的代码补全）；pass^k
看**可靠性**（k 次全对，适合 agent / SLA 场景——GPT-4o 在 τ-bench retail 域
pass^8 < 25%）。补全画幅：avg@k 看期望且方差小（MathArena 每题 4 次），greedy
给出可复现下限；强调 **pass@1（期望）≠ greedy 准确率**，业界常混用要主动区分。

### 2. 如何设计一个面向自家业务的评测集？——**高频**

真实线上失败 case 优先 + 专家构造 + 合成扩量；**50–200 条**高质量 Gold 起步；
每条带期望结果与可接受路径（不只一个标准答案）。防泄漏：滚动更新 + canary；
Gold 集 / prompt / 模型配置三件套版本化。指标双 gate：primary 用任务成功率，
guardrail 卡幻觉率与工具误调率。

### 3. 静态 benchmark 分数可信吗？怎么防数据污染？——**高频**（2025 后必问）

静态集饱和 + 被爬进训练语料不可避免。检测三板斧：n-gram 重叠、Min-K% Prob、
引导式补全 Time Travel（92–100% 精度）。根本防线是**时间轴正交**：滚动新题 +
canary + 全量 completion 开源审计；公开 Gold 集定期换血并保留私有 holdout。

### 4. 怎么评估 agent 的 trace 质量？——**中高频**

两层：结果层（成功率）与过程层（步数、工具调用准确率、重复调用率、无效回溯
率）。τ-bench 的教训：**优先终态判分而非轨迹判分**（正确路径不唯一）；轨迹质量
用 LLM-as-judge rubric（计划合理性、工具参数正确性、错误恢复）+ 5–10% 人工
抽检。一句话收口：答案对但瞎蒙路径的，上线迟早翻车。（agent 过程层的指标细目见
《多 Agent 与评测》，本篇不重复展开。）

### 5. 厂商榜单分数怎么被 hack？社区怎么反制？——**中高频**

手段四连：评测集进训练（或改写泄漏）、风格过拟合、挑子集换口径（GPT-5 n=477
是合规披露的正面例）、judge self-enhancement + 隐藏测试期算力。反制：滚动新题、
人工过滤子集、强制披露环境与子集口径、judge 脱钩 + 版本化、统一 harness 并要求
开源 trajectory。

### 6. LLM-as-judge 有什么坑？怎么让它可信？——**高频**

三类偏差及对策：position bias → 交换顺序双面裁判；verbosity bias → rubric 限长
+ 要求证据；self-enhancement bias → judge 与被测脱钩。合法性依据：GPT-4 judge
与人一致率超 80%，约等于人与人一致性（arXiv:2306.05685）。工程三件套：judge
模型与 prompt 版本化、5–10% 人工抽检、多 judge 投票；开放题 rubric、事实题
reference-guided。

### 7. 为什么是 SWE-bench 而不是 HumanEval 成了 coding 事实标准？——**中频**

HumanEval 函数级、测试少、已饱和，被 EvalPlus 证明虚高 19–29 个点；SWE-bench
仓库级真实 issue，考长上下文 + 跨文件修改 + 环境交互，判分客观（fail-to-pass
测试，无需 judge）。三要素收口：**接近真实工作 + 判分客观 + 曾长期未饱和**——
现在 Verified 逼近 80%，正在重走 HumanEval 的老路，所以变体和滚动集接力。

### 8. 怎么设计评测才不被 RL/SFT 过拟合？——**中频**

时间滚动（LCB/MathArena）；分布上让评测分布 ≠ 可抓取公开分布（私有 Gold 集定期
换血）；同时报 pass@1 与 pass^k 防采样刷分；分数 + 成本 + 置信区间三报
（MathArena 式）；保留 holdout 私榜——公榜对外声明、私榜真实回归。

### 9. AIME / LCB 头部都 90+ 了，换什么？——**中频**（2026 新热点）

换代路径：AIME → HMMT / MathArena 新赛题；LCB → LiveCodeBench Pro（hard 档头部
仍 0%）；SWE-bench Verified（约 80% 近天花板）→ Multilingual / Multimodal /
Pro 变体；知识类 → HLE（Deep Research 带工具仅 26.6%）；Agent 单控 τ-bench →
双控 τ²-bench、BrowseComp（难搜易验的 1266 题）。

### 10. 评测平台工程上怎么保证可复现？——**中频**

背五件套：逐题容器化 + 依赖锁定（SWE-bench 逐 repo Docker）；模型版本与解码
参数写进结果元数据；判分器开源可插拔（inspect-ai 模式）；trajectory/completion
全量落盘开源；多次运行报均值 ± 误差（avg@4）。补丁：统一 harness 官方复核 +
社区审计仓库（SWE-bench/experiments 每期预测全开源）。
