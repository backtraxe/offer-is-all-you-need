# 推理引擎实战：tiny-llm / nano-vllm / mini-sglang 与 kernel 副件

> 本篇面向投「推理 infra / 推理引擎」岗的读者，对应面试考察全景的
> 技术栈纵向线：
> [推理 Infra 社招面经与备战](../interview-questions/inference/推理infra社招面经与备战.md)。
> 读完你会获得：一个主项目三选一对照（tiny-llm / nano-vllm / mini-sglang）、
> kernel 三个副件（llm.c / Liger / GPU MODE 题集）、benchmark 报告的
> 标准化出品流程、以及「面经里那些真题 ↔ 项目哪个模块能答」的对照。
> star 数为 2026-10 当日 gh 实测。

## 一、主项目三选一：对照与互不能替代

| 项目 | star | 语言/后端 | 一句话 | 优势 | 风险 |
|---|---|---|---|---|---|
| [skyzh/tiny-llm](https://github.com/skyzh/tiny-llm) | 4.8k | Python / MLX（Apple Silicon） | 系统工程师向 tiny vLLM 12 周课程：从零搭推理系统，Qwen2/Qwen3 MoE、量化、prompt cache、sampling、structured output | 课程驱动、覆盖最全（调度→KV→量化→MoE）、star 少=差异化 | MLX 栈 ≠ CUDA 栈，面试需话术平移到机制层；12 周有压缩空间 |
| [GeeeekExplorer/nano-vllm](https://github.com/GeeeekExplorer/nano-vllm) | 15.7k | Python / CUDA | vLLM 离线核心精简复刻：Continuous Batching + Block 化 KV BlockManager + CUDA Graph + TP，可跑 Qwen3 | 小红书/字节近期面经点名的「标准第二项目」，吞吐对标原版 | 已开始烂大街，**只有增量改造才值钱**；复刻跑通不算项目 |
| [sgl-project/mini-sglang](https://github.com/sgl-project/mini-sglang) | 5.2k | Python | SGLang 官方 mini 版：RadixCache 前缀共享、chunked prefill、CPU offload、多后端 dispatcher；带 "Read and learn" 文档和 first PR 指引 | 官方维护、直接衔接真源码与 PR 路径、RadixCache(前缀缓存) 面经必问 | 全量比较大，只逐行透 scheduler + RadixCache 两文件即可 |

**选择逻辑**：

- 面拔/字节系/中文社招 → **nano-vllm** （勤中点名） + 吃透一个增量；
- 投 SGLang 生态八卦（月暗/DeepSeek 类推理组） → **mini-sglang**；
- 时间充足且无狠卡环境限制（Mac） → **tiny-llm** 为主线全程跟；
- 无论选哪个，另一个都当**对照组**（面试追问「SGLang 和 vLLM 差在哪」
  时轮到你讲——见
  [vllm与sglang深度对比](../interview-questions/inference/vllm与sglang深度对比.md)）。

配套课材：datawhalechina/zero-to-sglang（1.4k，官方课程：理解推理 →
手写 mini-sglang → 读真源码 → 落第一个 PR）；bcefghj/learn-nano-vllm
（245，20 节课 + 72 道八股中文版）；slwang-ustc/nano-vllm-v1（100，
补了 vLLM v1 调度 + chunked prefill——可以直接当你的**增量改造 fork**）。

## 二、面试官必问的主项目追问预演

以 nano-vllm/mini-sglang 为主线，五层追问这套家现在就能预演：

1. **调度层**：continuous batching 的调度循环里 prefill/decode 怎么
   解耦？token budget 怎么分配？chunked prefill 解决什么问题
   （长 prefill 霸占 GPU 导致 decode 中断）；
2. **存储层**：BlockManager 的物理 block 分配与 free list、序列结束后的
   引用计数回收；RadixCache 怎么做前缀共享（树节点与 block 的映射、
   驱逐策略）；
3. **kernel 层**：PagedAttention 为什么 decode 是 memory-bound？
   IO 复杂度推一遍（对照
   [长上下文推理与kv体系](../interview-questions/inference/长上下文推理与kv体系.md)）；
4. **推理性能层**：CUDA Graph 为什么要 discard padding batch？capture
   的前提条件？TP 下 all-reduce 通信量建模、NCCL 阻塞 vs CUDA Graph
   的顺序问题（nano-vllm issue #25 就是现成的事故案例）;
5. **工程验证层**：吞吐/延迟怎么测的？不同输入输出长度分布下曲线
   长得不一样说明什么？——接下面第四节 benchmark 报告。

**砍圈顺序**（时间不足时）：先砍 TP 与 CUDA Graph，保住「调度器 +
BlockManager + benchmark」三件套即可讲满 20 分钟；如果还有余粮，
加 RadixCache（前缀缓存）一层——这是 SGLang 系的分水岭题。

## 三、kernel 三副件：CUDA 话题的弹药库

| 副件 | star | 投入 | 产出 |
|---|---|---|---|
| [karpathy/llm.c](https://github.com/karpathy/llm.c) | 31k | 2-3w 挑 3-4 个 kernel | fused kernel 复现 + nsys profiling 报告 + 「为什么比 cuBLAS 慢」标准答案（tail effect、occupancy、寄存器压力、缺 split-k） |
| [linkedin/Liger-Kernel](https://github.com/linkedin/Liger-Kernel) | 6.6k | 0.5-1w | 接入自己的 nano/训练脚本，前后显存/吞吐实测表；讲清「kernel fusion 降低 per-token HBM 访问量」 |
| [gpu-mode/reference-kernels](https://github.com/gpu-mode/reference-kernels) | 315 | 按题 (1-2 道) | Triton block size/num_warps/num_stages 调参与 autotune 代价；**榜单名次可截图直入简历** |

技巧：kernel 副件不需要做成完整项目，简历上一行「复现/接入 X
并给出 profiling 数据」就够，回答「写过 kernel 吗」这类懒问时就是
你的**真证据**（对照面试考察全景的 kernel 副泳池）。深读不需复现的
两份参考：官方 flash-attention（CUTLASS/CUTE 源码）与
deepseek-ai/FlashMLA（13k，Hopper 上 MLA kernel，聊 DeepSeek 架构必引）——
能画出 tiling 图即可，别自研（自研成本极高且与主项目抢时间）。

## 四、benchmark 报告：任何项目的「最后一节」

主项目 90% 的面试区分度都在这一节里。标准出品流程：

1. **工具**：vLLM 官方 `benchmarks/benchmark_serving.py`（TTFT/TPOT/
   P99/ITL 口径从这里来）+ ninehills/llm-inference-benchmark（440，
   中文社区常用）。
2. **控制变量**：固定 seed、输入/输出长度分布写明（不是一句"标准
   分布"）、分开 prefill/decode 峰值、多次运行取分位数不是均值。
3. **必出四张图**：并发×吞吐曲线、TTFT/TPOT×并发曲线、KV 打满点
   （显存/容量撞墙点）、算力 vs 带宽分界（roofline 定位）。
4. **必答三问**：阈值（多少并发后 TPOT 急剧变差）/归因（瓶颈是显存、
   带宽还是调度？依据是什么）/trade-off（为 AFL 让了什么）。

口径续接 [infra面试计算题专项](../interview-questions/inference/infra面试计算题专项.md)
的压测口径与 [推理服务slo与运营](../interview-questions/inference/推理服务slo与运营.md)
的 SLO 拆解——面官问「你愿意为负载牺牲什么」时，这是标准答法框架。

## 五、源码 PR：最强信号，成本最低

2026-10 快照（两边仓库都在消化）：

- **vLLM**（93.5k★）：good first issue 15 个开放——文档/NIXL 指标
  文档、量化 config refactor（Int8ScaledMMLinearLayerConfig）、
  环境变量整理 RFC、KV-cache update 从 attention backend 抽取。
- **SGLang**（36.9k★）：12 个开放——diffusion time breakdown /
  update-weights profiling / 启动并行化 / JIT 李编译缓存统一 /
  SGLang Cookbook 社区贡献 Roadmap。

玩法：先提 docs/typo 级 PR 混脸熟 → 再挑 profiling/测试类 issue。
**合入一个 PR 的信号强度大于全部玩具项目加和**；投没合也成立——
面试讲 issue 链接和讨论记录。风险：上游 review 周期长，别把合入
当时间节点的硬依赖。

## 六、与面试真题的对照（面经 ↔ 项目模块）

| 面经高频真题（来源） | 主项目里的答出来处 |
|---|---|
| 只有 batch size 1→128、prefill 也组 batch、padding 缩短、按预估长度排序——3500s→130s 链（百度三面） | 调度器改造第二条主线，全部四步都在你的调度器+benchmark 里可复现 |
| PagedAttention 的 pages 是怎么分配的、free 后怎么回收（阿里系/字节） | BlockManager 那一千行代码 |
| Prefix cache 命中率是上 SLO 的核心、怎么设计前缀匹配（SGLang 系） | RadixCache 一节 + 命中率剖面实验 |
| 量化 kernel 为什么 per-channel 比 per-tensor 难（量化岗） | Liger/llm.c int8 实验 + runq.c 读法 |
| 让你设计一个 KV block allocator 手撕（社招 20% 题型） | 直接就是 BlockManager 的面试手撕版 |
| Triton 手搓 GEMM / flash-attn（一线 cross 层拷打） | GPU MODE 题集 + llm.c kernel 复现 |
