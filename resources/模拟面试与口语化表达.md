# 模拟面试与口语化表达：把「背过」变成「讲得出」

> 2469 赞面试官帖的结论：简历清一色写满关键词，**落地细节撑不过三轮
> 追问**。面试是口试——仓库所有专题解决「你知道」，本篇解决「你讲得
> 出、接得住、卡壳了能救回来」。三部分：答案结构、STAR 故障叙事、
> 两套组好的模考卷。

## 一、90 秒答案四拍结构

任何概念题按四拍组织，总时长控制在 60-120 秒：

```text
① 问题     10s：这是什么、解决什么痛点（一句话定义，别背书）
② 权衡     30s：为什么这样设计 / 和其他方案的取舍（这是区分度所在）
③ 结果     30s：落地时的关键细节、数字、坑（证明你碰过）
④ 收口     10s：主动给出追问方向（把节奏拿回来）
```

### 示范 1：RAG 的 bad case 怎么分析（百度一面原题）

> ① 检索没召回和模型乱编是两类完全不同的病，先分诊再治。
> ② 我的方法是**从查询处理、检索、重排、上下文拼接到生成，逐层
> 检查正确证据第一次消失的位置**——证据在检索层就丢了改召回，
> 重排后被挤掉了调 topK 或换模型，拼上下文时被截断了改预算分配。
> ③ 实际操作里我会建一个 badcase 集，每个 case 标注消失层，修复
> 后回归跑一遍防止修旧坏新。
> ④ 这套方法在多路召回上调通道权重时也用，要不要展开？

### 示范 2：Workflow 和 Agent 的分界线（月之暗面/腾讯一面）

> ① 分界线是控制权在代码还是模型：Workflow 控制流代码预设，模型
> 只干节点任务；Agent 的下一步由模型结合当前状态定。
> ② 复杂不等于该用 Agent——流程可枚举时 Workflow 稳定便宜易测试，
> 只有动态规划的收益超过随机决策、循环失控和工具误用的成本时才
> 上 Agent。我项目里用的是外层状态机限路径、局部节点放动态决策。
> ③ 落地时的真问题是停止条件和预算：最大轮数、总 token、费用、
> 截止时间四个预算都要设，耗尽了退化成 Workflow。
> ④ 这块跟 ReAct 的stride 控制是一脉的，可以继续聊。

### 示范 3：KV Cache 是什么（追到场算）

> ① 自回归生成每步都要用到历史 K/V，缓存它们避免每步重算。
> ② 代价是显存：**公式是 2×B×S×KV 头数×头维×字节数×层数**——
> 追问到数字就现场算（见
> [coding/手写kv显存公式](../coding/模型手撕/手写kv显存公式.md)）。
> ③ 所以长上下文优化都在动这个公式：GQA 减 KV 头、MLA 压缩低维、
> SWA 把 S 封顶、量化减字节、分页管理减碎片。
> ④ 部署侧 PD 分离、前缀缓存也都是围着它转。

## 二、STAR 故障叙事模板（「讲一次线上故障」题）

面试官补充的判断标准（评论区口径）：**只跑过 demo 的人讲不出
「发现」那一环**。模板五拍：

```text
S 场景  什么系统、什么规模（一句话）
T 任务  你负责的部分
A 行动  分三层：怎么发现（监控/告警/用户反馈？）
        → 怎么定位（什么排查路径，排除了什么）
        → 怎么修（方案与取舍）
R 结果  数字：恢复时长、错误率变化、后续回归防护
+ 沉淀  你补了什么机制/文档/测试，让它不复发
```

没有生产故障可讲时的诚实替代：压测中暴露的问题、开源项目复现的
issue、课程项目的容量实验——**讲清发现路径，比夸大事故更得分**。

## 三、模考卷 A（Agent 应用方向，10 题 / 45 分钟）

组卷来源：2026-10 六轮面经调研。自测标准：每题能按四拍讲满 90 秒、
关键点覆盖数 ≥ 标注值，不达标回括号内章节。

1. Workflow 和 Agent 的分界线（4 关键点，agent基础与规划）
2. 工具调用报错/参数不合 schema/下游超时的三层处理（3，工具调用与mcp）
3. 第二十轮丢失最早关键信息的排查路径（3，记忆与上下文工程）
4. Agent 死循环怎么兜底——步数上限之外还有什么（2，同工具同参数检测）
5. RAG 从查询到答案的完整链路 + 每层评测指标（5，rag全链路）
6. 为什么选状态机而不是线性 Chain？分支失败怎么回滚（3，langchain与编排框架）
7. Function Call 返回 JSON 不标准的兜底方案（3：重试/正则/schema 降级）
8. MCP 和 Skills 的区别、各自底层怎么工作（4，mcp与工具调用深度对比）
9. 怎么设计一个覆盖完整 RAG 链路的评测方案（三层口径，agent评测与观测闭环专题）
10. 多智能体并发修改同一状态怎么仲裁（3，多agent与评测）

## 五、救场话术与边界礼仪

- **不会的正常降级**：「这块我没实操过，但我的理解是……如果要落地
  我会先用 X 方案验证」——字节面试官原话「现在都 vibe coding，更
  看重定义问题的能力」，**定义清楚问题比背出答案得分高**。
- **连环追问被问穿**：别编，「这个深度我没到过，下来我确认后同步
  您」比硬撑专业。
- **AI 工具问题大方认**：日常 vibecoding 工作流是什么、产出怎么
  review、踩过什么坑——装不用反而可疑（平头哥评论区：「面试造
  航母，实际 codex 启动」）。
- 语速：紧张时先写三个关键词再开口，或要求「我想 10 秒」——这是
  加分动作不是减分动作。
- 别用 AI 提词器：快节奏面试一眼被看穿（智谱面经口径）。

## 六、时长配比：面试时间预算怎么花

实测样板：丁师兄大模型「大模型面试现场：八股、项目细节拷问」
（抖音模拟面试剧场，14 分 44 秒，2293 赞；商家认证账号演出体裁，
取结构不取题目）。平台章节要点四段直录：

- 大模型基础拷问：2 分 24 秒，约 16%
- 大模型项目介绍：2 分 20 秒，约 16%
- 项目细节拷问：4 分 35 秒，约 31%
- 大模型核心技术拷问：5 分 12 秒，约 35%

项目相关（介绍+细节拷问）合计约 7 分钟，占全场近一半——八股是
入场券，项目才是主战场（与合集项目深挖六问、题目跟着简历走多源
同向，详见 [面经合集](../interview-experiences/小红书社招面经合集-2026h2.md)
四十七节）。45 分钟自测按同比例切片：约 7 分钟基础快问快答、
约 7 分钟项目陈述、约 15 分钟项目追问、约 16 分钟核心技术拷问
——模考卷 A/B 计时就照这个预算执行，前段八股别恋战。

行情注：该卡收藏 1334 / 点赞 2293，收藏赞比 58%——素材式消费、
收藏备用，模拟面试口述训练是真需求。
