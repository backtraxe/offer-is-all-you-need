## 发布前自查清单（勾满才发出去）

**防造假三问**（每个项目过两遍）：

1. 最大难点是**这个项目特有**的吗？「资源不够」「显存大」一票否决；
2. 每个量化数字三方对账了吗——原代码 / 真实日志 / 你今天随口能不能
   报出口径（样本量、输入分布、硬件环境、消融对照）；
3. 证明「真能用」的材料是什么——repo 可点？benchmark 曲线？还是
   badcase 集？「提升明显」「大幅优化」「参与了」全部清空。

**60s 初筛密度检查**：

- [ ] 第一屏（基础信息 + 个人优势）有 ≥3 个带单位带起止值的数字；
- [ ] 两行禁忌词扫描：无「搭建了一个」「使用知名框架」「提升明显」；
- [ ] 技能分层 ≤15 行，写上去的技能都敢被手撕；
- [ ] 主项目难点句不含共性词；
- [ ] GitHub 链接全部点开过、README 有 benchmark 结论；
- [ ] 规操红线扫描：未出现「规约算法 / bank 冲突 / 性能分析工具 /
  FP16·32 量化」类表述；量化写的是 FP8 / INT8；
- [ ] 每项收益旁有基线说明 + 距 Roofline 极限的剩余空间（防「基线太烂」
  反问）；
- [ ] 差异化锚存在：主项目不是 nano-vllm 裸复刻成品图，最好有 upstream
  merged PR 或 profile 找瓶颈的深度改造；
- [ ] 关键数字已加粗；整份仅 1 页，定位专一（部署优化与算子不混写）。

换成 Agent/RAG 分层（抄范文 B 的技能分层），投英伟达/外企换英文
