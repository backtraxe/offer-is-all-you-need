# 简历结构与量化写法：骨架、公式、防造假三问与工具盘点

> 本篇给「写完觉得自己简历没问题，投出去被秒挂」的读者。骨架部分基于
> 面试官自述「看三个地方就定」的初筛红笔；量化与防造假部分基于小红书
> 面试官帖的三问框架；工具部分基于 GitHub 2026-10 实测（star 为当日值）。

## 一、骨架六块（按重要性排序）

| # | 模块 | 面试官几秒读完什么 | 写法要点 |
|---|---|---|---|
| 1 | 基础信息 | 城市/手机/邮箱/工作年限/当前职级 | 一行收完，别占半屏；教育背景按岗回溯（非应届只留一行学历） |
| 2 | 个人优势/概览 | **第一屏的核心**——3-5 条能力 × 落地成果 | 不要堆技能词；每条「能力 + 一句话证据数字」。例：「熟悉 LLM 推理系统优化：在某引擎上落地 Continuous Batching 与 Prefix Caching，P99 TTFT 降 35%」 |
| 3 | 技能清单 | 扫一遍判断技术栈边界 | **分层写**（引擎/框架/语言/Infra 基建/LangChain 类生态），面试官一眼看懂你的技术栈范围；别超过 15 行 |
| 4 | 工作经历 | 公司/岗位/时长 + 一两句职责 | 社招重此块，校招可弱化；空降得名后面必须能和项目绑定 |
| 5 | 项目经历 | **正文**（详见第二节 4 段式） | 主项目 1-2 个写透 > 罗列五个；工程/研究背景按岗加权 |
| 6 | 其他 | 论文/开源/博客/竞赛 | GitHub 需要能点开——面试官**真的会提前翻 GitHub**（百度三面实测：全部看完后要求「别念稿挑关键讲」） |

**HR 60s 初筛漏斗**：城市/岗位匹配（2s）→ 个人优势区数字锚（5s）→
最近一段项目的技术关键词（10s）→ 其余扫读（40s）。**把密度最高的
数字放在前两屏**。

## 二、项目 4 段式（大模型/infra 简历的事实标准）

简历贴里反复出现的「经典 4 段式」，每段 1-3 行：

```
项目背景 → 一句话：业务痛点是什么、为什么用大模型/为什么是你
核心难点 → 一句话：该项目 *特有* 的技术难点（不是「资源不够」）
核心工作 → 3-6 条 bullet：系统设计/关键决策/还对比过什么
项目成果 → 全部量化：指标基线值前后对比 + 度量口径一行备注
```

面试官给的两条注释：

- **难点必须是「这个项目的」**，「训练资源不够」「显存大」是所有
  长训/大模型项目的共性，写出来等于说「我搞不清难点」；
- **成果必须可追问**：每个数字要能接住「怎么测的、几个样本、
  什么环境、消融怎么做的」——资上「提升 60%」就是被反问的入口。

## 三、量化公式与句式库

**优化句式模板**（面试官原话级抄答案）：

> 针对 [实际瓶颈] 引入 [工具检索/模型路由/角色记忆]，在固定任务
> 条件下，将 [成本或耗时] 由 [A] 改善至 [B]，同时记录通过率与
> 错误副作用变化。

四类可以直接改写的量化 bullet（真实简历里反复出现的句式）：

1. **准确率类**：「检索准确率从基线 65% 提升到 82%（固定 100 条
   标注集的 top-5 命中率）」
2. **成本/延迟类**：「单位成功任务 LLM 成本 A→B（langfuse 按 trace
   统计）、TTFT P99 降 35%（同卡型 7B 引擎压测口径）」
3. **吞吐/容量类**：「单卡吞吐提升 4×（stateless 压测脚本、输入
   长度分布 [X±Y]，结论跨三种卡型一致）」
4. **可信度类**：「故障后续跑成功率 x% → y%（三账并发记账 +
   幂等键远端核对，注入 39 类故障分支回归）」

**禁忌词与句式**（写了就减分）：「提升明显」「大幅优化」「使用
知名框架」「搭建了一个」「参与了」——没有单位与起止值。**一个
不可追问的数字 = 零；没有数字的表述 = 负（占排版）**。

## 四、防造假三问（写完简历必自查）

抄自面试官「几个问题，造假项目就现行」帖——简历上的每个项目用
这三问自己打两遍，任何一层卡住就下修：

1. **最大难点是什么？**——必须给出该项目**特有**的技术难点，
   「资源不够」「显存大」不算数；
2. **数据/材料从哪来，怎么配？**——**按能力配比，不按长度/占比
   配比**：「多跳推理拉胯，就定向合成推理问答对补那一类」，占比
   只是结果，能力缺口才是核心；
3. **怎么证明真能用？**——**别记总分记短板**：「检索能撑满 128K
   但多跳有效长度只有 40K、lost-in-middle 在 60K 有个坑」，
   记住的子任务短板才是你下一步迭代的依据。

对应到项目篇的仓库项目，三问都能接住（每个详解里都标注了「特有
难点 / 数据配比逻辑 / 分项短板」）。

## 六、红线三条（面试官亲述）

1. **GitHub 会被提前翻完**：写的项目必须仓库可点、README 有 benchmark
   结论，「别念稿挑关键讲」；代码不行宁可不放链接；
2. **模拟数据不能写成真实业绩**：模拟环境产出（如 harness 项目帖的
   「虚拟时钟推七天」）写成「真实业务产出」是红线，简历要写清
   「实现与接入边界」；
3. **AI 润色后必须事实复核**：每个数字三方对账（原代码/真实日志/
   你昨天还能不能随口报出）——AI 爱编口径。
